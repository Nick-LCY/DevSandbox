# 镜像缓存清单与缓存优先拉取引导

> 日期：2026-11-14
> 来源：[[current-state.md|当前状态]]「规划」区 2026-11-14 登记的方向，已与用户讨论收敛，**本文全部口径为已拍板定论**
> 关联：TODO「统一镜像代理缓存 GC 命令待做」——与本轮共享同一套缓存扫描底座，**GC 不在本轮范围**
> 先例：机制落核心包 + 接口在服务端（[[prds/runtime-file-transfer.md|运行期文件传输]]）；平台强制 env 注入（`SANDBOX_NETWORK` / locale，文件窗格轮落地）

## 背景

统一镜像代理（`rpardini/docker-registry-proxy:0.8.0`，HTTP 层 MITM 透明缓存代理）的平台级缓存，对沙箱内是**不可见**的：沙箱 A 拉过 `postgres:16` 后缓存已命中，但沙箱 B 的 agent 看不到这份事实——它仍可能拉 `postgres:18`。当 16 与 18 对任务皆可接受时，这次拉取就是一次**本可避免的缓存未命中**：重复走外网、重复占缓存。

要做的不是改代理，而是把「**当前已完整缓存的镜像清单**」变成可查询的事实：

1. **console 可视**——运营者在设置页能看到缓存里有什么；
2. **沙箱内命令可查**——agent 拉依赖镜像前先查清单，在可接受的版本集合中**优先选已缓存版本**，提高缓存命中率。

代理的缓存落盘在宿主 `<数据根>/registry-proxy/cache`（nginx `proxy_cache`，内容寻址、完整下载后才落盘），这是**可扫描、可验证**的结构化事实，不是猜出来的提示。

## 目标

- **清单可查询（两出口）**：新增 `GET /api/proxy/cache/images`（JSON + 预渲染文本两种格式）；console 设置抽屉代理状态区旁新增「缓存镜像清单」视图。
- **沙箱内可查**：平台基础镜像新增 `cached-images` 纯 bash 命令（curl 拉文本格式直接输出），随基础镜像版本 bump 发布。
- **沙箱内可达**：服务端在创建 / 启动沙箱时，把「后端可达地址 + 受限令牌」以平台强制 env 注入容器（console 路径）。
- **受限令牌**：第二把只读钥匙，**平台全权管理**（不由用户管理），仅对缓存清单这一条读径有效。
- **引导约定落地**：agent 拉依赖镜像前先查清单、可接受版本集合中优先选已缓存版本——以基础镜像内提示 + 文档口径承载。
- **保守且不误导**：清单只收「已完整缓存」的镜像；任何失败态都显式降级提示，agent 回退正常拉取，**不阻塞**。

## 非目标

- **缓存 GC 命令**：TODO 在册，共享本轮扫描底座，本轮不做、不留任何 GC 入口。
- **CLI 子命令**（`sandboxctl cache-images` 之类）：范围裁剪，用户拍板不做。
- **代理层透明改写**：拉 `postgres:18` 给 `16` 的内容替换——**明确排除**（保持拉取语义诚实：拉什么得什么）。
- **`docker images` 劫持**：不封装、不改写 docker 语义——**明确排除**。
- **manifest 过期条目的补捞**：过期落榜可接受（见「已接受边界」），不做反向补捞。
- **多级令牌体系**：只做「完整 + 受限」两把钥匙，不做角色 / 权限分级。

## 方案

### 0. 链路总览

```
扫描器（核心包，特权通道读缓存目录）
   └→ 服务端：GET /api/proxy/cache/images（TTL 内存缓存，json | text 两种格式）
         ├→ console「缓存镜像清单」视图（完整令牌，json）
         └→ 沙箱内 cached-images 命令（受限令牌，text）
               ↑ 注入链路：服务端创建/启动沙箱时递参 → 核心包平台强制注入
                  SANDBOX_IMAGE_CACHE_URL + SANDBOX_IMAGE_CACHE_TOKEN
```

### 1. 分层归属：扫描器在核心包、端点与令牌在服务端

- **扫描器落核心包**（`apps/core`）：作为 `RegistryProxyManager` 的**邻居能力**——它已有的 `cache_size_bytes()` 就在经特权通道读同一个缓存目录（`du -sb` + 30 秒超时封顶），扫描走同一条通道、同一套纪律。
- **端点与令牌管理在服务端**（`apps/web/backend`）。
- **惯例先例**：运行期文件传输（机制 `transfer.py` 在核心包、接口在服务端）、端口转发同理。
- 本轮**不做 CLI 子命令**。

### 2. 清单口径（保守）：「已完整缓存」的定义

**「已完整缓存」= manifest 条目在缓存中 + 该 manifest 声明的全部 blob（config + layers）在缓存中。**

- blob 缓存是**内容寻址**的，且 nginx **完整下载后才落盘**——存在即完整，无需额外校验内容。
- 字段至少含：**仓库、标签列表、manifest 摘要（digest）、总大小、缓存时间**。
- **多架构镜像**：必须从 index（manifest list）解析到 **linux/amd64** 平台的 manifest，再验该 manifest 的 blob；解析不到 amd64 或 blob 不全 → 整条落榜。
- **manifest 缓存条目有独立较短有效期**（上游分层：10m / 1h / 60d）：过期条目落榜——**这是已接受边界**：只少一次优先提示，不会误导（清单永远不会把不完整的东西说成已缓存）。

### 3. 扫描算法（侦察已实证，直接采用）

| 事实 | 内容 |
|---|---|
| 缓存键 | 原始请求 URI（`proxy_cache_key $uri` / `$original_uri`，302 重定向后键不变） |
| 缓存文件名 | `md5(键)`，`levels=1:2` 三级布局：`cache/<md5末1位>/<md5倒数第3-2位>/<32位md5全串>` |
| 前向验证 | `md5("/v2/<repo>/blobs/sha256:<digest>")` 即可 `test -f` 判存在（**实测双向命中**） |
| 反向枚举 | 读文件头约 100 字节内的 `KEY:` 明文行（如 `KEY: /v2/library/nginx/blobs/sha256:b9c6…`）即得 repo + 类型 + digest，**无需算哈希** |
| 缓存目录 | `<数据根>/registry-proxy/cache`；叶目录 0700、文件 0600、属主为容器内 nginx 用户映射（usbmux:lxd）→ **服务用户直读必败，必须经既有特权通道**（先例：`proxy.py` `certificate_ready` 的 `PermissionError → sudo cat` 回退） |
| 脏条目 | 非 32 位 hex 文件名的条目（临时 / 半截文件）**跳过** |
| 有效期 | blob 200/206 60d；manifest 10m / 1h / 60d 分层；inactive 60d；max_size 32g |

实现口径：**纯解析函数与特权 IO 分离**（解析可单测）；特权枚举 + 读头尽量一次批量完成（避免逐文件 sudo 抖动），30 秒超时封顶；digest 只进的 manifest（无标签引用）同样上榜，标签列表为空；同仓库多标签指向同一 digest 时归并为一条。

### 4. 端点：`GET /api/proxy/cache/images`

- 挂**既有代理路由旁**（`routes/proxy.py`，同 `prefix="/proxy"`）。
- `?format=json|text` 两种格式（缺省 `json`；非法值 422）：
  - **json**：生成时间戳 + 清单数组（字段同第 2 节）；
  - **text**：**预渲染文本**（`text/plain`）——供沙箱内 bash 直接输出，**基础镜像只有 curl 没有 jq，禁止让 bash 解析 JSON**；文本含表头、逐行条目与生成时间。
- **扫描按需执行 + 短 TTL 内存缓存**（钉 **60 秒**）：避免每次请求扫盘；当前缓存仅 140 文件 / 382MB、扫描成本低，但 `max_size=32g` 会涨，TTL 兜底；json 与 text **共享同一份**扫描结果（同一生成时间戳）。
- **超时纪律**：沿用 `cache_size_bytes` 的 **30 秒封顶**。
- **失败语义**：特权读失败或超时 → 端点 **503 + 固定中文文案**，**不静默回空清单**（空清单会误导「没有缓存」，误导比失败更糟）。

### 5. 受限令牌：平台全权管理的第二把钥匙

- **服务端生成与全权管理**（用户拍板「不由用户管理，平台全权管理」）：随机值存平台数据根下新凭据文件（钉名 `cache-images-token.json`，0600，仿 `console-token.json` 先例；令牌 `sbxr_` 前缀，与 `sbx_` / `sbxt_` 同族）。**不得**放进 `<数据根>/registry-proxy/` 子树——该子树是 root 属主排除区。
- **语义**：完整令牌可访问全部 API 含新端点（**现状不变**）；受限令牌**仅**对 `GET /api/proxy/cache/images` 这一条只读读径有效，其余一律 401（含换票据——票据是全权能力）。
- **`BearerAuthMiddleware`（`auth.py`，现为单令牌）扩展**为识别两种凭据：请求期与两个值比对（常量时间），命中受限令牌时按**路由 + 方法**限界放行；受限令牌值在启动时加载；轮换 = 重写凭据文件即时生效（每请求读文件或 mtime 失效缓存皆可，机制实现时定），**缺失 / 损坏不阻断服务启动**（打 WARNING、受限读径 401）——与主令牌「缺了起不来」刻意不同：主令牌是唯一准入边界，受限令牌只是增益能力。

### 6. 注入管线：创建 / 启动时平台强制注入两个 env

- **服务端**在创建沙箱时把「可达地址 + 受限令牌」作为**可选创建参数**递给核心包创建接口（先例：模板注入——服务端读自己的状态、以参数递核心包执行，核心包不知模板存在）；**启动（重启）路径同样递参**——服务端两个值都可随时重推导（URL 由配置 / 探测得出、令牌从自己的凭据文件读出），故**不进 metadata**。
- **核心包**在容器装配时（`_run_sandbox_container`，创建与启动两条路径共用）**平台强制注入**两个 env（命名沿用 `SANDBOX_` 前缀惯例，仿 `SANDBOX_NETWORK` / locale 注入口径）：
  - `SANDBOX_IMAGE_CACHE_URL`——后端可达地址；
  - `SANDBOX_IMAGE_CACHE_TOKEN`——受限令牌。
  - 四口径：**平台值优先**（覆盖用户声明的同名变量）、**不进 metadata**。
- **可达地址** = 服务端配置项 `SANDBOX_CONSOLE_SANDBOX_URL` 优先 + **宿主 IP 自动探测兜底**（宿主非回环 IPv4 + 实际监听端口拼 `http://`；沙箱容器 → 宿主后端实测仅宿主 LAN IP 一条路可达）。两者皆不可得 → 跳过注入并打日志，**创建不失败**。
- **CLI 创建路径不传参 → 沙箱缺这对 env，属已知边角：console 里对该沙箱执行一次「停止 → 启动」（重启）即自愈**（启动路径重装配容器重新注入）。对称的另一半同样成立：CLI 直接 start 也不传参、env 缺失——同一已知边角，文档写明。
- **令牌轮换** = 重写凭据文件：旧令牌立即 401，已注入沙箱内旧 env 失效（cached-images 进入降级态），console 重启一次即重新注入新值。
- **部署前提（已接受）**：当前部署绑 `0.0.0.0:28642` 可用；仓库单元默认 `127.0.0.1:8000`——**部署绑回环时本功能沙箱侧失效**（cached-images 走降级提示），console 视图不受影响。

### 7. 沙箱内消费：`cached-images` 命令与引导约定

- 平台基础镜像新增 **`cached-images` 纯 bash 命令**（`curl` 拉文本格式直接输出；**不解析 JSON、不依赖 jq**；对后端调用显式绕过 HTTP(S)_PROXY——沙箱 env 里有代理变量，平台后端调用不走镜像代理），随基础镜像版本 bump 发布：**`base:0.3.1` → `base:0.4.0`**（新增命令，minor bump，按仓库惯例）。
- **新建沙箱自带，存量沙箱重建后才带**。
- **三态**：① 正常——输出清单文本，退出 0；② 缺凭据 / 缺 URL（env 缺失）——一行明确中文提示 + 固定非零退出码（两个失败态退出码不同，写进帮助文本）；③ 不可达——明确中文提示 + 固定非零退出码（curl 连接 5s / 总 10s 封顶，不挂 shell）。任何失败态**不阻塞**：提示 agent 回退正常拉取。
- **引导约定**（agent 拉依赖镜像前先查清单、可接受版本集合中优先选已缓存版本）以**基础镜像内提示**（命令输出尾部 / 帮助文本）+ **文档口径**承载——**模板无指令字段，不塞模板**。

### 8. console 侧：缓存镜像清单视图

- 设置抽屉**代理状态区旁**新增「**缓存镜像清单**」视图；前端用**完整令牌**访问同一端点（json 格式）。
- 展示：仓库 / 标签 / 摘要 / 大小（人读格式）/ 时间。
- 空清单给空态文案；端点失败给错误展示（不白屏）；打开时加载 + 手动刷新，**不加常驻轮询定时器**。

### 9. 关联

- 与 TODO「统一镜像代理缓存 GC 命令待做」**共享同一套扫描底座**（扫描器独立成模块、解析与特权 IO 分离，GC 将来直接复用）；GC 本轮不做、不留入口。

## 验收标准

### A. 扫描器与清单口径（核心包）

- [ ] 1. **真缓存实测**：扫描器对 `<数据根>/registry-proxy/cache` 实扫产出清单，清单中每条都满足「manifest 条目在缓存 + 其声明的全部 blob（config + layers）在缓存」；至少抽 1 条真实条目按前向公式核对 blob 文件存在（`cache/<md5末1位>/<md5倒数第3-2位>/<32位md5>`，md5 输入 = `/v2/<repo>/blobs/sha256:<digest>`）。
- [ ] 2. **多架构解析**：多架构 index 解析到 linux/amd64 平台 manifest 再验 blob；无 amd64 manifest 或其 blob 不全 → 整条落榜（不在清单）。
- [ ] 3. **单架构镜像**：直接验该 manifest 的全部 blob，齐全才上榜。
- [ ] 4. **反向枚举健壮性**：非 32 位 hex 文件名的条目（临时 / 半截文件）跳过；`KEY:` 头缺失或不可解析的文件跳过；跳过只影响条目数、不报错。
- [ ] 5. **字段完整**：每条至少含仓库 / 标签列表 / manifest 摘要（digest）/ 总大小 / 缓存时间；总大小 = manifest + config + layers 字节数之和，与宿主实际文件大小抽样一致。
- [ ] 6. **标签归并**：同仓库多标签指向同一 digest 归并为一条（标签列表聚合）；digest 直拉的 manifest 上榜且标签列表为空。
- [ ] 7. **过期落榜边界**：超过有效期的 manifest 条目（10m / 1h / 60d 分层）不出现在清单且扫描不报错——「只少一次优先提示，不会误导」的已接受边界被实测钉住。

### B. 端点与鉴权矩阵（服务端）

- [ ] 8. `GET /api/proxy/cache/images`：**无凭据 401**、错误完整令牌 401、错误受限令牌 401（固定文案，不泄露宿主路径与文件名）。
- [ ] 9. `?format=json`（缺省同）返回 JSON：生成时间戳 + 清单数组，字段同验收 5；`Content-Type: application/json`。
- [ ] 10. `?format=text` 返回预渲染文本（`text/plain`）：bash 直接输出可读（表头 + 逐行条目 + 生成时间）；与 json 来自同一份扫描结果（同一生成时间戳）。
- [ ] 11. `format` 非法值 → **422**（API.md 写明）。
- [ ] 12. **鉴权矩阵**：完整令牌对新端点与既有全部 API 一切照旧 200；受限令牌**仅** `GET /api/proxy/cache/images` 200——对其余路径（实测至少 GET `/api/proxy/status`、`GET /api/sandboxes`、`GET /api/health`）与任何非 GET 方法（实测对新端点 POST 一次）一律 **401**；受限令牌**不能换票据**（POST `/api/auth/ticket` 401）。
- [ ] 13. **受限令牌凭据文件**：平台数据根下新文件（**不在** `registry-proxy/` 子树）、权限 0600、随机值（`sbxr_` 前缀）、启动幂等（已存在不覆盖）；文件缺失 / 损坏时服务**照常启动**（WARNING + 受限读径 401），不阻断。
- [ ] 14. **TTL 缓存**：扫描按需执行、TTL 钉 60 秒——TTL 内重复请求生成时间戳不变、过期后重扫时间戳更新；json 与 text 共享同一缓存。
- [ ] 15. **失败语义**：特权读失败或超时（30 秒封顶，对齐 `cache_size_bytes` 纪律）→ 端点 **503 + 固定中文文案**，**不静默回空清单**。

### C. 注入链路

- [ ] 16. console 创建沙箱：容器内 `SANDBOX_IMAGE_CACHE_URL` / `SANDBOX_IMAGE_CACHE_TOKEN` 在场（docker inspect 可验）；两值**不进**沙箱 metadata（详情接口 env 只回用户声明键）。
- [ ] 17. **平台值优先**：创建参数 env 声明同名键 → 容器内取平台值（对齐 `SANDBOX_NETWORK` / locale 口径）。
- [ ] 18. **可达地址解析**：配置项 `SANDBOX_CONSOLE_SANDBOX_URL` 优先；未配置 → 宿主非回环 IPv4 + 实际监听端口自动探测兜底（真机验证沙箱内 curl 可达）；两者皆不可得 → 跳过注入打日志、**创建不失败**（与 CLI 路径同归缺 env 边角）。
- [ ] 19. **自愈口径**：CLI 创建的沙箱缺这对 env（已知边角，行为与现状一致）；console 对该沙箱「停止 → 启动」一次后 env 在场（服务端在 start 路径同样递参、核心包重装配容器时平台强制注入）；CLI 直接 start 仍缺 env——同一边角的另一半，文档写明。
- [ ] 20. **令牌轮换**：重写凭据文件后旧令牌立即 401；既有沙箱内旧 env 失效（cached-images 进入降级态），console 重启一次即重新注入新值。
- [ ] 21. **端到端**：console 创建的沙箱内执行 `cached-images`，输出与端点 text 格式内容一致（同数据源）。

### D. `cached-images` 命令

- [ ] 22. 基础镜像 **`base:0.4.0`**（0.3.1 → minor bump）新增 `cached-images` 纯 bash 命令（PATH 内）：curl 拉 `?format=text` 直接输出，不解析 JSON、不依赖 jq；对后端调用显式绕过 HTTP(S)_PROXY（`--noproxy`）；Dockerfile ARG / LABEL / README 同步 bump。
