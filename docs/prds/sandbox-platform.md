# Agent 开发沙箱平台

## 背景

面向 pi agent 的开发环境有三个结构性缺口，导致「agent 改完代码、验收仍要靠人」：

1. **环境不可复现。** 一个真实全栈项目要跑起来至少需要应用服务、Postgres、MinIO、Logto 四件套。人肉装依赖既慢又因人而异，最终表现为「我这跑得过、你那跑不过」。
2. **验收证据不足。** agent 能拿到单测通过和 HTTP 200，却拿不到界面截图，无法判断页面是否真的渲染、交互是否生效，只能由人打开浏览器逐个点。
3. **依赖必须造假。** 把对象存储当本地目录、用桩服务顶替真实依赖服务，测出来的行为与生产不一致，验收结论不可信。

因此 agent 需要一个自己能完全掌控、可复现、能产出多模态证据（截图）的隔离环境，把「改码 → 起环境 → 端到端 → 看截图 → 修复 → 全绿」变成 agent 自己能闭合的循环，人只审阅结果。

## 目标

- **隔离可复用的沙箱**：每个沙箱一套完整全栈运行环境（沙箱容器 + 依赖容器），agent 自主决定依赖起不起、起什么。
- **依赖一律容器化**：Postgres / MinIO / Logto 等一律以容器运行，不做原生进程，不做协议模拟器；MinIO 就是真实 S3 协议端点。
- **镜像即产品**：平台提供基础镜像与默认全栈沙箱镜像，用户在沙箱镜像上自由叠加；环境差异全部通过挂载注入。
- **镜像来源统一**：一切外部镜像统一经镜像代理拉取，缓存命中走本地，既省流量也便于审计来源。
- **免 root 运行**：每个沙箱一套专属 Linux 用户 + 独立子 UID/GID 段 + systemd 用户级 Docker 守护进程；沙箱内 agent 不获得宿主机特权。
- **端到端闭环**：Playwright 脚本为主、探索为辅；健康检查门禁保证「依赖就绪 → 迁移 → 种子 → 起测」的顺序；截图与 trace 留存到代码目录。
- **可演进**：一期交付本地闭环，控制面逻辑从第一天就写成可复用服务模块（CLI 只是薄壳），二期直接服务化。

## 非目标

- **不做 UI 精细审美验收的替代品**：截图用于判定功能是否跑通（元素存在、交互生效、页面无报错），不用于像素级视觉回归；视觉审美仍由人判断。
- **不做原生进程依赖**：不在宿主机安装 Postgres / MinIO / Logto 进程。
- **不做协议模拟器**：不接受用假实现替代真实依赖服务。
- **一期不做网页界面、不做资源配额、不做快照、不做自动清理。**
- **不做厚沙箱的默认形态**：特权内嵌 Docker 的厚沙箱是三期可选模式，接口与薄沙箱一致但优先级低。
- **不做弱网模拟**（进 backlog）。
- **平台不做任何 git 操作**：代码目录由用户自行挂载并交给 git 自己管理，平台只执行挂载声明。
- **平台不管理用户挂载数据的生命周期**：用户声明挂载的宿主机目录由用户自己创建、保留与清理，平台只负责回收自己创建的资源。
- **代理不可达时不直连降级**：镜像拉不到就明确报错，不自动改走公网直连。
- **不做多云混合的完整形态**：一期云边混合仅支持单容器本地回环（边缘经 WebSocket 连云侧端口）。

## 方案

### 总体分层

宿主机控制面 → 每沙箱专属 Linux 用户的免 root Docker 守护进程 → 沙箱容器与依赖容器（同属该守护进程）。

| 层次 | 职责 | 关键约束 |
|---|---|---|
| 控制面 | 建用户、分配子 ID 段、起守护进程、拉容器、回收资源 | 一期以 CLI 暴露，逻辑写成可复用服务模块 |
| 沙箱守护进程 | 以沙箱用户身份运行 rootless Docker | 用户级 systemd 单元 + linger 保活；沙箱容器也由它启动 |
| 沙箱容器 | agent 的工作环境与终端 | 启动即 bash，无 profile；挂载套接字与用户声明的挂载 |
| 依赖容器 | Postgres / MinIO / Logto 等 | 同一守护进程启动，与沙箱容器同网桥，按容器名互访 |

### 一期：本地闭环

**1. 守护进程与分层落地**
- 三层结构固定为上面的总体分层，不做扁平化（控制面不直接调用宿主 Docker 守护进程）。
- 依赖服务一律容器化：不做原生进程、不做协议模拟器。MinIO 直接提供真实 S3 协议端点；Logto 每沙箱自建一个容器实例，用完即弃，不跨沙箱共享。

**2. 镜像两层**
- **平台基础镜像**（`sandbox-platform/base`）：只含 docker 客户端 + 纯 bash 入口脚本 + 套接字默认路径与容器层空目录约定；不含任何业务运行时，不内置任何 volume 挂载点。
- **沙箱镜像**（默认全栈 `sandbox-platform/sandbox-default`）：在基础镜像之上提供 pi、git、uv、nvm + node、pnpm、Playwright 浏览器；用户可在其上自由叠加自己的层。
- **统一镜像代理**：Postgres / MinIO / Logto 三件套以及一切外部镜像统一经镜像代理拉取，缓存命中走本地，未命中由代理拉一次外网并缓存；基础镜像不再内置依赖镜像离线包。代理不可达即报错，不降级直连。
- **本地构建镜像**：只在宿主本地构建、不存在于任何仓库的平台镜像（如 `sandbox-default`）走宿主导出注入。
- 凭证一律只读挂载注入，不写进镜像。
- 过渡状态：本轮只重建平台基础镜像（0.2.0），默认全栈沙箱镜像暂不重建、仍为 0.1.0，其中仍含已废弃的离线包层。

**3. 用户与权限模型**
- 每沙箱一个专属 Linux 用户 + 一段独立的子 UID/GID 段（在 `/etc/subuid`、`/etc/subgid` 登记）+ 一个 systemd 用户单元 + `loginctl enable-linger` 保活。
- 守护进程的 Docker 套接字（`/run/user/<uid>/docker.sock`）挂载进沙箱容器。
- 沙箱容器也由该守护进程启动，因此该用户执行 `docker ps` 只会看到本沙箱的容器。
- 兜底设计：agent 误删自身容器时，依赖状态存放在家目录、代码目录由用户自行挂载并归 git 管理，控制面可在秒级重建容器，不丢数据。

**4. 挂载契约**

| 挂载 | 权限 | 生命周期 | 说明 |
|---|---|---|---|
| Docker 套接字（唯一固定挂载） | 读写 | 随沙箱容器存在 | 创建时自动挂到容器内默认路径 `/var/run/docker.sock`，docker 客户端默认可见，用户无需声明 |
| 用户声明挂载 | 由用户指定，可只读 | 平台不创建、不删除、不修改其宿主机目录 | 用户用 `--mount 宿主路径:容器路径[:ro]` 声明，可多次；平台原样执行、不解释用途 |
| 典型用法示例（非平台概念） | 由用户决定 | 用户自担 | 会话目录挂到 pi 会话路径、凭证只读挂载、代码目录挂到自选路径，均属文档指引 |

- 创建沙箱时不声明任何挂载，就只挂套接字一个；平台不预置任何默认挂载目录，也不创建任何宿主目录。
- 基础镜像不内置 volume 挂载点；容器内保留一个便捷空目录 `/workspace` 作为容器层临时目录，随容器删除而消失，文档中注明。
- 控制面不做任何 git 操作。未提交的改动会不会丢，取决于用户把代码目录挂在哪里，平台不替用户兜底。

**5. 网络与生命周期**
- 沙箱容器与依赖容器挂在同一网桥，按容器名互访，例如 `postgres://postgres:5432`、`http://minio:9000`；不发布任何宿主机端口，不使用 nsenter。
- 创建：建用户 + 分配子 ID 段 → 起守护进程 → 起沙箱容器并挂入套接字与用户声明的挂载。
- 关闭：停止容器（可顺带停止依赖容器）。
- 删除：回收平台创建的一切（容器、守护进程、用户与家目录、子 UID/GID 映射段、平台元数据）；用户声明挂载的宿主机目录一律不触碰。删除提示输出回收清单，并注明「用户挂载的宿主机目录不受影响」。

**6. 运行时极简**
- 沙箱容器启动即 bash，不加载 profile 脚本；依赖服务起不起、起什么完全由 agent 自主决定，平台不预置任何常驻服务。

**7. 端到端基建**
- Playwright 脚本为主、探索为辅（两种模式并存）。
- 每个用例一个独立数据库：用模板库秒级克隆 + 固定种子数据。
- 健康检查门禁：依赖就绪 → 执行迁移 → 载入种子 → 才允许跑用例，任一步失败即整体失败。
- data-testid 规范统一元素定位方式。
- 截图与 trace 留在代码目录，不上传到外部服务。

**8. 一期范围裁剪**
- AWS 侧仅支持 S3。
- 云边混合仅支持单容器本地回环（边缘经 WebSocket 连云侧端口）。
- 不引入 LocalStack。
- 弱网模拟进 backlog。
- 厚沙箱（特权内嵌 Docker）作为可选模式保留接口，优先级低。

**9. 一期交付形态与跨期约束**
- 代码布局：`platform/` 下放镜像构建（`base-image/`、`sandbox-image/`）、控制面 Python 包（`src/sandbox_platform/`）、薄壳 CLI（`cli/`）、打样探针脚本（`probe/rootless/`）、端到端基建（`e2e/`）、示例项目（`examples/`）。
- 控制面命令：`sandboxctl create / start / stop / delete / list`；CLI 只做参数解析与结果打印，业务逻辑全在 `sandbox_platform` 包内。
- 跨期约束一：控制面逻辑一期就写成可复用服务模块，CLI 只是薄壳。
- 跨期约束二：镜像即产品，环境差异全靠挂载注入。

### 二期：控制面服务化

> 实施范围以 [[prds/phase2-console.md]]（2026-10-29 定稿）为准：本节中「控制台自身使用 Logto 认证」已裁剪——本系统为内部部署、个人使用，不做认证；FastAPI 生命周期接口与网页终端两项由该 PRD 细化落地。

- 把一期 `sandbox_platform` 包暴露为 FastAPI 生命周期 API（创建 / 关闭 / 删除 / 列表），与 CLI 行为等价。
- 网页终端：tmux 式附着到沙箱会话，断线可重连且状态不丢。
- 控制台自身使用 Logto 认证（平台账号体系，与沙箱内自建的 Logto 依赖实例是两套东西，不要混用）。

### 三期：代理与多沙箱运营

- URL 代理：守护进程把沙箱端口发布到宿主机回环地址，网页侧再做一层反向代理，形成可点击的沙箱 URL。
- 每沙箱配额：2 核 / 4GB 起步。
- 快照、自动清理。
- 厚沙箱模式（特权内嵌 Docker），接口与薄沙箱一致。
- 可选弱网模拟。

架构决策细节以 ADR 为准，见 [[architecture/decisions/README.md]]。

## 验收标准

### 一期总验收（必须全绿）
- [ ] 在真实全栈示例项目（React / Vue / Astro 任一前端 + FastAPI 后端 + Postgres + MinIO + Logto）上，agent 在**无任何人工介入**的情况下独立跑通「改码 → 起环境 → 端到端 → 看截图 → 修复 → 全绿」全程。

### 一期分项
- [ ] 免 root：沙箱以专属用户运行，全流程不需要宿主 root 凭据；该用户执行 `docker ps` 只显示本沙箱容器。
- [ ] 权限隔离：容器内无法读写其他沙箱的用户目录与宿主机挂载目录；子 UID/GID 段生效（容器内 `id` 显示 UID 0、宿主侧显示映射后的高位 UID）。
- [ ] 挂载：固定挂载的套接字可用且位于 `/var/run/docker.sock`；用户声明的挂载按声明的权限生效；未声明任何挂载的沙箱仅挂载套接字即可正常使用。
- [ ] 镜像：基础镜像可用；默认全栈镜像内 pi / git / uv / node / pnpm / Playwright 浏览器齐备；外部镜像经统一镜像代理拉取，缓存命中不再走外网。
- [ ] 网络：依赖容器按容器名互访；宿主无任何由沙箱发布的新增监听端口。
- [ ] 生命周期：`create / stop / delete / list` 行为符合本 PRD；`delete` 前提示包含平台资源回收清单与「用户挂载的宿主机目录不受影响」字样；删除沙箱后平台资源全部回收，用户挂载的外部目录原样存在且内容未变。
- [ ] 端到端：脚本模式与探索模式均可执行；健康检查门禁生效；每用例独立数据库；截图与 trace 落在代码目录内。
- [ ] 证据：总验收全程留存截图与 trace，可回溯。

### 二期 / 三期验收（概要）
- [ ] 二期：HTTP API 与 CLI 对同一沙箱产生等价状态；网页终端断线重连后会话状态不丢。
- [ ] 三期：沙箱端口可经宿主机回环 URL 访问；每沙箱配额生效；快照可恢复；自动清理按策略执行；厚沙箱模式接口与薄沙箱一致。
