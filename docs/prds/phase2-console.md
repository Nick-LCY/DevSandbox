# 二期：控制面服务化与网页控制台

> 日期：2026-10-29
> 一期需求见 [[prds/sandbox-platform.md]]（一期本地闭环已完成，本期在其上做服务化）

## 背景

一期把沙箱生命周期的全部逻辑沉淀成可复用的 Python 包 `sandbox_platform`，命令行 `sandboxctl` 只做参数解析与结果打印。这套逻辑能跑，但只能靠人在终端里敲命令：

- 起一个沙箱要先想清楚镜像名与挂载声明，再敲命令、盯输出；
- 想看沙箱里发生了什么，得另开一个终端手动 `docker exec`；
- 镜像代理起没起、健不健康、缓存占了多少磁盘，只有翻日志才知道。

二期把同一套控制面逻辑常驻为一个服务，并把日常操作搬到网页上：沙箱的创建、列表、停止、启动、删除在网页完成；沙箱内的工作通过网页终端直接操作；镜像代理的状态在设置页一眼可见，必要时一键重启。

一期已有的一切契约都不变：挂载契约、镜像两层契约、回收契约、免 root 分层。命令行保持原样，不改一行。

## 目标

- **常驻服务**：把既有控制面核心模块包装成 FastAPI 服务常驻运行，与命令行调用同一批函数、行为等价。
- **沙箱管理**：创建时从宿主本地镜像中直接选择启动镜像、声明挂载；列表展示全部沙箱；支持停止与删除。
- **网页终端**：在网页里直接进入沙箱容器操作，同一沙箱可开多个独立终端，断线可重连。
- **代理设置**：设置页展示镜像代理的运行状态、健康状态、缓存占用与证书就绪状态，并支持重启代理。

## 非目标

- **不做认证与多用户**：服务只监听回环或内网接口，不得暴露公网。
- **不动宿主 Docker 的任何配置**：不配代理、不加镜像加速。宿主本地镜像如何获取与构建是用户自己的事，不属于平台职责。
- **镜像代理职责保持一期边界**：只服务各沙箱守护进程的依赖镜像拉取；沙箱启动镜像不走它。
- **不做镜像选项清单、不做网页拉取镜像**：创建沙箱时实时枚举宿主本地镜像即可。
- **不做代理缓存回收**：只增不减现状维持，页面仅展示占用大小。
- **不改造命令行为服务客户端**：延后。使用纪律：同一沙箱避免网页与命令行同时操作。
- **三期范围不变**：URL 代理、配额、快照、自动清理。

## 方案

### 总体结构

| 层 | 组成 | 职责 | 约束 |
|---|---|---|---|
| 浏览器 | React + Vite 单页应用 | 沙箱管理、网页终端、代理设置 | 不含认证；只调同源 REST 与 WebSocket |
| 服务层 | `sandbox_platform.server` 子包（FastAPI） | 路由、请求校验、错误映射、静态托管 | 只做编排与转译，不重复实现任何生命周期逻辑 |
| 控制面 | `sandbox_platform` 核心包（一期已落地） | 创建 / 启动 / 停止 / 删除 / 列表 / 回收清单 | 行为与命令行完全等价 |
| 宿主 | 宿主 root 守护进程、每沙箱免 root 守护进程 | 镜像代理容器、沙箱容器与依赖容器 | 免 root 分层与回收契约不变 |

数据流向：浏览器 → REST 接口 + WebSocket 终端 → 控制面核心模块 → 宿主 Docker / 各沙箱守护进程 / 平台数据目录。

既有契约一律不变：挂载契约（套接字是唯一固定挂载，其余由用户声明）、镜像两层契约（平台基础镜像 → 沙箱镜像）、回收契约（删除只回收平台自建资源，用户声明挂载的宿主机目录一律不触碰）、免 root 分层（每沙箱专属用户 + 独立子 UID/GID 段 + 用户级守护进程）。

### 服务形态与启动方式

- 服务进程：FastAPI + uvicorn，单进程常驻；以宿主特权身份运行（进程本身是 root 时直接执行，否则走免密 `sudo`），权限要求与一期命令行完全一致。
- 监听地址：默认 `127.0.0.1:8000`，可用环境变量 `SANDBOX_CONSOLE_HOST` / `SANDBOX_CONSOLE_PORT` 覆盖。允许改内网地址，**不得暴露公网**。
- 启动入口：`uv run python -m sandbox_platform.server`（模块入口在 `platform/src/sandbox_platform/server/__main__.py`）。
- 前端构建产物 `platform/console/dist` 由同一进程在 `/` 路径托管，单端口对外，不引入跨域与额外鉴权。
- 开发模式：前端 `pnpm dev` 起在 5173，通过 Vite 代理把 `/api`（含 WebSocket）转发到后端。
- 建议随附 systemd 单元模板 `platform/server/sandbox-console.service`（system 级），但服务本身不自动安装、不自动开机。

### 代码布局

| 路径 | 内容 |
|---|---|
| `platform/src/sandbox_platform/server/` | 服务层：`app.py`（应用工厂与生命周期）、`deps.py`（依赖注入）、`schemas.py`（请求/响应模型）、`routes/`（路由模块）、`terminal.py`（终端会话管理）、`sessions.py`（终端会话表）、`__main__.py`（启动入口） |
| `platform/console/` | 网页控制台前端（React + Vite + TypeScript，pnpm 管理） |
| `platform/src/sandbox_platform/`（一期既有） | 控制面核心模块，服务层只调用不重写 |

服务端源码沿用一期分层契约：不得出现 `argparse` 与 `print(`，一律走日志；宿主交互仍收敛在 `daemon.py` / `proxy.py` / `images.py` 内。

### 接口清单（草案）

统一前缀 `/api`，错误响应统一为 `{"detail": "中文错误消息"}`。

| 方法 | 路径 | 入参 | 出参 | 说明 |
|---|---|---|---|---|
| GET | `/api/health` | — | 服务版本、平台数据根、代理是否健康 | 服务自检 |
| GET | `/api/sandboxes` | — | 列表项数组 | 全部沙箱（含停止态） |
| POST | `/api/sandboxes` | `name`、`image`、`image_source`、`mounts[]`、`command`、`env`、`workdir` | 创建结果（步骤、连接方式、镜像） | 创建沙箱 |
| GET | `/api/sandboxes/{name}` | — | 沙箱详情 | 单个沙箱 |
| POST | `/api/sandboxes/{name}/start` | — | 沙箱详情 | 启动 |
| POST | `/api/sandboxes/{name}/stop` | `stop_dependencies`（默认 true） | 沙箱详情 | 停止 |
| GET | `/api/sandboxes/{name}/reclaim` | — | 回收清单、用户挂载目录、固定提示语、是否可能不完整 | 删除前预览 |
| DELETE | `/api/sandboxes/{name}` | — | `existed`、`removed[]`、`failed[]` | 删除 |
| GET | `/api/images` | — | 镜像引用、镜像 ID、体积、创建时间 | 宿主本地镜像实时枚举 |
| GET | `/api/proxy/status` | — | 容器状态、健康状态、缓存占用、证书就绪、代理地址 | 代理状态 |
| POST | `/api/proxy/restart` | — | 同上 + `ca_changed` | 重启代理 |

错误映射：沙箱名或入参非法 → 400；沙箱不存在 → 404；沙箱已存在 → 409；其余平台异常 → 500，消息取平台异常原文。

### 沙箱管理

- **创建**：前端下拉实时枚举宿主 Docker 本地镜像供选（含用户自己本地构建、任何仓库都没有的镜像），可声明挂载目录。选定后平台把该镜像从宿主导出并注入新沙箱的守护进程（复用一期宿主导出注入机制），**沙箱启动镜像不经镜像代理**。其余语义与一期完全一致：固定 7 步创建、失败回滚、代理预检先行（代理不可达即失败，不降级直连）。
  - 实现口径：核心包 `CreateRequest` 增加可选字段 `image_source`，取值 `auto`（默认，一期行为：守护进程已有 → 平台自建镜像导出注入 → 经代理拉取）或 `host`（强制从宿主注入，宿主无此镜像直接报错）。命令行不传该字段，一期行为零变化。
  - 挂载声明沿用一期语法 `宿主路径:容器路径[:ro]`，平台原样解析校验，不创建、不删除、不修改用户挂载的宿主目录。
- **列表**：全部沙箱含停止态，字段为名字 / 状态 / 镜像 / 创建时间。
- **停止 / 启动 / 删除**：沿用一期语义（停止保留沙箱与用户、守护进程、家目录、挂载目录；启动复用同一用户、同一子 UID/GID 段、同一守护进程；删除按固定回收清单全量回收，且不碰用户挂载目录）。删除前网页先展示回收清单与「用户挂载的宿主机目录不受影响」字样，用户确认后才执行。

### 网页终端

- 首选自研：WebSocket 端点与容器执行接口的终端流双向桥接，宿主侧用伪终端承载，容器内进程拿到真实 TTY，配真实伪终端语义（行编辑、全屏程序可用）；同一沙箱可开多个独立终端（每终端一个独立 exec 进程）；窗口大小变化实时同步到容器内 TTY。
- 断线语义：浏览器断开后终端会话由服务保留（容器内进程不退出，输出继续写入环形缓冲）；重连携带原 `session_id` 时先回放缓冲再接实时流，现场不丢。
- 服务重启则会话全部丢失、需新开（已确认可接受）。服务启动时把持久化会话表内全部记录标记为孤儿并清理，按记录的进程号终止遗留 exec 进程（仅当该进程命令行含本次会话标记时才终止，避免误杀复用的进程号）。
- 降级备选（仅在自研遇阻时启用）：容器内用 `abduco` / `dtach` 做会话保活，代价是需在沙箱镜像中加入该工具并重建镜像。本期不引入该依赖，只在自研受阻时另立任务评估。

### 终端会话表

本期唯一新增的持久化数据，落在平台数据目录 `<平台数据根>/terminal-sessions/<session_id>.json`：

| 字段 | 说明 |
|---|---|
| `session_id` | 服务生成的会话标识 |
| `sandbox_name` / `container_name` / `system_user` | 所属沙箱、容器名、执行身份 |
| `created_at` / `last_attached_at` | 创建与最近附着时间 |
| `state` | `running` / `exited` / `orphaned` |
| `exit_code` | 终端进程退出码（未退出为空） |
| `pid` | 宿主侧 exec 进程号，用于服务重启后清理遗留进程 |
| `cols` / `rows` | 最近一次窗口大小 |
| `attached_count` | 当前附着的浏览器连接数 |

会话表只登记会话元数据；伪终端与容器内进程存活在服务进程内存中，服务重启即失效（与「服务重启会话全丢」的口径一致）。

### 代理设置页

- 状态展示：代理容器运行状态、健康状态（端口可连 + 能取到 CA 证书）、缓存目录占用大小、代理 CA 证书就绪状态、代理访问地址。
- 重启：重启代理容器并轮询到健康；重启期间依赖镜像拉取失败属预期行为，不做降级。
- 重启后比对代理 CA 指纹：指纹变化则自动为已有沙箱用户重装合并 CA 束，避免沙箱内 TLS 链路失效。
- 不提供任何清理代理缓存的入口：只增不减现状维持。

### 安全边界

- 服务不做认证与多用户；只监听回环或内网地址，不得暴露公网。
- 沙箱名、镜像名、网络名、环境变量名等一律沿用一期白名单校验后再进特权命令。
- 删除路径不信任元数据：用户信息现查 `getent passwd`，回收清单实时扫描；用户声明挂载的宿主机目录一律不触碰。
- 同一沙箱避免网页与命令行同时操作（本期不改造命令行，使用纪律约束）。

## 验收标准

- [ ] 网页独立完成「从宿主本地镜像选一个创建沙箱 → 开终端操作 → 停止 → 再启动 → 删除」全流程。
- [ ] 不存在于任何仓库的本地构建镜像，可经网页选用并成功创建沙箱（注入路径走通）。
- [ ] 同一沙箱多个终端并行可用；断线重连后终端现场不丢（服务重启例外）。
- [ ] 网页触发的沙箱操作与一期命令行对同一沙箱产生等价状态。
- [ ] 删除沙箱的资源回收语义与一期一致，用户挂载目录不受影响。
- [ ] 沙箱内依赖镜像拉取仍统一经镜像代理，一期行为无回归。
- [ ] 服务只监听回环或内网地址，不做认证，不暴露公网。
- [ ] 一期命令行行为零变化（`sandboxctl` 源码未改，一期 141 项 pytest 与冒烟判定全通过）。
