# 终端交互增强

## 背景

控制台终端已有终端键盘与系统剪贴板的基础约定，但设置抽屉中的「后端配置」仍未承载终端交互偏好，终端也缺少 `Shift+Enter` 的可选映射、限定在终端区域内的右键复制 / 粘贴，以及容器内程序与系统剪贴板之间的 OSC 52 互通。本轮把这三组前端体验能力一起收口；后端与核心包保持不变。

既有前端口径以 [[conventions/console-frontend.md|控制台前端约定]] 为准：终端快捷键仍交给容器内 shell、剪贴板成功零反馈且失败使用 `terminal-clipboard` 来源的 toast、粘贴必须走 `term.paste`，设置抽屉使用 Base UI Tabs 与 keepMounted。

## 目标

- 将设置抽屉的「后端配置」tab 改造为第一位、改名为「通用设置」并默认激活；在其中放入终端交互区和既有连接配置表单。
- 提供两个独立的前端偏好开关：`Shift+Enter` 映射与终端右键接管；二者默认关闭且持久化，关闭时维持现有行为。
- 开启 `Shift+Enter` 映射后，终端收到 `Shift+Enter` 时发送 `ESC+回车`（`0x1b 0x0d`）。
- 开启终端右键后，仅接管发生在 xterm 终端区域内的右键：有选区复制到系统剪贴板，无选区读取系统剪贴板并经 `term.paste` 粘贴；阻止原生菜单和 xterm 自带右键选区行为。
- 无开关、常开地支持 OSC 52 选择区 `c`：容器内程序设置剪贴板时写系统剪贴板，查询剪贴板时读取系统剪贴板、base64 编码并回写 PTY。
- 对 OSC 52 payload 限制 64 KiB；读取失败沿既有终端剪贴板失败口径处理，不发送响应、不做降级。
- 保持既有终端键盘、剪贴板、设置 tab、连接配置以及网页 / 桌面共用前端产物的语义不回归。

## 范围

### 设置抽屉

- tab 顺序调整为「通用设置」→「代理」→「模板」；「通用设置」默认激活。
- 原「后端配置」tab 改名为「通用设置」，原有后端地址、访问令牌、测试连接、保存配置表单继续位于该 tab。
- 「通用设置」增加「终端交互」区，包含且仅包含两个开关：`Shift+Enter` 映射、终端右键。
- 两个开关使用前端偏好存储，默认值均为关闭；挂载时读取，用户切换后持久化，不增加后端字段或接口。

### Shift+Enter 映射

- 开关开启：终端内 `Shift+Enter` 发送字节序列 `0x1b 0x0d`。
- 开关关闭：沿现状发送 `0x0d`。
- 既有 Ctrl / Meta / Alt 组合分类、浏览器保留键和 Ctrl+Shift+C / Ctrl+Shift+V 语义不改变。

### 终端右键

- 开关关闭：不接管右键，保留现有浏览器 / xterm 行为。
- 开关开启：只有右键点位位于 xterm 终端区域内时才接管；终端外的右键不受影响。
- 有选区：复用既有 Ctrl+Shift+C 的复制路径、成功零反馈、失败弹失败 toast，来源标识固定为 `terminal-clipboard`。
- 无选区：读取系统剪贴板并调用 `term.paste` 注入终端；读取失败弹「读取系统剪贴板失败」toast，来源标识固定为 `terminal-clipboard`。
- 被接管的右键必须阻止原生右键菜单与 xterm 自带右键选区行为。

### OSC 52

- 处理 OSC 52 的选择区 `c`，忽略 `p`、`s` 与 cut buffer。
- 容器内程序设置剪贴板：前端按 OSC 52 载荷解码后写入系统剪贴板；成功不弹 toast。
- 容器内程序查询剪贴板：前端读取系统剪贴板，按 OSC 52 约定 base64 编码后经统一 `sendInput()` 回写给 PTY，不走 `term.paste`，也不在终端画面中插入响应文本。
- OSC 52 payload 按 base64 长度先做 64 KiB 预检，解码后再做字节数二次校验；超限时拒绝处理，不写系统剪贴板、不发送查询响应，并按失败路径记录可验收结果。
- 系统剪贴板读取失败：弹失败 toast，来源标识 `terminal-clipboard`，不发送响应，不做降级。
- 信任边界沿既有口径：容器内程序视为受信，OSC 52 是已知边界；本轮登记边界，不新增权限确认流程。

## 非目标

- 不做整套自定义快捷键体系；本轮只增加 `Shift+Enter` 这一项明确映射。
- 不改后端、不改核心包、不增加后端接口或协议字段。
- 不增加桌面剪贴板插件，除非真机实测读取被拒；若未触发该条件，保持浏览器系统剪贴板 API 路径。
- 不新增第三个终端交互开关，不把 OSC 52 做成可配置项。
- 不改变既有 Ctrl+Shift+C / Ctrl+Shift+V、终端保留键、括号粘贴、连接配置或终端会话协议语义。
- 不把终端外的右键点击纳入接管范围，不提供全页面右键菜单替代品。

## 设计要点

### 偏好与设置抽屉

- 两个开关是独立布尔偏好，默认关闭；存储键分别为 `sandbox-console-terminal-shift-enter-escape` 与 `sandbox-console-terminal-right-click-clipboard`，值只认 `'1'` / `'0'`；存取失败或值非法时回落关闭，挂载时不写存储。
- 设置 tab 使用既有 Base UI Tabs 封装和 keepMounted 约定；tab 的可访问标识与现有设置 tab 标识体系保持一致，新增 / 调整标识在实现阶段同步前端 README 标识表。
- 连接配置表单的字段、测试连接、保存配置行为保持现状，只改变其所在 tab 的名称、顺序和默认激活状态。

### 终端键盘与右键

- `Shift+Enter` 映射只影响该组合键；映射关闭时不得改变现有回车编码。
- 右键接管先判断事件目标是否在当前 xterm 终端区域内，再按选区是否存在分流复制 / 粘贴；接管路径统一复用既有终端剪贴板反馈与 `term.paste` 语义。
- 右键复制成功不反馈；复制或读取失败使用现有 toast 机制，来源固定为 `terminal-clipboard`。

### OSC 52 与安全边界

- OSC 52 仅承担系统剪贴板桥接，不改变 PTY 会话或后端协议；查询响应从前端回写 PTY。
- 仅处理选择区 `c`，忽略其他选择区与 cut buffer；base64 长度先做 64 KiB 预检，解码后的字节数再做一次校验，超限不得产生部分写入或部分响应。
- 容器内程序被视为受信主体，因此程序可通过 OSC 52 读写用户系统剪贴板；这是已知信任边界，实施后在验收与留档中登记，不在本轮扩大权限模型。
- 系统剪贴板读取失败必须可见地失败：toast 来源为 `terminal-clipboard`，不发送响应、不做桌面插件或其他降级。
