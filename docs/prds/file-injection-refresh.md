# 文件注入副本手动刷新

> 日期：2026-11-23
> 基线需求：[[prds/file-injection.md|文件注入轮 PRD]]（创建时注入，本轮在其之上追加刷新能力）
> 机制与信任边界：[[architecture/decisions/0012-文件注入采用复制加改属主而非改造挂载预检.md|ADR 0012 文件注入采用复制加改属主而非改造挂载预检]]
> 相邻通道：[[prds/runtime-file-transfer.md|运行期文件传输 PRD]]（把字节搬进容器内的可写工作文件，与本轮**不是同一条通道**）
> 状态：**PRD 已落，待拆任务**——本轮只落需求文档，未拆任务、未改代码、未建分支、未动部署。

## 背景

创建时文件注入是**快照**语义：平台在创建沙箱时把声明的宿主文件复制一份到沙箱用户家目录内的托管副本，再以只读方式挂进容器（见 [[architecture/decisions/0012-文件注入采用复制加改属主而非改造挂载预检.md|ADR 0012]] 第 1、2 条）。宿主原件之后的变更**不回灌**，沙箱里挂着的永远是创建那一刻的内容——ADR 0012 与 [[prds/file-injection.md|旧 PRD]] 都把这条代价写成明面上的非目标：「要新鲜内容就重建沙箱」。

代价落在两类典型场景上：

- **凭证与私钥轮换**：宿主上的 ssh 私钥、pi `auth.json` 一换，沙箱里挂的还是旧的那份。
- **只想要新内容，不想重建**：重建沙箱意味着容器、终端会话、agent 运行状态一并重来，而用户要的只是「这一条注入换个版本」。

本轮的选择：把「刷新」做成一个**用户显式触发**的动作（目录镜像含同步删除），先落 PRD 再拆任务——不是把注入通道改造成后台实时同步。

两条现状约束决定了「刷新」不能拿现成通路凑：

1. **实例元数据里没有宿主源路径**：现有元数据只保留托管副本路径与容器目标路径，原始宿主源**不留**。服务端收到一条刷新请求时手里没有可读的源，无从查起；启动模板是「下次创建时回填表单用的配置」，不是实例事实，拿它反查属于凭空推断，**不能当作刷新源**。
2. **平台的「启动」不能当刷新用**：现有启动动作会**删除旧容器再创建**，容器一换终端会话与 agent 状态就断了，与「不中断容器」的诉求正面冲突。

因此本轮要**新增一条显式刷新通道**，并且**在新建沙箱时把宿主源路径一并存进实例元数据**。

**本轮定位**：在**创建时快照**之上加一个用户显式触发的「刷新副本」动作——没有后台同步、没有自动轮询、没有增量推送，副本变新的唯一途径是用户点一次「刷新副本」。

## 目标

- **运行中可刷新**：沙箱**运行中**也能对**一条**已保存注入手动刷新副本，**单文件与整目录都支持**；**不 stop/start、不重挂载、不 `docker cp`**，不中断容器、终端与 agent 会话。
- **目录镜像同步（含删除）**：源稳定的情况下，目录刷新成功后副本的**递归成员与内容与源一致**，宿主源里**已不存在**的文件与子目录从副本删除（同步删除），源里**真实存在的空目录**保留。
- **源可寻址**：新建沙箱在**实例元数据**里保存「宿主源路径 ↔ 托管副本 ↔ 容器目标 ↔ 类型」的对应关系（**实例事实**，不是模板动态查找）。
- **入口在详情抽屉**：沙箱详情抽屉新增「注入文件」清单，每条一行、一个「刷新副本」按钮。
- **接口不接受任意路径**：刷新请求只带**已保存的条目标识**，宿主源 / 容器目标 / 副本路径一律由服务端从该沙箱条目查得，请求不得指定或改写。
- **刷新后可见**：写完后在容器内重新读取该路径可见新内容（不承诺 app 热加载）。
- **原件零接触**：刷新全程宿主原件只读——不 chmod / chown / 写 / 删，内容与 mtime 不变。

## 非目标

- **不是实时同步、不是自动同步**：不做后台轮询同步、不做文件监听、不做增量推送；刷新只由用户显式触发。
- **不做批量刷新**：一次一条。
- **不做命令行入口**：`sandboxctl` 本轮不加刷新参数（与既有「`sandboxctl` 增加文件注入参数」待办是两条独立待办）。
- **不做迁移工具**：不提供旧实例补录源路径、不反查模板、不做批量迁移脚本。
- **不做通用宿主文件读取**：不新增「任意路径读宿主文件」的能力——刷新服务读源字节只为复制，详情 / 刷新响应 / 日志都不含正文。
- **不保留备份、不做回滚**：用户已拍板不需要备份、直接刷新——不留旧副本、不留备份目录、不提供回退操作。
- **不承诺原子性与事务性**：目录刷新**不是目录事务**；单文件**不承诺原位写的原子性**，读者可能看到写入中间状态。
- **不承诺 app 热加载**：写完后重新读取路径可见即可；应用是否自行重载由应用侧决定。
- **不做自动停机 / 重建降级**：刷新失败不触发停机、不触发重建沙箱。
- **不改创建路径语义**：创建仍是快照，本轮只加刷新，不改创建时的复制语义与校验口径。

## 方案

### 一、刷新语义

- **单文件**：**保留挂载的文件身份、原位覆盖**副本内容——不得用 rename 换掉文件本身，挂载的是文件身份，换 inode 容器内看到的仍是旧文件。
- **目录**：**保留挂载根本身**，递归镜像成员，覆盖四类变化：
  - **新增**：宿主源里新增的文件 / 子目录出现在本条托管副本里。
  - **更新**：宿主源里内容变化的文件在副本里被更新。
  - **删除**：宿主**合法源目录中已不存在**的文件与子目录，从本条托管副本里删除。
  - **空目录**：宿主源里**真实存在的空目录**允许清空副本对应子项（子项被清掉），但该空目录**本身保留**（不因变空而被删）。
- **镜像的目标状态**：源稳定的情况下，刷新成功后副本的递归成员与内容与源一致、空目录仍保留。这是**结果口径**；具体实现手段（写原位、递归复制、删除次序等）由实现与实测决定，不在 PRD 写死。
- **注入根类型改变（文件 ↔ 目录）**：拒绝刷新并报错——副本形态与挂载形态不可变。
- **删除边界**：删除只允许发生在**本条托管副本内部**——不触碰宿主源、不触碰其它注入条目、不触碰普通挂载、不触碰沙箱数据。

### 二、元数据：新建沙箱把源路径存成实例事实

- 新建沙箱时，逐条把注入条目写进**实例元数据**：条目标识、**已校验的**宿主源路径、托管副本路径、容器目标路径、类型（普通文件 / 目录）。
- 「已校验」沿用创建时的口径（路径归一化 + 真实路径双重比对，见 [[architecture/decisions/0012-文件注入采用复制加改属主而非改造挂载预检.md|ADR 0012]] 第 3 条）；**校验不过的源不会进元数据**。
- 这是**实例事实**，不是配置回填：刷新**不查模板、不反查模板**。

### 三、刷新接口

- **入参只有已保存的条目标识**（定位到「该沙箱的该条目」），服务端据此查得源 / 副本 / 目标 / 类型。
- 请求**不得**携带或改写宿主源路径、容器目标路径、副本路径——**任意路径入参一律拒绝**，服务端不接受「用户指定刷哪」。
- 走**既有管理鉴权**与**既有特权通道**（与创建时复制同路），不新增鉴权分支、不新增特权机制。

### 四、刷新时的校验与安全边界

刷新是一次**新的复制动作**，校验口径与创建时同档（见 [[architecture/decisions/0012-文件注入采用复制加改属主而非改造挂载预检.md|ADR 0012]] 第 3、4 条），且**必须重新校验实际源**，不能只信元数据里创建时那份快照。

- **源校验（重新、按现有受限路径范围）**：对**实际源**重跑受限范围校验——路径归一化 + 真实路径双重比对、宿主敏感目录拒绝清单、任何已存在的沙箱用户家目录、平台数据根；**源自身是符号链接即拒绝**，**源目录树内的符号链接与非常规文件（FIFO / 设备 / 套接字）一律拒绝**；源必须存在且可读，类型与元数据一致（普通文件 / 目录），源是目录时校验**整棵目录树**。
- **目的校验**：写入目标**确是该条托管副本**，不得从托管副本越界；实际读写 / 删除限定在本条副本内，**不得因并发中的路径变化越界**。
- **失败不动副本**：**任一预校验失败、或整目录枚举失败，副本一个字节都不动**——不写、不删。
- **权限与属主**：副本仍属沙箱用户、普通文件 **0600** / 目录 **0700**，容器内**仍只读**；宿主**原件**只读——不 chmod、不 chown、不写、不删，内容与 mtime 不变。
- **正文不外泄**：刷新服务读取源字节**用于复制**，但详情、刷新响应与日志**不返回、不展示正文**（私钥、凭证一律不读出）。

### 五、失败语义与重试

- **进入写入阶段后失败**：报「**可能部分更新**」；**停止后续的副本更新与镜像删除**，**不回滚**（不恢复到旧副本），不续跑剩余步骤。
- **修正后允许用户手动重试**：重试是用户动作，平台不自动重试。
- **不做备份、不做回滚、不做自动降级**（用户已拍板不需要备份、直接刷新）。

### 六、互斥与并发

- **同一沙箱内互斥**：刷新之间互斥；刷新与该沙箱的**生命周期冲突操作**（启动 / 停止 / 删除）互斥——已钉死，不另按条目分互斥。
- **入口层**：按钮加载态禁止重复触发。

### 七、界面：沙箱详情抽屉的「注入文件」清单

- 在**现有沙箱详情抽屉**内新增「注入文件」清单区（与既有「**挂载**」区同一层，见 [[conventions/console-frontend.md|前端约定]]），**不新增抽屉**。
- **每条一行**：宿主源 → 容器目标（只读）+ 一个「**刷新副本**」按钮。**不展开目录树**、不逐级列成员。
- **只显示元数据**：界面不展示文件正文（私钥、凭证）。
- **按钮加载态**禁重复；**操作结果沿用现有成功 / 失败提示**（右上角 toast 口径）。
- **既有「刷新详情」是读操作**，**不能**触发刷新副本——两者不可混为一谈。
- **网页与桌面共用**这一套交互，不做形态差异。

### 八、旧实例口径

- 旧实例缺宿主源路径 → **不迁移、不补录、不反查模板**；**不给刷新入口**，但**仍可正常管理与删除**。
- 平台**不自动删除、不自动迁移**旧实例；需要刷新的，**由用户在新版上线后自行重建**。
- 重建是一次新的创建：旧沙箱**仅存于其内部的数据不会自动带到新沙箱**，不提供无损迁移。

## 验收标准

以下各条**均未勾选**：本轮只落 PRD，功能尚未实现。

### 刷新生效（真沙箱）

- [ ] 真沙箱：容器**运行中**、终端会话保持连接，对一条**单文件**注入刷新后，在**同一容器内**（经终端 / 容器内命令）重新读取该路径，得到**新版内容**。
- [ ] 刷新过程中容器**未被删除重建**：容器 id / 启动时间不变，终端与 agent 会话**未中断**（不出现 stop/start、不重挂载、不 `docker cp`）。
- [ ] 刷新后同一沙箱的**其它内容不受影响**：其它注入条目、普通挂载、沙箱数据均无变化。

### 目录语义

- [ ] 目录注入刷新后**递归镜像**生效：宿主源新增的文件 / 子目录出现在副本里，内容变化的文件被更新。
- [ ] 宿主源中**已不存在**的文件与子目录从本条托管副本中**被删除**（同步删除）。
- [ ] 宿主源中**真实存在的空目录**：副本对应子项被清空，但该空目录**本身保留**（不被删除）。
- [ ] **注入根类型改变**（文件 ↔ 目录）时刷新被**拒绝**并给出明确报错，副本未被改动。
- [ ] 目录刷新**不删除挂载根本身**（挂载仍在、容器内路径仍可访问）。

### 边界与安全

- [ ] 刷新后容器内对注入路径**写入仍失败**（只读生效）；副本**属主仍为沙箱用户**、普通文件 **0600** / 目录 **0700**。
- [ ] 宿主**原件**在刷新前后：权限位、属主、内容、mtime **完全不变**（不 chmod / chown / 写 / 删）。
- [ ] 详情、刷新响应与刷新日志**只显示元数据**，**不出现文件正文**。
- [ ] 刷新时**重新校验实际源**：源自身为符号链接、源落入受限范围、或源目录树内出现符号链接 / 特殊文件时，刷新被**拒绝**且副本未被修改；写目的不得越出本条托管副本。

### 失败、重试与互斥

- [ ] **坏路径**：源路径不存在 / 不可读时刷新**失败并报错**，副本**未被修改**；源目录**枚举失败**时**不执行删除**（副本内容未被清空）。
- [ ] **失败语义**：进入写入阶段后失败时报「可能部分更新」，界面明确提示该语义，不静默；后续更新与镜像删除**停止**，**不回滚**到旧副本。
- [ ] **失败后可重试**：修正源后由用户手动重试成功。
- [ ] **无备份**：刷新后**不残留**旧副本、备份目录或回退入口。
- [ ] **不承诺原子性**：刷新过程中读者**可能看到中间状态**；验收只断言最终状态收敛，不要求过程无中间态。
- [ ] **互斥**：同一沙箱的两次刷新不并发；刷新与该沙箱的启动 / 停止 / 删除冲突时被拒绝且不影响既有操作。

### 旧实例

- [ ] 旧实例（无宿主源路径）**详情抽屉不出现刷新入口**，且**仍可正常查看、管理与删除**；平台**不自动删除、不自动迁移**，用户在新版上线后自行重建，旧沙箱内的数据不会自动带到新沙箱。

### 接口与界面

- [ ] 刷新接口**只接受已保存的条目标识**：传入任意宿主源路径 / 容器目标路径 / 副本路径**一律被拒绝**（不构成越权写入），走**既有管理鉴权**。
- [ ] 详情抽屉「注入文件」清单每条一行、显示宿主源 → 容器目标（只读）与一个「刷新副本」按钮；**不展开目录树**。
- [ ] 按钮**加载态禁止重复触发**；操作结果走**现有成功 / 失败提示**。
- [ ] **既有「刷新详情」（读操作）不触发刷新副本**；**网页与桌面两端行为一致**。

## 待技术验证点

拆任务时需实测定案的三点：

- **挂载可见性与原件 / 只读不变**：单文件原位覆盖的落点（写同一 inode 等手段）需真机确认——容器内只读挂载能读到新内容、挂载的文件身份不变（rename 换 inode 不可用），且宿主原件全程零接触。
- **目录源缺失 / 读不全与真正空目录的区别**：实现上如何保证「源缺失 / 读失败 / 枚举不全」绝不被判成「源为空」——这是镜像删除的安全前提。
- **冲突操作的互斥落点**：同沙箱互斥、并与启动 / 停止 / 删除互斥的具体实现落点（锁的粒度与获取点）。
