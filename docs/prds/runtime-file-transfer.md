# 运行期文件传输：运行中沙箱的文件上传 / 下载

> 日期：2026-11-09
> 一期需求见 [[prds/sandbox-platform.md]]，二期需求见 [[prds/phase2-console.md]]，三期需求见 [[prds/phase3-desktop.md]]，文件注入轮见 [[prds/file-injection.md]]
> 本轮任务集见 [[tasks/runtime-file-transfer/README.md|运行期文件传输任务集]]
> 机制选型决策见 [[architecture/decisions/0018-运行期文件传输机制选型.md|ADR 0018]]（**已落档为已接受**：01 轮真机实测验证、06 轮复核）

## 背景

平台至今有两条把文件带进沙箱的路，都是**创建时**的一次性动作：

- **用户声明挂载**（[[architecture/decisions/0005-挂载契约与数据归属.md|0005]]）：挂载只在建容器时生效，且要求宿主路径可读可穿过。
- **文件注入**（[[architecture/decisions/0012-文件注入采用复制加改属主而非改造挂载预检.md|0012]]）：创建流程内「复制 + 改属主 + 只读挂载」，宿主原件零接触、副本随沙箱回收。

两条路的共同前提是**沙箱还不存在**。沙箱跑起来之后，agent 要往里塞一份新数据、或把跑出来的产物取出来，平台没有任何通路——这不是权限问题，是**通道不存在**。

三期把端口转发做成了一条生产验证的字节通道：后端用 `docker exec -i` 起字节泵（核心包 `forwarding.py` 的 `spawn_stream` + `BytePump`），把容器内的字节流搬到用户机。这套资产（**stderr 排空、短写循环、进程组回收**三个坑都已踩平）**与搬什么无关**——换一条容器内命令就能搬文件。

本轮做的是这条通道的**文件搬运版**：类 `docker cp`、**单文件**粒度、上传下载双向、web 与桌面两形态可用。

**与既有通道的边界（贯穿全文）**：

| | 文件注入（创建时） | 运行期文件传输（本轮） |
|---|---|---|
| 时序 | 创建沙箱时 | **沙箱运行中** |
| 方向 | 宿主 → 容器（单向） | 宿主 ⇄ 容器（**双向**） |
| 产物 | 只读副本 + 注入声明 | 容器内的可写工作文件 / 用户机上的落盘文件 |
| 生命周期 | 副本随沙箱家目录回收 | 上传件随容器消失；下载件在用户机侧，**平台不托管** |
| 通道 | 挂载（容器启动时固定生效） | `docker exec -i` 每次现开、用完即回收 |

两条通道**互不依赖、互不影响**：本轮对创建时注入通道**零改动**（创建请求、模板字段、注入副本语义一律不动），对命令行**零改动**。

## 目标

- **运行中沙箱可传文件**：上传（宿主 → 容器）与下载（容器 → 宿主）两条通路，**单文件**粒度。
- **两形态都能用**：web 形态（浏览器）与桌面形态（Tauri）各自可用，桌面形态下载走**原生「保存为」对话框**。
- **机制可复用、依赖不膨胀**：主通道复用三期端口转发已生产验证的 `docker exec -i` 字节泵资产，核心包新增与 `forwarding.py` **平级**的 `transfer.py`，**零新增第三方依赖**。
- **规模不设限**：大小**不限**（无 413），后端全程流式、内存有界。
- **与创建时注入彻底区分**：文档与界面用词一律「**运行期传输**」vs「**创建时注入**」，不混用「文件传输」这种含混说法。
- **命令行零改动**。

## 非目标

- **不做命令行入口**：`sandboxctl 增加 --file` 是**创建时注入**的另一条独立待办（见 [[current-state.md|当前状态]] 的 TODO 段），与本轮无关，本轮**不碰命令行**。
- **不做目录 / 多文件 / tar 传输**：本轮只搬**单个普通文件**。目录整体传输与多文件打包留待以后（`docker cp` 通道可作后手，见「机制选型」）。
- **不做文件管理操作**：重命名、删除、移动、复制等一律不做——本轮是「搬运」不是「文件管理器」。
- **不做拖拽上传**：上传入口是文件选择控件。
- **不做断点续传**：大文件靠流式一次性传完，失败重来。
- **不做字节级双向进度**：上传进度用 XHR 的上传进度事件即可；下载进度按 `Content-Length` + 流式读取估算。
- **不做「落到宿主文件系统」方向**：不提供把容器内文件直接写到**平台宿主**磁盘的通路（避免新增宿主攻击面）。下载落盘只发生在**用户机侧**（浏览器下载目录 / 桌面端用户自选路径）。
- **不做跨账号隔离**：沿用既有口径「调用者视为受信主体」——拿到访问令牌即拥有平台全部能力，文件传输不额外分层。

## 方案

### 机制选型（主通道）

**主通道 = `docker exec -i` + 容器内 `sh` / `cat`**，完全复用三期端口转发已生产验证的字节泵资产：

- 核心包 `forwarding.py` 的 `spawn_stream`（起 exec 进程、拿 stdin / stdout 管道）+ `BytePump`（双向搬运、**stderr 排空**、**短写循环**、**进程组回收**）三个坑照抄，不重新踩。
- 核心包新增与 `forwarding.py` **平级**的 `transfer.py`（路径校验 / upload / probe / 下载泵 / list），**零新增第三方依赖**。

**01 轮实测结论（2026-11-09）**：主通道**成立**——沙箱专属用户的免 root 守护进程下 `docker exec -i` 完全可用，`BytePump` 原样复用，**零新增依赖、零新增进程模型**。四条否决路线**无需复议**。全部实测口径（含 10 条被推翻/精化的设计点）见 [[architecture/decisions/0018-运行期文件传输机制选型.md|ADR 0018]]。

替代路线与否决理由（四条否决 + 一条采用）：

| 候选 | 结论 | 理由 |
|---|---|---|
| Docker SDK（Python 客户端库） | **否决** | 破坏核心包**零第三方依赖**约束 |
| `docker cp` 直接调用 | **否决**（留作以后目录传输的后手） | 版本差异多、**不能控属主** |
| 借道「创建时注入」通道 | **否决** | 挂载只在建容器时生效，运行期**时序不符** |
| 另起 WebSocket 通道 | **否决** | 通道语义拧：字节泵已是点对点流，再套一层 WS 只是多一跳、多一处状态（本轮**不新增 WebSocket**） |
| `docker exec -i` + 容器内 `sh` / `cat` | **采用** | 复用已验证资产、零新增依赖、能控属主与覆盖语义 |

### 上传语义

- 字节流写入容器内**临时名**，再 `mv` **原子替换**目标（rename 不跟随末端符号链接）。
- **临时名必须与目标同目录**：跨设备 `mv` 走 copy + unlink，**非原子、中途失败留半截文件**。
- **路径一律 argv 直传**（`docker exec … cat -- <path>`），**禁止**拼进 `sh -c` 脚本文本——含换行 / 引号的路径会被拆碎；`sh -c` 只用于固定脚本，路径经 `"$1"` 位置参数传入。
- 写入失败 → **平台侧显式清理临时文件**（不留残骸）：实测 exec 被杀时容器内会留下半截临时文件，`cat` **不会自清理**——清理是平台侧行为，不是容器的自愈。
- **目标已存在 = 覆盖**（用户拍板）。前端在同名时弹**覆盖确认框**——语义仍是覆盖，确认框是 UI 防误触，不是另一种语义。
- **目标为「已存在目录」必须前置拒绝**：实测 `mv 临时名 目录` **rc=0 假成功**，文件被搬进目录里（用户侧极难察觉）→ 探测阶段发现**目标是目录即拒绝上传**。**不依赖 `mv -T`**（busybox 不支持）。
- **目标文件自身只读（`0444`）不是错误**：父目录可写时 `mv` 静默覆盖成功（root 与非 root 同）。错误类别只有三类——**父目录缺失 / 父目录不可写（EACCES）/ 只读挂载（EROFS）**；把「目标只读」当错误会**把正常覆盖误判成失败**。

### 下载语义

- `cat` 流出字节；前置**探测**拿类型与字节数——**分层判定**（见下表）。
- **前置探测是硬要求，不是优化**：实测 **FIFO 会挂死 `cat`**（GNU 与 busybox 都挂，一条请求就能占住一条 exec 进程），`/dev/null` 会静默返回 0 字节的空下载。
- **只允许普通文件**：目录回 **400** 并给明确文案；**管道 / 设备 / 套接字一律拒**——防挂起。**这是类型检查，不是路径限制。**
- **大小首选 `stat -c %s`**（O(1)），`wc -c < file` 为备选（要读完整个文件）；`ls -l` 解析**不采用**（GNU 与 busybox 列宽不同）。
- **错误分类只按 stderr 关键词子串**（`nonexistent` / `Directory nonexistent` / `Permission denied` / `Read-only file system` / `Is a directory` / `No such file or directory`），**不按整句、不按退出码**——dash 与 busybox ash 的措辞与退出码都不同（父目录缺失：dash rc=2 / busybox rc=1）。
- 响应带 `Content-Length`（探到时）与 `Content-Disposition: attachment`（`filename*` 走 UTF-8、附 ASCII 回退，**中文文件名必须正确**）。

**探测的分层判定**（实测 GNU 与 busybox 均可区分）：

| 判定 | 含义 | 处置 |
|---|---|---|
| `-d` | 目录 | **拒**（400） |
| `-f` | 普通文件 | **放行**；大小取 `stat -c %s` |
| `-p` / `-c` / `-b` / `-S` | FIFO / 字符设备 / 块设备 / 套接字 | **拒**（防挂起） |
| `-e`（以上都不成立） | 其余特殊文件 | **拒** |
| 兜底 | 不存在 | 报「文件不存在」 |

> PRD 草案的 `test -d` / `test -f` / `else missing` 口径**达不到目的**：FIFO / 设备 / 套接字与「不存在」**同落 `missing`**，「管道 / 设备可区分」这条要求必须靠上面的分层判定才成立。

### 容器内路径与大小

- 容器内路径一律**绝对路径**、词法校验（不做符号链接解析、不跟随）。
- **无黑名单、全部允许**（用户拍板）：不设路径黑名单，容器内的权限由容器自身的用户与文件系统决定。
- 平台**不主动创建父目录**：父目录缺失即报错并引导用户先建好（或先导航过去）。
- **符号链接语义（显式定义）**：**类型探测跟随符号链接**（`test -f` / `wc -c <` 跟随；`stat` 不跟随 ⇒ mtime 取 `stat -L -c %Y`）；**上传的 rename 不跟随末端符号链接**（替换链接本身，链接目标不受影响）。两处口径**刻意不同**，不得「顺手统一」。
- **大小上限：不限**（用户拍板，无 413）。后端全程流式、内存有界（详见「服务端」）。
- **「大小不限」的前提是端点用 raw 流式 body**（见「服务端」）：FastAPI 的 JSON body 会被整体缓冲进内存（实测 200 MiB ⇒ 控制台进程 RSS 44.5 → 433.9 MiB）。
- **部署链反代的读超时是硬约束（01 轮已核对）**：本机 Traefik v3.7.13 反代 `sandbox-api.sankabox.com` → `192.168.2.135:28642`，该 service 无 `transport` 覆盖 ⇒ 默认 `readTimeout=60s`；**同一 200 MiB 慢上传直连跑满 201.23 s 成功、经反代 61.13 s 被掐断**（下载方向不受限：200 MiB 响应经反代 0.09 s 完整送达）。**反代与后端都无 body 大小上限（不会 413），但单次请求的总时长受反代读超时约束**——落地须为该 service 调 `transport.respondingTimeouts.readTimeout`（`0` 或显式大值），并要求**远程部署自查反代**（本机结论不外推）。

### 服务端

- REST **流式**；字节搬运进**专用线程池**（`TRANSFER_IO_EXECUTOR`，对齐转发轮的 `PUMP_IO_EXECUTOR` 惯例），**不进事件循环**。
- **上传端点必须 raw 流式读 body**（`request.stream()` 逐块消费），**不得用 JSON 模型 / pydantic 接 body**——后者把整个 body 一次性缓冲进内存，「内存有界」将只在字节泵层成立、端到端不成立。
- **客户端断开** → 关泵 + 清临时文件（不挂死后台进程、不留容器内残骸）。
- 错误响应固定中文文案，形状是 `{"detail": "<中文>"}`；**容器内 stderr 原文只进日志**，不回显给调用方。
- **错误分类只按 stderr 关键词子串**（不按整句、不按退出码）；三类失败（父目录缺失 / 父目录不可写 / 只读挂载）各有固定中文文案；**报错文本里的临时名要换成用户的目标路径**再拼文案。
- 鉴权：端点挂在 `/api` 下即被**令牌中间件自动保护**（无需新增鉴权代码）。
- 本轮**不新增 WebSocket**；只用 GET / POST → **CORS 白名单零改动**。

### 接口草案（3 个端点）

| 方法与路径 | 入参 | 出参 | 要点 |
|---|---|---|---|
| `POST /api/sandboxes/{name}/files/upload?path=<容器内绝对路径>` | **raw body**（`application/octet-stream`，**无 multipart**、**流式读**） | `{path, bytes}` | 写同目录临时名 → `mv` 覆盖；父目录缺失报错；**目标是已存在目录 → 前置拒绝** |
| `GET /api/sandboxes/{name}/files/download?path=<...>` | 查询参数 `path` | `StreamingResponse` | 带 `Content-Length`（探到时）+ `Content-Disposition: attachment`；**前置分层探测**，只放行普通文件 |
| `GET /api/sandboxes/{name}/files/list?path=<目录>` | 查询参数 `path` | 目录条目列表 | 名称 / 内部类型 / 大小 / 修改时间；**隐藏文件包含**；底层命令兼容不同镜像（busybox / GNU）并正确处理**空格、中文与换行**等名字 |

### 前端

- **入口**：工作台沙箱操作区的「**文件**」按钮，与「详情」「停止」**同级** → 打开**独立的文件浏览抽屉**（不塞进沙箱详情抽屉）。
- **面板 = 迷你文件管理器**：**面包屑**导航 + **列表**。
  - 列表**三列**：**图标 + 名称** / **大小** / **修改时间**——**无类型列**。
  - **文件夹在前**，按名称排序；**隐藏文件（`.` 开头）显示**。
  - **点击文件行本身即下载**：无下载按钮。
  - **界面一律不加副标题 / 解释说明性文字**（见 [[conventions/console-frontend.md|前端约定]] 新增两条）。
- **面包屑**各级可点击，**不重复展示纯文本形式的当前目录**（demo 反馈修正项）。
- **上传**：只能传进**当前浏览目录**（要传别的路径先导航过去，**无手动路径输入框**）；行内**进度条** + **可取消**；目标同名时弹**覆盖确认框**。
- **进度条必须有**：上传用 **XHR**（fetch 拿不到上传进度事件）；下载按 `Content-Length` + 流式读取计算。
- **下载分形态**：
  - **web 形态** = 标准浏览器行为：`fetch` → `blob` → `a[download]`；**不得导航 blob: URL**（桌面 CSP 只在 `img-src` 放行 blob）。
  - **桌面形态** = **原生「保存为」对话框**（`tauri-plugin-dialog`）→ Rust 侧带令牌下载落盘。
- **上传两形态完全共用** `<input type="file">`（WebView2 原生可用），**Rust 上传零改动**。
- **图标**：material-icon-theme（vscode-material-icon-theme）风格。正式实现把所需 **SVG 子集 vendor 进前端仓库构建资产**（**不用运行时 CDN**：桌面 CSP 与离线场景都不允许）；**通用兜底图标 = 用户提供并已验证的 `folder.svg` / `file.svg`**（现暂存仓库根目录，前端实现任务负责移入前端资产目录并接入映射）。素材来源与映射口径已在视觉 demo 中验证：CDN tag `v5.40.0`、108 个图标逐一验证可用；注意该版本**没有**通用 `folder.svg` / `file.svg` 与 `*_open` 变体（所以兜底用用户自备的两个，「展开态」用样式表达）。视觉底座沿用控制台既有 token。

### 桌面端

- Rust：`reqwest`（**rustls-tls + stream 特性，不引 OpenSSL**，对齐既有 rustls 栈）实现下载落盘命令 + `tauri-plugin-dialog` 保存框；落盘路径 = **用户所选**；capabilities 补 dialog 权限。
- release profile `panic = "abort"`：新增 Rust 代码**禁 unwrap / 越界索引**，错误一律 `Result` 收口。
- 本机无法验 WebView2 真机行为 → 必须产出 **Windows 真机验证清单**（上传选文件 / 保存框 / 中文文件名 / 大文件 / 中途取消），**未验不宣称完成**。

对齐三期「核心包 → 服务端 → 前端 → 桌面 → 验收」的拆法；**01 是硬前置，不通过不进 02**。

| 03 | 服务端 | `routes/files.py` 三端点 + 流式装配 + 错误文案表 + schemas + `API.md` 新章节 + 单测；**raw 流式 body（禁 JSON body）** + **Traefik `sandbox-api-service` 的 `transport.respondingTimeouts.readTimeout` 落地调整**（本机部署链属本平台自管的基础设施，属本轮落地范围） |

## 验收标准

### 接口与后端

- [ ] 三个端点（`upload` / `download` / `list`）行为符合接口草案；端点挂在 `/api` 下即**被令牌中间件自动保护**——无令牌 / 错令牌一律 401，不另写鉴权分支。
- [ ] 上传走 **raw body**（`application/octet-stream`，无 multipart），返回 `{path, bytes}`，字节数与实际写入一致。
- [ ] 上传是**原子替换**：写**同目录**临时名 → `mv` 覆盖，**目标已存在 = 覆盖**（不报错、不提示歧义）；写入失败时**临时文件被清理**，不留残骸。
- [ ] 上传**不主动创建父目录**：父目录缺失时报错并给出可行动的引导文案。
- [ ] 上传**前置拒绝「目标是已存在目录」**（`mv` 对目录目标 rc=0 假成功）；**目标文件自身只读（`0444`）不报错**（被覆盖）；错误类别只有**父目录缺失 / 父目录不可写（EACCES）/ 只读挂载（EROFS）** 三类。
- [ ] 上传与下载的**容器内路径一律 argv 直传**（含换行 / 引号 / `-` 开头的路径不拆碎）。
- [ ] 下载**只允许普通文件**：探测**分层判定**，目录 → **400** + 明确中文文案；FIFO / 设备 / 套接字 → **拒**（不挂起）。**这是类型检查，不是路径限制。**
- [ ] 下载响应带 `Content-Length`（探到时）与 `Content-Disposition: attachment`，**中文文件名正确**（`filename*` UTF-8 + ASCII 回退），下载字节与容器内文件**逐字节一致**。
- [ ] 目录列表返回名称 / 内部类型 / 大小 / 修改时间，**隐藏文件（`.` 开头）包含在内**；底层命令在 busybox 与 GNU 两种镜像下都正确，**含空格、中文与换行的名字**不乱（`find` 单次 exec 产出 NUL 分隔记录）。
- [ ] **大小不限**：无 413 判定；**后端全程流式、内存有界**——200MB 级传输的服务端内存曲线有实测证据（打样轮与验收轮各留一份）。**前提**：上传端点用 **raw 流式 body**（不得用 JSON 模型接 body）。
- [ ] **部署链反代的读超时已核对并落地**：本机 Traefik `sandbox-api-service` 的 `transport.respondingTimeouts.readTimeout` 已调（`0` 或显式大值），并**经域名**（过反代）验证慢速大上传不再被 60 s 掐断；**远程部署自查反代**的口径写进 API.md / 部署说明。
- [ ] 错误响应形状固定为 `{"detail": "<中文>"}`；**容器内 stderr 原文只进日志**，不回显给调用方；**错误分类只按 stderr 关键词子串**（不按整句、不按退出码）。
- [ ] **客户端断开 → 关泵 + 清临时文件**：不留挂死的 exec 进程、不留容器内残骸。
- [ ] 字节搬运走**专用线程池**（`TRANSFER_IO_EXECUTOR`），**不进事件循环**。
- [ ] **命令行零改动**；**创建时注入通道零改动**（创建请求、模板字段、副本语义一律不动）。

### 前端

- [ ] 工作台沙箱操作区有「**文件**」按钮，与「详情」「停止」**同级**，打开**独立文件浏览抽屉**。
- [ ] 列表**三列**：图标 + 名称 / 大小 / 修改时间——**无类型列**；文件夹在前按名称排序；**隐藏文件显示**。
- [ ] **点击文件行本身即下载**——不另加下载按钮。
- [ ] **界面一律不加副标题 / 解释说明性文字**（该约定已写进 [[conventions/console-frontend.md|前端约定]]）。
- [ ] **面包屑**各级可点击，且**不重复展示纯文本形式的当前目录**。
- [ ] 上传**只能传进当前浏览目录**（**无手动路径输入框**）；行内**进度条** + **可取消**；目标同名时弹**覆盖确认框**。
- [ ] **进度条必须有**：上传用 XHR（fetch 拿不到上传进度事件）；下载按 `Content-Length` + 流式读取计算。
- [ ] 下载**分形态**：web 形态 = `fetch` → blob → `a[download]`（**不得导航 blob: URL**）；桌面形态 = **原生「保存为」对话框** → Rust 侧带令牌下载落盘。
- [ ] 上传两形态**完全共用** `<input type="file">`；**Rust 上传零改动**。
- [ ] 图标为 material-icon-theme 风格；所需 **SVG 子集已 vendor 进前端构建资产**（**不用运行时 CDN**）；**通用兜底图标** = `folder.svg` / `file.svg`（已从仓库根目录**移入前端资产目录**并接入映射）。

### 桌面端

- [ ] Rust 侧用 `reqwest`（**rustls-tls + stream 特性，不引 OpenSSL**）实现下载落盘命令；`tauri-plugin-dialog` 保存框可用，capabilities 已补 dialog 权限。
- [ ] 落盘路径 = **用户所选**；新增 Rust 代码**无 unwrap / 越界索引**（release profile `panic = "abort"` 下的硬要求），错误一律 `Result` 收口。
- [ ] **Windows 真机验证清单**已产出并逐条验过：上传选文件 / 保存框 / 中文文件名 / 大文件 / 中途取消；**未验不宣称完成**。

### 验收、门禁与文档

- [ ] 质量基线全绿：核心包 pytest + ruff；服务端 pytest + ruff；前端 vitest + typecheck + build；`cargo check` / `cargo test`。
- [ ] Playwright 真机 spec 覆盖**主链路**（上传 → 容器内校验内容与属主 → 下载 → 字节比对）与**负例**（下载目录 400 / 沙箱停止 409 / 非法路径 400）。
- [ ] 文档同步：`API.md` 新章节、[[conventions/console-frontend.md|前端约定]]、看板、词汇表；**ADR 0018 复核**（状态已是已接受，06 只复核不改状态）；任务集收口留档。
- [ ] [[glossary.md|词汇表]] 有「运行期文件传输」词条，与「文件注入（创建时）」明确区分（通道 / 时序 / 读写方向 / 生命周期）。
