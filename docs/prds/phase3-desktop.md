## 背景

二期把控制台做成了「后端托管前端 + 单端口同源」：前端全部 API 走同源相对路径（`apps/web/frontend/src/api/client.ts` 的 `request()` 统一发 `fetch`），网页终端的 WebSocket 地址由 `window.location` 现拼（`src/lib/terminal.ts` 的 `terminalSocketUrl()`），后端没有 CORS 中间件、也没有任何认证（[[architecture/decisions/0009-二期控制台服务化与范围裁剪.md|ADR 0009]] 第 1 节把安全边界定成「只绑回环或内网」）。

这套形态隐含了一个前提：**浏览器与后端同机同源**。一旦要跨机器用，两处前提同时塌掉：

1. **请求发不到对的地方**。请求路径写死成相对路径 `/api/...`，基址不可配置；WebSocket 更是从 `location.host` 推出来的。
2. **没有凭据**。后端一旦从回环改绑内网（跨机器访问的必经之路），按 ADR 0009 的口径就是「完全信任」——服务以宿主特权身份运行，拿到接口等价于拿到宿主 root 级能力，没有任何第二层拦截。

同时，「沙箱里的服务端口怎么从外面访问」这件事一直缺位。一期把「不做宿主机端口发布」写进了隔离契约（[[architecture/decisions/0003-每沙箱专属用户与免root守护进程.md|ADR 0003]] 第 5 节）；原定三期想用「容器端口发布到宿主回环 + 宿主页反代对外」的 URL 代理解决，已随原定三期整体退役（[[architecture/decisions/0001-项目定位与三期路线.md|ADR 0001]] 修订行）。

本期的做法与 URL 代理**不是同一件事**，方向也相反：

| | URL 代理（已退役） | 端口转发（本期） |
|---|---|---|
| 谁发起访问 | 浏览器访问网页里的链接 | 桌面应用访问自己机器上的 `127.0.0.1:<端口>` |
| 对外暴露面 | 宿主页反代出的网页 URL（局域网可达） | 只在本机回环，不出本机 |
| 语义 | 平台代为提供一个「可分享的网址」 | 桌面端到沙箱端口的一条私有通道 |

第三条规划方向「前后端分离部署」（后端独立 API + token 认证、前端静态站托管到 Cloudflare、凭「后端地址 + token」远程连接）与本期的桌面端方向高度重叠。桌面壳自带前端，**Cloudflare 静态托管不再需要**；后端独立 API 与 token 认证则**被本期整体吸收**——它正是桌面端能连远程后端的前提。因此「前后端分离部署」不再单独立项，其内容按下面的口径并入本期，原「前后端分离部署」在规划看板上的条目作废并标注退役。

第四条需要点明的现实约束：开发机是 Linux，Windows 安装包的构建路径需要单独选型（见「打样前置项与风险清单」R1）。目标平台以 **Windows（Tauri + WebView2）** 为主，Linux / macOS 只保证源码层面可构建，不承诺出包。

### 一处必须先纠正的事实（影响整个端口转发工作包）

侦察给出的 `-p` 先例属于**宿主 root 守护进程**，不是免 root 守护进程：全仓唯一的 `-p` 用法在统一镜像代理 `apps/core/src/sandbox_platform/proxy.py`（`-p 127.0.0.1:<端口>:3128`），而那个容器跑在**宿主 root 守护进程**下（`Privilege.wrap()` 在进程本身是 root 时不加前缀，走的是宿主 `docker`）。沙箱的免 root 守护进程按 `apps/core/src/sandbox_platform/userspace.py` 固定了 `DOCKERD_ROOTLESS_ROOTLESSKIT_DETACH_NETNS=true`（守护进程留在宿主网络命名空间、容器在 slirp4netns 命名空间），且一期打样任务 `01-rootless-probe.md` 的「端口发布判定」写的是「宿主 `ss -ltn` **不出现**由探针容器新增的监听端口」。

因此「免 root 守护进程 `-p` 发布宿主回环」在本平台配置下**未被证实**，必须作为端口转发工作包的硬前置打样项 P1，并预置 Fallback B（`docker exec -i` 字节泵）。这一条写进了风险清单、ADR 0014 的「影响」段与任务 01。

> **2026-11-03 修订（决策 C）**：P1 打样**已实测通过**（`-p` 在本平台**可用**，结论见 [[tasks/phase3-desktop/RESULTS.md|三期留档]]），但**该路径不再采用**——理由不是技术不可行，而是产品形态上后端宿主机不该持有端口。**Fallback B（`docker exec -i` 字节泵）升为唯一路径**；`-p` 主路径与宿主端口区间（默认 `18000-18999`）分配**整体废除**。本 PRD 全文中涉及宿主端口的条款按此改写，原文保留并标注「已按 2026-11-03 决策 C 废除/取代」。

### 数据流全景

> **2026-11-03 修订（决策 C：链路两点化、后端宿主机零端口）**：链路只有「沙箱 ⇄ 用户机」两点，后端宿主是**纯中继**——不发布端口、不监听转发端口。

```
┌──────────────────────── 用户机（桌面机，Windows 为主）────────────────┐
│  Tauri 壳                                                                  │
│   ├─ 前端产物（与 web 形态同一份源码、同一份 dist）                       │
│   ├─ 连接配置：后端地址 + token（src/lib/connection.ts）                    │
│   └─ Rust 核心：本机 127.0.0.1 TCP 监听 ⇄ 隧道 WS 字节桥接                 │
└───────────────┬──────────────────────────────────┬───────────────────────┘
                │ HTTP/WS（Authorization: Bearer）  │ WS 隧道（二进制帧透传）
                ▼                                  ▼
┌──────────── 后端机（跑沙箱的宿主 · 纯中继 · 转发零端口）────────────────┐
│  控制台服务 sandbox_console                                                │
│   ├─ /api/** 全量 token 保护（含终端 WS，浏览器侧走一次性票据）            │
│   ├─ CORS 任意来源（allow_origins=["*"]，不带凭据）                              │
│   ├─ /api/forwards（列表/建立/停止）                                      │
│   └─ /api/forward/tunnel/{id}（隧道 WS，Rust 侧走 Authorization 头）        │
│        │  字节泵：docker exec -i <转发容器> socat - TCP:<沙箱容器名>:<端口> │
│        ▼                                                                  │
│   控制面（核心包 sandbox_platform，薄壳在服务端）                          │
│   转发编排：转发容器（沙箱守护进程起，接沙箱网络，**不发布端口**）          │
│        ▼                                                                  │
│   沙箱网络 <sandbox>-net：sandbox-<name>:<用户指定端口>                    │
└──────────────────────────────────────────────────────────────────────────┘
```

（立稿口径：后端宿主持有一个被 `-p` 发布到宿主回环的端口，链路是「沙箱 → 转发容器 → 宿主回环 → 隧道 → 桌面监听」。**已按 2026-11-03 决策 C 废除/取代，留档**。）

## 目标

- **桌面壳跑起来**：把现有前端产物装进 Tauri v2 应用，在 Windows + WebView2 上可用；应用是**纯连接器**——只装前端与连接配置（后端地址 + token），**不负责拉起后端服务**，支持连接部署在别的机器上的后端。
- **连接层真正独立**：后端所有 `/api`（含终端 WebSocket）受 token 保护；前端支持可配置的请求基址与凭据；跨源可读（CORS 任意来源、不带凭据，2026-11-03 修订）；WebSocket 有可用的鉴权通道（准入边界 = 令牌 + 票据）。
- **端口转发可用**：用户显式指定「沙箱名 + 容器端口」，平台把该端口经「后端隧道」送到**用户机（桌面机）的 `127.0.0.1`**；监听面只在本机回环，不暴露到局域网。**链路只有「沙箱 ⇄ 用户机」两点，后端宿主不发布、不监听任何转发端口**（2026-11-03 决策 C）。
- **控制面能力可复用**：转发容器编排落核心包（`sandbox_platform`），服务端只是薄壳；转发容器属平台自建资源，纳入回收与清理语义；**沙箱容器与依赖容器零改动**；**桌面端不要求用户改任何镜像**。
- **既有验收不回归**：既有 9 条控制台验收用例在 token 模式下全量回归通过，并补认证与转发的负向 / 正向用例。

## 非目标

- **不承诺 Linux / macOS 打包**：只保证源码层面可构建，不出安装包、不做平台验收、不承诺平台专属行为。
- **Cloudflare 静态站托管退役**：桌面壳自带前端，不需要独立静态托管；原「前后端分离部署」规划里的静态站部分作废，不再规划。
- **不做多用户 / 多租户隔离**：token 是**单一访问凭据**，谁拿到 token 谁就能访问整个平台的全部能力（含沙箱生命周期这种宿主特权操作）。本期不做账号体系、不做 per-user 沙箱隔离、不做令牌吊销与权限分级。
- **原三期退役项一律不做**：URL 代理（容器端口发布到宿主回环后由网页反代对外）、沙箱快照、每沙箱资源配额、过期沙箱自动清理、厚沙箱模式、可选弱网模拟。
- **不做端口转发的对外暴露**：转发端点只在本机回环；**后端宿主不持有转发端口**（2026-11-03 决策 C）；不做内网可达、不做公网可达、不做端口转发器的鉴权分级（拿到 token 就能建转发）。
- **不做转发目标的协议改写**：不把 HTTP 升级成 HTTPS、不做路径改写、不做 TLS 终止、不注入任何响应头。转发是**字节级透明通道**。
- **不做登录 / 会话 / 多令牌 / 令牌轮换 UI**：本期只有一个令牌；轮换靠「删令牌文件 + 重启服务」（见「开放问题清单」Q1）。
- **不做自动更新**：桌面端不引入 Tauri updater 插件。
- **不改任何沙箱镜像**：平台不要求用户镜像预装 `socat` 之类工具；转发容器是平台自建的独立容器，走平台自己的镜像。
- **不改命令行**：`sandboxctl` 保持直连核心包，不改造成服务客户端（ADR 0009 的推迟继续有效）；命令行不做转发相关入口。
- **不做 Web 形态的端口访问**：web 形态**不提供任何转发管理操作**（不列表、不新建、不停止），只渲染说明卡与「安装桌面端」指引；**不能**在浏览器里直接访问沙箱端口——那正是已退役的 URL 代理。

## 方案

五个工作包按依赖顺序推进：打样 → 连接层后端 → 连接层前端 → 端口转发（核心包 → 服务端 → 桌面侧）→ 打包与回归。

### 工作包一：打样轮（前置硬门槛）

打样轮不产出用户可见功能，只回答「这条路走不走得通」，结论不成立时整个工作包四要改方案。先做，因此排在最前。

- **P1 免 root 守护进程的端口发布**（**阻断端口转发工作包的硬前置**）：在沙箱专属用户的免 root 守护进程下 `docker run -p 127.0.0.1:<宿主端口>:<容器端口>`，判定「宿主 `ss -ltn` 出现该端口」且「从宿主 `curl 127.0.0.1:<端口>` 能连到容器内的目标服务」。
  - 依据与风险：全仓唯一的 `-p` 先例（`apps/core/src/sandbox_platform/proxy.py`）跑在**宿主 root 守护进程**下；沙箱的免 root 守护进程固定了 `DOCKERD_ROOTLESS_ROOTLESSKIT_DETACH_NETNS=true`（`userspace.py`），一期打样的「端口发布判定」写的是宿主**不出现**新监听端口。**结论未验证，属未知**。
  - 不成立时的备案路径（Fallback B，见 ADR 0014）：转发容器仍由沙箱守护进程起、仍接沙箱网络，但**不发布端口**；宿主侧改用 `docker exec -i <转发容器> socat - TCP:<沙箱容器>:<端口>` 建立双向字节管道，平台侧再把字节泵到宿主回环端口。代价：每条连接一个 exec 进程、延迟与吞吐不如直连、`exec` 管道非 TTY 需要额外分帧与超时处理；优点是完全不依赖 `-p`，只依赖终端伪终端桥接已经在用的 `docker exec` 机制。
- **P2 Tauri 壳 + WebView2 三项冒烟**：Tauri v2 壳加载现有前端产物后，在真机 Windows + WebView2 上验三项：① `oklch()` 配色（Tailwind v4 的色板底座，旧版 WebView2 不支持 `oklch` 会整页掉色）；② `xterm.js`（字体度量、`fit` 插件量算、终端表面不溢出）；③ `navigator.clipboard`（安全上下文判定 + 授权弹窗）。
- **P3 转发镜像可拉**：转发容器用的镜像（`alpine/socat`，钉 digest）在沙箱守护进程内经统一镜像代理可拉取（代理职责只服务沙箱守护进程的镜像拉取，ADR 0009）。
- **P4 Windows 出包路径**：GitHub Actions / 自有 Windows 机两条路各试一次，确认哪条在本仓库现实可用（仓库当前**没有**任何 CI 配置，也没有远端）。

### 工作包二：连接层后端改造（token 认证 + CORS + WS 鉴权）

- **令牌生成与配置**：服务启动时若环境变量 `SANDBOX_CONSOLE_TOKEN` 有值则直接采用；否则在平台数据根生成随机令牌，落 `<数据根>/console-token.json`（权限 `0600`，与既有 `metadata.json`、模板文件同款口径）。**服务永远不会在没有令牌的情况下对外提供接口**。启动日志只打印令牌文件路径与「首次启动已生成访问令牌」，**绝不打印令牌本体**。
- **HTTP 鉴权**：统一 `Authorization: Bearer <token>`；比较用 `hmac.compare_digest`（常量时间）；缺失或错误一律 `401` + `{"detail": "访问令牌无效或缺失"}`（不回显收到的令牌、不区分「缺失」与「错误」以免形成探测 oracle）。令牌不匹配时不写日志正文。
- **WebSocket 鉴权（浏览器侧）**：浏览器的 `WebSocket` API 不能设自定义头，因此终端 WebSocket 走**一次性票据**：
  - `POST /api/auth/ticket`（带 `Authorization: Bearer`）→ 返回 `{"ticket": "...", "expires_in": 30}`；票据为 32 字节随机值、**一次性**、30 秒过期、服务内存态。
  - 终端 WebSocket 握手改为 `ws(s)://<后端>/api/terminal/sessions/<id>?ticket=<票据>`；握手时校验并**立即作废**票据，非法则拒握手。
  - **不采用 `?token=` 直传**：令牌会进访问日志与任何中间代理的日志。票据即使泄漏也只在 30 秒内有效且用过即废。
  - **不采用 `Sec-WebSocket-Protocol` 夹带令牌**：可行但非标准用法，部分代理 / 中间件会改写子协议列表；票据方案更通用。
  - **Rust 侧不需要票据**：桌面 Rust 核心用 `tokio-tungstenite` 打开隧道 WebSocket，可以直接设 `Authorization` 头，走标准 Bearer 通道。
- **CORS**：**任意来源**——`allow_origins=["*"]`，**不带凭据**（`allow_credentials=False`，凭据与 `*` 不能共存）；方法与头白名单不变：`allow_methods=["GET","POST","DELETE","OPTIONS"]`、`allow_headers=["Authorization","Content-Type"]`。（**2026-11-03 修订**：原口径「只放行 `http://tauri.localhost`、`http://localhost:5173`、`http://127.0.0.1:5173`、不放行任何通配符」已作废，改为任意来源。见 [[architecture/decisions/0013-三期定位改定与认证重启.md|ADR 0013]] 第 4 节的第二次修订。）
- **WebSocket 的 Origin 校验**：**取消门禁**——CORS 管不到 WebSocket 握手，但**握手不再校验 `Origin`**（2026-11-03 修订：原「Origin 头不在放行清单内直接拒握手」的口径已作废，包含其后的「同源放行」修订一并作废）。**准入边界收敛为「令牌 + 票据」**：WS 握手必须带一次性票据，中间件对 WebSocket scope 默认拒绝、fail-closed。见 [[architecture/decisions/0013-三期定位改定与认证重启.md|ADR 0013]] 第 4 节的第二次修订。
- **`/docs` 与 `/openapi.json`**：不受令牌保护（仅 `SANDBOX_CONSOLE_DOCS=1` 时开启，默认关闭）；CORS 放开后**跨源可读**——接口清单不含凭据，但会暴露 API 形状（2026-11-03 修订的已知代价）。
- **`/api/health` 不豁免**：保持「所有 `/api` 受保护」的口径一致。好处是前端能区分「后端不可达」（连接失败）与「令牌无效」（401）两种状态；代价是外部监控探活必须带令牌（可用 socket 层探活替代）。
- **非回环监听的告警改写**：ADR 0009 的「绑非回环 = 完全信任」前提已被令牌推翻，因此 `apps/web/backend/src/sandbox_console/__main__.py` 的 `warn_if_not_loopback()` 改为：已配置令牌时打「已启用令牌认证」的提示；未配置令牌时**不可能发生**（启动必生成），但代码路径仍保留兜底告警。
- **代理重启端点的口径更新**：`POST /api/proxy/restart` 原是「未认证的特权端点」，本期起受令牌保护，README 与 API.md 的相关说明同步改写。

### 工作包三：连接层前端改造（基址抽象 + 连接配置 + 未配置态）

- **连接配置模型**：`{ backendBaseUrl: string; token: string }`，落 `localStorage`，键 `sandbox-console-connection`。读写收敛在 `src/lib/connection.ts`（纯函数 + `useConnection()` Hook），**配单元测试**，口径与既有的 `theme.ts` / `sidebar-collapsed.ts` 同款：只认自己写进去的值，非法值 / 读取失败回落默认，存储不可用时静默忽略不打断交互。
  - `backendBaseUrl` **默认 `http://127.0.0.1:8000`、可编辑、不可为空**（2026-11-03 决策 D：取代原「基址一律可选、空即同源」——「空 = 同源」语义与整条空基址逻辑链（归一分支、桌面守卫、推导回退、占位文案）删除；旧存储里基址为空的配置读取时归一为默认值）。
  - 令牌在 `localStorage` 里是**明文**：本期接受这个代价（单人自用、平台非公网），并在 UI 与文档里写明；「存操作系统凭据库」列为开放问题（Q5）。
- **请求基址抽象**：`src/api/client.ts` 的 `request()` 改为先经 `resolveApiBaseUrl()` 取基址，再拼路径；每个请求自动带 `Authorization: Bearer <token>`。错误映射口径不变（仍直接展示后端 `detail`）。
- **WebSocket 地址推导**：`src/lib/terminal.ts` 的 `terminalSocketUrl()` 不再从 `window.location` 现拼，改为从连接配置推导：

### 工作包四：端口转发（核心包能力 + 服务端接口 + 桌面侧）

> **2026-11-03 修订（决策 C：链路两点化、后端宿主机零端口）**：本工作包整段按新链路改写。原「四段链路 + 宿主端口分配」口径（`-p` 发布宿主回环 + 18000-18999 区间分配）**已按 2026-11-03 决策 C 废除/取代**，在各条中逐条留档。

**链路（两点：沙箱 ⇄ 用户机）**

```
沙箱容器 :<用户端口>
   │  （同网络按容器名互访）
转发容器（平台自建，由沙箱的免 root 守护进程起，接沙箱网络，**不发布端口**）
   │  后端每条连接起一个字节泵：
   │  docker exec -i <转发容器> socat - TCP:<沙箱容器名>:<端口>
后端宿主（纯中继：只跑隧道服务与字节泵，**不发布、不监听任何转发端口**）
   │  隧道 WS /api/forward/tunnel/{forward_id}（二进制帧透传）
用户机 Rust 核心
   │  （本机 TCP <-> WS 字节桥接）
用户机 127.0.0.1:<本机端口>   ← 用户访问的就是这个
```

（原「四段链路」：转发容器 `-p 127.0.0.1:<宿主端口>:<转发容器内部端口>` → 后端宿主 `127.0.0.1:<宿主端口>` → 隧道 → 桌面监听。**已按 2026-11-03 决策 C 废除/取代，留档**。）

- **转发容器编排（核心包，新增 `apps/core/src/sandbox_platform/forwarding.py`）**：
  - 容器名 `<沙箱名>-fwd-<端口>`，带平台标签（`sandbox-platform.role=forward` 等）便于枚举与回收。
  - 镜像：平台自有的转发镜像（`alpine/socat`，钉 digest），经统一镜像代理拉取到沙箱守护进程；**不改任何沙箱镜像**。
  - **无端口发布**：不传 `-p`、不发布任何端口；容器主进程常驻、不做 TCP 监听，`socat` 二进制专供 exec 字节泵使用；`--restart=no`（生命周期由平台显式管理）。
    - （立稿口径：命令 `socat TCP-LISTEN:<内部端口>,fork,reuseaddr TCP:<沙箱容器名>:<用户端口>` + `-p 127.0.0.1:<宿主端口>:<内部端口>`。**已按 2026-11-03 决策 C 废除/取代，留档**。）
  - 由**沙箱自己的免 root 守护进程**启动（这样才能接入沙箱网络），与沙箱容器、依赖容器同属一个守护进程。
- **用户机侧端口规则**（端口选择权在桌面端，后端不感知）：默认 = 容器端口；可编辑、**不可为空**；**被占自动换空闲端口并显示实际值**；**允许 <1024**（Windows 可绑、macOS 现代版可绑、Linux 非 root 不可绑；目标平台 Windows 为主，Linux 上绑低端口失败必须明确报错）。
  - （立稿口径「**宿主端口分配与占位**：后端宿主回环端口由平台自动分配（可配区间，默认 `18000-18999`），分配时先做「端口可绑定」探测，分配结果落进转发记录形成占位；启动转发容器时 Docker 绑定失败（端口被占）即换端口重试，仍失败则明确报错」。**已按 2026-11-03 决策 C 整体废除，留档**。）
- **通道机制**：`docker exec -i <转发容器> socat - TCP:<沙箱容器名>:<端口>`（在沙箱守护进程下执行），后端把该进程的 stdin/stdout 与隧道 WS 做双向搬运；**连接断开 → exec 进程立即回收**。每条连接一个 exec 进程是**既定既接受**的代价。
- **隧道协议**（`/api/forward/tunnel/{forward_id}`）：
  - **一条 WebSocket 对一条 TCP 连接**（本期不做多路复用）。
  - 客户端 → 服务端：二进制帧 = 透传字节；文本帧 = 控制（本期仅保留扩展位）。
  - 服务端 → 客户端：二进制帧 = 透传字节；文本帧 = `{"type":"hello", ...}` / `{"type":"error","message":"..."}`。
  - 关闭：任一侧 EOF 即关另一侧；转发不存在或已停止 → 关闭码 `1008`；正常关闭 `1000`。
- **转发管理 REST**：
  - `GET /api/forwards` → 裸数组。
  - `POST /api/forwards` → `{sandbox, port}`，返回转发记录（**记录字段：id / sandbox / container_port / state / created_at / updated_at，无 `host_port`**）。
  - `DELETE /api/forwards/{id}` → 停止转发（停并删转发容器、删记录；**不释放任何端口**——宿主侧无端口）。
- **生命周期与清理语义**：
  - 转发记录落 `<数据根>/forwards/<id>.json`（`0600`）。
  - **沙箱停止** → 该沙箱的转发容器一并停止（记录保留）。
  - **沙箱启动** → 不自动重建；隧道建立时若容器缺失则幂等重建。
  - **沙箱删除** → 转发容器与转发记录纳入回收清单（`reclaim_plan` 增列、删除流程增回收），符合「平台只回收自建资源」。
  - **服务重启** → 全部转发会话丢失（与终端会话「服务重启即丢」同口径），启动时清理上次遗留的转发容器与记录（对齐既有 `purge_leftover_sessions` 的做法）。
  - **桌面端断开** → 隧道 WS 断开即关本机监听、回收 exec 字节泵，界面显示「转发已断开」。
- **桌面侧（Rust 核心 + UI）**：
  - Rust 核心在 `127.0.0.1` 上起 TCP 监听（**默认 = 容器端口，用户可指定**；被占自动换空闲端口，**显示实际值**），每来一条连接就开一条隧道 WS 并做字节桥接；**Rust 侧不落盘令牌**（连接时由前端经 IPC 传入）。
  - UI 落在**沙箱详情抽屉新增的「端口转发」区**。
    - **web 形态**：只渲染**说明卡 + 「安装桌面端」按钮**（点击开 ModalShell 安装指引弹窗），**不渲染列表 / 新建 / 停止等任何管理操作**；说明卡写明「访问端口需要桌面应用」，避免与已退役的 URL 代理混淆。
    - **桌面形态**：**完整管理**——新建只填容器端口、列表按「容器端口 → 本机端口」呈现、开启 / 关闭本机监听、停止转发、开启后显示 `http://127.0.0.1:<port>` 与复制按钮。
    - （立稿口径：「web 形态下该区只做管理」「「在桌面端开启」是 Tauri 专属动作，在 web 形态下不渲染该按钮」。**已按 2026-11-03 决策 C 改写：web 形态不做任何管理，留档**。）
  - 端口转发界面遵守 [[conventions/console-frontend.md|网页控制台前端约定]] 全部约定（Base UI 原语、令牌色、toast、`data-testid`、ModalShell / DrawerShell 外壳复用）。

### 工作包五：桌面壳与打包

- **工程位置**：新增 `apps/desktop/`（Tauri v2 工程），前端产物直接指向 `../web/frontend/dist`——**桌面与 web 形态共用同一份源码与同一份构建产物**，不存在第二份前端。
- **纯连接器**：Rust 侧只做三件事——装载前端静态产物、按连接配置设定 CSP、维护端口转发的本机监听与隧道桥接。**不拉起后端、不托管后端进程、不管理后端生命周期**。
- **运行形态探测**：前端用特性探测判断是否运行在 Tauri 里（检查 `window.__TAURI_INTERNALS__`），**不引入 `@tauri-apps/api` 依赖**，web 形态的构建产物因此不被 Tauri 污染。
- **CSP**：Tauri v2 的 CSP 需允许 `connect-src` 指向用户配置的后端。静态 CSP 无法枚举运行期地址，因此由 Rust 侧在连接配置变更时**动态设置 CSP**（`connect-src 'self' http://<后端host>:* ws://<后端host>:*`），不整体关闭 CSP。
- **vite base**：改 `base: './'`（相对路径）。前端用哈希路由（`#/sandboxes/...`），不依赖服务端回退规则，相对 base 在 Tauri 资源协议（Windows 下 `http://tauri.localhost`）与后端 `StaticFiles` 托管两种形态下都能正确解析 `/assets/*`。
- **打包**：Windows 目标（NSIS 安装包 + 可选 MSI）。本机是 Linux，出包路径三选一（详见风险 R1）。
- **验收套件 token 化**：`tests/helpers/server.ts` 启动后端时注入固定测试令牌；Playwright 用 `storageState` 预置连接配置（localStorage），使页面自带令牌；新增负向用例（无令牌 / 错令牌 → 401）。

## 验收标准

### 桌面壳

- [ ] Tauri 应用在 Windows + WebView2 上启动，加载的是 `apps/web/frontend/dist` 同一份产物（无第二份前端源码）。
- [ ] 应用只包含「前端 + 连接配置」，不拉起、不托管、不探测后端进程；后端未启动时应用仍能启动并进入连接引导态。
- [ ] 应用可连接**部署在另一台机器**上的后端（后端地址在连接配置里指定），沙箱列表、创建、终端全部可用。
- [ ] 真机 WebView2 三项冒烟全过：`oklch()` 配色正常、xterm.js 终端渲染与 `fit` 正常、`navigator.clipboard` 在安全上下文下可读可写。
- [ ] 前端构建产物在 web 形态（后端 `StaticFiles` 托管）下行为零变化。

### 连接层（后端）

- [ ] 未带令牌访问任何 `/api`（含 `/api/health`）一律 `401`，响应体是 `{"detail": "访问令牌无效或缺失"}`，不泄露令牌是否正确。
- [ ] 令牌比较为常量时间（`hmac.compare_digest`），代码里不出现普通 `==` / `in` 比较令牌。
- [ ] 日志里搜不到令牌：启动日志只打令牌文件路径；请求日志不打 `Authorization` 头；错误响应不回显令牌。
- [ ] 令牌来源两条都成立：`SANDBOX_CONSOLE_TOKEN` 注入时用注入值；未注入时自动生成并落 `<数据根>/console-token.json`（权限 `0600`），服务正常启动。
- [ ] `POST /api/auth/ticket` 必须带有效令牌；票据一次性、30 秒过期；用过即废；过期 / 伪造票据的 WebSocket 握手被拒。
- [ ] 终端 WebSocket 在无票据 / 错票据时握手被拒；带有效票据时行为与二期一致（先回放缓冲再接实时流）。
- [ ] ~~WebSocket 握手的 `Origin` 不在放行清单内时被拒。~~ **（2026-11-03 修订：该项作废——WS 握手不再校验 `Origin`，准入边界 = 令牌 + 票据；票据缺失 / 过期 / 伪造仍拒握手。）**
- [ ] CORS 允许**任意来源**：`allow_origins=["*"]`、`allow_credentials=False`；方法与头白名单仍为 `GET/POST/DELETE/OPTIONS` 与 `Authorization/Content-Type`。（2026-11-03 修订：原「只放行三个白名单来源；不放行通配符；不放行任意来源」已作废。）
- [ ] 绑非回环地址时的启动日志按新口径改写（不再宣称「完全信任」）。

### 连接层（前端）

- [ ] `src/lib/connection.ts` 有单元测试：正常值往返、非法值回落默认、读取失败回落、存储不可用时不抛异常。
- [ ] 请求基址可配置：同一份前端产物能分别连「本机后端（默认地址 `http://127.0.0.1:8000`）」与「远端后端」，两种形态下沙箱列表 / 详情 / 创建 / 终端全部可用。
- [ ] 每个 API 请求都带 `Authorization: Bearer`；令牌缺失时不发请求（进入引导态）。
- [ ] 终端 WebSocket 地址从连接配置推导（含 `http→ws` / `https→wss`），票据由前端自动获取并在每次重连时重新获取。
- [ ] 未配置态有引导 UI（后端地址 + 令牌 + 保存并连接），且**不是路由**（地址栏仍是 `#/`）。
- [ ] **后端地址默认 `http://127.0.0.1:8000`、可编辑、不可为空**；旧存储里基址为空的配置读取时归一为默认值；「空 = 同源」的逻辑链已删除（2026-11-03 决策 D）。
- [ ] 设置抽屉有「连接配置」区，可改配置并「测试连接」；结果按 toast 规范反馈。
- [ ] 前端改造不违反 [[conventions/console-frontend.md|网页控制台前端约定]] 的任何一条（Base UI、令牌色、toast、`data-testid`、ModalShell / DrawerShell 外壳、纯逻辑收敛在 `src/lib/`）。

### 端口转发

- [ ] 转发容器由**沙箱自己的免 root 守护进程**启动并接入沙箱网络；**不发布任何端口**；沙箱容器与依赖容器零改动；用户的沙箱镜像零改动。
- [ ] ~~宿主端口由平台自动分配并占位；端口被占时换端口重试，仍失败给出明确错误。~~ **（已按 2026-11-03 决策 C 废除：宿主侧无端口、无区间、无占位。）**
- [ ] **隧道字节泵走 `docker exec -i <转发容器> socat - TCP:<沙箱容器名>:<端口>`**；连接断开后 exec 进程被回收。
- [ ] 桌面端开启转发后，桌面机 `127.0.0.1:<本机端口>` 可访问沙箱内该端口上的服务；该监听**不出本机**（局域网不可达）。
- [ ] **本机端口默认 = 容器端口、可编辑且不可为空、被占自动换空闲端口并显示实际值、允许 <1024**。
- [ ] **后端宿主不持有任何转发端口**（既不发布也不监听）；转发记录与响应模型中**无 `host_port`**。
- [ ] 同一沙箱的多个端口可同时转发，互不串扰；同一转发的多条并发连接互不串扰。
- [ ] 转发 REST 三条接口行为正确：列表 / 建立（`{sandbox, port}`）/ 停止；建立时沙箱不存在或端口非法返回明确错误。
- [ ] 沙箱删除时，转发容器与转发记录一并被回收，且出现在删除前的回收清单里。
- [ ] 服务重启后：全部转发会话丢失、遗留转发容器被清理（与终端会话「服务重启即丢」同口径）。
- [ ] 桌面端断开 / 停止转发后，本机监听被关闭，不留僵尸监听。
- [ ] 端口转发相关能力落在核心包（`sandbox_platform`）可复用模块，服务端只做编排与转译。

### 打包与回归

- [ ] Windows 安装包产出成功（NSIS），可在干净 Windows 机器上安装并启动。
- [ ] 既有 9 条控制台验收用例在 token 模式下全量回归通过。
- [ ] 新增负向用例：无令牌 / 错令牌访问 `/api` → 401；有效令牌 → 200。
- [ ] 核心包 pytest、服务端 pytest、ruff（`E4/E7/E9/F`）、前端 vitest / typecheck / typecheck:tests / build 全绿。
- [ ] 文档同步：`docs/current-state.md`、`docs/glossary.md`、`docs/architecture/overview.md`、三张 ADR 清单表、`docs/conventions/console-frontend.md`、`apps/web/backend/API.md`、`apps/web/frontend/README.md`、仓库根 `README.md` 全部更新到位。

## 开放问题清单

> 需要用户拍板（**★** = 强烈建议本期拍板**）或实施时再定。

| 编号 | 问题 | 建议 | 影响面 |
|---|---|---|---|
| **Q1** | **★ 令牌怎么分发到桌面端？** | **推荐：服务端启动生成并落 `<平台数据根>/console-token.json`（`0600`），同时支持 `SANDBOX_CONSOLE_TOKEN` 环境变量注入（优先级更高）。** 理由：① 与平台既有口径一致（元数据、模板都是数据根下的 `0600` 文件）；② 环境变量会出现在 `systemd` 单元文件与 `/proc/<pid>/environ` 里，落盘文件更可控；③ 用户取令牌的方式是「读文件」，不需要在桌面端做「服务端生成 → 传输 → 落盘」的引导。**代价**：需要 root 读文件这一步；令牌轮换无 UI（只能删文件 + 重启服务） | 任务 02、03、07、09；README 与 API.md 的操作说明 |
| **Q2** | **★ `/api/health` 是否豁免认证？** | **推荐：不豁免。** 理由：① 与「所有 `/api` 受 token 保护」的口径完全一致，不留例外；② 前端能借此区分「后端不可达」（连接失败）与「令牌无效」（401），这是实打实的体验收益；③ 版本号等字段不外泄给未认证调用方。**代价**：外部监控 / LB 探活必须带令牌或改用 socket 层探活 | 任务 02、03、07 |
| **Q3** | **★ 转发会话在服务重启后的语义？** | **推荐：服务重启即全部丢失**（与终端会话既有口径一致），并在启动时清理上次遗留的转发容器与记录（对齐 `purge_leftover_sessions` 的做法）。理由：不发明第二套状态机；转发容器是平台自建资源，重启后无人认领的容器必须被回收，否则会变成孤儿 | 任务 04、05；ADR 0014 第 7 节 |
| **Q4** | **★ Windows 安装包的构建路径？** | **推荐：GitHub Actions `windows-latest` 出包**（需要先给仓库建远端，当前无远端无 CI）；**备案：用户自有 Windows 机器本地构建**；**不采用从 Linux 交叉编译**（Tauri v2 不支持）。代价已列在风险 R1 | 任务 01（P4）、08 |
| **Q5** | 桌面端令牌存哪？ | **推荐 v1 存 `localStorage`**（与主题、侧栏折叠、抽屉宽度同一层，存取收敛在 `src/lib/connection.ts`，配单元测试），把「存操作系统凭据库」列为后续可换实现项（**不改前端契约即可替换**）。代价：明文、同源脚本可读 | 任务 03；ADR 0015 第 2 节 |
| **Q6** | 转发容器用什么镜像？ | **推荐：`alpine/socat` 钉 digest，经统一镜像代理拉取到沙箱守护进程**（改动最小，代理已有缓存与 CA 机制）。备案：平台自建转发镜像（本地构建 + 宿主导出注入）。代价：多一个需要平台维护 digest 的外部镜像 | 任务 01（P3）、04 |
| **Q7** | 桌面本机端口由谁分配？ | **已关闭（2026-11-03 用户拍板，决策 C）**：**由桌面端持有**——默认 = 容器端口、**可编辑且不可为空**、**被占自动换空闲端口并显示实际值**、**允许 <1024**（Windows 可绑、macOS 现代版可绑、Linux 非 root 不可绑；目标平台 Windows 为主，Linux 上绑低端口失败须明确报错）。**后端不感知本机端口**；宿主侧的端口分配与区间已随 `-p` 一并废除 | 任务 06；ADR 0014 第 4 节 |
| **Q8** | web 形态要不要也支持连远程后端？ | **已关闭（2026-11-03 用户拍板，决策 A）**：**支持，无形态差异**——网页端同样可配置后端地址，连接配置只有一套模型；唯一保留的形态差异是桌面运行时的机制层（CSP 同步 + 保存后按需重载），不是配置差异。**2026-11-03 决策 D 补充**：基址改为**默认 `http://127.0.0.1:8000`、可编辑、不可为空**，「空 = 同源」语义删除；已知边界——从其他机器的浏览器访问网页控制台时默认地址指向用户本机，需手动改成后端地址（健康检查 / 「测试连接」会立即暴露）。见 [[architecture/decisions/0015-桌面壳与连接配置抽象.md|ADR 0015]] 第二次与第三次修订 | 任务 03 |
