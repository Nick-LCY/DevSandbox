# 控制台模板轮：基础镜像工具层与启动模板

> 日期：2026-10-31
> 一期需求见 [[prds/sandbox-platform.md]]，二期需求见 [[prds/phase2-console.md]]

## 背景

平台跑了两轮之后，暴露出两个互相独立的缺口，本轮各补一个：

1. **底座缺通用工具。** 平台基础镜像只装了 Docker 客户端与纯 bash 入口脚本，git、vim、curl、xz 这些开发里天天要用的命令全都没有。用户每次建沙箱都要现装一遍，装完也不随镜像沉淀，等于每个沙箱都从零手搓一遍环境。
2. **没有「保存的启动配置」。** 每次新建沙箱都要重敲镜像名、挂载声明、环境变量、命令、工作目录。同一个开发环境反复重建时，这套参数每次都靠人肉回忆复述，抄错一个字符就是一轮返工。网页控制台目前只有一次性填参的表单，没有把「上次那套配置」沉淀下来的地方。

因此本轮做两件事：把常用工具装进基础镜像升到 0.3.0；在网页控制台上新增「启动模板」——把一套沙箱启动配置存起来，下次一键回填。

## 目标

- **基础镜像 0.3.0 的工具层**：在 bash + Docker 客户端底座上新增 9 个通用工具包（git、openssh-client、vim、curl、ca-certificates、unzip、xz-utils、procps、less），构建方式从「零网络」改为「联网 apt 拉包」，判定脚本同步扩到 42 项。
- **模板服务端能力**：模板落平台数据根的 `templates/` 目录，提供列表、创建、重命名、删除四条接口；挂载宿主路径支持 `~` 展开；内置模板提供种子注入机制。
- **模板前端与字体**：新建沙箱抽屉加「加载模板 / 保存为模板」两个动作；侧边栏「代理设置」改名「设置」并在同一抽屉里加模板管理区；字体字符源并入常用汉字表后重生成子集。
- **真机验收与文档收口**：三套测试全绿、两篇架构决策记录归档、看板与约定同步。

## 非目标

- **不做全栈默认镜像退役与 git 历史抹除**：默认全栈沙箱镜像（`sandbox-platform/sandbox-default`）的退役与历史清理是独立轮次，且需要干净工作树才能安全执行，本轮不碰。
- **不做「禁止命令行零参数创建」的强约束**：命令行零参数创建沙箱的口径本轮只记录不改，不在本期加硬性拦截。
- **不删除 `sandbox-platform/` 镜像前缀限制**：本地镜像前缀白名单与对应环境变量本轮保持原样，不下线。
- **不把个人镜像放进仓库**：个人自建镜像（含个人工具链与配置）在仓库外自建自用，本轮不引入任何个人镜像内容。
- **不做内置模板的真实内容**：内置 pi + git 模板本期只落地种子注入机制（删除后写墓碑、不复活），真实模板内容等个人镜像建成并实测后再补。
- **不做会话目录按挂载声明归类**：会话目录挂载的归类口径等个人镜像启用时一并落地。

## 方案

### 工作包一：基础镜像 0.3.0 的通用工具层

- **做什么**：`platform/base-image/Dockerfile` 增加一层 apt 安装 9 个通用工具包（git、openssh-client、vim、curl、ca-certificates、unzip、xz-utils、procps、less），安装与清理放在同一层避免残留索引；镜像版本参数改为 0.3.0；构建命令从 `--network=none` 改为联网 apt 拉包。判定脚本默认镜像改 0.3.0，删掉「无 git」「无 curl」两条否定断言，新增 9 条「已安装且有版本输出、命令在 PATH」的判定，判定总数由 35 变为 42 项。
- **不做什么**：不动 `platform/sandbox-image/`，不重建默认全栈沙箱镜像；不动 `platform/src/sandbox_platform/config.py` 的默认镜像与本地镜像前缀配置；不动镜像两层契约本身。
- **验收命令**：`docker build --build-arg DOCKER_CLI_VERSION=29.6.2 -t sandbox-platform/base:0.3.0 platform/base-image` 后执行 `platform/base-image/verify.sh`，42 项判定全过；镜像体积与分层实测写入 `platform/base-image/RESULTS.md`。

### 工作包二：模板服务端

- **做什么**：新增 `platform/src/sandbox_platform/server/templates.py` 管理模板库（每个模板一个 JSON 文件，原子替换写入、文件权限 0600）；请求响应模型加 `TemplateConfig`（镜像、挂载、命令、工作目录、环境变量、网络，全部选填）；新增四条路由（列表、创建、重命名、删除）；应用启动时准备模板目录并注入内置模板种子（失败只记日志、不阻断启动）；挂载声明里的 `~` 在服务端展开为服务运行用户的家目录。
- **不做什么**：核心包（`server/` 目录之外）与命令行 `platform/cli/` 零改动；模板不落数据库、不做多用户隔离、不做模板导入导出。
- **验收命令**：后端 pytest 全绿；分层契约测试红线不触发（新增服务端源码不得出现带空格的 git、小写独立 docker、`print(`、`subprocess`、`sudo`、`os.system`、`os.popen`）。

### 工作包三：模板前端与字体

- **做什么**：新建沙箱抽屉加「加载模板」（可搜索下拉，本地筛选、选中即回填）与「保存为模板」（命名弹窗）；侧边栏「代理设置」改名「设置」，抽屉里在代理设置区之下加模板管理区（列表、行内重命名、删除确认）；模板应用语义为「出现字段整体替换、缺失字段保持现状」，支持 `{name}` 占位符；字体脚本的字符源并入常用汉字表后重生成子集。
- **不做什么**：不做模板导入导出、不做模板分类与搜索后端、不做多套模板并行编辑；不引入新依赖，反馈一律走右上角 toast。
- **验收命令**：前端 typecheck、typecheck:tests、vitest、build 全绿；Playwright 真机用例覆盖「保存 → 加载回填 → 重命名 → 删除 → 刷新不复活」全流程。

### 工作包四：真机验收与文档收口

- **做什么**：三套测试全量跑绿（后端 pytest + ruff、前端 vitest + typecheck + build、Playwright 真机）；补两篇架构决策记录（启动模板收敛为控制台私有功能、基础镜像增加通用工具层并转联网构建）；同步看板、词汇表、前端约定与工程说明。
- **不做什么**：不改既有架构决策的结论，不重写历史任务的完成标准。
- **验收命令**：三套测试命令全部退出码 0；仓库内自查不得出现个人家目录路径与个人专属内容。

### 两条必须写清的边界口径

1. **`~` 展开的目标是控制台服务运行用户的家目录。** 服务以 root 身份运行时，`~` 展开为 `/root`，会命中核心包的宿主敏感目录拒绝清单并返回 400——这是既有契约的自然结果，不是缺陷。文档写明这一点，避免后续被当成 bug 反复排查。
2. **模板名零限制。** 模板名不做长度、字符集、保留字校验，只做空串拒绝；模板标识由服务端生成，与名称解耦，因此重命名不影响模板标识。

## 验收标准

- [ ] 基础镜像 0.3.0 构建成功，`platform/base-image/verify.sh` 42 项判定全过，镜像体积与分层数据留档到 `platform/base-image/RESULTS.md`。
- [ ] 模板接口四类行为正确：列表返回全部模板、创建返回 201、重命名只改名称不影响模板标识、删除内置模板写墓碑。
- [ ] `~` 展开与 `{name}` 占位符行为正确：挂载宿主路径的 `~` 与 `~/` 前缀展开为服务运行用户家目录，`~other` 不展开；`{name}` 替换为沙箱名，沙箱名为空时保留占位符。
- [ ] 模板前端两条流程可用：加载模板把配置回填进新建沙箱抽屉、保存为模板把当前配置存成模板。
- [ ] 设置抽屉的模板管理区可用：模板列表可见、行内重命名生效、删除走确认弹窗且文案说明不影响已建沙箱。
- [ ] 字体子集按新增文案与常用汉字表重生成入库。
- [ ] 后端 pytest 与 ruff 全绿；前端 typecheck、typecheck:tests、vitest、build 全绿；Playwright 真机用例全绿。
- [ ] 仓库内自查：本轮新增文件不含个人家目录路径与个人专属内容。
