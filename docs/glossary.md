# 词汇表

统一人与 AI 沟通时对项目术语的理解。每条一个术语：「词 — 在本项目中的含义」。

## 格式
- **术语** — 在本项目中的含义。

## 清单

### 结构与角色
- **沙箱** — 交给 agent 的隔离工作环境。一个沙箱包含沙箱容器、它专属的依赖容器，以及支撑二者的专属用户与守护进程。
- **沙箱容器** — agent 真正执行指令的容器，入口是一个 bash，是「agent 执行世界」的边界。
- **依赖容器** — 与沙箱容器同属一个守护进程的独立容器，提供 Postgres、MinIO、Logto 等真实依赖服务。
- **控制面** — 宿主机上编排沙箱生命周期的逻辑层，负责创建、关闭、删除沙箱并维护镜像与挂载契约；一期写成可复用服务模块，命令行只是薄壳。
- **平台基础镜像** — 平台维护的底座镜像，只含 Docker 客户端、入口纯 bash 脚本和套接字默认路径与容器层空目录约定，不含语言工具链，不内置任何 volume 挂载点。
- **沙箱镜像** — 在平台基础镜像之上叠加自选工具的镜像；官方默认全栈沙箱镜像含 pi、git、uv、nvm + node、pnpm 与 Playwright 浏览器。
- **厚沙箱模式** — 可选模式：沙箱容器以特权方式运行并在内部自带一套 Docker，对 agent 的接口与普通沙箱完全一致，按沙箱配置切换，优先级低。

### 隔离与权限
- **每沙箱专属用户** — 每个沙箱独享的 Linux 账号，承载该沙箱的守护进程与文件权限，是隔离边界的起点。
- **每用户守护进程** — 以沙箱专属用户身份运行的免 root Docker 守护进程，负责起停该沙箱的沙箱容器与依赖容器；用 systemd 用户级服务单元启动，靠 linger 保活。
- **免 root 模式** — 沙箱容器与依赖容器均由每用户守护进程以非 root 身份创建与运行的模式，是默认模式。
- **子 UID/GID 段** — 为沙箱专属用户分配的一段独立子用户 ID / 组 ID 区间，供免 root 容器映射容器内的用户 ID。

### 数据与挂载
- **固定挂载** — 平台唯一自行挂载的项：Docker 套接字（读写），创建沙箱时自动挂到容器内默认路径 `/var/run/docker.sock`，docker 客户端默认可见，用户无需声明。
- **用户声明挂载** — 用户在创建沙箱时用 `--mount 宿主路径:容器路径[:ro]` 声明的挂载，可声明多次；平台原样执行、不解释用途，其宿主机目录一律不被平台创建、删除或修改。
- **工作区**（典型用法，非平台概念） — 代码与测试产物常放的目录；平台不再内置该概念，是否存在、落在何处完全取决于用户是否声明挂载。
- **会话目录**（典型用法，非平台概念） — pi 会话数据的宿主机目录；常见做法是把它挂到容器内 pi 的会话路径，删除沙箱时平台不处置该目录。
- **凭证挂载**（典型用法，非平台概念） — 模型 API key 与 pi 配置以只读方式挂进容器的常见做法；平台不提供该挂载，密钥不进镜像层，轮换只改宿主机文件。

### 流程与验证
- **生命周期** — 沙箱的三个状态流转动作：创建、关闭、删除，各自规定哪些资源被创建、停止或回收。
- **健康检查门禁** — 端到端测试运行前的固定关卡：等依赖就绪 → 执行数据库迁移 → 灌入种子数据，全部通过才允许跑测试。
- **打样验证** — 在真实宿主机上用最小可行配置验证关键技术可行性（例如免 root 守护进程与 systemd 用户级 cgroup 委托是否成立），先于正式开发完成。
- **URL 代理** — 三期能力：把沙箱容器端口发布到宿主机回环地址，再由宿主机网页反向代理对外提供访问，不暴露到局域网。
