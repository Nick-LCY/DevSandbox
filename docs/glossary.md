# 词汇表

统一人与 AI 沟通时对项目术语的理解。每条一个术语：「词 — 在本项目中的含义」。

## 格式
- **术语** — 在本项目中的含义。

## 清单

### 结构与角色
- **沙箱** — 交给 agent 的隔离工作环境。一个沙箱包含沙箱容器、它专属的依赖容器，以及支撑二者的专属用户与守护进程。
- **沙箱容器** — agent 真正执行指令的容器，入口是一个 bash，是「agent 执行世界」的边界。
- **依赖容器** — 与沙箱容器同属一个守护进程的独立容器，提供 Postgres、MinIO、Logto 等真实依赖服务。
- **控制面** — 宿主机上编排沙箱生命周期的逻辑层，负责创建、关闭、删除沙箱并维护镜像与挂载契约；一期写成可复用服务模块，命令行只是薄壳；二期起常驻为控制台服务（FastAPI），命令行与网页共用同一套核心逻辑。
- **平台基础镜像** — 平台维护的底座镜像，只含 Docker 客户端、入口纯 bash 脚本和套接字默认路径与容器层空目录约定，不含语言工具链，不内置任何 volume 挂载点；0.3.0 起另加 9 个通用系统工具（git、openssh-client、vim、curl、ca-certificates、unzip、xz-utils、procps、less），仍不含任何语言链与运行时（见 [[architecture/decisions/0011-基础镜像增加通用工具层并转联网构建.md|0011 基础镜像增加通用工具层并转联网构建]]）。
- **沙箱镜像** — 在平台基础镜像之上叠加自选工具的镜像，由沙箱创建者显式指定（平台不再提供默认镜像；官方默认全栈沙箱镜像含 pi、git、uv、nvm + node、pnpm 与 Playwright 浏览器的那一套已退役）。
- **厚沙箱模式** — 可选模式：沙箱容器以特权方式运行并在内部自带一套 Docker，对 agent 的接口与普通沙箱完全一致，按沙箱配置切换，优先级低。

### 镜像供给
- **统一镜像代理** — 平台侧唯一的外部镜像拉取入口：以 HTTP 透明缓存代理的形式跑在宿主 root 守护进程下、绑定回环地址，拦截任意仓库（含 GHCR）的镜像请求；缓存命中走本地，未命中由代理拉一次外网并写入缓存。代理不可达时拉取直接失败，不降级直连。
- **宿主导出注入** — 把宿主本地镜像导出成包再导入沙箱守护进程的传递方式。默认来源下它是代理拉取失败后的回退路径，实际只对本地构建镜像生效（这类镜像不在任何仓库，代理必然拉不到）；强制宿主来源时一律走这条路径，不经镜像代理。依赖镜像不走此路径，一律由沙箱守护进程经统一镜像代理拉取（见 [[architecture/decisions/0009-二期控制台服务化与范围裁剪.md|0009 二期控制台服务化与范围裁剪]]）。

### 隔离与权限
- **每沙箱专属用户** — 每个沙箱独享的 Linux 账号，承载该沙箱的守护进程与文件权限，是隔离边界的起点。
- **每用户守护进程** — 以沙箱专属用户身份运行的免 root Docker 守护进程，负责起停该沙箱的沙箱容器与依赖容器；用 systemd 用户级服务单元启动，靠 linger 保活。
- **免 root 模式** — 沙箱容器与依赖容器均由每用户守护进程以非 root 身份创建与运行的模式，是默认模式。
- **子 UID/GID 段** — 为沙箱专属用户分配的一段独立子用户 ID / 组 ID 区间，供免 root 容器映射容器内的用户 ID。

### 数据与挂载
- **固定挂载** — 平台唯一自行挂载的项：Docker 套接字（读写），创建沙箱时自动挂到容器内默认路径 `/var/run/docker.sock`，docker 客户端默认可见，用户无需声明。
- **用户声明挂载** — 用户在创建沙箱时用 `--mount 宿主路径:容器路径[:ro]` 声明的挂载，可声明多次；平台原样执行、不解释用途，其宿主机目录一律不被平台创建、删除或修改。
- **文件注入** — 创建沙箱时把宿主文件复制一份送进沙箱的通道（与挂载并行的另一条路），声明格式 `宿主路径:容器路径`（固定两段，容器内强制只读）：平台把原件复制到沙箱用户家目录内的暂存目录 `.sandbox-files`（文件 0600 / 目录 0700、属主沙箱用户），再以只读方式挂进容器；**原件零接触**（不 chmod、不 chown、不改内容），副本随沙箱删除被「回收用户家目录」一起销毁，**复制是创建时快照**（宿主原件后续变更不回灌）；注入源由平台以特权身份读取，**控制台 / 命令行调用者视为平台受信主体，文件注入不提供跨账号隔离**（见 [[architecture/decisions/0012-文件注入采用复制加改属主而非改造挂载预检.md|0012 文件注入采用复制加改属主而非改造挂载预检]]）。
- **工作区**（典型用法，非平台概念） — 代码与测试产物常放的目录；平台不再内置该概念，是否存在、落在何处完全取决于用户是否声明挂载。
- **会话目录**（典型用法，非平台概念） — pi 会话数据的宿主机目录；常见做法是把它挂到容器内 pi 的会话路径，删除沙箱时平台不处置该目录。
- **凭证挂载**（典型用法，非平台概念） — 模型 API key 与 pi 配置以只读方式挂进容器的常见做法；平台不提供该挂载，密钥不进镜像层，轮换只改宿主机文件。

### 流程与验证
- **生命周期** — 沙箱的三个状态流转动作：创建、关闭、删除，各自规定哪些资源被创建、停止或回收。
- **健康检查门禁** — 端到端测试运行前的固定关卡：等依赖就绪 → 执行数据库迁移 → 灌入种子数据，全部通过才允许跑测试。
- **打样验证** — 在真实宿主机上用最小可行配置验证关键技术可行性（例如免 root 守护进程与 systemd 用户级 cgroup 委托是否成立），先于正式开发完成。
- **URL 代理** — 把沙箱容器端口发布到宿主机回环地址，再由宿主机网页反向代理对外提供访问，不暴露到局域网。**原三期能力，已随原定三期完整退役、不再规划**（见 [[architecture/decisions/0001-项目定位与三期路线.md|ADR 0001 修订行（2026-11-03）]]）；桌面端的**端口转发**是桌面应用直连沙箱端口，与此不是同一件事。

### 路线与轮次
- **三期** — 路线图第三期，现指**桌面端打包轮**：前端打包为桌面应用（Tauri），并在此基础上支持端口转发等能力；三条规划中最重，独立成期立项（见 [[architecture/decisions/0001-项目定位与三期路线.md|ADR 0001 修订行（2026-11-03）]]）。**原定三期（URL 代理与快照方向，连同每沙箱配额、自动清理、厚沙箱模式、可选弱网模拟）已完整退役，不再规划**——不是延期，是被桌面端方向取代；将来若重提其中某项，按新需求独立立项，不挂在「三期」名下。端口转发属平台新能力（涉及核心包 / 服务端），范围与验收以立项 PRD 细化。**2026-11-03 已立项**：需求见 [[prds/phase3-desktop.md|三期 PRD]]，任务集见 [[tasks/phase3-desktop/README.md|三期任务集]]，决策依据见 [[architecture/decisions/0013-三期定位改定与认证重启.md|0013]]、[[architecture/decisions/0014-端口转发机制选型.md|0014]]、[[architecture/decisions/0015-桌面壳与连接配置抽象.md|0015]]。

### 控制台（二期）
- **控制台服务** — 二期起把控制面核心包常驻运行的 FastAPI 服务，托管网页控制台（沙箱管理、网页终端、代理设置）与 REST/WebSocket 接口；二期口径是不做认证、只绑回环或内网（**该裁剪已被 [[architecture/decisions/0013-三期定位改定与认证重启.md|ADR 0013]] 推翻**：三期起所有 `/api` 改由访问令牌保护，绑非回环不再等于「完全信任」；**连接层后端侧已落地**，见 [[tasks/phase3-desktop/02-backend-token-and-cors.md|三期任务 02]]；前端侧未改造前网页控制台拿不到数据，须与 03 同批发布；**现状：前端侧（[[tasks/phase3-desktop/03-frontend-connection-layer.md|三期任务 03]]）也已落地，同批发布条件具备）。**
- **终端会话表** — 网页终端会话的持久化记录（落平台数据目录 `terminal-sessions/`），登记会话状态、附着数、窗口大小与进程号，用于断线重连、空闲回收与服务重启后的遗留清理。
- **工作台** — 网页控制台的单页形态：左侧边栏常驻沙箱列表与全局工具（新建、健康自检、设置、主题切换），右侧工作区承载选中沙箱的摘要与操作、终端会话标签。新建沙箱、沙箱详情、设置三个大面板以右侧滑出抽屉呈现，删除 / 停止 / 关闭会话走确认弹窗，不做整页跳转。
- **设置抽屉** — 侧栏「设置」入口打开的抽屉（原「代理设置」面板改名）：第一区是代理设置（状态字段区 + 「刷新状态」「重启代理」两个按钮），第二区是启动模板管理区（模板列表、行内重命名、删除确认）。抽屉**没有全局页脚**——只管代理的两个按钮归代理设置区。
- **抽屉** — 从右侧滑出的大面板容器（新建沙箱 / 沙箱详情 / 设置共用），宽度可拖拽且三者共用一份宽度；与居中弹窗的分工是「内容多、需要就地对比用抽屉，二选一确认用弹窗」。
- **终端会话标签** — 工作区终端标签条上的一个标签，直接对应终端会话表里的一条会话（即容器内一个带真实终端的 shell）；点标签即附着到该会话，标签尾的关闭按钮是关闭会话而非只收起面板。
- **设计令牌** — 集中定义的视觉变量（颜色、字体、圆角、阴影），以 `--app-*` 形式写在样式底座里，再由 Tailwind 映射成 `--color-*` 等工具类；组件只引用令牌，不写死色值。

### 控制台模板轮
- **控制台模板轮** — 路线图三期之后的一次独立交付轮次，做两件事：把通用工具装进平台基础镜像（0.3.0），以及在网页控制台上新增「启动模板」。本轮不叫「三期」——「三期」现指桌面端打包轮（见 [[architecture/decisions/0001-项目定位与三期路线.md|ADR 0001 修订行（2026-11-03）]]），两者不得混用；原路线图里「三期 = URL 代理与快照」的口径已随该修订退役（见 [[architecture/decisions/0001-项目定位与三期路线.md|0001 项目定位与三期路线]]）。
- **启动模板** — 保存下来的一套沙箱创建配置快照，含镜像、挂载、文件注入、环境变量、工作目录、网络、命令七项（全选填）。控制台私有能力，数据存服务端平台数据根的模板目录；**应用语义 = 出现的字段整体替换、缺失的字段保持现状**；**模板声明原样透传**（前端不做任何占位符替换）与宿主路径 `~` 展开是网页创建专属口径，命令行不承接模板（见 [[architecture/decisions/0010-启动模板收敛为控制台私有功能.md|0010 启动模板收敛为控制台私有功能]]）。
- **内置模板** — 平台预置、随服务启动注入的启动模板清单条目（当前一条：`tpl_pi_dev`「pi agent」，配置体只含 `files` 五条注入声明，镜像等其余字段留空、创建时自选）；种子不覆盖同标识的既有文件，删除后写墓碑不再复活（见 [[architecture/decisions/0010-启动模板收敛为控制台私有功能.md|0010 启动模板收敛为控制台私有功能]]）。
- **模板墓碑** — 内置模板被用户删除后留下的记录，防止种子机制在下次启动时把它复活；**只对内置模板生效**，用户自建模板删除后不存在「复活」问题（见 [[architecture/decisions/0010-启动模板收敛为控制台私有功能.md|0010 启动模板收敛为控制台私有功能]]）。

### 连接层与桌面端（三期）
- **桌面端** — 装在用户机器上的 Tauri v2 桌面应用（Tauri 壳 + 与 web 形态**同一份前端产物**），定位是**纯连接器**：只装前端与连接配置，不拉起、不托管、不探测后端进程；目标平台只承诺 Windows（Tauri + WebView2），Linux / macOS 只保证源码层面可构建（见 [[architecture/decisions/0015-桌面壳与连接配置抽象.md|0015 桌面壳与连接配置抽象]]）。
- **连接配置** — 前端持有的一份「后端地址 + 访问令牌」配置（模型 `{ backendBaseUrl, token }`，存 `localStorage` 的 `sandbox-console-connection` 键，存取收敛在 `src/lib/connection.ts`）。**后端地址默认 `http://127.0.0.1:8000`、可编辑、不可为空**（2026-11-03 决策 D：「空 = 同源」语义与整条空基址逻辑链删除；旧存储里基址为空的配置读取时归一为默认值）；（2026-11-03 决策 A 取消了两条形态差异——网页端同样可配置后端地址；未配置判定 = 令牌为空）。请求基址与终端 WebSocket 地址均从它推导（见 [[architecture/decisions/0015-桌面壳与连接配置抽象.md|0015 桌面壳与连接配置抽象]]）。
- **请求基址** — 所有 API 请求的 URL 前缀，由连接配置推导：**恒有值**（默认 `http://127.0.0.1:8000`，**不可为空**——2026-11-03 决策 D 删除了「空基址 = 同源、拼相对路径」这条分支），值是去尾部斜杠的绝对地址。请求路径一律在它之后拼接，不再假定「后端一定在 `/` 下面」；**web 与桌面同口径，无形态差异**（见 [[architecture/decisions/0015-桌面壳与连接配置抽象.md|0015 桌面壳与连接配置抽象]]）。
- **未配置态** — 前端**没有可用连接配置**时的形态：**令牌为空即未配置**（基址恒有默认值，不构成未配置原因；2026-11-03 决策 A 取消形态区分，决策 D 取消空基址语义）。此时**不渲染工作台**，改渲染一块引导面板（后端地址 + 访问令牌 + 「保存并连接」+ 来源说明）。它是**页面状态、不是路由**（地址栏仍是 `#/`），工作台的轮询一个都不启动（见 [[architecture/decisions/0015-桌面壳与连接配置抽象.md|0015 桌面壳与连接配置抽象]]）。
- **动态 CSP** — 桌面壳按运行期才知道的后端主机**在主文档被请求时生成**的内容安全策略：`tauri.conf.json` 里存基线策略（`connect-src` 只留 `'self'`），Rust 侧再补上当前后端主机的 `http(s)://<host>:*` 与 `ws(s)://<host>:*`（**host 级，不放行 scheme 通配**）。时序契约：保存连接配置 → 同步 Rust 状态 → 按需重载主文档（顺序不能反）（见 [[architecture/decisions/0015-桌面壳与连接配置抽象.md|0015 桌面壳与连接配置抽象]]）。**它属于桌面运行时的机制层，是两种形态间仅存的差异**（配置层已无形态差异，见「连接配置」条）。
- **访问令牌** — 控制台接口的**单一访问凭据**：`Authorization: Bearer <token>`；来源优先环境变量 `SANDBOX_CONSOLE_TOKEN`，未注入时服务启动生成并落 `<平台数据根>/console-token.json`（`0600`）。令牌即平台全部能力（含沙箱生命周期这类宿主特权操作），本期不做多用户、账号体系与吊销（见 [[architecture/decisions/0013-三期定位改定与认证重启.md|0013 三期定位改定与认证重启]]）。
- **一次性票据** — 浏览器侧 WebSocket 用的短期凭据：`POST /api/auth/ticket` 凭 Bearer 换一张 30 秒过期、用过即废、只存在于服务内存的票据，再以 `?ticket=` 带上。存在的理由是长期令牌不能进 URL（会进访问日志与中间代理日志）；桌面 Rust 侧能设请求头，直接走 Bearer，不需要票据。
- **准入边界** — 控制台接口的**唯一准入判据**：HTTP 请求带 `Authorization: Bearer <访问令牌>`，浏览器侧 WebSocket 握手带**一次性票据**。**WebSocket 握手的 `Origin` 门禁已取消、CORS 不做来源限制**（2026-11-03 决策 B：任意来源、不带凭据）——这两处曾承担「来源筛选」职责，现已全部收敛到凭据本身（见 [[architecture/decisions/0013-三期定位改定与认证重启.md|ADR 0013]] 第 4 节第二次修订）。
- **端口转发** — 用户显式指定「沙箱名 + 容器端口」后，平台把该端口经「**用户机本机监听 ⇄ 隧道 WebSocket ⇄ 后端 `docker exec -i` 字节泵 ⇄ 转发容器 ⇄ 沙箱容器端口**」送到**用户所在机器的 `127.0.0.1`** 的字节级透明通道。**链路只有「沙箱 ⇄ 用户机」两点，后端宿主是纯中继、零端口**（2026-11-03 决策 C：不发布也不监听任何转发端口；`-p` 主路径与宿主端口区间分配已废除）。**端口选择权在用户机**：默认 = 容器端口、可编辑且不可为空、被占自动换空闲端口并显示实际值、允许 <1024。**平台侧留台账**：转发记录落 `<平台数据根>/forwards/<id>.json`（`0600`，原子替换），字段含 **`host_pid`**（建这条记录的**服务进程号**）且**没有 `host_port`**（链路两点化，后端宿主零端口）；`host_pid` 用于**跨实例保护**——清理遗留转发时，**归属进程仍存活**的那条转发（**另一个服务实例正在用**）记录与容器都跳过不删，归属进程没了的才按「上次遗留」清掉（判据同终端会话表）。**与已退役的 URL 代理不是同一件事**：它没有对外的网页入口、没有反代层、没有可分享地址（见 [[architecture/decisions/0014-端口转发机制选型.md|0014 端口转发机制选型]]）。**隧道关闭码口径**（客户端据此处理重连）：`1000` 正常收尾 / `1001` 服务退出（客户端据此重连）/ `1008` 策略违规（鉴权未过、转发不存在或已失效）/ `1011` 字节泵异常结束（**客户端按可重试处理**）；隧道错误帧与 HTTP `detail` 只给固定中文文案，核心异常原文只进日志（见 [[tasks/phase3-desktop/05-port-forward-server-api.md|三期任务 05]]）。
- **转发容器** — 端口转发链路上的平台自建容器（`alpine/socat`，钉 digest），由**沙箱自己的免 root 守护进程**启动并接入沙箱网络，**不发布任何端口**、主进程常驻不监听（`socat` 二进制专供后端的 exec 字节泵使用）；沙箱容器与依赖容器零改动、用户沙箱镜像零改动。它属平台自建资源，纳入回收清单（删除沙箱时一并回收），并受统一镜像代理的拉取口径约束（见 [[architecture/decisions/0014-端口转发机制选型.md|0014 端口转发机制选型]]）。**它是「空转容器」**：主进程 `tail -f /dev/null` 常驻、**不监听任何端口**，只提供 `socat` 二进制与沙箱网络内的容器身份（exec 字节泵的落点）——「转发容器不发布端口」不是省事，是链路两点化（后端宿主零端口）的要求；镜像的 ENTRYPOINT 被显式覆盖，不覆盖就会把 `socat` 当监听命令跑起来。
- **隧道** — 端口转发链路上的字节通道载体：**一条 WebSocket**（路径 `/api/forward/tunnel/{forward_id}`，握手带 `Authorization: Bearer`），承载的是**双向字节流**（二进制帧为主，不是消息协议），后端一侧落到转发容器的 `docker exec -i` 字节泵上。**一条隧道对一条 TCP 连接**（本期不做多路复用）。**只有桌面端的 Rust 侧会建立它**——浏览器的 `WebSocket` 不能设自定义头，前端**不得**直连这条通道，只经 Tauri IPC 调命令。关闭码口径：`1000` 正常收尾 / `1001` 服务退出（客户端据此重连）/ `1008` 策略违规（鉴权未过、转发不存在或已失效）/ `1011` 字节泵异常结束（客户端按可重试处理）（见 [[architecture/decisions/0014-端口转发机制选型.md|0014 端口转发机制选型]]、[[tasks/phase3-desktop/05-port-forward-server-api.md|三期任务 05]]）。

### 已废弃
- **依赖镜像离线包**（已废弃） — 原方案：把 Postgres / MinIO / Logto 打成 tar 随基础镜像分发、沙箱首启自动加载。2026-10-29 起废弃，改由统一镜像代理拉取，见 [[architecture/decisions/0008-统一镜像代理与离线包废弃.md|0008 统一镜像代理与离线包废弃]]。
