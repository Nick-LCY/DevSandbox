# 系统总览

> 本项目的系统架构（稳定层，很少变更）。

## 概述

给 pi agent 提供隔离、可复用的全栈开发沙箱的平台：agent 在沙箱内自主完成端到端测试（Playwright 操作浏览器 + 多模态截图反馈），最终以网站形式提供随时启动沙箱、网页终端指挥 agent、URL 代理访问容器端口的能力（其中 URL 代理方向已随原定三期一并退役，三期现指桌面端打包轮，见 [[architecture/decisions/0001-项目定位与三期路线.md|ADR 0001 修订行（2026-11-03 三期方向改定）]]）。

## 架构

### 代码布局

2026-11-01 起，平台目录由 `platform/` 整体上移并重排为 `apps/` 结构：`apps/core`（控制面核心包，Python 包 `sandbox_platform`）、`apps/web/backend`（控制台服务端，独立 Python 包 `sandbox_console`）、`apps/web/frontend`（网页控制台前端）、`apps/web/e2e`（端到端基建）、`apps/cli`（命令行薄壳）；平台基础镜像在仓库根 `base-image/`。`apps/pyproject.toml` 是 uv 工作区根，成员只有核心包与服务端包两个（命令行是单文件薄壳，不是成员）。核心包与服务端是两个独立包，依赖方向单向：服务端依赖核心。重组前的 `platform/` 目录已完全消失。

### 分层结构

| 层级 | 组成 | 职责 | 关键约束 |
|---|---|---|---|
| 宿主机 | 控制面逻辑 + 平台数据 | 编排沙箱生命周期，维护镜像与挂载契约 | 控制面从一期就写成可复用服务模块，命令行只是薄壳 |
| 每沙箱专属用户 | 专属 Linux 用户 + 子 UID/GID 段 | 身份与资源映射的隔离边界 | 用户未登录时靠 linger 保活守护进程 |
| 每用户守护进程 | 免 root Docker 守护进程 | 起停沙箱容器与依赖容器，维持内部桥接网 | 沙箱容器也由它启动，不由宿主机 root 的 Docker 启动 |
| 沙箱容器 | agent 执行世界，入口一个 bash | 跑 agent、pi、工具链与端到端测试 | 不加载任何 profile，依赖起不起由 agent 决定 |
| 依赖容器 | Postgres、MinIO、Logto | 提供真实依赖服务 | 与沙箱容器同一守护进程、同一内部网络，按容器名互访 |

### 运行链路

- 创建沙箱：建专属用户与子 UID/GID 段 → 启动守护进程 → 复制声明的注入文件副本到沙箱用户家目录 → 由守护进程启动沙箱容器，并挂入套接字、用户声明的挂载与注入文件副本。
- 关闭沙箱：停止沙箱容器，可顺带停止依赖容器释放内存；守护进程、专属用户、家目录与用户挂载的宿主机目录全部保留。
- 删除沙箱：回收平台创建的一切，不触碰用户挂载的外部目录。

细节见 [[architecture/decisions/0003-每沙箱专属用户与免root守护进程.md|0003 每沙箱专属用户与免 root 守护进程]]。

### 挂载契约

| 挂载 | 读写 | 内容 | 规则 |
|---|---|---|---|
| Docker 套接字（唯一固定挂载） | 读写 | 每用户守护进程的套接字 | 创建时自动挂到容器内默认路径 /var/run/docker.sock，用户无需声明；随沙箱容器存在 |
| 用户声明挂载 | 由用户指定，可只读 | 用户在创建时用 `--mount 宿主路径:容器路径[:ro]` 声明的宿主机目录 | 平台原样执行、不解释用途；宿主机目录一律不创建、不删除、不修改 |

创建沙箱时不声明任何挂载，就只挂套接字一个；平台不预置任何默认挂载目录。代码目录、会话目录、凭证只读挂载属于典型用法示例，写在用户指引里，不是平台概念。

平台只回收自己创建的资源：沙箱容器、依赖容器、守护进程、专属用户及其家目录、子 UID/GID 段、平台元数据。用户声明挂载的宿主机目录不在回收范围内。

**文件注入副本**是挂载之外的第二条通道：平台在创建时把声明的宿主文件复制一份到沙箱用户家目录内的暂存目录（属主沙箱用户、容器内强制只读），再挂进容器。它有三条边界——**平台自建**（不是用户声明的目录，「平台不处置用户目录」那条承诺不适用于它）、**落沙箱用户家目录、随删除沙箱时的家目录回收一起消失**（不进回收清单里「用户挂载的宿主机目录不受影响」那一份）、**容器内一律只读**（不支持容器写回宿主）。机制依据见 [[architecture/decisions/0012-文件注入采用复制加改属主而非改造挂载预检.md|0012 文件注入采用复制加改属主而非改造挂载预检]]。

### 镜像契约

平台基础镜像（bash + docker 客户端 + 入口纯 bash + 套接字默认路径与容器层空目录约定，不内置任何 volume 挂载点；0.3.0 起另加 9 个通用系统工具，仍不含任何语言链与运行时）→ 沙箱镜像（由沙箱创建者显式指定，平台不再提供默认镜像：官方默认全栈沙箱镜像已退役）。镜像来源分两类：依赖镜像（含 Postgres、MinIO、Logto 三件套）统一经统一镜像代理拉取，缓存命中走本地；沙箱启动镜像的来源由创建者指定——默认来源先经统一镜像代理拉取，代理拉不到且宿主本地有该镜像时回退宿主导出注入（本地构建镜像不在任何仓库，只能走这条路径），强制宿主来源则不经代理、直接从宿主枚举并注入。

细节见 [[architecture/decisions/0004-镜像契约与默认沙箱镜像.md|0004 镜像契约与默认沙箱镜像]]、[[architecture/decisions/0008-统一镜像代理与离线包废弃.md|0008 统一镜像代理与离线包废弃]]、[[architecture/decisions/0009-二期控制台服务化与范围裁剪.md|0009 二期控制台服务化与范围裁剪]]、[[architecture/decisions/0011-基础镜像增加通用工具层并转联网构建.md|0011 基础镜像增加通用工具层并转联网构建]] 与 [[architecture/decisions/0010-启动模板收敛为控制台私有功能.md|0010 启动模板收敛为控制台私有功能]]。

## 核心模块

- `控制面` — 编排沙箱的创建、关闭、删除；一期实现为可复用服务模块，命令行只是薄壳，二期对外暴露 FastAPI 接口。
- `控制台服务（二期）` — 把控制面核心包常驻为 FastAPI 服务并提供网页控制台（沙箱管理、网页终端、代理设置），不做认证，只绑回环或内网。**（三期起改为访问令牌保护，`/api` 全量受保护；该口径由 [[architecture/decisions/0013-三期定位改定与认证重启.md|ADR 0013]] 推翻 0009 的裁剪。连接层后端侧已落地（[[tasks/phase3-desktop/02-backend-token-and-cors.md|三期任务 02]]），前端侧未改造前网页控制台拿不到数据，须与 03 同批发布；**现状：02 与 03 均已落地，同批发布条件具备（03 已于 2026-11-04 闭合：远端形态真机实测通过，本机形态按偏离记录闭合）。** **默认以非 root 用户运行（2026-11-06：仓库 systemd 单元 `User=sankabox`，root 直跑仍受支持但降为非默认路径，见 [[architecture/decisions/0016-控制台默认运行用户改为非root.md|ADR 0016]]）。**
- `守护进程管理` — 在宿主机上创建沙箱专属用户、分配子 UID/GID 段、拉起 systemd 用户级免 root 守护进程并配置 linger。
- `镜像构建与分发` — 平台基础镜像的构建与版本管理（官方默认沙箱镜像已退役，沙箱镜像由创建者显式指定）；外部镜像统一经统一镜像代理拉取，代理拉不到时才回退宿主本地副本注入。
- `挂载装配` — 按契约挂载套接字，并原样应用用户声明的挂载；不创建、不修改、不清理用户挂载的宿主机目录。
- `文件注入` — 在创建流程内把声明的宿主文件复制成沙箱用户拥有的副本，再以只读方式挂进容器；原件零接触、副本随沙箱回收、复制是创建时快照。
- `依赖编排` — 按 agent 的指令起停依赖容器（Postgres、MinIO、Logto），并对外暴露就绪状态。
- `端到端测试基建` — Playwright 脚本化用例、静态页可达冒烟、健康检查门禁、`data-testid` 规范（每用例独立数据库与依赖三件套已随示例项目出栈）。
- `URL 代理`（原三期，已退役） — 免 root 守护进程把端口发布到宿主机回环地址，再由宿主机网页反向代理接走。该方向随原定三期一并退役，不再规划（见 [[architecture/decisions/0001-项目定位与三期路线.md|ADR 0001 修订行（2026-11-03 三期方向改定）]]）。
- `快照与自动清理`（原三期，已退役） — 沙箱快照与过期沙箱的自动回收。同样随原定三期退役，不再规划（见 [[architecture/decisions/0001-项目定位与三期路线.md|ADR 0001 修订行（2026-11-03 三期方向改定）]]）。

### 三期规划中的新模块（2026-11-03 立项；连接层前后端侧均已落地并闭合，端口转发的**核心包侧、服务端侧与桌面侧均已落地**——桌面侧 2026-11-04 真机连通通过；**Windows 打包与冒烟亦已闭合（2026-11-04）**）

- `连接层与认证` — 后端所有 `/api` 受访问令牌保护（浏览器侧 WebSocket 走一次性票据）、**CORS 任意来源**（不带凭据）、**WS 握手不再设 Origin 门禁**（准入边界收敛为令牌 + 票据）、前端请求基址与 WebSocket 地址从「连接配置」推导（基址**默认 `http://127.0.0.1:8000`、可编辑、不可为空**——「空 = 同源」已废除；形态间无配置差异）。**后端侧已落地**（[[tasks/phase3-desktop/02-backend-token-and-cors.md|任务 02]]），**前端侧已落地**（[[tasks/phase3-desktop/03-frontend-connection-layer.md|任务 03]]，done：远端形态已 Windows 11 真机 + 真后端实测通过，本机形态按用户拍板的「偏离记录」口径闭合）；桌面侧 CSP 按 0015 收敛为「配置基线 + Rust 运行期 host 级动态生成」。见 [[architecture/decisions/0013-三期定位改定与认证重启.md|0013]]、[[architecture/decisions/0015-桌面壳与连接配置抽象.md|0015]]。
- `端口转发` — 链路**只有「沙箱 ⇄ 用户机」两点**：用户机本机回环监听 ⇄ 隧道 WebSocket ⇄ 后端 `docker exec -i` 字节泵 ⇄ 转发容器（平台自建、由沙箱的免 root 守护进程起、接沙箱网络、**不发布端口**）⇄ 沙箱容器端口；**后端宿主零端口**（不发布也不监听转发端口）。端口选择权在用户机（默认 = 容器端口、可编辑非空、被占自动换并显示实际值、允许 <1024）；编排能力落核心包。**核心包侧已落地**（[[tasks/phase3-desktop/04-port-forward-core.md|任务 04]] done：`forwarding.py`——转发容器编排（不发布端口）/ exec 字节泵 / 转发记录原子读写 / 生命周期联动与遗留清理）；**服务端侧已落地**（[[tasks/phase3-desktop/05-port-forward-server-api.md|任务 05]] done：三条转发管理 REST + 隧道 WebSocket——Bearer 鉴权、固定中文文案错误帧、关闭码 1000/1001/1008/1011）；**桌面侧已实现并真机通过**（[[tasks/phase3-desktop/06-port-forward-desktop.md|任务 06]] done：Rust 本机监听 + **每条连接各开一条隧道 WS**、端口转发界面——**单条隧道断开只关该连接，监听器保留到用户显式 `stop_forward`**；门禁 vitest 527 / cargo test 20；**2026-11-04 真机连通通过、整体验收由用户实际使用确认**；界面已由端口转发区 UI 重构轮的表格化重构替代，原卡片行口径以追加轮为准）。见 [[architecture/decisions/0014-端口转发机制选型.md|0014]]。
- `桌面端` — Tauri v2 壳，与 web 形态共用同一份前端产物；纯连接器，不拉起后端。**（Windows 打包与冒烟已于 2026-11-04 闭合：NSIS `setup.exe` 约 3.7 MB，默认路径、不入库；构建耗时未统计；冒烟通过——[[tasks/phase3-desktop/08-windows-package.md|任务 08]]。）** 见 [[architecture/decisions/0015-桌面壳与连接配置抽象.md|0015]]。

| [[architecture/decisions/0018-运行期文件传输机制选型.md\|0018 运行期文件传输机制选型]] | 运行期文件传输主通道 = `docker exec -i` + 容器内 `sh`/`cat`，复用端口转发的字节泵资产（**零新增第三方依赖**）；上传走「同目录临时名 → `mv` 原子替换」，下载走 `cat` 流出 + **前置分层探测**（FIFO 会挂死 exec），目录列表用 `find` 单次 exec 产出 **NUL 分隔**记录；**大小不限**但**受部署链反代读超时约束**（本机 Traefik 默认 `readTimeout=60s`，落地须调该 service）；含 10 条被实测推翻 / 精化的设计口径 |
