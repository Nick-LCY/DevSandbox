# 0021. 文件注入副本刷新采用显式触发与原位写

- 日期：2026-11-23
- 状态：已接受

## 背景

[[architecture/decisions/0012-文件注入采用复制加改属主而非改造挂载预检.md|ADR 0012]] 定了文件注入的机制：平台在创建时把声明的宿主文件**复制**一份到沙箱用户家目录内的托管副本（改属主、容器内只读挂载），宿主原件零接触。**「复制是创建时快照」被写成明面代价**——「要新鲜内容就重建沙箱」。

代价落在两类场景：宿主上的凭证 / 私钥轮换后，沙箱里挂的还是旧的那份；只想换一条注入的版本，却要连带容器、终端会话与 agent 运行状态一起重来。

2026-11-23 立项的刷新轮要回答的是：**能不能不重建沙箱，让运行中沙箱的托管副本变新？** 结论是可以，但只能走**用户显式触发**的一条窄通道，不能把注入改造成后台实时同步。

## 决策

1. **创建仍是快照**：创建路径的复制语义与校验口径**一字不改**；刷新是**新增的旁路**，不是创建语义的替换。
2. **显式触发**：刷新**只由用户点一次「刷新副本」**发起——无后台同步、无轮询、无增量推送、无自动重试；一次一条，不做批量。
3. **单文件原位写**：保持**同一 inode**（`st_dev` + `st_ino` 不变）覆盖内容。只读 bind mount 绑的是**文件身份**，rename 换 inode 会让容器内仍读旧内容——「刷新看起来没生效」。**不承诺原子性**。
4. **目录递归镜像**：**保留挂载根本身**，递归镜像成员的新增 / 更新 / 删除，**真实存在的空目录保留**（空目录本身不被删）。**不是目录事务**。
5. **无备份、无回滚、无回退入口**：写入阶段失败报「**可能部分更新**」，停止后续更新与镜像删除，**不回滚、不续跑**；修正源后由用户手动重试。
6. **元数据 additive**：新建沙箱把**已校验的宿主源路径**存进实例元数据（**实例事实**，不反查模板）；原 `files` 语义保留；**旧实例不迁移、不补录、无刷新入口**。
7. **接口只收条目标识**：宿主源 / 托管副本 / 容器目标路径一律由服务端从条目查得，请求**不接受任意路径、不接受查询参数、不接受请求体**；走既有管理鉴权。
8. **特权通道不放宽**：helper **随当前发布包内置**（**仅标准库**、**受信绝对路径** + `python -I`），经既有 `Privilege` 调用；**不加** `/usr/local` 安装、**不加** env 配置、**不加** sudo 规则；写入**降到沙箱用户身份**执行，目标用验证过的 inode / 目录句柄。
9. **受信控制面沿用**：沿用 0012 的「注入源以特权读取、调用者视为受信主体」——本轮**未引入新的调用者类型**，也**未收窄**这条信任边界（宽免密 sudo 的收窄仍是 [[architecture/decisions/0016-控制台默认运行用户改为非root.md|0016]] 的遗留待办）。

## 影响

- **代价**：原位单文件写**不原子**、目录刷新**非事务**，读者可能看到中间状态；应用可能须**重新读取**路径才见新内容；旧实例拿不到刷新入口（需用户重建，旧沙箱数据不自动迁移）。
- **留白**：写者退场无法确认时，锁保底到持锁进程退出，可能**保留含新内容的专属暂存**（**不是备份**）；须先确认写者退场再重启持锁进程。
- **未收窄**：宿主特权面仍经一条宽口径免密 sudo，实际权限 ≈ root；本轮只保证**不进一步放宽**。
