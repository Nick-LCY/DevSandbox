# 0010. 启动模板收敛为控制台私有功能

- 日期：2026-10-31
- 修订：2026-10-31（初版）
- 修订：2026-11-01（验收反馈：移除 `{name}` 占位符机制，模板声明原样透传）
- 状态：已接受

## 背景

网页控制台上新建沙箱要手填镜像、挂载声明、环境变量、命令、工作目录。同一套开发环境反复重建时，这套参数靠人肉回忆复述，抄错一个字符就是一轮返工；平台本身也没有「保存的启动配置」这个东西。

但「保存一套启动配置」这件事有三个容易被想当然的接法，必须先拍板：

1. **落在哪一层**。平台自一期起就是「核心包 + 命令行」双入口直连的结构，网页控制台只是服务层里的一个前端。模板若做成核心包能力，等于让核心包开始认识「一组创建请求」这个概念；若做成命令行能力，网页就用不上。
2. **哪些字段有特殊语义**。挂载声明在既有契约里要求写绝对路径，网页表单却天然希望用户写 `~`；模板里若存了 `~/code` 这样的路径，换台机器就失效，模板必须有机会把它翻译成「服务运行用户家目录下的路径」。
3. **存不存得下**。模板是「快照」还是「配方」——只支持重命名的快照，实现简单、语义清楚；支持逐字段编辑的配方，要引入字段级 diff 与部分更新语义。

同期还有两条既有约束会牵动这件事：核心包与命令行「一行不改」的纪律，以及内置模板机制「删除后不复活」的期望。本决策把上述口径一次写死。

## 决策

### 1. 模板是控制台私有能力，核心包与命令行零改动

- 模板的服务端能力全部落在控制台服务层（`platform/src/sandbox_platform/server/` 子包内），**控制面核心包（服务层之外）与命令行 `platform/cli/` 一行未改**。
- 理由：模板是「网页交互的便捷层」，不是沙箱生命周期的概念。核心包只认「一次创建请求」，不认「可复用的创建请求集合」；命令行是薄壳，不该为网页交互承担概念。
- 判定口径：分层契约测试红线不触发——新增服务端源码不得出现带空格的 git、小写独立 docker、`print(`、`subprocess`、`sudo`、`os.system`、`os.popen`。

### 2. 模板存储落在平台数据根

- 模板库落 `<平台数据根>/templates/` 目录，**一个模板一个 JSON 文件**；写入走「写临时文件 → 改权限 0600 → 原子替换」，枚举只扫顶层 `*.json`（内置状态子目录 `.builtin` 天然不参与枚举）。
- 模板标识由服务端生成（`tpl_` + 12 位十六进制），**与名称解耦**，重命名不动标识；模板标识一律以文件名为准，记录内容里的 id 不可信。
- 落盘用 `model_dump(exclude_unset=True)`，保住「这个字段用户填过没有」——「字段缺失」与「字段填了空值」在模板语义里是两回事，不混同。

### 3. 合并语义：出现字段整体替换，缺失字段保持现状

- 模板应用（回填表单）时：**模板里出现的字段整体替换表单对应值，没出现的字段保持表单现状**。挂载列表与环境变量是**整组替换**，不是逐条并入。
- 判「字段是否出现」用「键是否存在」（`hasOwnProperty`），不能用「值是否为空」。
- 这条口径在服务端与前端各落一次：服务端靠 `exclude_unset=True` 保住字段是否出现过，前端靠键存在性判断，两边同源。

### 4. 模板声明原样透传，`~` 展开是网页创建专属口径

- **模板声明原样透传**：模板配置里的字符串**不做任何占位符替换**——加载模板时原样回填表单，提交时原样进创建请求（挂载路径、环境变量值、命令、工作目录、网络名一律不替换）。模板里写了 `{name}` 这样的字面量，平台就收到这个字面量，由后端既有校验兜底（路径不存在会得到明确报错）。
- **`~` 展开**：只发生在服务端把创建请求翻译成核心包请求的那一处，**挂载声明的宿主路径段**上。`~` 与 `~/` 前缀展开为**服务运行用户的家目录**，`~other` 不展开；容器路径、环境变量值、命令、工作目录一律不展开（展开会让用户无法预期内容被改写）。
- **命令行仍要求宿主路径写绝对路径**：这条展开口径不推广到命令行，命令行不承接模板，也不需要 `~`。
- **边界口径**：服务以 root 身份运行时，`~` 展开为 `/root`，会命中核心包的宿主敏感目录拒绝清单并返回 400。这是既有契约的自然结果，不是缺陷，已写进接口文档（`platform/src/sandbox_platform/API.md` 第 13 节），避免后续被当 bug 反复排查。

> 2026-11-01 修订：原第 4 条的「`{name}` 占位符（加载时替换一次、提交前兜底替换一次）」被**移除**——验收反馈认定这套替换机制让用户无法预期最终提交的内容，改为「模板声明中的任何字面量原样提交」。前端 `lib/templates.ts` 的占位符替换函数与抽屉提交前的兜底替换一并删除，接口文档与前端约定同步改口径。
>
> 2026-11-01 补充：同期的界面轮（文案精简 + 箭头入框、空列表贴合、候选项指针、设置抽屉去页脚）**不改变本决策口径**——模板声明仍原样透传，`~` 仍是唯一的网页专属展开口径。

### 5. 模板名接口层零限制，空名由前端拦

- 接口层**不校验名称**：不 strip、不限长、不校验字符集，**空串也收**（创建返回 201）。
- **空名拦截由前端的保存交互负责**（命名弹窗空名禁提交）。
- 理由：名称是展示用标签，服务端做字符集校验会挡住将来出现的任意命名需求；空名是交互问题，不是数据问题。

### 6. 内置种子与墓碑机制

- 服务端维护一份内置模板清单常量，**本期内置清单为空**——只落地机制，不预置真实内容。
- 注入时机两处：**服务启动时**、**列表首次读取时**；同标识的模板已存在则不覆盖（用户改过的内置模板不被种子覆盖）。
- 删除内置模板时写**墓碑**（`templates/.builtin/state.json`），墓碑里的标识在后续注入时跳过——**删了不复活**。墓碑是「读-改-写」，进程内加锁串行化，否则并发删两个内置模板会互相覆盖条目（漏记就会让被删的内置模板复活）。
- **将来补内容即自动生效**：往清单里加一条，重启或首读一次就出现在列表里，不需要额外迁移动作。

### 7. 不做模板字段编辑，只做重命名

- 四条接口只提供**列表 / 创建 / 重命名 / 删除**，重命名只改名称、不改标识与配置体。
- 理由：模板是「快照」不是「配方」。要改内容就重新保存一份；支持逐字段编辑要引入字段级 diff、部分更新语义与「改了一半保存什么」的歧义。
- 代价：改一个字段只能重建模板。

## 影响

- **命令行与核心包零感知**：命令行用不上模板，只能人工复制参数；核心包接口不因模板变动而改，一期定下的分层契约与「核心包不承载网页概念」纪律不被打破。
- **root 运行服务时的 `~` 边界已知并接受**：以 root 跑服务时 `~` 展开为 `/root`，会命中宿主敏感目录拒绝清单返回 400。该行为是既有契约的自然结果，不是缺陷；文档已写明，避免被当 bug 排查。
- **无跨实例并发保护**：模板文件与墓碑都是本地文件，并发锁只在进程内。服务按「单机单实例」部署，不考虑多实例同时写同一个数据根；**多实例部署前必须补文件锁**。
- **内置模板本期是空机制**：列表里不会出现任何内置模板，用户看不到「内置」这一层；但「删除后不复活」的口径已经成立，将来补内容即自动生效。
- **模板能力不含导入导出、不含分类与后端搜索**：候选集全量返回前端，本地按模板名做子串筛选。
- **提交历史里有一处非独立绿**：`ba8c6d7`（模板前端与设置抽屉改名）把组件文件改名，同名测试文件的内容重写落在其后一提交 `6a86a7c`，因此该提交单独检出时测试不绿。历史不改写，已在控制台测试目录的说明文件（`platform/console/tests/README.md`）留注，避免二分排查时误判。
- **验收**：后端 pytest **354 项全绿**、ruff 钉死 `E4/E7/E9/F` 零告警；前端 vitest **269 项全绿**、typecheck 与 build 全绿；Playwright 真机 **22 条全绿**（含模板全流程三条）。两轮独立代码审查的发现全部修完（服务端修异常面缺口与墓碑并发锁，前端修镜像回填时序缺陷与命令数组崩溃等）。
