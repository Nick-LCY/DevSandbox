# 0015. 桌面壳与连接配置抽象

- 日期：2026-11-03
- 状态：已接受

## 背景

[[architecture/decisions/0013-三期定位改定与认证重启.md|ADR 0013]] 定下了「桌面壳是纯连接器、连远程后端、token 认证」的方向，[[architecture/decisions/0014-端口转发机制选型.md|ADR 0014]] 定下了端口转发的链路。剩下的是**连接这件事怎么在前端与桌面壳两侧落地**，有三个具体问题必须一次说清。

**第一，前端现在把「后端在哪」写死了。** `apps/web/frontend/src/api/client.ts` 的 `request()` 统一发同源相对路径；`src/lib/terminal.ts` 的 `terminalSocketUrl()` 从 `window.location` 现拼协议与 host；`vite.config.ts` 的 `BACKEND_URL` 只用于 dev proxy、**不注入产物**；全 `src/` 无 `import.meta.env`、无 `.env`；构建未设 `base`，产物资源是绝对路径 `/assets/*`。桌面端要连远端后端，这些口径都得改，而且改法必须**不破坏 web 形态**（后端托管前端的同源部署仍是本地开发与自托管部署的主力形态）。

**第二，「连接配置」是一份新状态，存哪、谁读、怎么推导地址。** 它同时被三方需要：HTTP 请求（基址 + Bearer 头）、浏览器 WebSocket（基址 + 票据）、桌面 Rust 核心（后端 WS 基址 + Bearer 头）。如果散落在各组件里，很快会出现「HTTP 走 A 地址、WS 走 B 地址」这类难查的问题。

**第三，桌面壳有它自己的运行时约束。** Tauri v2 在 Windows 上从 `http://tauri.localhost` 提供页面（macOS / Linux 是 `tauri://localhost`）；它有 CSP；它的 WebView2 是一套独立的浏览器运行时（Chromium 版本由目标机器决定）；而 `navigator.clipboard` 只在安全上下文可用。现有前端对这些一无所知——它是按「跑在普通浏览器标签页里」写的。

## 决策

### 1. 桌面与 web 共用同一份前端源码与同一份构建产物

- Tauri 工程的 `frontendDist` 直接指向 `apps/web/frontend/dist`。**没有第二份前端**，没有为桌面端 fork 的组件。
- 两形态的差异全部收敛在一层**连接抽象**里，不渗进业务组件。

### 2. 连接配置模型与存储

- 模型：`{ backendBaseUrl: string; token: string }`。
- 存储：`localStorage`，键 `sandbox-console-connection`。
- 存取收敛在 `src/lib/connection.ts`（纯函数 + `useConnection()` Hook），**配单元测试**；口径与既有的 `src/lib/theme.ts`、`src/lib/sidebar-collapsed.ts` 同款：只认自己写进去的值，非法值 / 读取失败回落默认，存储不可用时静默忽略不打断交互。
- `backendBaseUrl` 为空串 = **同源**（web 形态默认）；桌面形态必填非空。

### 3. 基址与 WebSocket 地址的推导

- **HTTP**：`src/api/client.ts` 的 `request()` 先取基址再拼路径，并统一附加 `Authorization: Bearer <token>`；错误映射口径不变（仍直接展示后端 `detail`）。
- **WebSocket**：`src/lib/terminal.ts` 的 `terminalSocketUrl()` 改为从连接配置推导：`http://` → `ws://`，`https://` → `wss://`；基址为空（同源）时仍从 `window.location` 推导，**web 形态行为零变化**。浏览器侧连接前先取一次性票据（ADR 0013 第 4 节），每次重连都重新取。
- **Rust 侧**：桌面 Rust 核心需要后端 WS 基址与 Bearer 头，由前端在调用 Tauri 命令时经 IPC 传入；**Rust 侧不落盘令牌**。

### 4. 运行形态探测

- 用**特性探测**判断是否运行在 Tauri 里（检查 `window.__TAURI_INTERNALS__`），**不引入 `@tauri-apps/api` 依赖**。这样 web 形态的构建产物与依赖树不被 Tauri 污染，也不需要条件编译。
- 形态差异只影响两处：是否显示「连接引导态」、是否提供「在桌面端开启转发」这类 Tauri 专属动作。

### 5. 未配置态引导

- 没有令牌（桌面形态还没有基址）时**不渲染工作台**，改为渲染一块连接配置引导面板：后端地址输入框（web 形态下固定同源、只读）、令牌输入框、「保存并连接」按钮、一句来源说明（令牌在后端部署处的 `<平台数据根>/console-token.json`）。
- 引导态**不是路由**：路由仍然只有 `#/` 与 `#/sandboxes/<名>[/<会话>]` 两层，地址栏不变。
- 引导面板是**页面状态**，不是弹窗 / 抽屉，因此不涉及 `ModalShell` / `DrawerShell` 的复用约束；其中的输入框与按钮是既有原语，不新增交互原语。
- 设置抽屉新增「连接配置」区，可随时改配置并「测试连接」（打一次 `/api/health`，成功 / 失败各弹一条对应 toast）。

### 6. 桌面壳的运行时约束

- **CSP**：Tauri v2 的 CSP 必须允许 `connect-src` 指向用户配置的后端。静态 CSP 无法枚举运行期地址，因此由 Rust 侧在连接配置变更时**动态设置 CSP**（把 `http(s)://<后端host>:*` 与 `ws(s)://<后端host>:*` 加进 `connect-src`），**不整体关闭 CSP**。
- **vite base**：改 `base: './'`（相对路径）。前端是哈希路由，不依赖服务端回退规则；相对 base 在 Tauri 资源协议（Windows 下 `http://tauri.localhost`）与后端 `StaticFiles` 托管两种形态下都能正确解析 `/assets/*`。
- **WebView2 冒烟**：把「`oklch()` 配色正常 / xterm.js 渲染与 fit 正常 / `navigator.clipboard` 在安全上下文下可用」列为打样轮的**硬项**，逐项在真机 Windows 上验，不允许「在 Chromium 里过了就算过」。
- **纯连接器**：桌面端不拉起、不托管、不探测后端进程；只做「装载前端 + 按连接配置设 CSP + 维护端口转发的本机监听与隧道桥接」。

## 影响

- **同源假设被拆掉了**，前端不再有「后端一定在 `/` 下面」的隐含前提。这要求所有请求入口都走统一基址抽象——漏改一处就是一个只在桌面形态暴露的 bug。因此连接配置与基址推导的**单元测试是硬要求**，不能省。
- **令牌明文存 `localStorage`**。桌面 WebView 与浏览器页面的 localStorage 都能被同源脚本读到。平台是个人自用形态，本期接受；「存操作系统凭据库」列为开放问题（Q5），后续可在不改前端契约的前提下换实现。
- **未配置态是一块新的界面**，意味着后端不可达与令牌无效这两种失败态要在引导面板与健康自检两处分别表达，文案不能混。
- **CSP 动态设置**意味着 CSP 不再是构建期常量，配置变更与 CSP 更新之间存在一个极短的时间窗（配置已存、CSP 未更新）。实现上把两者放在同一次 IPC 调用里同步完成。
- **vite base 改动影响 web 形态的产物**：资源引用从 `/assets/*` 变成相对引用。对哈希路由无影响，对 `StaticFiles` 托管也无影响，但**这是一次全量产物变更**，必须重跑既有验收（尤其资源加载相关的用例）。
- **WebView2 的运行时版本不由我们控制**。`oklch()` 需要 Chromium ≥ 111；旧版 WebView2 上 Tailwind v4 的整套色板会失效。这是一个「用户机器决定」的兼容性面，只能靠打样轮的冒烟与文档明示来管理，无法在构建期消除。
- **桌面端不承诺 Linux / macOS**：本决策只保证「同一份源码在两种形态下可构建」，平台打包与验收只做 Windows。
