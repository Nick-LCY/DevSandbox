## 背景

[[architecture/decisions/0013-三期定位改定与认证重启.md|ADR 0013]] 定下了「桌面壳是纯连接器、连远程后端、token 认证」的方向，[[architecture/decisions/0014-端口转发机制选型.md|ADR 0014]] 定下了端口转发的链路。剩下的是**连接这件事怎么在前端与桌面壳两侧落地**，有三个具体问题必须一次说清。

**第一，前端现在把「后端在哪」写死了。** `apps/web/frontend/src/api/client.ts` 的 `request()` 统一发同源相对路径；`src/lib/terminal.ts` 的 `terminalSocketUrl()` 从 `window.location` 现拼协议与 host；`vite.config.ts` 的 `BACKEND_URL` 只用于 dev proxy、**不注入产物**；全 `src/` 无 `import.meta.env`、无 `.env`；构建未设 `base`，产物资源是绝对路径 `/assets/*`。桌面端要连远端后端，这些口径都得改，而且改法必须**不破坏 web 形态**（后端托管前端的同源部署仍是本地开发与自托管部署的主力形态）。

**第二，「连接配置」是一份新状态，存哪、谁读、怎么推导地址。** 它同时被三方需要：HTTP 请求（基址 + Bearer 头）、浏览器 WebSocket（基址 + 票据）、桌面 Rust 核心（后端 WS 基址 + Bearer 头）。如果散落在各组件里，很快会出现「HTTP 走 A 地址、WS 走 B 地址」这类难查的问题。

**第三，桌面壳有它自己的运行时约束。** Tauri v2 在 Windows 上从 `http://tauri.localhost` 提供页面（macOS / Linux 是 `tauri://localhost`）；它有 CSP；它的 WebView2 是一套独立的浏览器运行时（Chromium 版本由目标机器决定）；而 `navigator.clipboard` 只在安全上下文可用。现有前端对这些一无所知——它是按「跑在普通浏览器标签页里」写的。

## 决策

### 1. 桌面与 web 共用同一份前端源码与同一份构建产物

- Tauri 工程的 `frontendDist` 直接指向 `apps/web/frontend/dist`。**没有第二份前端**，没有为桌面端 fork 的组件。
- 两形态的差异全部收敛在一层**连接抽象**里，不渗进业务组件。

### 2. 连接配置模型与存储

- 模型：`{ backendBaseUrl: string; token: string }`。
- 存储：`localStorage`，键 `sandbox-console-connection`。
- 存取收敛在 `src/lib/connection.ts`（纯函数 + `useConnection()` Hook），**配单元测试**；口径与既有的 `src/lib/theme.ts`、`src/lib/sidebar-collapsed.ts` 同款：只认自己写进去的值，非法值 / 读取失败回落默认，存储不可用时静默忽略不打断交互。
- `backendBaseUrl` **不可为空**：默认值 `http://127.0.0.1:8000`，可编辑，**不允许置空**（第三次修订，决策 D：原「空串 = 同源」「基址一律可选」**已废除**——见本节末的留档条）。
- **「空 = 同源」的语义与整条空基址逻辑链删除**（第三次修订，决策 D）：归一分支（空基址 → 相对路径）、桌面形态的「留空」守卫、地址推导里的空值回退分支、引导面板里的空基址占位文案，**一律不保留**。
- **未配置态的判定只有一条**：令牌为空（基址恒有默认值，故不再有「基址缺失」这一未配置原因）。
- **形态差异只剩机制层**：桌面壳运行时才有 CSP 同步与「保存后按需重载主文档」，网页形态没有这一层；**配置层无形态差异**。基址不可为空是**两种形态共通的模型约束**，不再有「桌面形态留空基址」的表单层校验分支。
- **旧存储归一**：读取连接配置时，若存下来的 `backendBaseUrl` 为空，**归一为默认值** `http://127.0.0.1:8000`（不报错、不丢弃整个配置）。
  - 留档（第二次修订，决策 A 的原口径，已按 2026-11-03 决策 D 废除/取代）：「`backendBaseUrl` 为空串 = **同源**；**基址一律可选**，桌面与网页形态**同口径**（原先「桌面形态必填非空」与「网页形态固定同源只读」两条形态差异均已取消）。」「**未配置态的判定只有一条**：令牌为空（不再按形态区分「桌面缺基址 / 网页缺基址」——基址空就是同源，网页端同样可以填一个远端后端地址）。」「**形态差异只剩机制层**……桌面形态留空基址在**表单层本地校验**拦截（桌面壳与后端不同源，留空无法访问），这是界面约束，不是配置模型的差异。」

### 3. 基址与 WebSocket 地址的推导

- **HTTP**：`src/api/client.ts` 的 `request()` 先取基址再拼路径，并统一附加 `Authorization: Bearer <token>`；错误映射口径不变（仍直接展示后端 `detail`）。
- **WebSocket**：`src/lib/terminal.ts` 的 `terminalSocketUrl()` 改为从连接配置推导：`http://` → `ws://`，`https://` → `wss://`；基址**恒有值**（默认 `http://127.0.0.1:8000`），**「基址为空即同源、从 `window.location` 推导」的分支删除**（第三次修订，决策 D）。浏览器侧连接前先取一次性票据（ADR 0013 第 4 节），每次重连都重新取。
  - 留档（第二次修订口径，已按 2026-11-03 决策 D 废除/取代）：「基址为空（同源）时仍从 `window.location` 推导，**web 形态行为零变化**。」
- **Rust 侧**：桌面 Rust 核心需要后端 WS 基址与 Bearer 头，由前端在调用 Tauri 命令时经 IPC 传入；**Rust 侧不落盘令牌**。

### 4. 运行形态探测

- 用**特性探测**判断是否运行在 Tauri 里（检查 `window.__TAURI_INTERNALS__`），**不引入 `@tauri-apps/api` 依赖**。这样 web 形态的构建产物与依赖树不被 Tauri 污染，也不需要条件编译。
- 形态差异**不在配置层**：连接配置的字段、可选性、取值含义在两种形态下完全一致（第二次修订：唯一保留的形态差异是桌面运行时的机制层——CSP 同步 + 保存后按需重载）。Tauri 专属动作（如端口转发的完整管理界面）按形态探测决定是否渲染——**web 形态的端口转发区只渲染说明卡与「安装桌面端」指引，不提供任何管理操作**（2026-11-03 决策 C）。

### 5. 未配置态引导

- **没有令牌**时**不渲染工作台**，改为渲染一块连接配置引导面板：后端地址输入框、令牌输入框、「保存并连接」按钮、一句来源说明（令牌在后端部署处的 `<平台数据根>/console-token.json`）。
- **后端地址输入框在两种形态下都可编辑**，**默认值 `http://127.0.0.1:8000`**；**两种形态下都要求非空**（第三次修订，决策 D：基址不可置空，不再区分形态的校验差异——原「桌面形态要求非空、网页形态不强制」的口径随之作废）。
  - 留档（第二次修订口径，已按 2026-11-03 决策 D 废除/取代）：「（原先「web 形态下固定同源、只读」已取消——网页端同样可配置后端地址，默认空即同源）。桌面形态在**表单层**要求基址非空（桌面壳与后端不同源，留空无法访问），网页形态不强制。」
- **已知边界（登记）**：默认地址指向**用户本机**。从**其他机器的浏览器**访问网页控制台时，必须手动把后端地址改成真正的后端地址；健康检查 / 「测试连接」会立即暴露这一点（连不上）。该边界本期接受，不做自动探测。
- 引导态**不是路由**：路由仍然只有 `#/` 与 `#/sandboxes/<名>[/<会话>]` 两层，地址栏不变。
- 引导面板是**页面状态**，不是弹窗 / 抽屉，因此不涉及 `ModalShell` / `DrawerShell` 的复用约束；其中的输入框与按钮是既有原语，不新增交互原语。
- 设置抽屉新增「连接配置」区，可随时改配置并「测试连接」（打一次 `/api/health`，成功 / 失败各弹一条对应 toast）。

### 6. 桌面壳的运行时约束

- **CSP**：Tauri v2 的 CSP 必须允许 `connect-src` 指向用户配置的后端。静态 CSP 无法枚举运行期地址，因此由 Rust 侧在连接配置变更时**动态设置 CSP**（把 `http(s)://<后端host>:*` 与 `ws(s)://<后端host>:*` 加进 `connect-src`），**不整体关闭 CSP**。
- **vite base**：改 `base: './'`（相对路径）。前端是哈希路由，不依赖服务端回退规则；相对 base 在 Tauri 资源协议（Windows 下 `http://tauri.localhost`）与后端 `StaticFiles` 托管两种形态下都能正确解析 `/assets/*`。
- **WebView2 冒烟**：把「`oklch()` 配色正常 / xterm.js 渲染与 fit 正常 / `navigator.clipboard` 在安全上下文下可用」列为打样轮的**硬项**，逐项在真机 Windows 上验，不允许「在 Chromium 里过了就算过」。
- **纯连接器**：桌面端不拉起、不托管、不探测后端进程；只做「装载前端 + 按连接配置设 CSP + 维护端口转发的本机监听与隧道桥接」。

### 7. 打样轮临时偏离（2026-11-03）

- **偏离点**：打样骨架 `apps/desktop/src-tauri/tauri.conf.json` 暂设 `app.security.csp` 为 `null`（Tauri v2 默认行为），与第 6 节「不整体关闭 CSP、由 Rust 侧动态设置 CSP」存在**临时偏离**。本条只覆盖打样骨架，决策本身不修改。
- **原因**：静态 CSP 会拦截前端产物里的内联防闪烁脚本；动态生成 CSP 属连接层实现内容（[[tasks/phase3-desktop/03-frontend-connection-layer.md|03 前端连接层]]、[[tasks/phase3-desktop/06-port-forward-desktop.md|06 桌面侧]]），打样轮只保持最小骨架。
- **闭合闸门**：任务 03 与 06 的完成标准已新增「`app.security.csp` 不得为 `null`」一条；**任务 08（[[tasks/phase3-desktop/08-windows-package.md|08 Windows 打包]]）出包前必须闭合**，闭合后本条失效、回到第 6 节口径。
- 打样结论与实测留档见 [[tasks/phase3-desktop/RESULTS.md|三期留档]]。

> **2026-11-03 修订（打样轮临时偏离闭合）**：本条偏离**随 03 落地而闭合**，回到第 6 节口径。落定形态是**「配置基线 + Rust 运行期 host 级动态生成」**：`apps/desktop/src-tauri/tauri.conf.json` 的 `app.security.csp` **不再是 `null`**，而是基线策略（`connect-src` 只留 `'self'`）；Rust 侧（`apps/desktop/src-tauri/src/csp.rs`）在主文档被请求时按当前后端主机动态补 `http(s)://<后端host>:*` 与 `ws(s)://<后端host>:*`——**host 级粒度，不放行 `http:` / `https:` / `ws:` / `wss:` 这类 scheme 通配**（scheme 通配等于「页面能往任意主机连」，CSP 就失去意义；真正的准入边界仍是令牌与一次性票据）。**时序契约 = 保存连接配置 → 同步 Rust 状态 → 按需重载主文档**：主文档的 CSP 只在主文档被请求时生成，故必须先更新桌面壳状态（`set_backend_base_url`），再问当前 CSP 是否已跟上（`csp_needs_reload`），没跟上才重载主文档（重载后重新被请求，这一版 CSP 才带上后端主机）——**顺序不能反**。**闸门状态**：任务 03 的完成标准（`app.security.csp` 不得为 `null`）**已闭合**；**任务 06 的同款闸门保留**（[[tasks/phase3-desktop/06-port-forward-desktop.md|06 桌面侧]]仍须守住该条）。

## 影响

- **同源假设被拆掉了**，前端不再有「后端一定在 `/` 下面」的隐含前提。这要求所有请求入口都走统一基址抽象——漏改一处就是一个只在桌面形态暴露的 bug。因此连接配置与基址推导的**单元测试是硬要求**，不能省。
- **令牌明文存 `localStorage`**。桌面 WebView 与浏览器页面的 localStorage 都能被同源脚本读到。平台是个人自用形态，本期接受；「存操作系统凭据库」列为开放问题（Q5），后续可在不改前端契约的前提下换实现。
- **未配置态是一块新的界面**，意味着后端不可达与令牌无效这两种失败态要在引导面板与健康自检两处分别表达，文案不能混。
- **形态差异收敛到机制层之后，「桌面 vs 网页」不再是配置的分野（第二次修订）**：网页端现在也能填远端后端地址（与 [[prds/phase3-desktop.md|三期 PRD]] 开放问题 Q8 的答案一致：支持，无形态差异），连接配置只有一套模型。代价是**未配置态的判定只剩令牌一条**——网页端填了基址但没填令牌同样是未配置，引导面板与健康自检的表达要覆盖这一情形。桌面形态的空基址靠**表单层本地校验**拦截（桌面壳与后端不同源，留空无法访问），这条约束只活在界面里、不在配置模型里；将来若桌面壳改为能同源托管页面，这层校验要跟着撤掉。**（第三次修订，决策 D 后半句作废：基址已是模型层的「不可为空」约束，不再是形态专属的界面校验。）**
- **基址不可空是模型约束，不只是界面约束（第三次修订，决策 D）**：「空 = 同源」删除后，前端少了一整类分支——归一分支、地址推导回退、空基址占位文案、桌面形态的「留空」守卫。代价是**「同源部署」不再是一等公民**：后端托管前端时必须显式填一个地址（默认值 `http://127.0.0.1:8000` 恰好覆盖本地自托管场景），非默认端口的同源部署要用户手动填一次。旧存储里基址为空的配置在**读取时归一为默认值**，不报错、不丢弃整份配置。
- **默认地址指向用户本机（已知边界，登记）**：从**其他机器的浏览器**访问网页控制台时，默认值 `http://127.0.0.1:8000` 指向的是浏览器所在机器而非后端，用户必须手动改成真正的后端地址；**健康检查 / 「测试连接」会立即暴露这一点**。本期不做自动探测。
- **CSP 动态设置**意味着 CSP 不再是构建期常量，配置变更与 CSP 更新之间存在一个极短的时间窗（配置已存、CSP 未更新）。实现上把两者放在同一次 IPC 调用里同步完成（**2026-11-03 修订：实际落为「更新桌面壳状态 → 问是否需重载 → 按需重载主文档」三步，命令名与顺序见第 7 节末尾的修订说明**）。
- **vite base 改动影响 web 形态的产物**：资源引用从 `/assets/*` 变成相对引用。对哈希路由无影响，对 `StaticFiles` 托管也无影响，但**这是一次全量产物变更**，必须重跑既有验收（尤其资源加载相关的用例）。
- **WebView2 的运行时版本不由我们控制**。`oklch()` 需要 Chromium ≥ 111；旧版 WebView2 上 Tailwind v4 的整套色板会失效。这是一个「用户机器决定」的兼容性面，只能靠打样轮的冒烟与文档明示来管理，无法在构建期消除。
- **桌面端不承诺 Linux / macOS**：本决策只保证「同一份源码在两种形态下可构建」，平台打包与验收只做 Windows。
