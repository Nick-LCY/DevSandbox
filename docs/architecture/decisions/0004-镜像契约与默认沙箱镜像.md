# 0004. 镜像契约与默认沙箱镜像

- 日期：2026-10-29
- 修订：2026-10-29（挂载契约修订：固定挂载点约定收窄为套接字默认路径与容器层空目录）
- 状态：已接受

## 背景

使用者有两类：平台自己维护的默认环境，以及用户自定的工具链。平台镜像如果把全部工具链焊死，用户改一个版本就得等平台发版；平台镜像如果做得极简，用户每次起沙箱都要自己装一遍工具，端到端测试的启动成本会吃掉大部分时间。

同时，每个沙箱都从网络重复拉取 Postgres、MinIO、Logto 镜像，会让「随时启动一个沙箱」变成分钟级操作。

## 决策

### 1. 镜像契约分两层

- 平台基础镜像：只包含 Docker 客户端、入口纯 bash 脚本、固定挂载点约定，不含具体语言工具链。
- 沙箱镜像：在平台基础镜像之上，由用户自由叠加工具。官方默认全栈沙箱镜像包含 pi、git、uv、nvm + node、pnpm、Playwright 浏览器。

两层分开是硬契约：平台只保证基础镜像那一层的契约，沙箱镜像层由用户自己负责。

### 1.1 固定挂载点约定收窄

- 基础镜像不再内置任何 volume 挂载点：`docker image inspect` 的 `Volumes` 字段应为空，镜像里不预置会话目录、代码目录等宿主机挂载目标。
- 固定挂载点只剩两项约定：
  - **Docker 套接字默认路径** `/var/run/docker.sock`——控制面创建沙箱时把每用户守护进程的套接字挂到这里，docker 客户端默认可见，用户无需声明。
  - **便捷空目录 `/workspace`**——只是容器层的一个可写空目录，供容器内临时使用；它不是 volume，不落到宿主机，随容器删除而消失，文档中明确注明。
- 其余宿主机目录一律由用户在创建沙箱时声明挂载，平台不预置、不创建、不清理。

### 2. 依赖镜像离线分发

Postgres、MinIO、Logto 等常用依赖镜像以离线包形式随平台基础镜像分发，首次启动自动加载，不必每个沙箱重复拉取。

### 3. 运行时极简

沙箱启动即一个 bash，不加载任何 profile 脚本。启动哪些依赖服务（Postgres、MinIO、Logto 等）完全由 agent 自主决定。

## 影响

- 基础镜像保持极小、启动快；但只有官方默认沙箱镜像能做到开箱即用，两层都要维护与发布。
- 「入口纯 bash、无 profile」意味着不能靠 shell 初始化脚本注入环境变量与别名，一切配置必须通过挂载注入——这与「镜像即产品」的跨期约束一致。平台唯一自行注入的是 Docker 套接字，其余配置由用户声明的挂载提供。
- 基础镜像不内置 volume 挂载点，镜像体积与层数更干净；代价是 `/workspace` 里的内容随容器消失，需要长期保留的数据必须由用户显式声明挂载，文档与起步指引必须把这层区别讲清楚。
- 离线分发依赖镜像会显著增大平台基础镜像体积；依赖镜像升级需要重新打包发布，发布节奏与依赖版本绑定。
- 依赖是否启动交给 agent 决定，agent 就必须知道依赖怎么起。示例项目与起步指令文档要写清启动方式，否则 agent 容易漏起服务，端到端测试会以「环境未就绪」失败。
- Playwright 浏览器随默认沙箱镜像分发，镜像体积上升，换来的是开箱即用的浏览器端到端测试能力。
