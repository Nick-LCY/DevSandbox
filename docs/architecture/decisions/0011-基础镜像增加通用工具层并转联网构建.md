# 0011. 基础镜像增加通用工具层并转联网构建

- 日期：2026-10-31
- 修订：2026-10-31（初版）
- 状态：已接受

## 背景

平台基础镜像自 0.1.0 起就是「入口纯 bash + Docker 客户端」的极简底座（见 [[architecture/decisions/0004-镜像契约与默认沙箱镜像.md|0004 镜像契约与默认沙箱镜像]]），构建口径是「所有 RUN 步骤不触网、构建命令显式带 `--network=none`」。这个口径的好处是构建可复现、离线可做。

实际使用暴露的缺口很具体：git、openssh-client、vim、curl、ca-certificates、unzip、xz-utils、procps、less 这 9 个通用工具在容器里全部缺席。用户每起一个沙箱都要现装一遍，装完不随镜像沉淀，等于每个沙箱都从零手搓一遍同样的环境。

可选的两条路：

1. **保持零网络构建**，把工具层挪进沙箱镜像层（用户自建镜像里装）。底座不变轻，但平台默认体验不变——用户要么自己装，要么自建镜像。
2. **在基础镜像里加一层通用系统工具**，构建改为联网 apt 拉包。底座变重，但常用工具开箱即用。

两条路的差别不只是「装在哪」，还包括「构建还剩多少确定性」：联网 apt 拉包意味着同一个 Dockerfile 在不同时间可能产出不同内容。本决策把这条确定性代价显式写下来，而不是当作没发生。

## 决策

### 1. 底座从「bash + Docker 客户端」扩为「+ 9 个通用系统工具」

- 在 `platform/base-image/Dockerfile` 的最终阶段新增一层 apt 安装，装齐 9 个通用工具包：**git、openssh-client、vim、curl、ca-certificates、unzip、xz-utils、procps、less**。
- 安装参数 `--no-install-recommends`；**安装与清索引写在同一个 `RUN` 层内**，镜像内不残留 apt 索引。
- 该层放在 `FROM` 之后、`ARG DOCKER_CLI_VERSION` 重新声明之前，客户端版本升级不必重跑 apt。
- 镜像版本参数 `ARG BASE_VERSION` 改 `0.3.0`，镜像标签与 OCI label 的版本信息同步。

### 2. 构建由零网络转为联网

- 构建口径从「所有 RUN 不触网 + 显式 `--network=none`」改为**联网 apt 拉包**；构建命令不再带 `--network=none`。
- **0.2.0 是最后一个零网络构建的版本**，保留为离线可回退底座——需要无网构建时回退到它，而不是临时改 Dockerfile。

### 3. 体积与耗时代价如实记录

- `docker image inspect .Size` = **98,494,563 B = 98.5 MB**（0.2.0 为 47,693,426 B = 47.7 MB，**+50.8 MB**）；构建耗时 **18 秒**。
- 分层数据（`docker history`，未压缩）合计 298,659,623 B，其中新增 apt 层 164,626,432 B；底座层与 Docker 客户端层与 0.2.0 共用同一层。

### 4. 扩展 0004 的「运行时极简」条款，边界写死

- 0004 第 1 节把基础镜像定义为「只包含 Docker 客户端、入口纯 bash 脚本、固定挂载点约定，**不含具体语言工具链**」。本决策把「通用系统工具」明确划进 base 层职责范围，并把该条款的边界钉死：

| 进 base（通用系统工具） | 不进 base（语言链与运行时） |
|---|---|
| git、openssh-client、vim、curl、ca-certificates、unzip、xz-utils、procps、less | node、pnpm、python3、psql、mc 等任何语言链与运行时 |

- **两层镜像契约不变**：语言工具链仍属沙箱镜像层，由用户自选；base 仍不含任何语言链与运行时。
- 0004 第 3 节的「运行时极简」指的是**沙箱启动即一个 bash、不加载任何 profile 脚本**，与镜像里装了什么无关，本决策**不动该条款**。
- 沙箱镜像层零改动：`platform/sandbox-image/` 目录、默认全栈沙箱镜像、`platform/src/sandbox_platform/config.py` 的默认镜像与本地镜像前缀配置均未动。

### 5. 判定脚本同步扩项

- `platform/base-image/verify.sh` 判定总数由 35 变 **42**：35 项原有判定 − 2 条被删的否定断言（「镜像内无 git」「镜像内无 curl」，这两个命令现在应当在镜像内）+ 9 条新增判定（逐个断言「包查得到版本 + 命令在 PATH」，`ca-certificates` 断言证书文件 `/etc/ssl/certs/ca-certificates.crt` 存在）。
- `platform/base-image/verify-rootless.sh` 的默认镜像从 0.2.0 跟到 0.3.0，与静态判定脚本对齐。

## 影响

- **构建确定性下降**：联网 apt 拉包后，同一份 Dockerfile 在不同时间可能因 apt 源变动产出不同内容；「离线可复现」变成「依赖 apt 源快照」。回退路径明确：需要无网构建时用 0.2.0。
- **镜像体积 +50.8 MB**（47.7 MB → 98.5 MB），换取常用工具开箱即用，不再每个沙箱现装一遍。
- **判定口径变严也变准**：基础镜像「在场」的工具由断言列表钉死，不再靠「跑起来没报错」这种间接判断。
- **底座与沙箱镜像的职责边界仍清晰**：base 只装与语言无关的系统工具，任何语言链仍不进 base；用户自建镜像的叠加工具链不受本决策影响。
- **验收**：`verify.sh` **42 项判定全通过**；免 root 联调 `verify-rootless.sh` **5 项 + 6 项回收校验全通过**，脚本自建资源已全部回收；构建耗时 18 秒。
- **可复现性的兜底**：基础镜像不是唯一入口——需要完全可控的工具链时，用户仍可在沙箱镜像层自行叠装，平台不强制工具层进 base 之外的任何路径。
