# 0020. 控制台终端采用后端模拟器与快照接入

- 日期：2026-11-19
- 状态：已接受
- 备注：本轮同时落地「前端实例常驻」（施工单步骤 8 的增量），两者是**一条方案的上下半段**，不是两个独立决策。原四项待办里的 ③（自定义按键映射）④（系统剪贴板互通）**仍登记不做**。
- 证据留档：任务集见 [[tasks/console-terminal-emulator/README.md|控制台终端全步方案任务集]]（01 模拟器 / 02 接入协议 / 03 实例常驻 / 04 验收）；全轮留档见 [[tasks/console-terminal-emulator/RESULTS.md|全轮收口留档]]；需求见 [[prds/console-terminal-emulator.md|PRD（交付后补记）]]。

## 背景

2026-11-17 登记的「pi × 控制台终端四项待办」有四条症状，主线两条同源，根因都在**「终端状态没有权威持有者」**：

1. **xterm 实例不是常驻的**：`TerminalPanel.tsx` 用 `key={activeId}` 渲染，切标签即销毁旧实例、新建实例。pi 全屏时开启的 DEC 私有模式（鼠标 1000/1002/1003/1006、焦点上报 1004、括号粘贴 2004、备用屏 1049）**挂在 xterm 实例上**，实例重建即全部归零；pi 侧不知情、也不会重发 ⇒ 切标签后鼠标、焦点事件、括号粘贴全部失效。
2. **重连靠「整段重放历史」**：新实例靠服务端 256 KiB 环形缓冲回放把画面拼回来。历史字节里有 pi 启动时发的两包终端探测（kitty 键盘协议查询 `\e[>7u\e[?u` + DA1 `\e[c`；主题色查询 `\e]10;?` / `\e]11;?` / `\e]4;0..15;?` + DA1），新 xterm 实例把历史里的探测**当新请求再答一遍**，应答经 WebSocket 写进 PTY 输入——pi 还在前台时由 pi 自己消费（无症状），pi 退出后 bash 把应答当键盘输入回显成乱码（用户实测捕获的乱码与两包应答逐字对上）。

**只修第 1 条不够**：前端常驻只能覆盖「切标签」这一条路径。刷新页面、从 Obsidian tab 切回（分屏整体卸载是既有口径）、后端重启后重连，实例照样重建，模式照样丢；而且**重放历史里的探测还在**，新实例仍会再答一遍——症状②不会消失。只要「历史字节」还是恢复介质，问题就一直在。

**模式也不能靠重协商补**：DEC 私有模式由「往终端写字节的那一方」设置，平台没有资格要求任意程序（pi、bash、任意 TUI）在 attach 后重发一遍设置；「attach 时剥离重放内容里的探测序列」只是把再应答**推迟**（下一次重连还有别的东西可答），而且剥离规则要跟着所有 CLI 的探测习惯改。

因此需要一个**能持续解析容器输出、始终知道「屏幕 + 光标 + 模式现在是什么」的权威**，附着时下发「当前状态」而不是「历史字节」。

## 决策

### 1. 服务端为每个终端会话常驻一份终端模拟器（能力落点）

- 每个终端会话在服务进程内常驻**一个** VT 模拟器实例（`apps/web/backend/src/sandbox_console/emulator.py`），底座是 **pyghostty 0.1.4**（Python 绑定，进程内跑 libghostty-vt，与 ghostty 同一套 VT 核心）。
- 容器输出照旧转发前端，**并在 `_publish` 锁内并行喂给模拟器**：输出路径的唯一权威仍是 PTY 字节流，模拟器是它的**影子状态**，不参与转发决策。
- **几何三者恒一致**（模拟器 / 宿主伪终端 / 会话记录）：resize 时先改模拟器、再改 PTY，PTY 改不动就**回滚模拟器**；模拟器改不动则两边都不改。不留「半套几何」——恢复流按字面换行相对定位，尺寸不一致画面就错位。
- 会话删除 / 会话结束 / 服务退出时，模拟器随会话生命周期一起释放。

**方案对比（本轮选型）**：

| 候选 | 结论 | 理由 |
|---|---|---|
| 仅「前端实例常驻 + attach 时模式重协商」 | **否决**（只作为方案的一半保留） | 只覆盖切标签一条路径，刷新 / Obsidian 往返 / 重连仍重建；重放历史里的探测仍会被再答；平台也无权重协商任意程序的模式 |
| **pyghostty 进程内模拟器** | **采用** | 直接绑 libghostty-vt（真实终端核心，不是「够用的子集」），**进程内零 IPC**、随服务进程生命周期管理、可用 Python 同步调用；代价：**只发 wheel**（glibc Linux x86_64/aarch64 + macOS，无 sdist）⇒ 必须留降级路径（服务端见第 2 节末的开关，前端见第 3 节末的降级兑底） |
| Rust 边车（自起一个 VT 进程，经 IPC 通信） | **否决** | 能力面最强，但引入**新进程模型 + 跨语言协议 + 边车生命周期与崩溃恢复**，与「控制面单进程、终端 I/O 线程在进程内」的现有形态冲突；代价远超本轮收益 |
| pyte（纯 Python 终端模拟库） | **否决** | 安装零门槛，但**解析覆盖与 DEC 私有模式语义不足**以保证「模式权威」——恢复流的质量取决于解析器的真实终端语义，这里恰恰不能打折 |

> 三条否决路线**未做同轮打样对比**（本轮无打样轮）：选型依据是**能力面与进程模型**，不是基准测试。若将来 pyghostty 的 wheel 供给或版本兼容出问题，Rust 边车是保留的升级路线。

### 2. 接入协议换代：`attach` → 对齐 → 静默 → `snapshot` → 续实时流

客户端附着不再「连上就等你回放」，而是**先报尺寸、再收快照**：

1. 客户端连上后先发 `{"type":"attach","cols","rows"}`（**第一个控制帧**）；
2. 服务端把会话对齐到该尺寸（模拟器 → PTY，失败回滚），**保持几何三者一致**；
3. 等一个**静默窗口**（0.12 秒无输出 / 上限 0.8 秒），让容器内的程序把重绘做完；
4. 从模拟器导出「当前画面 + 光标 + 终端模式」的 **VT 恢复流**，按 **48 KiB 原文切片**（base64 后约 64 KiB，不越中间代理单帧上限）装进 `{"type":"snapshot",part,parts,data,cols,rows,pwd}` 文本帧下发，`pwd` 携带最近一条 OSC 1337 载荷；
5. 下发完毕后续实时字节流。

派生口径：

- **旧客户端**（不发 `attach`）⇒ 超时 **1 秒**判定，回退环形缓冲回放（二进制帧按 64 KiB 原文切片），**行为与历史一致、功能不崩**，只是少了快照恢复。
- **迟到的 `attach`**（1 秒超时之后才到）⇒ **补发快照**：按该尺寸 resize → 等静默 → 取快照 → 同样分片下发；**不新开输出流**（两条流会把同一块输出投递两遍），分片发送**持锁串行**（保证同一连接上的分片不交错）。丢弃它的后果是新前端**只拿到历史回放、且毫不知情**——症状②会悄悄复发。
- **旧后端**（不认 `attach`）⇒ 回一条「无法识别的终端指令」错误帧，新前端**静默豁免**（不弹提示、不改状态）并补发一帧 `resize` 让旧后端照常同步尺寸。
- **开关**：环境变量 `SANDBOX_TERMINAL_EMULATOR`（`terminal.py` 的 `ENV_EMULATOR` 常量；`0` / `off` / `false` 显式关停）关掉后**走同一条回退路径**（环形缓冲回放）。pyghostty 装不上时同理，整条能力缺失但不影响服务启动。

### 3. 前端恢复口径（与协议成对）

- **顺序固定**：`term.resize(快照 geometry)` → `term.reset()` → `term.write(恢复流)`。先对齐几何（恢复流按字面换行相对定位）、再清旧画面与旧模式、再写。
- **分片拼不拢就丢弃**（缺片 / 序号重复 / 非法 base64 一律不写）：宁可不写，也不写半截画面。判定收敛在纯函数 `terminal-snapshot.ts`。
- **pwd 随快照恢复**：快照帧带最近一条 OSC 1337 载荷，接入即恢复会话工作目录（后端会话记录仍不加字段，pwd 仍是前端内存产物）。
- **降级兜底**：attach 后窗口内**一个快照分片都没收到**（旧后端 / 模拟器关停）时，补一次「尺寸真变化」的两步 resize 逼 readline 重画提示符，从而重新拿到 OSC 1337 pwd；正常路径收到分片即不做，避免多余 SIGWINCH。

### 4. 两条红线（实现层硬约束，不是调优项）

1. **状态与恢复流的结构体字段一律逐字段显式 ctype**。按默认类型推断会让字段宽度与实际内存布局不符，**堆越界直接崩进程**——命中的不是「这个会话坏了」，而是**整条控制台服务进程挂掉**。
2. **不注册模拟器的应答回调**（探测应答**静默丢弃**）。模拟器解析到终端探测时会自己生成应答；一旦把应答转发出去，历史里的探测就等于被**再应答**一次——那正是本轮要根治的症状②。**「模拟器只读屏幕与模式，永不写 PTY」**是这个方案的隐含边界。

### 5. 前端实例常驻（同轮落地的另一半）

- 终端标签之间**不再销毁重建 xterm 实例**：删掉 `key={activeId}`，改由终端栈（`TerminalStack.tsx`）给每个会话一个常驻槽位，非激活的用 `display:none` 藏起来。
- **只有访问过的会话才挂载**（挂载集合 = 已访问 ∩ 仍在会话表 ∪ 当前激活，纯函数 `terminal-residency.ts`）：不自动附着用户没点过的会话。
- 变可见时补一次 fit（隐藏态量不到尺寸），滚动位置按「距底部」还原。
- **切 Obsidian tab 仍是分屏整体卸载**（既有约定与 e2e 断言不动）：切回来重新挂载，走 attach + 快照恢复——**这正是模拟器方案必须存在的原因**。
- 焦点回填从「挂载时布尔」改为**按会话的回填请求序号**（`focusRequestId`）：一次请求只回填一次，重连不重放旧请求。

## 影响

**收益**

- 症状①**根治**：模式状态由服务端模拟器权威维护，任何重建路径（刷新、Obsidian 往返、重连、后端重启后重连）都能一次性恢复鼠标 / 焦点 / 括号粘贴 / 备用屏。
- 症状②**根治**：探测请求不再进任何回放（快照里没有探测、模拟器的应答不外出），再应答从源头消失。
- 代价是**恢复介质的换代**：从「历史字节」改为「当前状态」。这带来一组**刻意的取舍**：

**已知限制（写死，不当作缺陷修）**

| 限制 | 内容 | 后果 |
|---|---|---|
| **快照只恢复活动屏** | 主屏滚动历史不进快照：pi 全屏（备用屏）期间主屏里的早期输出**不回放** | 「不再重放历史」的必然代价；屏幕上看得见的内容一定在 |
| **回滚深度两侧不同** | 服务端模拟器保留 **1000 行**，前端 xterm 保留 **5000 行** | 长会话重挂载后，可回滚的历史从 5000 行降到 ≤1000 行 |
| **键盘协议标志不可恢复** | kitty 键盘协议等「键盘能力协商」标志**不在**恢复流里（前端 xterm.js 5.5.0 不支持该协议） | 快照带了也用不起来 ⇒ 待办 ③（shift+enter → ESC+回车）仍需前端自定义映射 |
| **Obsidian 往返后「已访问集合」清零** | 分屏整体卸载 ⇒ 组件重建 ⇒ 已访问集合从空开始 | 各会话再点开时**重走一次快照**（画面正确，但多一次恢复）；属可接受代价 |
| **隐藏会话持有 WebSocket** | 常驻槽位各持一条连接（单沙箱会话上限 5） | 连接数上升有界（≤5/沙箱），不随标签数量增长 |
| **依赖 wheel 供给** | pyghostty 只有 wheel、无 sdist | 换平台或升级 Python 版本时可能装不上 ⇒ 走关停开关与降级路径（功能降级、不崩） |

**评审遗留（登记不修，后续可领）**

1. 快照的格式化仍在会话锁内（已打点，未移出）——极短尾延迟可能落在锁内；
2. `pwd` 每个分片都重复下发（带宽冗余，无正确性问题）；
3. 错误帧没有机器可读的 `code` 字段，前端的「旧后端识别」靠**字符串匹配**文案（文案一改就失效）；
4. `snapshotParts` 未按连接隔离（同一会话多连接同时附着时的边界未收敛）。

**验收边界**

- 单次 e2e 全量 **75/75** 未能取得：宿主内存不足（11 GiB 用满 + swap 满）导致 headless Chrome 被 OOM 杀掉（dmesg 实证），**每条用例都至少通过过一次、无稳定失败**，归因为宿主资源而非代码。
