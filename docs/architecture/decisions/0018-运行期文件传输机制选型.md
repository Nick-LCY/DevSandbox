# 0018. 运行期文件传输机制选型

- 日期：2026-11-09
- 状态：已接受
- 备注：机制经 01 打样轮真机实测验证；**06 轮只复核，不再改状态**。
- 证据留档：01 轮实测记录见 [[tasks/runtime-file-transfer/01-prototype-and-mechanism.md|任务 01]]（原始实测过程与全部数字）；需求见 [[prds/runtime-file-transfer.md|运行期文件传输 PRD]]

## 背景

平台有两条把文件带进沙箱的路，都是**创建时**的一次性动作：用户声明挂载（[[architecture/decisions/0005-挂载契约与数据归属.md|0005]]）与文件注入（[[architecture/decisions/0012-文件注入采用复制加改属主而非改造挂载预检.md|0012]]）。两条路的共同前提是**沙箱还不存在**。沙箱跑起来之后，agent 要往里塞一份新数据、或把跑出来的产物取出来，平台**没有任何通路**——不是权限问题，是通道不存在。

三期把端口转发做成了一条生产验证的字节通道：后端用 `docker exec -i` 起字节泵（核心包 `forwarding.py` 的 `spawn_stream` + `BytePump`），把容器内的字节流搬到用户机（[[architecture/decisions/0014-端口转发机制选型.md|0014]]）。这套资产与「搬什么」无关——换一条容器内命令就能搬文件。

本决策要钉死的是这条通道**搬文件时的具体形态**，并且必须把 PRD 草案里那些**凭直觉写下的假设**逐条换成实测口径。01 打样轮的实测推翻/精化了 PRD 草案里的**十条设计点**（见第 7 节），其中四条是硬要求而非调优项：**目标为已存在目录必须前置拦截**（否则 `mv` 报成功但文件不在目标路径）、**探测必须区分特殊文件**（FIFO 会挂死 exec）、**错误分类只能按 stderr 关键词子串**（dash 与 busybox ash 的措辞与退出码都不同）、**路径必须 argv 直传**（`sh -c` 拼接会被含换行的路径拆碎）。

## 决策

### 1. 主通道：`docker exec -i` + 容器内 `sh` / `cat`，复用既有字节泵资产

- **通道**：沙箱的免 root 守护进程下执行 `docker exec -i <沙箱容器> <cmd>`，宿主侧用 `forwarding.BytePump` 双向搬运。**零新增第三方依赖、零新增进程模型**——01 轮实测确认 `spawn_stream` + `BytePump` 原样可用，**stderr 排空 / 短写循环 / 进程组回收**三个坑不必重踩。
- **能力落点**：核心包新增与 `forwarding.py` **平级**的 `transfer.py`（路径校验 / upload / probe / 下载泵 / list），服务端（03 轮）只做编排与转译。**命令行零改动、创建时注入通道零改动。**
- **范围**：**单文件**粒度，双向（上传 + 下载），覆盖 web 与桌面两形态。目录整体传输与多文件打包**本期不做**。

**否决路线与理由**：

| 候选 | 结论 | 理由 |
|---|---|---|
| Docker SDK（Python 客户端库） | **否决** | 破坏核心包**零第三方依赖**约束 |
| `docker cp` 直接调用 | **否决**（留作以后目录传输的后手） | 版本差异多、**属主不可控**；本期要控属主与覆盖语义 |
| 借道「创建时注入」通道 | **否决** | 挂载只在建容器时生效，运行期**时序不符**，无从插入 |
| 另起 WebSocket 通道 | **否决** | 通道语义拧：字节泵已是点对点流，再套一层 WS 只是多一跳、多一处状态；本轮**不新增 WebSocket**（CORS 白名单零改动） |
| `docker exec -i` + 容器内 `sh` / `cat` | **采用** | 复用已验证资产、零新增依赖、能控属主与覆盖语义 |

### 2. 上传语义：同目录临时名 → `mv` 原子替换

- 字节流写入**与目标同目录**的临时名，再 `mv` 原子替换目标。实测三条硬结论全部成立：**原子替换成立**、**目标已存在 = 覆盖**、**rename 不跟随末端符号链接**（链接本身被替换，链接指向的文件不受影响）。
- **「临时名 + `mv」这个模式本身就是防写穿的关键，不可省**：实测对照表明直接重定向到符号链接会**写穿**到链接目标。
- **临时名必须与目标同目录**：跨设备 `mv` 走 copy + unlink（rename 必 EXDEV），**非原子、中途失败留半截文件**（实测 inode/设备号从 `2 215` 变为 `12990840 179`）。
- **路径必须 argv 直传**（`docker exec … cat -- <path>`），**禁止**拼进 `sh -c` 脚本文本；`sh -c` 只用于固定脚本，路径经 `"$1"` 位置参数传入。
- **写入失败后清理临时文件由平台侧负责**：实测 exec 被杀时容器内留下半截临时文件（8 MiB `.rtf-tmp-interrupt`），`cat` 不会自清理（`sh` 拿不到执行 `mv` 的机会，`cat` 也没有 trap）。
- 平台**不主动创建父目录**：父目录缺失即报错并引导用户先建好。

### 3. 下载语义：`cat` 流出 + **前置类型探测**（硬要求）

- 下载走 `cat -- <path>` 流出字节，**前置探测是必须项，不是优化**：
  - **FIFO 会把 exec 挂死**——实测 GNU 与 busybox **都会挂**（宿主 8 s 超时 rc=124；busybox `timeout 3 cat` → rc=143）。一条 FIFO 下载请求就能占住一条 exec 进程。
  - **`/dev/null` 会「成功地」返回一个 0 字节下载**（rc=0、无 stderr）——客户端拿到一个静默的空文件。
- **探测命令必须分层，区分「不存在 / 目录 / 普通文件 / 特殊文件（FIFO·设备·套接字）」**。PRD 草案的命令做不到（见第 7 节第 3 条）。**探测不放行特殊文件是硬要求。**
- **大小首选 `stat -c %s`**（O(1)，实测 67.3 ms），`wc -c < file` 为备选（68.4 ms，但要读完整个文件，冷缓存下是全量 I/O）。`ls -ln` 解析**不采用**（GNU 与 busybox 列宽不同，规则不通用）。
- 响应带 `Content-Length`（探到时）与 `Content-Disposition: attachment`（`filename*` 走 UTF-8 + ASCII 回退，中文文件名必须正确）。

### 4. 目录列表：`find` 单次 exec 产出 **NUL 分隔**记录

- 用 `find <dir> -maxdepth 1 -mindepth 1 -exec sh -c '…' sh {} +` **一次 exec** 产出 **NUL 结尾**的记录（类型 / 大小 / mtime / 名称，字段用 TAB 分隔、解析时只按前 2 个 TAB 切）。
- 实测：换行名 / 空格名 / 中文名 / 引号 / 反斜杠 / 制表符 / `$` 与反引号 / `-` 开头 / 隐藏文件**全部保真**，15 条样本解析出 15 条记录（原始字节数 422），**缺失条目 `[]`、多余条目 `[]`**。
- **GNU 与 busybox 输出格式完全一致**，解析侧只需一套代码。
- **禁用写法**：`find -printf`（busybox 不支持）、`find -print0` + `read -d` 循环（dash 与 busybox ash 都**没有** `read -d`）、`ls -l` / `ls -A` 列解析（换行名会被劈开、列宽不通用）。

### 5. 大小**不限**，前提是端点用 raw 流式 body

- **字节层实测**：宿主进程峰值 RSS 在 200 MiB 与 1 GiB 两个量级下**几乎相同**（下载 23.2 MiB vs 23.3 MiB；上传 24.7 MiB vs 25.0 MiB），每 32 MiB 一采的曲线**全程平坦**、**不随文件大小线性增长**；`docker exec` 客户端同样平坦（采样 6.4 MiB / 峰值 27–28 MiB）。吞吐 571.0–1300.8 MiB/s。
- **字节完整性**：200 MiB 上行 sha256 `131d1542a59c587bc455b5401ac5ac9a0b3c9074ca1248303d87298adcba9179`，容器内与宿主侧一致；下行同样一致。200 MiB 上行 **629.4 MiB/s（0.32 s）**、下行 **730.7 MiB/s（0.27 s）**。
- **硬前提**：端点必须用 **raw 流式 body**（`request.stream()` 逐块消费），**不能用 FastAPI 的 JSON 模型接 body**——实测 JSON body 被**整体缓冲进内存**，200 MiB body 让控制台进程 RSS 从 **44.5 MiB 涨到 433.9 MiB**（经反代后 416.8 MiB）。**「内存有界」只在字节泵层成立，端到端成立的前提是 raw 流式读。**

### 6. 部署链约束：反代**读超时**是硬约束（Traefik）

本机部署链的实测形态（**结论不外推到其他部署**）：

| 项 | 实际 |
|---|---|
| 后端 | 直连 uvicorn，监听 `0.0.0.0:28642`（**任务书写的 8000 与本机实际不符**），service `sandbox-console.service`，`User=sankabox` |
| 反代 | **Traefik v3.7.13**（宿主 docker 容器），`sandbox-api.sankabox.com` → `http://192.168.2.135:28642`；该 service **无 `transport` 块** → **全部走默认值** |
| 默认超时 | `respondingTimeouts.readTimeout = 1m0s`（**读整个请求，含 body**）、`idleTimeout = 3m0s`；`writeTimeout` 未设 → **响应写入不设总时限** |
| body 大小 | **无任何上限**（Traefik v2/v3 无 `maxRequestBodyBytes` 类默认限制）→ **不会 413**；`maxHeaderBytes: 1048576` 只管请求头 |
| 响应缓冲 | `responseForwarding.flushInterval: 100ms` → **按 100 ms 周期刷出，不整段缓冲** |

**A/B 实测（「掐断的是反代，不是后端」）**：同一个 200 MiB 慢上传（限速 1 MiB/s ≈ 200 s）——

| 路径 | 结果 |
|---|---|
| **直连控制台**（不过反代） | **201.23 s 正常完成**（uvicorn / FastAPI 无请求超时） |
| **经线上 Traefik** | ★ **61.13 s 被掐断**（`ConnectionResetError`） |
| 隔离 Traefik（同镜像同默认配置） | ★ **61.07 s 被掐断**（`BrokenPipeError`） |

**下载方向不受此限**：200 MiB 响应经反代 **0.09 s 完整送达**（不缓冲）；慢响应（120 s、每秒 64 KiB）实测 **119.05 s 正常结束**——60 s 的 readTimeout 只管**读请求**，不砍响应。

**因此「大小不限」的口径必须写成两条**：

> **大小不限**（反代与后端都无 body 上限、不会 413），**但传输必须满足反代的读超时约束**——本机默认 `readTimeout = 60s`，单个请求的读取必须在 60 s 内完成，否则连接被重置（客户端看到 `ECONNRESET` / `BrokenPipe`）。换算成速率：60 s 内传完 ⇒ **速率 ≥ 文件大小 / 60 s**；200 MiB ⇒ 需 ≥ 3.4 MiB/s，1 GiB ⇒ 需 ≥ 17 MiB/s（本机实测 571–1300 MiB/s，局域网内毫无压力；但**慢速客户端 / 弱网 / 大文件（≥ 4 GiB）会踩线**）。

**落地要求**：**为该 service 调整 `transport.respondingTimeouts.readTimeout`**（`0` 或显式大值，如 `10m`），只改这一个 service 的转发超时，**不动后端、不动其他路由**；并要求**远程部署自查反代**（本机结论不能外推）。**此项列入 03 轮落地与 06 轮验证**。兜底：后端仍可**直连 28642** 绕过反代（已实测无 60 s 限制）。

### 7. 实测修正的设计口径（原假设 → 实测结论 → 修正）

> 这一节是本决策相对 PRD 草案的**核心增量**。PRD 草案有十条设计点被实测推翻或精化。

| # | 原假设（PRD 草案） | 实测结论 | 修正 |
|---|---|---|---|
| 1 | 「**只读目标**（不可写文件 / 不可写目录）时报错，要归类」 | 目标文件本身 `0444` + 父目录可写 ⇒ `mv` **静默覆盖成功**（root 与 uid=1000 **同**）。只有「父目录不可写」（`Permission denied`，EACCES）与「只读挂载」（`Read-only file system`，EROFS）才报错 | **「只读文件」不是错误类别**。错误类别只有三类：**父目录缺失 / 父目录不可写（EACCES）/ 只读挂载（EROFS）**。若服务端把「目标只读」当错误处理，会**把正常覆盖误判成失败** |
| 2 | 上传 = 写临时名 → `mv` 原子替换目标（隐含「目标是文件路径」） | 目标是**已存在目录**时 `mv` **rc=0 假成功**，文件被**搬进目录里** | **必须前置拦截**：探测阶段发现**目标是目录即拒绝上传**。**不要依赖 `mv -T`**（busybox 无 `-T`，实测 `mv: '/d' is a directory` rc=1） |
| 3 | 探测命令 `if [ -d ] … elif [ -f ] … else echo missing` | **FIFO / `/dev/null` / `/dev/zero` 全部落进 `else` 输出 `missing`**——「不存在」与「特殊文件」**无法区分**，达不到「管道 / 设备可区分」的目的 | 换成分层探测（见第 3 节）：`-d` 目录 / `-f` 普通文件 + `stat -c %s` 大小 / `-p` `-c` `-b` `-S` `-L` 逐级判别 / `-e` 其余 = 特殊文件 / 兜底 `missing`。**特殊文件一律拒**（FIFO 会**挂死 `cat`**，GNU 与 busybox 都挂） |
| 4 | 探测用 `wc -c` 拿字节数 | `wc -c < file` 要**读完整个文件**；`stat -c %s` 是 **O(1)**。实测 200 MiB 文件上 68.4 ms vs 67.3 ms（exec 开销占大头），但冷缓存下 `wc -c` 是全量 I/O | **首选 `stat -c %s`**，`wc -c < file` 留作兼容兜底；`wc < file`（取第 3 字段）1356.5 ms、`ls -ln` 解析 53.1 ms **均不采用** |
| 5 | 列表用 `find -print0` + `read -d` 循环逐项判类型与大小 | **`read -r -d ""` 在 dash 与 busybox ash 里都不支持**（实测 `sh: 1: read: Illegal option -d`，rc=2） | 列表改为 **`find -exec` 内直接产出 NUL 记录**（第 4 节）。另：`find -printf` 只有 GNU 支持（busybox `find: unrecognized: -printf`），**不能用** |
| 6 | 报错要归类（隐含「一类错误一句固定话」） | 同一类错误在 dash 与 busybox ash 下**措辞与退出码都不同**：父目录缺失 dash `Directory nonexistent` **rc=2** / busybox `nonexistent directory` **rc=1**；目录 GNU `Is a directory` / busybox `read error: Is a directory`；不存在 GNU `No such file or directory` / busybox `can't open '…': No such file or directory` | **只能按 stderr 关键词子串分类，不按整句、不按退出码**（退出码只当辅助信号）：`nonexistent` / `Directory nonexistent`（大小写不敏感）、`Permission denied`、`Read-only file system`、`Is a directory`、`No such file or directory` |
| 7 | （未规定）路径如何传给容器内命令 | 路径含换行时 `sh -c` 拼接**被拆碎**（`cat: /workspace/edge/a: No such file or directory` + `sh: 2: b: not found`）；**argv 直传正常** | **路径一律 argv 直传**（`docker exec … cat -- <path>`），**禁止**拼进 shell 脚本文本；`sh -c` 只用于固定脚本，路径经 `"$1"` 位置参数传入。`--` 守卫对 `-` 开头的路径有效 |
| 8 | 写入失败 → 清理临时文件（不留残骸） | exec 被杀时容器内留下半截临时文件（8 MiB `.rtf-tmp-interrupt`），`cat` **不会自清理** | **平台侧负责清理**：失败路径上再 exec 一条 `rm -f <临时名>`（**`rm` 也要 argv 直传**），或用「临时名带 PID + 定期扫」兜底。**临时名必须与目标同目录**（跨设备 `mv` = copy + unlink，非原子） |
| 9 | （未规定）符号链接的语义口径 | `test -d` / `test -f` / `wc -c <` **跟随**符号链接，而 `stat`（不带 `-L`）**不跟随**；两者混用会导致 mtime 取到**链接自身**的时间戳 | 探测组合要**显式定义符号链接语义**：本决策统一取「**跟随**」（链接按它指向的目标判类型与取大小），mtime 取 `stat -L -c %Y`（busybox 也支持 `-L`）。**注意上传的 rename 恰好相反——不跟随末端符号链接**（替换链接本身） |
| 10 | 缺 `wc` 时要有降级口径 | `sh` / `cat` / `wc` / `tar` / `find` / `stat` / `mv` / `ln` / `mkfifo` / `readlink` / `ls` / `od` / `printf` 在**平台基础镜像 `sandbox-platform/base:0.3.0` / `debian:bookworm-slim` / `alpine:latest` / `alpine/socat:1.8.1.3` 全部存在** | **无降级口径**。唯一要避开的写法是 GNU-only（`find -printf`）、shell-only（`read -d`）、busybox 不支持（`mv -T`）、列宽不通用（`ls -l` 解析）。**注意 `sh` 是 dash（基础镜像 / debian-slim）或 busybox ash（alpine / alpine-socat）**，措辞差异见第 6 条；`command -v` 在 dash 里**只接受一个参数**，存在性检查必须写循环 |

### 8. 错误分类与文案口径

上传 / 下载的错误按**容器内 stderr 的关键词子串**归类（stderr 原文**只进日志**，不回显调用方），映射为固定中文文案：

| 类别 | 触发条件 | 关键词（大小写不敏感） | 建议错误码 |
|---|---|---|---|
| 父目录缺失 | 目标父目录不存在 | `nonexistent` / `Directory nonexistent` | 400（文案：父目录不存在，请先创建） |
| 权限不足 | 父目录不可写、非 root 身份 | `Permission denied` | 400 / 403（文案：目录不可写） |
| 只读文件系统 | 目标在只读挂载点 | `Read-only file system` | 400（文案：路径所在挂载为只读） |
| 目标是目录 | 目标为已存在目录（**上传**） | —（**前置探测拦截**，不经 stderr） | 400（文案：目标是目录） |
| 目标是只读普通文件 | 目标 `0444`、父目录可写 | — | **不报错**（被静默覆盖，语义如此） |

三类失败的**报错文本都指向临时名**（dash：`cannot create /workspace/no-such-dir/.rtf-tmp-e126b54a93fa: …`），平台必须把临时名换成**用户的目标路径**再拼文案。

## 影响

- **机制风险已消除**：01 轮实测证明主通道成立、零新增依赖，四条否决路线**无需复议**——本轮没有发现能动摇它们的新证据。**01 是硬前置的门槛已通过，02 可以开工。**
- **PRD 草案被十条实测口径修正**，其中「目标为目录」「特殊文件放行」「错误按整句/退出码分类」「路径拼进 `sh -c`」四条若照原样实现会直接产生错误行为（假成功 / 挂死 / 分类错 / 路径拆碎）。
- **「大小不限」的口径被收窄成两句**：大小不限、**但受反代读超时约束**。这是本决策**唯一的部署侧硬要求**——03 轮必须落地 Traefik `sandbox-api-service` 的 `transport.respondingTimeouts.readTimeout` 调整（`0` 或显式大值），06 轮必须**经域名**（过 Traefik）验证慢速大上传不再被 60 s 掐断。**远程部署必须自查反代**——本机结论不外推。
- **端点实现方式成为硬约束**：上传端点必须 raw 流式读 body。若图省事用 JSON 模型，「内存有界」只在字节泵层成立（200 MiB body ⇒ 进程涨约 390 MiB）。
- **容器内会留残骸是已知副作用**：exec 中断后临时文件留在容器里，**平台侧负责清理**；临时名建议带 PID，便于定位与兜底扫描。
- **符号链接语义在两个方向上不一致是刻意的**：探测跟随、上传 rename 不跟随。ADR 与代码注释都要写死，避免后续实现「顺手统一」而改变行为。
- **本机端口是 28642，不是 8000**：任务书与 PRD 里的「8000」在本机不成立；后续轮次一律按实际部署核对。
- **本轮不产生宿主侧持久资源**：测试沙箱已由平台回收（容器 / 网络 / 系统用户 / 家目录 / 子 UID 段 / 元数据），隔离 Traefik 容器已删，用户既有的两个沙箱全程未被触碰。
