# 0017. 移除终端空闲回收

- 日期：2026-11-09
- 状态：已接受

## 背景

网页终端在二期落地时带了一条**空闲回收**：服务侧起一个后台巡检线程，**每 30 秒**扫一遍会话表，对同时满足三个条件的会话直接自动关闭——

1. **当前无附着**（没有任何浏览器连接连着它）；
2. **状态是运行中**（容器内的交互式 shell 还活着）；
3. **距上次附着已满 30 分钟**（按会话表里的 `last_attached_at` 算）。

回收后的会话退出原因记为 `reclaimed`；回收时长可用环境变量 `SANDBOX_TERMINAL_IDLE_TIMEOUT` 调整。这条机制在 [[architecture/decisions/0009-二期控制台服务化与范围裁剪.md|ADR 0009]] 的会话语义表里被写成一行「空闲回收：只针对运行中且无附着的会话；已退出的会话不参与回收」。

**它在线上触发过三次，每次都把用户正在用的会话收走了。** 根因是计时基准选错了：判据用的是「**上次附着**」的时刻，而**断开连接并不刷新这个时刻**。于是「关掉标签页」在语义上等于「宣告不再需要这个会话」——用户上午开着个终端跑构建、切到别的标签页干别的，一小时后回来，会话已经没了，现场不可恢复。同理，用户**刻意断开**（想去手机上接着看、想省点资源）在平台看来与「用户不再需要」无法区分。

用户的判断是：**这个功能不需要**。真实诉求是——关掉标签页之后会话与容器内进程**继续在后台活着**，重开标签页能接回**同一个 shell 现场**（这条能力本来就有：输出写环形缓冲，重连先回放缓冲再接实时流，见 [[architecture/decisions/0009-二期控制台服务化与范围裁剪.md|ADR 0009]] 的「浏览器断开」一行）。空闲回收与它直接冲突：一边要把现场留住，一边把它按时间抹掉。

## 决策

### 1. 整体移除空闲回收机制

- 服务侧**不再有任何自动关闭终端会话的路径**：后台巡检线程、「上次附着 ≥30 分钟」判据、`reclaimed` 退出原因、环境变量 `SANDBOX_TERMINAL_IDLE_TIMEOUT` **一并下线**。
- 该环境变量**不再被读取**：部署环境里若还留着它，**静默失效**（不报错、也不再有清理效果），以免留下「配了就一定在回收」的错觉。
- 代码落点：`apps/web/backend/src/sandbox_console/terminal.py`（会话管理器，巡检线程与容量判据所在）、`apps/web/backend/src/sandbox_console/sessions.py`（会话表与结束原因常量）。

### 2. 会话结束方式收敛为三类（用户可感知）+ 一类兜底

会话的结束原因由后端在退出帧里带出（`exit_reason`），前端据此给提示：

| 结束原因 | 触发场景 | 用户是否可感知 |
|---|---|---|
| `closed_by_user` | 用户在终端标签条上主动删除会话（「关闭并移除」或「移除记录」） | 是（用户自己点的） |
| `exited` | 容器内进程**自己退出或崩溃**；**沙箱删除**时容器被销毁、exec 连带死亡也走这条路径 | 是——**沙箱删除导致的「异常结束」提示属预期**，不是故障 |
| `shutdown` | 服务自身退出时的兜底收尾 | 否（服务已停，用户看不到提示） |

- 三种用户可感知的结束方式**穷尽了全部情形**：用户主动删除、会话进程自己退出、沙箱删除。**平台不再有第四种**。
- 沙箱删除导致的 exec 死亡归入 `exited`（而非另立一种原因），是为了不给前端增加一条只在校验路径上出现的分支；前端「异常结束」提示**保持现状**。

### 3. 保留不动的口径

- **服务重启仍作废全部会话**：启动时把持久化会话表内的全部记录标记为孤儿并清理（按记录的进程号终止遗留 exec 进程、并按注入标识收掉容器内残留 shell），随后删除会话表文件；**跨实例保护**（记录里的 `host_pid` 仍存活 = 另一个服务实例在用，就不动它）不变。这条与空闲回收无关，保留。
- **名额语义不变**：全局 20 个、单沙箱 5 个（`SANDBOX_TERMINAL_MAX_SESSIONS` / `SANDBOX_TERMINAL_MAX_SESSIONS_PER_SANDBOX` 仍可覆盖）；**已退出的会话照样占名额**，要腾位置必须手动移除。名额超限的报错文案改为引导**在终端标签条手动关闭会话**（原先指向的「后端保留的会话」列表早已下线，不得再指向它）。
- **`last_attached_at` 保留但仅供展示**：它不再参与任何自动判定，只作为「这个会话上次是什么时候被接上的」的记录字段。

### 4. 防回归测试

移除是「删掉一个机制」，最容易的回归是**它又悄悄长回来**。因此落三条断言：

- 服务端**不存在**回收用的后台线程（结构断言，不是「跑一会儿看有没有回收」）；
- **新建会话不触发任何清理**（新建后旧的空闲会话仍在、仍在占名额）；
- 会话状态按预期落盘为 `running`（不被误判成「无人使用」而改写）。

### 5. 文档口径同步

- 仓库内随代码一并更新的文档：`apps/web/backend/API.md` 第 12 节（终端接口与会话语义）、`apps/web/frontend/README.md`（终端会话的删除与提示口径）。
- 仓库内文档库（`docs/`）同步：[[glossary.md|词汇表]] 的「终端会话表」词条、[[prds/phase2-console.md|二期 PRD]] 与 [[tasks/phase2-console/03-web-terminal.md|二期任务 03]] 的指向性更新（历史结论不重写）、[[architecture/decisions/0009-二期控制台服务化与范围裁剪.md|ADR 0009]] 会话语义表的指向性更新。

## 影响

- **断开标签页后会话与进程在后台继续活着**，重开标签页接回**同一个 shell 现场**（环形缓冲回放照旧）——这正是用户要的行为。注意代价也在这里：会话进程不再被时间自动收走，**它会一直占着名额直到用户自己删**。
- **名额会持续积压**：移除回收后，**无附着的运行中会话**与**已退出的会话**都会一直占名额（全局 20 / 单沙箱 5，已退出也占）。占满后新建终端会报错，用户需在终端标签条手动关闭若干会话才能继续用。**这是已知后果，不是缺陷**：是否调整名额语义（已退出会话是否该让出名额）或补一个更顺手的清理引导，登记为看板待办（见 [[current-state.md|当前状态]] 的 TODO 段），**不阻断使用**。
- **`SANDBOX_TERMINAL_IDLE_TIMEOUT` 下线**：部署环境里的存量配置静默失效（不报错、也不再生效）。文案与接口文档里不得再出现该变量名，避免误导。
- **存量的 `reclaimed` 历史档案不需要专门迁移**：会话表里没有结束原因字段的旧记录按空值补齐（不炸），而这些遗留记录本身会被**下次服务启动清扫**自然清掉（启动清扫清空整张会话表）。不需要写迁移脚本，也不需要保留兼容分支。
- **沙箱删除的提示不变**：容器销毁连带 exec 死亡走 `exited`，前端仍提示「终端会话异常结束」——**这属预期**，不因本次改动改文案。
- **回归门禁**：后端 287 passed、前端 584 passed，ruff 与 tsc 干净。
