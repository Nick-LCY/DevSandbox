# 0007. 范围边界与云边形态

- 日期：2026-10-29
- 状态：已接受

## 背景

沙箱要覆盖两类外部形态：一是云服务（对象存储、单点登录等），二是「云边混合」——一部分逻辑跑在云侧、一部分跑在边缘侧，两侧通过网络通信。

这两类都存在「做全套模拟」与「只做够用的最小形态」两条路。全套模拟在早期会吞掉绝大部分工作量，而且模拟出来的行为容易让 agent 得出错误结论。

## 决策

### 1. 外部服务边界

- AWS 只覆盖 S3，由 MinIO 提供 S3 兼容能力，不引入 LocalStack 之类的本地 AWS 模拟器。
- 其余 AWS 服务本项目不模拟。

### 2. 云边混合：一期只做单容器本地回环

- 云侧与边缘侧进程跑在同一个沙箱内，通过本地网络栈互访；边缘侧经 WebSocket 连接云侧端口。
- 不做多容器网络模拟，也不模拟跨机的网络分区与公网暴露。

### 3. 弱网模拟

仅列为远期 backlog，不进入一期至三期的交付范围。

### 4. 与三期范围的关系

三期交付 URL 代理、资源配额、快照、自动清理、厚沙箱模式，以及可选的弱网模拟。其中 URL 代理的端口发布方式与厚沙箱模式都属于沙箱隔离机制的一部分，见 [[architecture/decisions/0003-每沙箱专属用户与免root守护进程.md|0003 每沙箱专属用户与免 root 守护进程]]。（该期已整体退役，方向由 [[architecture/decisions/0001-项目定位与三期路线.md|ADR 0001 修订行（2026-11-03 三期方向改定）]] 改定；以上为历史记录。）

## 影响

- 不做全面 AWS 模拟，示例项目与测试用例不得依赖未实现的 AWS 服务；需要这类能力时只能连真实服务，或自行在沙箱内起替代容器。
- 单容器本地回环无法覆盖真实云边部署的网络分区、跨机延迟与公网暴露差异，测试结论不能外推到生产拓扑；这一点必须写进示例项目文档，避免误用。
- 弱网模拟推后，agent 在弱网下的表现只能靠人工构造环境观察，不构成自动化保障。
- 范围收窄换来三期可交付性：代理、配额、快照、清理都能落在真实存在的本地回环形态上，而不是停在模拟层。（原三期已整体退役，见 [[architecture/decisions/0001-项目定位与三期路线.md|ADR 0001 修订行（2026-11-03 三期方向改定）]]。）
