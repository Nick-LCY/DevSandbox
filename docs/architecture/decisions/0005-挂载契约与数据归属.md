# 0005. 挂载契约与数据归属

- 日期：2026-10-29
- 修订：2026-10-29（挂载契约修订：套接字为唯一固定挂载，其余挂载全部由用户声明）
- 状态：已接受

## 背景

agent 需要在沙箱里持久化三类东西：改过的代码、pi 会话、模型 API key 与 pi 配置。三者的安全诉求不同——会话要跨沙箱删除后仍在（做到这点的前提是它落在宿主机上）、密钥绝不能进镜像层、代码则可能由用户自行决定留在哪里。

分歧点在于：这些目录该不该由平台决定位置、该不该由平台负责清理。平台如果替用户选好路径并代为回收，就等于对用户数据行使处置权；平台如果什么都不管，用户又容易踩到「数据到底在哪儿、删沙箱会不会丢」的坑。

结论是：**平台只对套接字这一项负责，其余挂载一律由用户声明，平台原样执行、不解释、不处置。**

## 决策

### 1. 唯一固定挂载是 Docker 套接字

| 挂载 | 读写 | 挂载点 | 说明 |
|---|---|---|---|
| Docker 套接字 | 读写 | `/var/run/docker.sock`（容器内默认路径） | 控制面在创建时自动挂入，docker 客户端默认可见，用户无需声明 |

套接字是平台自身的运行前提，因此由平台固定挂载。它同时意味着 agent 能看到并可能删掉自己的沙箱容器，这一条在 [[architecture/decisions/0003-每沙箱专属用户与免root守护进程.md|0003 每沙箱专属用户与免 root 守护进程]] 中作为明确接受的代价处理。

### 2. 其余挂载完全由用户声明

- 用户在创建沙箱时用 `--mount 宿主路径:容器路径[:ro]` 声明挂载，可声明多次。
- 平台原样执行：解析参数 → 转成容器挂载参数 → 交给守护进程启动容器。平台不解释用途，不追问路径用途，也不校验内容。
- 平台不再有任何默认挂载：创建时不声明挂载，就只有套接字一个。平台不预置、不创建任何宿主目录作为挂载目标。
- 挂载点是否只读由用户决定；平台不替用户加或减只读标记。

### 3. 平台不处置用户挂载的宿主机目录

- 删除沙箱时，平台只回收自己创建的资源：沙箱容器、依赖容器、守护进程、专属用户及其家目录、子 UID/GID 段、平台元数据。
- 用户声明挂载的宿主机目录，平台一律不创建、不删除、不修改——连空目录预建都不做。
- **原「工作区随沙箱回收、会话目录在删除后保留」的二分法废弃。** 它要求平台对用户自选路径行使处置权，而平台既没有权限也没有信息去判断某个目录该不该删；同一个目录对不同用户可能既是代码又是缓存，替用户猜错的代价高于不猜。

### 4. 数据生命周期由用户自担

- 未提交的改动会不会丢，取决于用户把代码目录挂在哪里：挂在容器层（如 `/workspace`）就随容器消失，挂在宿主机目录就原样保留。平台不替用户兜底，也不再输出特定字样的警告。
- 控制面不做任何 git 操作：克隆、提交、推回由用户或 agent 自主决定，提交责任在用户与 agent。
- 平台的职责边界是「执行挂载声明」，不是「管理数据」。

### 5. 典型挂载模式（文档指引，不是平台契约）

以下写法写进用户指引与起步 README，属于推荐用法，平台不强制、不校验：

| 场景 | 推荐做法 | 要点 |
|---|---|---|
| 会话持久化 | 把 pi 会话目录挂到容器内 pi 的会话路径 | 路径由用户决定，删除沙箱后平台不处置该目录 |
| 凭证注入 | 把模型 API key 与 pi 配置以只读方式挂进容器 | 不进镜像层，密钥轮换只改宿主机文件 |
| 代码目录 | 把自选宿主机路径挂到容器内工作路径 | git 提交由用户或 agent 主动执行，平台不代劳 |

## 影响

- 数据生命周期完全由用户自担。平台不再替用户判断「什么该留、什么该删」，这是有意的取舍：平台越小，越不会误删用户数据。
- git 提交责任明确落在用户与 agent 身上。用户指引必须写清「代码目录在哪里、怎么提交」，否则用户会误以为平台已自动保存或已推送。
- 删除沙箱的提示必须改成输出回收清单，并注明用户挂载的宿主机目录不受影响；原来的「未提交改动会丢失」字样作废，因为它描述的是平台已回收工作区时的行为，在新契约下没有对应事实。
- 平台变薄：控制面不再需要建目录、不再需要清理目录，删除流程少一类失败点。
- 代价是用户必须自己知道怎么挂：会话与凭证这类隐性需求如果没有文档示例，用户会遇到「会话断线即丢」「agent 拿不到密钥」的问题，因此典型挂载模式必须以 README 级别的形式交付。
- 平台无法校验用户挂载的路径是否合适：挂错路径、挂成只读导致写失败、挂了容器层目录导致数据不持久，都由用户在使用中自行发现。
