# 0013. 三期定位改定与认证重启

- 日期：2026-11-03
- 修订：2026-11-03（WS 握手的 Origin 放行清单新增「同源放行」——见第 4 节末尾的修订说明；本决策其余条款不变）
- 状态：已接受
- 修订说明：本决策**修订** [[architecture/decisions/0001-项目定位与三期路线.md|ADR 0001]] 的三期行，并**推翻** [[architecture/decisions/0009-二期控制台服务化与范围裁剪.md|ADR 0009]] 第 1 节「不做认证」的裁剪；ADR 0009 的其余结论（命令行不改、启动镜像走宿主本地注入、终端自研伪终端桥接）不受影响。

## 背景

三条规划方向里，「前后端分离部署」与「桌面端打包（Tauri）」的内容高度重叠，且互相矛盾：

- 前后端分离部署的形态是：后端独立成 API 服务器并引入 token 认证，前端构建成静态站部署到 Cloudflare，凭「后端地址 + token」远程连接。
- 桌面端打包的形态是：前端装进桌面壳。桌面壳**自带前端**，静态站托管这件事对它没有意义。

两者都要「后端独立 + token 认证」，所以真正的问题不是「做哪个」，而是「三期到底是什么」。

同时有一个被二期明确裁剪掉的东西需要重新捡回来。ADR 0009 写得很清楚：平台面向内部部署、个人使用，**控制台与接口不做任何认证**，安全边界改为「服务只绑回环或内网地址、不得暴露公网」，并诚实记下「无认证意味着内网暴露即完全信任……这是本决策最大的风险敞口，已知并接受」。

这条裁剪在二期是成立的：控制台与后端同机同源，浏览器就在服务旁边，网络边界够用。但桌面端把后端搬到了「别的机器」上——**跨机访问必须让后端绑非回环地址**，于是网络边界这条唯一防线当场失效，后端以宿主特权身份运行、接口能创建 / 删除沙箱 / 拉起容器，暴露面直接等于宿主 root 能力。桌面端要连远程后端，就必须有第二层拦截。

三期范围此前也已经走过一轮改动：ADR 0001 的修订行把三期从「URL 代理与多沙箱运营」改指为「桌面端打包（Tauri）与端口转发」，并把 URL 代理、快照、配额、自动清理、厚沙箱、弱网模拟整体退役。Cloudflare 静态托管此前只是「前后端分离部署」这条规划里的一个组成部分，并没有单独的退役决策——它需要在本决策里被显式标注吸收或退役，否则规划看板会一直挂着一条做不了的事。

## 决策

### 1. 三期 = 桌面端打包（Tauri）+ 端口转发

三期的范围由三块构成，缺一不可：

1. **桌面端打包**：前端装进 Tauri v2 应用，目标平台 Windows（WebView2）。
2. **连接层改造**：后端独立成 API + token 认证（吸收原「前后端分离部署」的后端侧内容）。
3. **端口转发**：用户显式指定沙箱与端口，桌面端在自己机器的回环上访问该端口。

原「前后端分离部署」**不再单独立项**，其内容按下列口径并入三期：

| 原规划内容 | 本期处置 |
|---|---|
| 后端独立 API + token 认证 | **吸收**：并入三期的连接层改造，是桌面端连远程后端的前提 |
| 前端静态站托管到 Cloudflare | **退役**：桌面壳自带前端，静态托管不再需要；不做任何 Cloudflare 相关部署 |
| 「后端地址 + token」的远程连接 | **吸收**：即桌面端的连接配置（地址 + token），且 web 形态复用同一套配置抽象 |

### 2. 桌面壳是纯连接器

桌面应用**只装两样东西**：前端产物 + 连接配置（后端地址 + token）。

- 应用**不负责拉起后端服务**，不托管后端进程、不探测后端进程、不管理后端生命周期。
- 应用**支持连远程后端**：后端地址是配置项，不是硬编码。
- 端口转发的「后端侧」由后端服务自己承担（见 [[architecture/decisions/0014-端口转发机制选型.md|ADR 0014]]），桌面端只承担本机监听与隧道桥接。

### 3. token 认证本期落地（推翻 ADR 0009 第 1 节）

- 后端**所有 `/api`**（含终端 WebSocket）受 token 保护。`/api/health` **不豁免**。
- 令牌是**单一访问凭据**：本期不做账号体系、不做多用户隔离、不做令牌分级与吊销。拿到令牌即拿到平台的全部能力。
- 令牌来源与安全要求：
  - 环境变量 `SANDBOX_CONSOLE_TOKEN` 注入优先；
  - 未注入时服务启动自动生成，落 `<平台数据根>/console-token.json`（权限 `0600`）；
  - **服务不会在没有令牌的状态下对外提供接口**；
  - 日志只打令牌文件路径，**不打印令牌本体**；令牌比较用常量时间。
- **ADR 0009 第 1 节的裁剪就此推翻**：原句「控制台与接口不做任何认证」「安全边界改为服务只绑回环或内网」「若平台要从个人自用变成多用户访问，认证必须重新成为硬需求」作废。新的边界是：**token 是硬需求，网络边界降级为第二层**。
- **连带修订**：绑非回环地址不再等于「完全信任」。启动告警口径改为「已启用令牌认证」；`/docs` 仍然默认关闭（接口清单不外泄）。

### 4. WebSocket 鉴权通道

浏览器 `WebSocket` API 不能设自定义头，因此 WS 鉴权与 HTTP 分两条通道：

- **HTTP**：`Authorization: Bearer <token>`。
- **浏览器发起的 WebSocket（终端）**：先用 Bearer 换一张**一次性票据**（`POST /api/auth/ticket`，30 秒过期、用过即废），再以 `?ticket=` 带上。**不把长期令牌放进 URL**（会进访问日志与中间代理日志）。
- **桌面 Rust 发的 WebSocket（端口转发隧道）**：Rust 客户端可以设请求头，直接走 `Authorization: Bearer`，不需要票据。

> 2026-11-03 修订（WS 握手的 Origin 放行清单新增「同源放行」）：本节隐含的「WS 的 Origin 放行清单 = 桌面 WebView 来源 + 本地开发来源」这一口径，在实现轮（[[tasks/phase3-desktop/02-backend-token-and-cors.md|三期任务 02]]）修订为**三类**：① **同源放行**——浏览器 Origin 与本次请求同源即放行；② 桌面 WebView 来源（`http://tauri.localhost`）；③ 本地开发来源（`http://localhost:5173`、`http://127.0.0.1:5173`）。**理由**：同源形态是二期沿用至今的既有网页使用形态，03（前端连接层改造）落地前必须保持可用——不放行同源等于把网页终端全线断掉。**同源判定的口径**：scheme 也要比（`http` 的 Origin 与 `https` 的连接不算同源），默认端口按 **Origin 的 scheme** 取（`https` → 443、`http` → 80）。**边界声明**：**Origin 校验不是安全边界**——同源判定基于 `Host` 头，Host 头可被伪造；真正的准入边界是**令牌与票据**（WS 握手必须带一次性票据，中间件对 WebSocket scope 默认拒绝、fail-closed）。因此放行同源不放松准入，只是不误伤既有形态。CORS 的放行清单**不含**同源（同源请求本就不走 CORS 预检），本修订只作用于 WS 握手判定。

### 5. 跨期约束的落实

- **控制面新能力可复用**：端口转发的编排能力落核心包（`sandbox_platform`），服务端只是薄壳。
- **镜像即产品**：桌面端不要求用户改任何镜像；转发容器是平台自建的独立容器，走平台自己的镜像。

### 6. Cloudflare 静态托管的退役

- 原「前后端分离部署」里的 Cloudflare 静态站托管**正式退役**，不再规划、不再留待办。
- 退役不是延期：将来若重提静态托管，按新需求独立立项。

## 影响

- **二期「不做认证」这条裁剪被推翻，是本期最大的一处口径反转**。ADR 0009 当时写下的风险敞口（「内网暴露即完全信任」）正是本期要补的洞。代价是后端多了一套凭据管理：令牌要发到桌面端、要在前端存、要能被轮换。轮换本期只做「删令牌文件 + 重启服务」，UI 轮换留作后续（见开放问题 Q1）。
- **认证不解决多用户问题，只解决「暴露即完全信任」**。令牌是单凭据：共享给第二个人等于共享整个平台。本期明确不做账号体系，这一点写进 PRD 非目标，不留模糊地带。
- **`/api/health` 不豁免带来两个后果**：① 前端能区分「后端不可达」与「令牌无效」，这是实打实的体验收益；② 外部监控 / 负载均衡探活必须带令牌或改用 socket 层探活。
- **CORS 与 WS Origin 校验成为新的必守约束**：后端一旦允许非回环来源，浏览器侧的跨源与 WS 握手就是新的攻击面。放行清单必须收窄到「桌面 WebView 来源 + 本地开发来源」（WS 握手另加「同源放行」，见第 4 节 2026-11-03 修订说明），任何通配符都不放。**Origin 校验不是安全边界**——真正的准入边界是令牌与票据。
- **「前后端分离部署」这条规划作废**，规划看板要改，否则会一直有人按它开工。Cloudflare 静态托管随之退役。
- **桌面壳定位为纯连接器**，省掉了「桌面端顺便把后端也拉起来」这类设计（进程管理、端口冲突、后端升级）的全部复杂度，代价是使用者要自己保证后端在跑——这与平台「个人自用」的定位一致。
- **跨机访问成为常态**，原先「服务只绑回环」的运维纪律要改成「服务可绑内网，但令牌必须配好」。既有参考部署 `apps/web/backend/sandbox-console.service` 的注释要同步改写。
