# 网页控制台前端约定

适用范围：`apps/web/frontend/`。本文只写「改了会被别人踩」的稳定约定；实现细节看 `apps/web/frontend/README.md`。

## 技术栈与依赖

- 样式底座：Tailwind CSS v4（`@tailwindcss/vite`）+ shadcn/ui（base-nova 预设），组件层落在 `src/components/ui/`。
- 交互原语：**只用 Base UI（`@base-ui/react`），不得引入 Radix**（任何 `@radix-ui/*` 包都不加）。shadcn 的 `data-*` 变体与 accordion 关键帧已内联进 `src/styles/globals.css`，不靠 devDependencies 里的 shadcn 样式文件。
- 图标：**只用 lucide-react**，不引第二套图标库。
- 新增交互原语时，先在 `src/components/workbench/ModalShell.tsx`（确认类弹窗）或 `src/components/workbench/DrawerShell.tsx`（大面板抽屉）这类统一外壳上扩展，不要在页面里各自造弹窗或抽屉。

## 设计令牌

- 颜色一律走令牌：底层写 `--app-*`（`src/styles/globals.css` 的 `:root` 与 `.dark`），主题层映射成 Tailwind 的 `--color-*`，组件里用 `bg-primary`、`text-status-running` 这类工具类。
- **组件里不得写裸色值**（十六进制、`rgb()`、`oklch()` 字面量一律禁止）。确需新色时先进令牌再引用。
- 新增令牌必须同时写 `:root` 与 `.dark` 两处（暗色逐项映射），并在 `@theme` 里补 `--color-*` 映射，否则暗色下会退回浏览器默认色。
- 透明度通道：所有颜色令牌的 alpha 槽位统一写 `oklch(L C H / var(--app-alpha))`，要整体调透明度只改 `--app-alpha` 一个值。
- 豁免清单（用字面 alpha、不跟通道缩放）：`--app-ring`（聚焦环）、`--app-shadow-sm` / `--app-shadow-md` / `--app-shadow-lg`（三层阴影需要各自不同的 alpha）、`--app-border` / `--app-border-strong` / `--app-input` / `--app-sidebar-border`（暗色下的白系边框与输入底需要固定低 alpha，挂了通道会变成纯白实线）。
- 状态色只有四个语义，不另造：运行 = 品牌绿、启动中 / 停止中 = 琥珀（脉动用 `animate-status-pulse`）、已停止 = 灰、失败 = 红。（**唯一的例外在「端口转发」小节**：本机状态点的「未开启」按产品口径映射为红，四态令牌语义本身未动，映射只发生在圆点层。）
- 侧栏两套主题下都是深常青绿；**终端区域恒定局部深色**（`--app-terminal-bg` / `--app-terminal-fg` / `--app-terminal-accent`），亮暗切换不影响终端可读性。

## 双主题

- 默认亮色，**不跟随系统**：只认用户明确选过的值，读取失败或值非法一律回落亮色。
- 存储键 `sandbox-console-theme`，读写统一走 `src/lib/theme.ts` 的 `useTheme()`；挂载时不写存储。
- 暗色由 `<html class="dark">` 表达（`@custom-variant dark`）；`index.html` 的首帧防闪烁脚本必须用同一套存储键。
- 会渗漏到外壳外的规则（选中态 `::selection`、`color-scheme`）一律收在 `[data-console-shell]` 作用域内；**外壳根元素必须携带 `data-console-shell` 属性**，否则这两条规则不命中。

## 字体

- 字体自托管：Noto Sans SC 400/500/600/700 与 Geist Mono 400/500 的子集化 woff2 已入库 `public/fonts/`，构建不依赖外网；文件缺失时浏览器自动回退系统字体栈。
- **新增中文文案后必须重跑 `bash apps/web/frontend/scripts/build-fonts.sh`**：字符集是从控制台前端、控制台测试、后端沙箱平台（核心包与服务端包两处，共四处源码）抽取，再补 ASCII 可打印区、界面常用符号与**常用汉字表**（`scripts/fonts/common-hanzi.txt`，通用规范汉字表一级字表 3500 字），不重跑就会出现新字缺字形（显示为方框）。
- **常用汉字表文件缺失时脚本报错退出**，不静默跳过：静默跳过会产出缺字形的子集，表现为界面上的方框。
- 脚本失败时（任一字重拿不到）会丢弃暂存产物、保留原 `public/fonts/`，不留半成品；此时先排查网络，不要手工往 `public/fonts/` 里塞文件。

## 组件与路由

- **弹窗与抽屉各一套实现**：确认类弹窗（删除沙箱 / 停止沙箱 / 关闭终端会话 / 保存为模板 / 删除模板）走 `src/components/workbench/ModalShell.tsx`，底层是 Base UI Dialog（焦点陷阱、Esc 关闭、点遮罩关闭、焦点归位）；三个大面板（新建沙箱 / 沙箱详情 / 设置）走 `src/components/workbench/DrawerShell.tsx`，底层是 Base UI Drawer（右侧滑出、宽度可拖拽）。
- 路由只有两层：`#/` 与 `#/sandboxes/<沙箱名>[/<终端会话标识>]`。**抽屉与弹窗都不入路由**（新建沙箱、沙箱详情、设置等开关状态不入 URL）。
- 地址里的百分号解码失败一律退回工作台，不抛异常打断渲染。
- 前端只做编排与展示：错误消息直接展示后端 `{"detail": "中文消息"}` 里的 `detail`，**不另造说法**。
- **操作结果反馈一律走右上角 toast**（`src/components/Toast.tsx`，底座是 Base UI 的 Toast 原语）：成功绿 / 失败红 / 提示蓝，5 秒自然消失，关闭键带与消失同步的倒计时圆环。页面里**不再挂内嵌的结果横幅**；**七处豁免**：本地表单校验红字（留在抽屉内就地展示）、删除确认弹窗里的**安全提示块**（`page-sandbox-detail-delete-untouched-note`，「用户挂载的宿主机目录不受影响」）、新建沙箱抽屉里镜像列表读取失败的**就地环境状态说明**（`page-sandbox-create-image-status`，`role="status"`；它是环境状态不是操作结果，但 toast 5 秒就消失，只留 toast 会让空的选择器没有解释）、新建沙箱抽屉里模板列表读取失败的**就地环境状态说明**（`page-sandbox-create-template-status`，`role="status"`；与镜像列表同一口径）、设置抽屉里模板列表读取失败的**就地环境状态说明**（`page-settings-template-status`，`role="status"`；管理区在设置抽屉里，同样要就地解释空列表）、**端口转发行内失败原因**（`page-forward-item-error`，`role="alert"`；toast 5 秒即逝，失败原因需留场直至用户下一步操作）、**文件面板的目录读取失败**（`page-file-browser-error`，`role="alert"`；列表读不出来时面板会空着，需就地解释）。
- **文件面板的反馈口径**：上传 / 下载等**操作结果**走右上角 toast，来源标识固定 `file-browser`（失败时是后端 `detail` 原文）；**目录读取失败是面板状态**（`page-file-browser-error`，`role="alert"`，就地显示、**不弹 toast**）。
- 后台轮询失败**逐次不弹**，**连续 3 次失败弹一条**（任一次成功即清零）：后端整体不可达时侧栏底部的健康自检已经常驻提示，但端点级失败（接口 500）它兜不住。用户主动触发的操作失败立刻弹。
- toast 的倒计时**只有窗口失焦会暂停**：失焦时倒计时停表、圆环停画；回前台时整条**重走 5 秒**（圆环重画 + 计时器重走），不是接着上次剩的时间继续。页面上悬停、点提示区、聚焦提示区、按下提示条都不暂停——Base UI 默认会暂停，必须逐条拦掉。Base UI 还会在 `window` 上接管 F6（把提示区聚焦并按停倒计时），同样要拦掉。倒计时由 `ToastProvider` 层的自有计时器统一管（Base UI 的自动关闭置 0），保证圆环画满与 toast 消失共用同一份时间。
- toast 条目带 `data-toast-kind`（类型）与可选的 `data-toast-source`（来源）：同一页面上可能先后出现多条失败提示，验收脚本靠来源把本用例关心的那条与前一步残留的无关那条区分开。
- **剪贴板成功路径零反馈是 toast 规范的一处明示例外**：终端剪贴板操作成功时不弹任何提示，失败才弹；失败提示的来源标识固定 `terminal-clipboard`（详见「终端键盘与剪贴板」）。
- **按钮加载态统一用旋转图标**：进行中的按钮保留文字、去掉省略号，文字前放一个旋转图标（lucide `Loader2`，`size-3.5` + `animate-spin`，`aria-hidden`）；不是按钮的加载文案（段落里的「正在读取…」）保持省略号不变。
- **可搜索选择器统一走 Base UI Combobox 原语封装**（`src/components/ui/combobox.tsx`）：**不得手搓 Popover + 自建列表**，也**不得引入其他组件库**。选中值语义、键盘导航（↑↓ / Enter）、列表的 ARIA 语义与本地筛选都由原语接管；页面只传候选集（`items`）、取值文案（`itemToStringLabel`）、相等比较（`isItemEqualToValue`）与筛选规则（`filter`），不自己维护命中列表。原生 `<select>` 不再用于候选多的场景（新建沙箱的镜像选择器已改）。
- **可搜索选择器的展开箭头贴在输入框内部**：绝对定位在输入框右侧、垂直居中，是**纯指示器**（`pointer-events-none`、对辅助技术隐藏、不进 Tab 序列），点击穿透到输入框、开合仍由输入框触发（原语默认点输入框即展开）；弹层展开时输入组带 `data-popup-open`，箭头据此旋转 180°（带过渡）。**候选项逐项给指针光标**（`cursor-pointer`，写在组件层）；**候选为空时列表去掉内边距**（`data-[empty]:p-0`），弹层高度贴合内容，底部不留空白带。
- 纯数据转换逻辑（路由解析、挂载声明、环境变量、格式化、终端帧协议、终端状态提示口径与去重、终端选中会话解析、终端焦点回填门控、终端尺寸自适应去抖、代理文案、主题存取、侧栏折叠存取、抽屉宽度的存取与换算、会话定序、轮询失败计数）收敛在 `src/lib/`，并有单元测试。
- **交互组件的 pointer 光标由 `src/styles/globals.css` 的 base 层统一兜底**（Tailwind v4 的 preflight 把 button 等元素的默认光标改成了 `default`，v3 时代是 `pointer`）：新增交互原语不必逐个补 `cursor-pointer`；要别的光标语义就用工具类覆盖（工具类层级高于 base）。**兜底清单里的 `[role=option]` 会被组件层的工具类盖住**：可搜索选择器的候选项渲染成 `role="option"` 的 div，组件层自己写了 `cursor-pointer`（工具类层级更高，与 base 层那条不冲突，只是它不决定最终光标）。

## 界面文案与操作语义

- **界面不写副标题、不写解释说明性文字**：面板 / 抽屉 / 区块的标题就是标题，**不加副标题、不加「这一段是干什么的」说明段**。功能由文档解释，界面不重复解释（既有「界面不重复解释模板」是这条的一个具体实例，现升格为**通用口径**，新增面板一律适用）。
- **操作即本体**：可交互元素本身承担操作语义——**点击文件行即下载**，不再另加下载按钮，也不在行内补「点击下载」这类说明文字；确实需要的额外操作走**独立的图标按钮**并带 `aria-label` / tooltip，不与行本身的点击语义重复。

## 抽屉外壳

- **三件套**：统一外壳 `src/components/workbench/DrawerShell.tsx` + 原语封装 `src/components/ui/drawer.tsx` + 宽度存取 `src/lib/drawer-width.ts`。原语是 `@base-ui/react` 自带的 Drawer（**零新增依赖**），页面里不自己拼 Drawer。
- **宽度三抽屉共用**：存储键 `sandbox-console-drawer-width`，存的是视口宽度的百分比，默认 40、钳位区间 [20, 80]；新建沙箱 / 沙箱详情 / 设置共用同一份，拖动任意一个其余跟着变，刷新后保持。读写包 try/catch，读不到或值非法一律回落默认宽度。
- **拖拽松手才落盘**：拖动中只更新外壳本地状态（每帧最多更新一次，避免每像素重渲染整个工作台），**松手才**把最终值上抛并写存储；指针捕获意外丢失也按松手收口，防止宽度悬着不落盘。把手上按左右方向键每次调 2 个百分点，`Home` 回默认宽度。
- **窄屏边界**：视口 < 640px 时抽屉占满整屏（宽度百分比不生效），**拖拽把手不提供入口**——可见但拖不动的把手会把脏宽度写进存储，窄屏干脆不给入口。
- **关闭四路锁**：抽屉禁用关闭时，Esc / 点遮罩 / 点右上角 × / 横向滑动关闭四条途径全部不响应（不可逆操作在途不能半途退出），口径与确认类弹窗一致。
- **滑动双保险**：Base UI 的横向滑动关闭没有开关，只能挡——把手挂 `data-base-ui-swipe-ignore="x"`、正文容器挂 `data-base-ui-swipe-ignore`，表单里拖选文本不会被滑动关闭吃掉。
- **传送 body 后配色不丢**：抽屉传送到 `body` 会脱离 `[data-console-shell]` 作用域，因此面板自己挂 `data-console-shell=""`，选中态与 `color-scheme` 规则照样命中。
- **设置抽屉没有全局页脚**：只管代理的「刷新状态」「重启代理」两个按钮放在**第一区代理设置里**（状态字段区之后、右对齐），不放抽屉页脚；两个按钮的标识与行为不变。页脚只放跟整张抽屉相关的动作（新建沙箱抽屉的页脚放「保存为模板」与「创建沙箱」，保存按钮在主按钮左侧）。

## 确认类弹窗

- **删除沙箱一步确认**：点「删除」直接开弹窗，点「确认删除」即发删除请求；不再有武装窗与倒计时，删除前不预取回收清单（回收清单接口保留给脚本与将来的清单预览，页面不再调用）。弹窗只说两件事：删了会怎样（不可撤销）、哪些东西不受影响（安全提示块 `page-sandbox-detail-delete-untouched-note`，留在弹窗原位不走 toast）。
- **停止沙箱也要确认**：工作区头部的「停止」按钮只开弹窗，不直接发请求；「同时停止依赖容器」勾选框在弹窗里，**默认勾选**（与命令行默认一致），每次打开都重置为默认勾选（上一次取消时的状态不粘到下一次）。
- **停止失败不关弹窗**：请求失败弹一条失败 toast，弹窗留在原地可以直接重试；只有成功才关。
- **关闭会话弹窗**删掉会话标识行，面板宽度 360px；弹窗外壳默认宽度 440px，确认类弹窗按内容再收窄（删除 400px、停止 400px）。
- **不可逆操作在途时锁死关闭**：删除、停止的请求在途时 Esc / 点遮罩 / × 都不响应。

## 终端键盘与剪贴板

- **终端聚焦时全量拦截键盘快捷键**：带 Ctrl / Meta / Alt 的组合一律拦下浏览器行为，但仍编码后转发给容器内的 shell——`Ctrl+C` 必须能到伪终端（发往容器的 SIGINT），`Ctrl+V` 仍然是字面量 0x16。
- **浏览器真保留键交回浏览器**：`Ctrl+N` / `Ctrl+T` / `Ctrl+W` / `Ctrl+Q` / `Ctrl+Tab` / `Ctrl+P` / `Ctrl+S`（带 Shift 的变体同样是保留键）、`F5` / `F11` / `F12`、`Alt+F4` 一律不拦、不转发。**`Ctrl+W` 仍是保留键**（关标签页）——「全屏 + `navigator.keyboard.lock` 接管浏览器保留键」的方案已评估、本轮未做，不得按「已支持」写文档或写代码。
- **剪贴板快捷键**：`Ctrl+Shift+C` 把终端选区复制到系统剪贴板，`Ctrl+Shift+V` 把系统剪贴板的内容粘贴进终端；macOS 的 `Cmd+Shift+C` / `Cmd+Shift+V` 同样触发。
- **粘贴必须走 `term.paste`**：不能直接往 socket 塞字节，否则绕过终端自身的输入处理，括号粘贴模式与换行归一失效。
- **成功零反馈、失败弹失败 toast**：复制成功不弹任何提示；失败弹失败 toast，来源标识固定 `terminal-clipboard`，文案「复制到系统剪贴板失败」/「读取系统剪贴板失败」。没有选区时按 `Ctrl+Shift+C` 静默不做任何事。
- **剪贴板 API 需要安全上下文**：`navigator.clipboard` 只在安全上下文可用（`127.0.0.1` 或后续反代 TLS）；非安全上下文下接口不存在，走失败路径弹提示，不做降级。
- **首用读取可能弹一次浏览器授权**：`readText` 首次调用时浏览器可能弹权限确认，属预期行为，不是失败，不要为此加绕行逻辑。
- **快捷键分类是语义锁**：分类规则收敛在纯函数 `src/lib/terminal-shortcuts.ts`（`classifyTerminalShortcut`），单元测试逐条钉死——`Ctrl+C` 仍是 SIGINT、`Ctrl+V` 仍是 0x16、保留键仍放行、只有 `Ctrl+Shift+C` / `Ctrl+Shift+V` 走剪贴板。改这段分类必须同步改测试。

## 终端全屏与焦点回填

- **终端全屏是纯 CSS 覆盖**：`src/components/TerminalPanel.tsx` 的面板切到 `fixed inset-0 z-40` 盖住整页，**不得改用 `requestFullscreen`**（那是浏览器全屏态，退出得靠 Esc / F11，与「再点按钮退出」的口径不合），**也不得用 `navigator.keyboard.lock` 接管浏览器保留键**（上一条里的禁令继续有效；CSS 覆盖与它不冲突，两者根本不在一层）。
- **全屏层必须低于浮层**：全屏层 `z-40`，弹窗与抽屉是 `z-50`，toast 是 `z-[100]`——关会话确认弹窗、设置抽屉、右上角提示永远浮在全屏面板之上，且真能点到（验收脚本要断这一点）。
- **全屏状态不入路由、不入存储**：只活在本地面板状态里，刷新页面回到常规布局；换沙箱时自动退出全屏（全屏是「当前沙箱终端」的局部状态）。
- **退出全屏 = 再点同一个按钮**：不绑 Esc、不绑 F11（Esc 归容器 shell 管）。
- **全屏按钮的 ARIA 语义是「动作名随状态变化的普通按钮」**：可访问名与 `title` 在「全屏终端 / 退出全屏」之间切换，**不带 `aria-pressed`**；侧栏折叠按钮同理，**不带 `aria-expanded`**（两者都是两个动作，不是开关）。
- **焦点回填只在两种情况下发生**：① 用户刚点了标签 / 点了终端表面 / 新建了会话（明确的操作意图）；② 判定当下焦点就在终端表面内（重挂载把焦点弄丢了，要恢复）。**焦点在别处（抽屉输入框等）一律不回填**——绝不抢别处的焦点。
- **焦点位置判定要活读 `document.activeElement`**（口径在 `src/lib/terminal-focus.ts`）：终端重挂载会把 xterm 的 helper textarea 从 DOM 摘掉，浏览器把焦点复位到 `body` 且**不派发 `focusin`**；只靠事件跟踪记下来的标志会永远停在 true，门控退化成「什么场合都往终端里塞焦点」。
- **一个终端实例只回填一次**：回填的开关取挂载时刻的快照，重试连接（重建 WebSocket）不把挂载时刻的值再拿出来用一次。

## 侧栏折叠

- **折叠只切样式、不卸载 DOM**：侧栏（`src/components/workbench/Sidebar.tsx`）折叠时一律用 `hidden` / `sr-only` 收起，**「新建沙箱」按钮必须始终挂载**——**页面上恒有两个 `page-sandbox-list-create-button`**（侧栏顶部 + 右侧空态引导块），验收脚本取第一个即可。
- **底部工具区永远贴底**：底部工具区（健康状态点 / 设置 / 主题切换 / 折叠按钮）的容器带 `mt-auto`，**不依赖列表（`nav`）撑高**——列表折叠收起后若没有这条约束，底部工具会一起浮到顶部去。
- **折叠状态存 localStorage，默认展开**：存储键 `sandbox-console-sidebar-collapsed`，存 `'1'`（折叠）/ `'0'`（展开）；非法值与读取失败一律回落**展开**。读写统一走 `src/lib/sidebar-collapsed.ts`（口径与 `src/lib/theme.ts` 同款）。
- **挂载时不写存储**：只有用户主动点折叠按钮才落盘；刷新页面读到什么就是什么。
- **健康状态的可访问名不能丢**：折叠态健康文字用 `sr-only` 收起来（视觉隐藏，**仍在可访问树里**），容器同时带 `aria-label="后端健康：<健康文案>"`，两者都跟随健康状态变化。

## 启动模板

- **模板数据存服务端**：模板库落平台数据根的模板目录（一个模板一个 JSON 文件，原子替换写入 + 0600 权限），前端只通过四条接口读写（列表 / 创建 / 重命名 / 删除），**不在前端或 localStorage 里存模板**。模板标识由服务端生成、与名称解耦，重命名不动标识。
- **合并语义口径**：「**出现的字段整体替换、缺失的字段保持现状**」——模板里出现的字段整组替换表单对应值（挂载列表、环境变量都是整组替换，不是逐条并入），没出现的字段保留表单现状。判「是否出现」用**键是否存在**，不能用「值是否为空」：填了空值与没填过是两回事。保存为模板时只写有值的字段（空挂载行不入库），否则「出现即替换」会变成「清空用户填的东西」。
- **`files` 字段口径与挂载同款**：文件注入列表也是**整组替换**——模板里出现 `files` 就整体替换表单的文件注入行，没出现就保持表单现状（判「是否出现」同样用键存在性，不用值是否为空）；模板里的文件注入声明原样解析，宿主路径与容器路径里的字面量一个都不替换，解析不了的条目跳过并报出条数。
- **不做任何占位符替换，声明原样透传**：模板配置里的字符串在**加载回填时原样回填**、在**提交时原样进创建请求**（挂载路径、环境变量值、命令、工作目录、网络名一律不替换）。模板里写了 `{name}` 这样的字面量，平台就收到这个字面量，由后端既有校验兜底（路径不存在会得到明确报错）。
- **`~` 是网页专属口径**：`~` 与 `~/` 前缀的宿主路径展开发生在服务端创建请求翻译处（展开为服务运行用户的家目录），**命令行仍要求宿主路径写绝对路径**；容器路径、环境变量值、命令、工作目录一律不展开。
- **toast 来源标识**：模板相关反馈的 `data-toast-source` 固定两个值——`sandbox-template`（新建沙箱抽屉里的模板列表读取失败、保存模板结果、模板里有解析不了的挂载声明）与 `settings-template`（设置抽屉里的模板列表读取失败、重命名与删除模板的结果）。验收脚本靠来源定位，别自造第三个值。
- **模板行定位用 `data-template-name` 属性**（`page-settings-template-item` 上）：**不要按行内文字筛选**——行内重命名一开始，模板名那一段会被输入框替掉（名字变成输入框的值，不再是行的文字内容），按文字筛出来的行当场就再也匹配不上。这是真机验收踩过的坑，定位器一律改用属性。
- **界面不重复解释模板**：新建沙箱抽屉的「加载模板」下拉下不挂说明段、设置抽屉的模板管理区不挂说明段、保存模板弹窗的说明只留一句「仅保存已填写内容。」——模板是什么由文档讲，界面不重复。

## 连接配置与请求基址

- **配置模型与存储**：连接配置是「后端地址 + 访问令牌」两字段（`{ backendBaseUrl, token }`），存 localStorage 的 `sandbox-console-connection` 键，存取收敛在 `src/lib/connection.ts`（`readStoredConnection` / `writeStoredConnection` / `setConnectionConfig`）。**挂载时不写存储**——只有用户主动保存（引导面板「保存并连接」/ 设置抽屉「保存配置」）才落盘；**读不到 / 解析失败 / 值非法一律回落默认**（= 未配置），存储不可用（隐私模式）时静默忽略、不打断交互。
- **基址恒非空、恒绝对地址**：基址**默认 `http://127.0.0.1:8000`、可编辑、不可置空**——「空 = 同源」语义与整条空基址逻辑链已删除（决策 D），请求恒为 `<基址>/api/...` 的绝对地址。**归一规则只有 `normalizeBaseUrl` 一处**（去空白 → 补 scheme → 去尾部斜杠；空值落回默认地址），配置存取、请求基址、桌面 CSP 同步、终端 WS 推导都用它；**旧存储里的空基址读取时归一为默认地址**（存量用户不受影响）。
- **基址只认「主机 + 端口」**：路径 / 查询参数 / `#` 一律拒绝（后端接口都在根路径下），只支持 `http` 与 `https`；校验失败给**就地红字**（`role="alert"`），不进 toast。
- **未配置只看令牌**：**令牌为空即未配置**（基址恒有默认值，不参与判定），**web 与桌面一个口径**。未配置时**不渲染工作台**、改渲染引导面板（`page-connection-setup`），**一个轮询都不启动**；未配置态是**页面状态、不是路由**（地址栏仍是 `#/`）。
- **每个请求都带 Bearer**：接口层（`src/api/client.ts`）统一加 `Authorization: Bearer <token>`；**令牌缺失时一个请求都不发**（抛 `ConnectionNotConfiguredError` 交给上层进引导态），不靠后端 401 兜。
- **终端 WebSocket 走一次性票据**：浏览器 `WebSocket` 不能设自定义头，先 `POST /api/auth/ticket` 换一张 30 秒有效、用过即废的票据，再以 `?ticket=` 带上；**票据不缓存**（每次连接 / 重连前现取）。终端 WS 地址**恒从基址推导**（`http→ws` / `https→wss`），**不按页面位置回退**。
- **健康检查失败要分两类说**：401 / 403 说「令牌无效」，其余说「后端不可达」（`describeHealthFailure`）——两者的下一步动作完全不同，不混说。
- **接口层与终端地址推导读内存缓存**：两者走 `getConnectionConfig()`（进程内缓存），不每次读存储——存储不可用时用户仍能在引导面板里填配置，并在本进程内连上后端。
- **两种形态在连接配置上没有差别**：同一份前端产物（网页端与桌面端）都能配任意后端地址；**唯一的形态差异是运行机制**——桌面壳的动态 CSP 要按后端主机在**运行期**生成（Rust 侧 `set_backend_base_url` → `csp_needs_reload` → 必要时重载主文档，**顺序不能反**）。**Rust 侧不落盘令牌**（令牌每次经 IPC 传入，只活在内存）。
- **桌面形态首次配置走「待验证草稿」**：跨主机的健康检查会被 CSP 拦死（主文档的 CSP 里还没有后端主机），必须先把后端主机告诉桌面壳并重载主文档；重载会把内存状态清掉，所以草稿先落 `sandbox-console-connection-pending`，**体检通过才提升为生效配置**（不通过就不保存、不挂载工作台）。

## 端口转发

- **界面位置**：**沙箱详情抽屉底部**的「端口转发」区（`src/components/workbench/PortForwardPanel.tsx`，由 `SandboxDetailDialog.tsx` 挂载）。**不新增第四个抽屉**。
- **两形态差异是硬约定**：
  - **web 形态**：**只渲染一张说明卡 + 一个「安装桌面端」按钮**（点击开 **ModalShell** 安装指引弹窗），**不渲染表格 / 新建 / 同步 / 编辑 / 删除等任何管理操作**——本机端口的监听由桌面端持有，在网页上建转发只会给出「建了却连不上」的半截功能；**面板自己不读任何数据**（转发记录由工作台经 props 送来，本机监听表不查）；**转发记录的读取在工作台层且仅桌面形态执行**——web 形态只刷沙箱详情，转发记录一个都不读。
  - **桌面形态**：**完整管理**——**新建表单卡在上 + 五列表格在下**（列：本地端口 / 容器端口 / 本地状态 / 容器状态 / 操作），表格行 = **后端记录 ∪ 本机监听**的并集（孤儿行 = 记录被删但本机还在听），操作列三个 icon 按钮：**同步 / 编辑本机端口 / 删除转发**。
- **本机端口规则**：**默认 = 容器端口**；**可编辑、不可为空**（空值是非法输入，表单层就拦）；**被占自动换空闲端口**（换端口在桌面端 Rust 侧做，候选从 `18000` 起扫）；**界面只显示实际生效的端口**，不得回显用户输入值（被占换过端口时提示要说清实际值）；**允许 <1024**——能不能绑**由操作系统决定**（Windows 可绑、macOS 现代版可绑、Linux 非 root 不可绑）：**绑不上时必须明确报错**，不静默失败。前端校验**不拦低端口**。
- **本机端口只存在于桌面端**：**后端 REST 不带本机端口字段**（转发记录只有 id / sandbox / container_port / state / created_at / updated_at）——链路两点化，**后端宿主零端口**；本机端口不进平台记录、不进转发台账。
- **三个操作的落点**：
  - **同步转发** = 把后端记录与本机监听对齐，两个方向按需执行：后端可用而本机无监听 → `start_forward`（`localPort` 传 `null`，端口交给桌面端挑）；本机在听而后端无记录 / 已停 → `POST /api/forwards`（后端幂等：复用旧记录并写回「可用」）。**记录重建后 `id` 可能变了 → 本机监听必须迁到新 id**（隧道按转发标识寻址，旧标识已失效）。
  - **编辑本机端口** = **停旧监听 → 按新端口重开**（`stop_forward` 再 `start_forward`），**仅本机监听中可用**。
  - **删除转发** = **先 `stop_forward` 再 `DELETE /api/forwards/{id}`**（顺序不能反：先收本机监听再删记录，不留僵尸监听）；**孤儿行**（后端无记录）只 `stop_forward`。
- **本机监听的生命周期完全手动**：**没有自动开启 / 自动关闭**——轮询只把**数据**刷回来，绝不碰监听；监听只随「新建 / 删除 / 行内同步 / 行内编辑 / 连接配置变更重开」变化。
- **状态用纯圆点 + tooltip**（不再是带文字的徽标）：本地状态与容器状态两列各一个圆点，**提示文案同时是圆点的 `aria-label`**（可访问名不能丢）；纯展示的圆点**不得渲染成 button**（用 Base UI Tooltip 的 `render` 渲染成 `span`）。
- **本机状态点的「未开启」是红点**（产品口径：转发记录在、后端可用，但本机没监听 = **待处理**状态，不是「一切正常」）：映射在 `listenerDotClass` 的**圆点层**做，**四态令牌语义本身未动**（`running` / `busy` / `stopped` / `failed` 四个令牌照旧），因此**灰色令牌在本区不可达**。
- **单条隧道断开不关监听**：隧道断开**只关那一条本机连接**（上报连接级事件），**本机监听保留**到用户显式停止——这是正式口径，**不要按「隧道断开关监听」实现**。
- **反馈口径**：操作结果**一律走右上角 toast**，来源标识固定 **`port-forward`**（`data-toast-source="port-forward"`）；**本地表单校验红字就地展示**（留在抽屉内，`role="alert"`，不进 toast）；后端返回的中文 `detail` **直接展示**，不另造说法。
- **标识命名**：端口转发区的新增标识统一 `page-forward-*`（如 `page-forward-panel` / `page-forward-notice` / `page-forward-install-button` / `page-forward-table` / `page-forward-row` / `page-forward-create-container-port-input`），登记进 `apps/web/frontend/README.md` 的标识表；**不复用已退役的名字**。
- **两处易踩**：
  - **隧道 WebSocket 由 Rust 发起，浏览器不碰**：前端**不得**直接连 `/api/forward/tunnel/{id}`（浏览器侧没有设 Bearer 头的能力，票据路径只服务终端 WS）；隧道只在桌面壳的 Rust 侧建立，前端**只经 Tauri IPC 调命令**。
  - **Rust 侧不落盘令牌**：令牌每次由前端经 IPC 传入，只活在内存（进程退出即失效）；Rust 侧只落**后端基址**（供动态 CSP 用）。
- **纯逻辑收敛**：端口校验、状态文案、圆点配色、tooltip 文案、地址推导在 `src/lib/port-forward.ts`；桌面 IPC 桥在 `src/lib/desktop-forward.ts`（走 `window.__TAURI_INTERNALS__.invoke`，**不引 `@tauri-apps/api`**，web 形态的构建产物与依赖树不被 Tauri 污染）。
- **转发记录由工作台持有**：面板**不拉**转发记录——工作台按 10 秒一拍**并行刷详情 + 转发记录**（合并轮询，失败连续 3 次才弹一条，来源 `sandbox-detail`），经 props 传给抽屉与面板；面板的写操作完成后回调工作台立即重拉。**转发记录的读取仅桌面形态执行**（web 形态只刷详情）。

## data-testid 规范

- 命名 `page-<页面>-<元素>`，字符集只允许小写字母、数字与连字符。
- 同页重复出现的元素**标识本身保持一致**，另挂属性区分：沙箱列表项带 `data-sandbox-name` 与 `data-sandbox-state`，终端标签与终端表面带 `data-session-id`（标签另带 `data-active`）。
- 同页双挂载的标识（侧栏与空态引导块各有一个「新建沙箱」按钮）按「取第一个」处理，不另造名字。
- 端到端脚本只使用 `apps/web/frontend/README.md` 标识表里的名字，不另造；helper 里的标识必须与实现一致。
- 旧四页与「后端保留会话」列表下线后，相关标识已退役，不得复用。抽屉改造后下线的标识（新建沙箱成功面板、删除武装提示与回收清单明细）同样不得复用。完整标识表与已退役清单见 `apps/web/frontend/README.md`。
