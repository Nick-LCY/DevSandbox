这一轮把「当前已完整缓存的镜像清单」变成可查询的事实：核心包扫描器（特权通道实扫缓存目录）→ 服务端 `GET /api/proxy/cache/images`（json | 预渲染 text + 60s TTL）→ 两个出口（console 设置抽屉视图、沙箱内 `cached-images` 命令），中间靠**受限令牌**（第二把只读钥匙，平台全权管理）与**平台强制 env 注入**（`SANDBOX_IMAGE_CACHE_URL` / `SANDBOX_IMAGE_CACHE_TOKEN`）打通，最终落地引导约定——agent 拉依赖镜像前先查清单、可接受版本集合中优先选已缓存版本，任何失败态显式降级、不阻塞。

**机制已由前置侦察双向实证**（前向 `md5(/v2/<repo>/blobs/sha256:<digest>)` 验证与反向 `KEY:` 头枚举均实测命中，缓存目录 140 文件 / 382MB），**本轮不设打样轮**——01 直接实装，真缓存实测即验收。

## 依赖顺序

```
01 ──▶ 02 ──┬──▶ 03 ──┐
            ├──▶ 04 ──┼──▶ 06
            └──▶ 05 ──┘
```

- **01 → 02**：端点调用核心包扫描器；02 的单测可先以伪扫描器注入开发，实机联调等 01。
- **02 → {03, 04, 05} 可并行**：03 动服务端递参与核心包注入（令牌值来自 02 的凭据文件）、04 动 base-image（正常态真机验证需 02 端点在场）、05 动前端（联调需 02 端点在场）——三者**代码零文件重叠**。
- **06 收口依赖全部（01~05）**。
- **外部硬前置**：04 的镜像构建推送后，**现有沙箱重建（用户执行）**是端到端验收（**PRD 21、26、30**）的硬前置——存量沙箱不会自动获得 `base:0.4.0`（平台自建镜像只存宿主 root 守护进程、沙箱守护进程经核心包注入，同上一轮口径），本轮不代劳重建。

## 硬约束继承（PRD，贯穿全轮）

| 禁令 | 落点 |
|---|---|
| **禁 bash 解析 JSON** | 02（text 预渲染格式的存在理由）、04（`cached-images` 只拉 text 直接输出）、06（核销复核） |
| **禁 jq 依赖** | 04（镜像内不装、脚本不依赖 jq）、06（复核） |
| **禁 `docker images` 劫持** | 全轮不封装、不改写 docker 语义；06 复核 |
| **禁代理层透明改写**（拉什么得什么） | 全轮明确排除；06 复核 |
| **无 GC 入口** | 01（扫描器独立成模块供 GC 将来复用，但本轮无任何 GC 入口）、06（全库检索零命中） |
| **CLI 零改动** | 01~06 各任务门禁；06 复核（CLI 创建缺 env 属已知边角，行为与现状一致，非缺陷） |
