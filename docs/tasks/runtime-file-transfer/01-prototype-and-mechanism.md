# 任务：打样与机制验证（运行期文件传输）

> **本任务是全轮硬前置**：机制验证不通过**不进 02**。需求见 [[prds/runtime-file-transfer.md|运行期文件传输 PRD]]。
>
> **状态：done（2026-11-09 收口）**。机制选型决策已随本轮落档为**已接受**：[[architecture/decisions/0018-运行期文件传输机制选型.md|ADR 0018]]（06 轮只复核，不再改状态）。

## 目标

不产出用户可见功能，只回答「这条路走不走得通」。要回答的问题有五组，每组都要有**实测结论**：

1. **exec 命令在真沙箱里成不成立**（上传 / 下载 / 探测三类）。
2. **部署链反代的缓冲与超时会不会打断大文件传输**。
3. **200MB 级传输的后端内存曲线与耗时**——这是「大小不限」的唯一可信证据。
4. **容器内 `sh` / `cat` / `wc` 在平台基础镜像与典型用户镜像里是否存在**。
5. **机制选型要不要落 ADR**（本轮产出 ADR 0018，**已随本轮落档为已接受**，06 轮只复核）。

## 实施步骤

### 1. 真沙箱实测 exec 命令

在**真实沙箱**（免 root 守护进程下的沙箱容器）里逐条跑，记录**退出码、stderr 原文、副作用**：

- **上传（临时名 + `mv`）**：写字节到容器内临时名 → `mv` 到目标。
  - 验证 `mv` 的**原子替换**语义成立；
  - 验证 **rename 不跟随末端符号链接**（目标是指向别处的符号链接时，替换的是链接本身，不是链接指向的文件）；
  - 验证**目标已存在 = 覆盖**；
  - 验证**父目录缺失**时报错（平台**不主动创建**父目录）；
  - 验证**只读目标**（不可写文件 / 不可写目录）时的报错形态与归属（属主权限问题还是文件系统问题）——**报错要归类**，服务端要据此映射错误码与文案。
- **下载（`cat` 流出）**：`cat` 目标文件，验证字节流可完整流出、退出码与 EOF 语义。
- **探测（`test -d` / `test -f` + `wc -c`）**：
  - **目录** → 可区分；
  - **普通文件** → 可拿到字节数；
  - **管道 / 设备 / socket** → 能区分（**这是类型检查，不是路径限制**）；
  - `wc -c` 缺失时备选口径（`stat -c %s` / `ls -l`）要一并试出来。

### 2. 部署链反代的缓冲与超时核对

- 查清部署链上**实际生效的反代**（若有）的缓冲与超时配置；
- 核对：**大小不限**与反代默认缓冲 / 超时是否冲突；
- 结论要落到「**要不要调、怎么调、调在哪一层**」——不定这条，06 轮的「大文件真机」会假失败。

### 3. 大文件的内存曲线与耗时

- 用**至少 200MB 级**的文件跑上传与下载，全程采样后端进程内存；
- 记录**峰值内存**与**耗时**；
- 结论：内存是否**有界**（不随文件大小线性增长）。

### 4. 容器内工具存在性核对

- 在**平台基础镜像**与**典型用户镜像**里逐个确认 `sh` / `cat` / `wc` 是否存在、版本差异；
- 缺失时的**降级口径**要写清楚（不是「不支持」，是「换哪条命令」）。

### 5. ADR 0018

产出**机制选型**的 ADR（编号 0018，落 `docs/architecture/decisions/0018-运行期文件传输机制选型.md`）：主通道、四条否决路线的理由、覆盖语义、类型检查口径、路径口径、大小不限的代价与反代约束。

**本轮状态**：ADR 0018 **已随本轮落档为「已接受」**（机制经真机实测验证）——落档时含一节「实测修正的设计口径」：PRD 草案的 **10 条设计点**被实测推翻或精化（逐条写明「原假设 → 实测结论 → 修正」）。**06 轮只复核，不改状态、不再出草案。**

### 关键实测数字

- **字节精确**：200 MiB 随机文件，宿主与容器内 sha256 均为 `131d1542a59c587bc455b5401ac5ac9a0b3c9074ca1248303d87298adcba9179`；上行 **629.4 MiB/s（0.32 s）**、下行 **730.7 MiB/s（0.27 s）**。
- **内存峰值**：见上表（宿主 23.2–25.0 MiB，客户端峰值 27.7–28.1 MiB）；采样方式：宿主 `/proc/self/status` 的 `VmRSS` 每 **32 MiB** 一采，峰值用 `resource.getrusage` 的 `ru_maxrss`（每个方向单独起进程测）。
- **反代 A/B（掐断的是反代，不是后端）**：同一 200 MiB 慢上传（限速 1 MiB/s ≈ 200 s）——**直连控制台 201.23 s 正常完成**、**经线上 Traefik 61.13 s 被掐断**（`ConnectionResetError`）；隔离 Traefik 复现 **61.07 s**（`BrokenPipeError`）。下载方向不受限：200 MiB 响应经反代 **0.09 s 完整送达**；慢响应（120 s）实测 **119.05 s 正常结束**。
- **JSON body 缓冲**：200 MiB JSON body 让控制台进程 RSS **44.5 → 433.9 MiB**（经反代后 416.8 MiB）⇒ **上传端点必须 raw 流式读 body**。
- **本机端口是 28642，不是 8000**：控制台监听 `0.0.0.0:28642`，直连 uvicorn，service `sandbox-console.service`（`User=sankabox`）。
- **目录列表保真**：15 条刁钻名字（含换行 / 空格 / 中文 / 引号 / 反斜杠 / 制表符 / `$` / 反引号 / `-` 开头 / 隐藏文件）→ 解析出 **15** 条记录（原始字节数 422），缺失 `[]`、多余 `[]`；GNU 与 busybox 输出一致。
- **收尾**：测试沙箱已由平台回收（容器 / 网络 / 系统用户 / 家目录 / 子 UID 段 / 元数据），隔离 Traefik 容器已删，宿主 docker 无残留；**用户既有的两个沙箱全程未被触碰**，仓库工作区零改动。

### 意外发现 D-1 ~ D-16（与 PRD / 任务书假设冲突之处，一句话摘要）

> 逐条的「原假设 → 实测结论 → 修正」见 [[architecture/decisions/0018-运行期文件传输机制选型.md|ADR 0018]] 第 7 节。

- **D-1** 「只读目标」**不是一个错误类别**——目标文件 `0444` + 父目录可写 ⇒ `mv` 静默覆盖成功（root 与非 root 同）；只有父目录不可写（EACCES）与只读挂载（EROFS）才报错。
- **D-2** 目标是**已存在目录**时 `mv` **rc=0 假成功**（文件被搬进目录里）⇒ 上传前**必须前置拦截**；**`mv -T` 不可用**（busybox 无）。
- **D-3** PRD 草案的探测命令**分不出「不存在」与「特殊文件」**（FIFO / `/dev/null` / `/dev/zero` 全落 `missing`）⇒ 改用分层探测；**FIFO 会挂死 `cat`**（GNU 与 busybox 都挂）。
- **D-4** FastAPI 的 **JSON body 整体进内存**（200 MiB ⇒ RSS 44.5 → 433.9 MiB）⇒ 上传端点必须 **raw body + `request.stream()`**。
- **D-5** 经线上 Traefik 的上传有 **60 s 硬上限**（`readTimeout: 1m0s`），61 s 被重置；**直连 28642 无此限**（201 s 成功）⇒「不限大小」要写成「不限大小 + 单次请求总时长受反代 readTimeout 约束」。
- **D-6** 容器内 `sh` **不是 bash**（dash / busybox ash），`read -r -d ""` **两者都不支持**、`command -v` 在 dash 里**只接受一个参数** ⇒ 列表改为 `find -exec` 内直接产出 NUL 记录。
- **D-7** `find -printf` **只有 GNU 支持**（busybox 报 `unrecognized`）、`mv -T` busybox 不支持、`ls -l` 列宽 GNU/busybox 不同 ⇒ 统一收敛到 `find -exec` / `test` / `wc` / `stat` / `printf`。
- **D-8** `wc -c < file` 要**读完整个文件**，`stat -c %s` 是 **O(1)** ⇒ 大小首选 `stat -c %s`。
- **D-9** exec 中断后容器内留下**半截临时文件**（8 MiB `.rtf-tmp-interrupt`），`cat` 不会自清理 ⇒ **平台侧负责清理**。
- **D-10** 路径含换行时 **`sh -c` 拼接会被拆碎**，**argv 直传正常** ⇒ 路径一律 argv 直传，**禁拼进 `sh -c`**。
- **D-11** 任务书的「后端 8000 端口」与本机实际（**28642**）不符；本机部署**存在 Traefik 反代层** ⇒ 后续轮次按 28642 核对，**远程部署必须自查反代**。
- **D-12** 本沙箱容器里**构造不出真实跨设备场景**（`/tmp` 与 `/workspace` 同一 overlay），改用 tmpfs 旁挂才验到（inode `2 215` → `12990840 179`）⇒ **临时名必须与目标同目录**。
- **D-13** 探针口径不一致：`test -d` / `test -f` / `wc -c <` **跟随**符号链接，`stat`（不带 `-L`）**不跟随** ⇒ 探测组合要**显式定义符号链接语义**。
- **D-14** 实验脚本曾把非 ASCII 字节按 latin-1 写入命令导致文件名**双重编码**（实验脚本的坑，非平台问题）⇒ 平台侧一律**显式 UTF-8 解码**，不依赖 locale 默认解码承载文件名。
- **D-15** 同一类错误在 dash 与 busybox ash 下**措辞与退出码都不同**（父目录缺失 dash rc=2 / busybox rc=1；目录 `Is a directory` vs `read error: Is a directory`；不存在 `No such file or directory` vs `can't open '…': No such file or directory`）⇒ **分类只按关键词子串**，退出码只当辅助信号。
- **D-16** busybox ash 的 `cat` 对 **FIFO 同样挂起**（`timeout 3 cat` → rc=143）⇒ 「只放行普通文件」的探测口径**在 busybox 上同样必要**。
