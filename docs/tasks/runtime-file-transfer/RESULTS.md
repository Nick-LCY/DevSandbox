## 四、06 轮 e2e 验收：spec 与证据链

**新 spec**：`12-file-transfer.spec.ts`（**903 行**、**2 条用例**——主链路 + 负例）。

**证据链（三方对账，刻意不走「被测接口自证」）**：

| 环节 | 取证方式 | 为什么这么取 |
|---|---|---|
| 容器内真值 | **宿主侧 `docker exec` 进容器内取证**：sha256 / 字节数 / **属主** | **不经过被测接口**——否则「接口说自己写对了」不算证据 |
| 下载回环 | 下载回来的字节与源文件**逐字节比对**（sha256） | 证明下行链路无损 |
| 列表元数据 | `list` 返回的名称 / 大小 / 类型与容器内真值**三方对账** | 证明元数据与真实文件一致 |

**负例**：**400 / 409 / 401** 三类失败**固定中文文案原文钉死**（不只断言状态码）。

**两条断言纪律**：

- **进度断言用 `MutationObserver`，与速度解耦**——不按「多久到某个百分比」判定，避免慢机器上假红；
- **负向断言必配正向对照**——同一条链路先跑通再验失败，防止「因为整体坏掉所以负例也绿」。

**结果**：**单跑 2 passed（约 60 s）**；**全量套件 50 passed / 0 failed / 0 flaky / 0 skipped（9.9 分钟，基线 48 + 2）**；**e2e gate 通过**。

**审查一轮 + 修复一轮**：

| 级别 | 问题 | 处置 |
|---|---|---|
| **Critical** | 残留沙箱复用冲突 | 已修（沙箱生命周期与复用口径收敛） |
| Warning | 进度观测竞态 | 已修（改 `MutationObserver`，与速度解耦） |
| Warning | 负向缺正向对照 | 已修（补正向对照） |
| Warning | 取消覆盖证据链弱 | 已修（取消路径也纳入证据链） |
| 低成本项 | 若干可读性 / 健壮性小项 | 已修 |

**修复一轮共 10 项落地**；修后**复跑全绿**——`expect` 断言共 **102** 处，**用例数不变**（2 条，不靠加用例掩盖问题）。

## 五、大文件真机证据（03 轮实现侧 + 01 轮机制侧，2026-11-09）

> 这一节的数字来自**真机实测**（直连控制台 + 经域名过 Traefik）：**实现侧**（端到端、raw 流式、经反代）出自 **03 轮**，**机制侧**（宿主字节泵的峰值内存与吞吐）出自 **01 轮**。**06 轮未新增独立的 e2e 级大文件复跑**——大文件级的端到端证据统一引用本节。

| 场景 | 结果 | 证明的事 |
|---|---|---|
| **JSON body 200 MiB**（对照实验） | 控制台进程 RSS **44.5 → 433.9 MiB** | **上传端点必须 raw 流式读 body**——JSON 模型接 body 会把整份缓冲进内存，「内存有界」只在字节泵层成立 |
| **raw 流式 250 MiB 经域名限速上传（Traefik 改前）** | **60.53 s 被 502 掐断**，只传上去 **190,316,544 / 262,144,000** 字节 | 掐断的是**反代读超时**，不是后端、也不是大小上限 |
| **raw 流式 250 MiB 经域名限速上传（Traefik 改后）** | **83.13 s 成功 + sha256 一致**（宿主源文件 ↔ 容器内文件） | 入口点级 `readTimeout=0` 落地后，**超 60 s 的慢速大上传成立** |
| **上传全程控制台 RSS** | **58.8 → 59.2 MiB**（平坦） | 端到端**内存有界**——不随文件大小增长 |
| **下载 200 MiB 经反代** | **0.09 s 完整送达** | 读超时**只管读请求**，不砍响应；下载方向不受 60 s 约束 |
| **宿主峰值内存（01 轮机制实测）** | 200 MiB 与 1 GiB 均 ≈ **23 MiB**；吞吐 **571–1300 MiB/s** | 「大小不限」在字节泵层成立（曲线平坦、不随大小线性增长） |

## 八、已知边界与留白

| # | 边界 / 留白 | 性质 | 说明 |
|---|---|---|---|
| 1 | **chunked 上传（无 `Content-Length`）不核对字节数** | **已知残余风险** | 没有契约值可比 ⇒ 客户端中断**仍可能在目标路径留下半截文件**（双保险的残余面）。调用方拿得到总长度时**应当带上 `Content-Length`**；服务端对非法头 **400 不静默降级**。已写进 `API.md` 第 16.2 节 |
| 2 | **Windows 真机 15 条清单未验** | **留白（唯一开口）** | 本机是 Linux，Playwright 覆盖不到 Tauri IPC 与原生对话框；**清单全文见 [[tasks/runtime-file-transfer/05-desktop-download.md\|05 任务]]**，**未验不宣称完成**，**待用户 Windows 真机执行** |
| 3 | **`readTimeout=0` 的 Slowloris 敞口** | **刻意接受，待条件触发时重审** | 读超时不限时在**公网暴露**时是 Slowloris 面；**当前域名只在内网解析**，不构成敞口。若将来公网暴露，**需重审**该入口点策略（并考虑改用显式大值而非 `0`） |
| 4 | **符号链接双口径**（探测**跟随** / `rename` **不跟随**） | **刻意保留** | 两处口径不同是有意为之（ADR 0018 第 2 / 第 7 节），**不得「顺手统一」** |
| 5 | **「大小不限但受反代读超时约束」** | **刻意保留的口径** | 「不限」指反代与后端都**无 body 上限**（不会 413）；单次请求总时长仍受**部署侧**读超时约束——**本机已解，远程部署须自查** |

### 11.1 用户反馈（1 个功能 bug + 4 项样式 / 交互）

| # | 类别 | 反馈（用户真机观察） |
|---|---|---|
| 1 | **功能 bug** | **已在根目录时点根目录面包屑 → 列表变空**；**点当前层级的 crumb 同样触发**（同源问题） |
| 2 | 样式 | 面包屑需要**固定底色**（当前态与抽屉背景不分离） |

| 4 | 交互 | 面包屑**单行**；溢出时**保留右侧深层级**，头部出现**省略号且不可点**，**变宽后恢复** |

### 11.2 根因（一句话）

**React 同值 setState bailout**——`navigateToRoot` **先清列表再 `setPath('/')`**，路径为**同值** ⇒ 加载 effect **不重跑** ⇒ `entries` **停在空数组**；「点当前层级 crumb」是**同一根因的同源问题**。

### 11.3 修复轮一：统一导航入口

- **统一导航入口 `goToPath`**：根图标钮与各级 crumb 的跳转**走同一个入口**，不再各写各的。
  - **同路径直接强制重读**——**绕开 setState 的同值 bailout**，不依赖加载 effect 重跑（这是本次 bug 的正解）。
  - **`depth < 0` 显式归一为 `/`**——根层级不再靠「无路径」隐式表达。
- **样式 / 交互四条**（11.1 的第 2~5 项）随本轮一并落实，核对见 11.6。

### 11.4 审查修复轮抓出的 Critical：裁剪链路死代码

- **现象**：用于**量宽**（列表列宽测量）的 ref 与 `ResizeObserver` **只在「常驻面板」挂载时取一次**；而**抽屉关闭时 Base UI portal 不渲染内容** ⇒ 观察器**永不挂载** ⇒ 这条**裁剪链路是死代码**（写得再对也不生效）。
- **修法**：改为**回调 ref**——**打开即挂观察器并量宽、关闭即断开**（随挂载周期走，不依赖「常驻」）。
