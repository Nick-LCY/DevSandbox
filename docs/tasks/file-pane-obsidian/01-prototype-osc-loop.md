# 任务：打样轮——OSC 1337 pwd 链路端到端打通

> 需求见 [[prds/file-pane-obsidian.md|文件窗格与 Obsidian 阅读器 PRD]]。
> **本任务是硬前置**：不打样通，后面的 02 / 03 不许开工（镜像注入写法与前端解析口径都在本轮定）。

## 目标

在**真沙箱**里把本轮**最不确定的一条链路**端到端打通：

```
镜像 PS1 注入 → xterm 注册 OSC 处理器 → 解析 pwd → 窗格定位 / 回跳
```

本轮**不产出完整功能**，只产出**可落地的口径结论**。要回答的问题有三条：

1. **bash 转义实测**：`/etc/bash.bashrc` 里注入的 PS1 片段，bash 到底渲染成什么？`\[\e]1337;CurrentDir="'$(pwd)\a\]'` 的转义与引号在 bash 里能不能原样成立？
2. **sh 降级实测**：`dash` / `sh` 会话里这段 PS1 语法不成立时，实际表现是什么（报错？静默？提示符变形？），会不会污染终端输出？
3. **断线重连 pwd 恢复方案实测**：重连后 shell 不会主动再报一次 pwd，那么「发一个空行」与「触发一次 resize」两种刷新方式，哪一种可靠？

**产出口径结论**（写进本任务文件的「进展」节，02 / 03 轮按结论施工）：
- 镜像注入的**最终写法**（含 bash 转义与引号的实测校准结果）；
- `sh` 降级的**实际表现**与前端降级口径的对应关系；
- 断线重连 pwd 恢复的**选定方案**。

## 涉及文件

- 基础镜像的 `/etc/bash.bashrc`（**本轮只在本地临时改，不 bump 版本、不推送**——正式注入在 02 轮）
- 前端 `apps/web/frontend/src/components/TerminalView.tsx` — 打样期临时挂 OSC 处理器（**02 / 03 轮收口**）
- 前端 `apps/web/frontend/src/lib/` — 打样期临时解析函数（**03 轮收口为正式纯函数模块 + 单测**）
- 本任务文件（**产出口径结论**）

## 完成标准

- [ ] **真沙箱**里用 `bash -i` 起会话，终端输出流里**实测捕获到** OSC 1337 的 `CurrentDir` 序列，且解析出的路径与容器内 `pwd` **一致**。
- [ ] **bash 转义实测结论**落档：注入片段在 bash 下的最终写法（保留原 PS1 + 追加 OSC 序列），以及**提示符渲染是否正常**（不得出现乱码、不得把转义字符原样打出来）。
- [ ] **`sh` 降级实测结论**落档：`dash` / `sh` 会话的实际表现，以及「会话不上报 pwd ⇒ 回跳按钮禁用 + tooltip『当前会话未上报工作目录』」这一降级口径与实测是否对得上。
- [ ] **断线重连 pwd 恢复实测结论**落档：空行 / resize 两种刷新方式**至少一种被证实可靠**，并写明选定方案（对应 PRD 验收项 **PWD-05**）。
- [ ] **注入行为与既有口径边界实测**：向 `/etc/bash.bashrc` 注入后，实测确认注入的**实际行为与边界**——容器 shell（`bash -i` 及其它形态）**是否确定读到**该注入；并核对与镜像「**沙箱启动即一个 bash、不加载 profile 脚本**」既有口径（[[architecture/decisions/0004-镜像契约与默认沙箱镜像.md|ADR 0004]] 第 3 节「运行时极简」、[[architecture/decisions/0011-基础镜像增加通用工具层并转联网构建.md|ADR 0011]] 第 4 节对 0004 条款的引用）**是否存在实际冲突**；**结论写进本轮打样留档**（供 02 轮落地时对齐、08 轮修订 ADR 0004 时引用）。
- [ ] **回跳链路走通**：在打样环境里能验证「解析出的 pwd ⇒ 窗格定位到该目录」与「回跳按钮点击 ⇒ 导航到该目录」两步（可以是临时代码，**03 / 04 轮收口**）。
- [ ] **越界检查**：打样期的临时改动**不留在主干**——02 / 03 轮开工前，本轮临时代码要么被正式实现取代、要么被摘掉（02 轮的镜像正式注入与 03 轮的前端正式实现落地后，本轮临时注入块与临时解析函数**必须清零**）。
