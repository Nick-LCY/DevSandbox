# 任务：管理 API

> 需求见 [[prds/file-injection-refresh.md|文件注入副本手动刷新 PRD]]；鉴权与接口风格沿用服务端既有管理面。
> 前置：[[tasks/file-injection-refresh/02-core-persistence-and-mutex.md|02 核心实例持久化与互斥]]（端点建在核心刷新能力与元数据条目之上）。

## 目标

### 一、详情回显（additive）

- 沙箱详情**新增** `injections` 字段（列表：条目标识 / 宿主源 → 容器目标（只读）/ 类型 / 是否可刷新）；既有字段**不动**。
- **旧实例**该字段为空列表（无刷新条目）。

### 二、刷新端点

- 新增一个 **POST** 端点：**按沙箱 + 条目标识**定位，成功 **204 无内容**。
- 入参**只有条目标识**：宿主源路径 / 托管副本路径 / 容器目标路径**一律不接受**——任意路径入参一律拒绝，不构成越权写入。
- **拒绝非空 body 与查询参数**（杜绝「借 body / query 夹带路径」）。
- 沿用**既有管理鉴权**（Bearer）与既有特权通道，**不新增**鉴权分支。

### 三、错误分类

- **预检 / 校验类**（源被拒绝、源缺失或不可读、枚举不全、注入根类型改变、条目不存在、旧实例无条目）：明确中文错误文案，**副本未被修改**。
- **写入阶段类**：报「**可能部分更新**」，并说明后续更新与镜像删除已停止、**不回滚**。
- 更新服务端 `API.md`（新端点 + 详情新字段 + 错误分类表）。

## 优先风险

| 风险 | 影响 | 处置口径 |
|---|---|---|
| **任意路径入参** | 变成「读 / 写任意宿主路径」 | 接口只收条目标识；路径一律服务端从条目查得；负例用例钉死 |
| **鉴权旁路** | 未授权即可刷新 | 复用既有中间件；401 / 403 用例 |
| **「可能部分更新」被吞** | 用户以为失败即未改动 | 错误文案固定包含该语义；前端直出后端 `detail` 原文 |
| **非空 body / 查询参数被忽略** | 夹带路径绕过校验 | 显式拒绝并各有负例 |

## 定向验证（**不跑全量**）

- 服务端 pytest 定向用例：正例（刷新成功 **204**）+ 负例（非空 body、查询参数、任意路径字段、未知条目、旧实例无条目、未授权）。
- **不得**在本任务跑全量 E2E（全量只在 [[tasks/file-injection-refresh/05-acceptance-and-delivery.md|05 定向验收与交付]] 单独跑一次）。
