# 文件注入副本手动刷新任务集

本目录是**文件注入副本手动刷新轮**的任务集，共 5 个任务，需求见 [[prds/file-injection-refresh.md|文件注入副本手动刷新 PRD]]，机制与信任边界沿用 [[architecture/decisions/0012-文件注入采用复制加改属主而非改造挂载预检.md|ADR 0012 文件注入采用复制加改属主而非改造挂载预检]]。

这一轮在**创建时快照**之上加一条**用户显式触发**的刷新通道：运行中的沙箱可以对**单文件**或**整目录**已保存注入手动刷新托管副本，**不停机**（不中断容器 / 终端 / agent 会话）；目录按镜像同步，宿主源里**已不存在的成员一并删除**。创建时的复制语义**不改**（仍是快照），本轮只加刷新。

**状态：01~05 全部 done（2026-11-23 收口；2026-11-26 更新）。** **用户手工验收已于 2026-11-26 通过、测试无问题。** 此前「10 个提交留本地 / 零 push」口径已过期：10 个提交 `6b694d4..ffcbdf9` 已随 2026-11-25 的 `v0.1.0` 发布推送至 `origin/main`；**零部署**（本轮本身未部署）。PRD 验收标准 **23 / 23 逐条挂证据核销**。**全量 E2E 只跑过一次**（77 = 76 通过 / 1 失败，退出码 1；唯一失败为 spec16 把共享缓存首行写死的脆化断言，与本轮代码无关，已由独立 test-only 提交 `ee7d970` 定向修复通过，**未跑第二次全量**）。本机走查方式见 [[tasks/file-injection-refresh/RESULTS.md|全轮收口留档]]第六节。看板见 [[current-state.md|当前状态]]。

**本轮不做**：不部署（**绝不 Cloudflare 部署**）、**不 push**；01~04 **不得**跑全量 E2E，全量只在 05 单独跑一次（**不自动二刷**）——**三条均已遵守**（全量只跑了那一次，见 [[tasks/file-injection-refresh/RESULTS.md|全轮留档]]第四节）。

## 关键口径（贯穿全轮）

| 口径 | 内容 |
|---|---|
| 触发 | **用户显式点一次**「刷新副本」；无后台同步、无轮询、无增量推送、无自动重试 |
| 单文件 | **原位覆盖、保持挂载身份**（同一 inode）；**不得**用 rename 换 inode（换掉 inode，容器里挂的还是旧文件） |
| 目录 | **保留挂载根本身**，递归镜像成员：新增 / 更新 / 删除（源里已不存在）/ **真实空目录保留** |
| 元数据 | **additive** 注入声明记录（来源 / 托管副本 / 容器目标 / 类型 / 目标文件身份）；原 `files` 语义保留，旧实例读出**无刷新条目** |
| 互斥 | 同一沙箱的 refresh 与 **start / stop / delete** 互斥（复用生命周期 name lock）；**同一平台数据根多进程**同样互斥 |
| 写入身份 | 写入**降到沙箱用户身份**执行；**不得**对沙箱用户可控的任意路径以 root 写 |
| 只读与属主 | 副本属主仍是沙箱用户、文件 **0600** / 目录 **0700**；容器内**仍只读**；宿主**原件零接触**（不 chmod / chown / 写 / 删，内容与 mtime 不变） |
| 失败语义 | 预检 / 枚举失败 ⇒ **副本一个字节都不动**；进入写入阶段后失败 ⇒ 报「**可能部分更新**」，停止后续更新与镜像删除、**不回滚**、不续跑 |
| 备份 / 原子性 | **没有**备份、没有回滚、没有回退入口；**不承诺原子性**（读者可能看到写入中间状态） |
| 正文 | 详情 / 刷新响应 / 日志**只含元数据**，不返回、不展示文件正文（私钥、凭证一律不读出） |
| 特权通道 | 复用现有 `Privilege`（`sudo -n`）+ **当前发布包内置**的**仅标准库**窄用途 helper（受信绝对路径 + `python -I` 调用）；**不**引入 `/usr/local` 安装、**不**新增 env 配置、**不**新增 sudo 宽规则 |
| 停机 | 刷新**只处理运行中沙箱**：不 stop/start、不重挂载、不 `docker cp`，容器与终端会话不中断 |

## 依赖顺序

```
01 ──▶ 02 ──▶ 03 ──▶ 04 ──▶ 05 ──▶ 单次全量 E2E + 归档
```

- **01 → 02 强顺序**：02 的刷新执行建在 01 的 helper 与预检 / 写入口径之上；01 的真机探针结论（单文件 inode 不变、目录镜像、只读仍失败）不回退不改写。
- **02 → 03 强顺序**：端点要按**已保存的条目标识**定位，条目标识来自 02 落进元数据的注入声明记录；旧实例无条目 ⇒ 端点无可刷对象。
- **03 → 04 强顺序**：界面接 03 的详情新字段与刷新端点。
- **04 → 05 强顺序**：定向 e2e 要在最终界面形态上取证（刷新副本按钮存在、读操作不触发写）。
- **全量只在 05 跑一次**：01~04 只跑**定向**测试；05 跑全量的三条硬前置是「01~04 全部交付完成 + 定向测试全部通过 + 无待修项」，缺一不可，**不自动二刷**。

## 关键前置与风险

| 项 | 性质 | 影响 | 现状 |
|---|---|---|---|
| **挂载身份**（只读 bind mount 绑的是文件身份） | 机制硬约束 | `rename` 换 inode ⇒ 容器内仍读旧内容，「刷新看起来没生效」 | 一律**原位写**（同一 inode），用 `st_dev` + `st_ino` 断言钉住；结论待 01 真机探针确认 |
| **枚举不全被判成「源为空」** | 机制硬约束 | 误删副本成员，**无备份不可回滚** | 「源缺失 / 读失败 / 枚举不全」与「源真的为空」必须可区分；枚举不全不执行删除 |
| **root 写沙箱用户可控路径** | 信任边界 | 提权写入面扩大 | 写入降到沙箱用户身份；目标用验证过的 inode / 目录句柄，不做二次路径解析 |
| **特权通道不得放宽** | 约束 | 免密 sudo 进一步变宽（既有收窄待办见 [[current-state.md\|当前状态]]） | helper 自包含、仅标准库、随当前发布包分发；不加 `/usr/local` 安装、不加 env 配置、不加 sudo 规则 |
| **跨进程互斥** | 实现层约束 | 同平台数据根第二进程可与刷新并发 | 锁落**平台数据根锁目录**（`flock` 口径，与既有名字占位同族）；不放沙箱可控路径、不放宽为任意用户可写 |
| **宿主内存不足以单次跑满 e2e** | 环境约束 | 全量可能中途被宿主杀掉 | 05 跑前确认内存与端口，必要时只停本机明确归属的资源；**不自动二刷**，如实留档 |
| **旧实例无刷新入口** | 已接受代价 | 旧沙箱不能刷新，需用户自行重建 | 不迁移、不补录、不反查模板；旧沙箱内数据不自动带到新沙箱 |
