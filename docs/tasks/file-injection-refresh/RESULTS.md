## 三、机制与关键实现口径（证据摘要）

- **helper 随包分发，不放宽特权通道**：helper 内置在**当前发布包**（core 包）内，**只依赖标准库**，以**受信绝对路径 + `python -I`** 经既有 `Privilege` 调用；不加 `/usr/local` 安装、不加 env 配置、**不加 sudo 规则**（宽免密 sudo 仍是既有待办，见 [[current-state.md|当前状态]]）。
- **写入身份降到沙箱用户**：写入不以 root 落在沙箱用户可控路径；目标用**验证过的 inode / 目录句柄**，不做二次路径解析。
- **单文件原位写**：保持**同一 inode**（`st_dev` + `st_ino` 不变）——只读 bind mount 绑的是文件身份，rename 换 inode 会让容器内仍读旧内容。**不承诺原子性**。
- **目录递归镜像**：保留挂载根本身，镜像成员**增 / 改 / 删**，**真实空目录保留**（空目录本身不被删）。**不是目录事务**。
- **审查修复换掉了「目录成员原位截断」**（`61ca7f9`）：目录成员改走「**新临时文件写完再替换**」，防共享 inode 误写；同时收紧请求限制与目标 spool——**spool 只暂存新内容，不是备份**。
- **写者收尾按本次操作令牌隔离**（`ad4751e`）：只用**随机、非敏感**的 `--job-id` 区分本次写者，**JSON 只走 stdin**；异常时**保留本沙箱的锁**直到本次写者确认退场。
- **互斥**：同一沙箱的 refresh 与 **start / stop / delete** 互斥（复用生命周期 name lock）；**同平台数据根的第二进程**同样互斥（第二进程锁抢占返回 **409**）。
- **元数据 additive**：原 `files` 语义一字未动；新建沙箱把**已校验的宿主源路径**写进实例元数据（**实例事实，不反查模板**）；**旧实例读出无刷新条目**。
- **接口只收条目标识**：`POST /api/sandboxes/{name}/injections/{entry_id}/refresh`，**不接受查询参数、不接受请求体**；成功 **204 无内容**；鉴权沿用既有 Bearer，不新增鉴权分支；错误分**预检类**（副本零改动）与**写入阶段类**（「**可能部分更新**」，不回滚、不续跑）。
- **界面**：抽屉内与「挂载」同级的「注入文件」清单，每条一行（宿主源 → 容器目标（只读）+「刷新副本」按钮），**不展开目录树、不展示正文**；既有「刷新详情」是**读操作**，不触发刷新副本。

## 五、已知边界与留白

1. **原位单文件写不原子、目录刷新非事务**：读者可能看到写入中间状态；验收只断言**最终状态收敛**（设计如此，PRD 已写明不承诺原子性）。
2. **应用可能须重新读取**：写完后**重新读取**路径可见新内容；应用是否自行热加载由应用侧决定，平台不承诺。
3. **旧实例不迁移**：缺宿主源路径的旧实例**无刷新入口**（仍可正常查看 / 管理 / 删除），平台**不自动删除、不自动迁移、不反查模板**；需要刷新的由用户在新版上线后自行重建（旧沙箱内的数据不会自动带到新沙箱）。
4. **仍沿用宽 sudo 信任边界**：本轮**没有**收窄 [[architecture/decisions/0016-控制台默认运行用户改为非root.md|ADR 0016]] 遗留的宽免密 sudo 规则；helper 自包含、随包分发是本轮的做法，收窄 sudo 规则仍是既有待办。
5. **写者退场无法确认时的保底**：极端情况下保底到**持锁进程退出**，可能**保留含新内容的专属暂存**（**不是备份**）；此时须**先确认写者退场**再重启持锁进程。
6. **控制面受信的信任边界未变**：沿用 [[architecture/decisions/0012-文件注入采用复制加改属主而非改造挂载预检.md|ADR 0012]]「注入源以特权读取、调用者视为受信主体」——本轮**未**引入新的调用者类型，也**未**收窄这条边界。
7. **用户手工验收尚未执行**：自动化与真机用例已取证，但真机浏览器的人工走查（第六节）**仍待用户执行**。

## 六、本机人工验收方式（**尚未执行**；本轮文档步骤未启动任何进程）

> 以下命令**由用户自行执行**；归档这一步**没有**拉起任何后端 / 前端进程。

1. **起新版后端**（8000 已被现有服务占用，另起 8100）——**在仓库根目录执行**（`--project apps/web/backend` 是相对仓库根的路径）：

   ```bash
   SANDBOX_CONSOLE_HOST=127.0.0.1 SANDBOX_CONSOLE_PORT=8100 \
     uv run --project apps/web/backend python -m sandbox_console
   ```

   令牌用**本人现有配置**或本机令牌，**不要把 secret 抄进文档或截图**。
2. **另开一个终端起前端**（nvm 22 + pnpm）——**先切到前端目录、切到 Node 22**，再**先 build、后 preview**：

   ```bash
   cd apps/web/frontend
   source "$HOME/.nvm/nvm.sh"
   nvm use 22
   pnpm run build
   pnpm run preview --host 127.0.0.1 --port 8200 --strictPort
   ```

   **`pnpm run build` 不能省**：preview 伺服的是 `dist` 静态产物，不先 build 就会伺服旧产物，看不到本轮界面改动。
3. **设置里填**后端地址 `http://127.0.0.1:8100` 与管理令牌，连接后**新建一个临时沙箱**。
4. **走查要点**：详情抽屉「注入文件」区每条一行（宿主源 → 容器目标，标「只读」）；点「刷新副本」→ 成功 toast「副本已刷新」；**单文件**：宿主源改内容后再刷 → 容器内该路径读到新内容；**整目录**：宿主目录加一个成员 / 改一个成员后再刷 → 副本成员随之增 / 改；**在宿主目录里删掉一个成员后再刷 → 副本里该成员被镜像删除**（容器内读不到该路径，**目录本身保留**）；**点「刷新详情」不会触发写请求**；刷新过程中容器不重建、终端会话不中断。
5. **约束**：验收用**合成文件**（**不要用真实凭证**）；**不自动删除或替换旧沙箱**；临时沙箱用完自行处置。
