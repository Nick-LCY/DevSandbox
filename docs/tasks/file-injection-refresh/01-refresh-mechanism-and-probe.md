# 任务：安全刷新机制与真机探针

> 需求见 [[prds/file-injection-refresh.md|文件注入副本手动刷新 PRD]]；机制与信任边界见 [[architecture/decisions/0012-文件注入采用复制加改属主而非改造挂载预检.md|ADR 0012 文件注入采用复制加改属主而非改造挂载预检]]。
> 本任务是全轮的**地基**：[[tasks/file-injection-refresh/02-core-persistence-and-mutex.md|02 核心实例持久化与互斥]]、[[tasks/file-injection-refresh/03-admin-api.md|03 管理 API]] 与 [[tasks/file-injection-refresh/04-detail-drawer.md|04 详情抽屉]] 都建立在它的机制结论上。

## 目标

### 一、当前发布包内置一个窄用途 helper

- 在**当前发布包**（core 包 `sandbox-platform-core`）里内置一个**仅标准库**的窄用途 helper 脚本（例如 `sandbox_platform/_refresh_helper.py`，随 wheel 分发）。
- 调用方式固定：**受信绝对路径** + `python -I`（隔离模式：不受 `PYTHONPATH` 与用户 site 目录影响），经**现有 `Privilege`** 通道执行（以 root 运行时直跑，否则 `sudo -n`）。
- **不做**：`/usr/local` 安装、新 env 配置项、新的 sudo 宽规则（免密 sudo 收窄是既有待办，见 [[current-state.md|当前状态]]，本轮不碰）。

### 二、预检与取数（阶段内不改目标）

- 对**实际源**重跑受限范围校验，沿用创建时口径：路径归一化 + 真实路径（`readlink -f`）双重比对、宿主敏感清单、任何已存在的沙箱用户家目录、平台数据根。
- 源自身是符号链接即拒绝；源目录树内的**符号链接**与**非常规文件**（FIFO / 设备 / 套接字）一律拒绝。
- 从实际源**完整枚举**：必须能区分「**源缺失 / 读失败 / 枚举不全**」与「**源真的为空**」——判错会把副本成员误删（无备份、不可回滚）。
- 把新数据准备到**私有暂存**：只存**新内容**，**不是备份**；不留旧副本、不留备份目录、不留回退入口。

### 三、写入（降到沙箱用户身份）

- 用**验证过的目标 inode / 目录句柄**写入，不靠路径拼接做二次解析。
- 写入过程**降到沙箱用户身份**执行（复用 `Privilege` 的用户身份前缀口径：`sudo -n -u <用户>` / `setpriv --reuid …`）；**不得**对沙箱用户可控的任意路径以 root 写。
- **单文件**：**原位**覆盖，保持挂载身份（同一 inode）；**目录**：**保留根**，递归镜像成员（新增 / 更新 / 删除过时项 / **保留真实空目录**）。
- **不承诺原子性**；无备份、无回滚。

### 四、先临时资源验证，再真机探针

- 先在**临时目录 / 临时容器**上用单元测试验证（不依赖真实沙箱、不动存量沙箱）。
- 再做**真机探针**（一次性临时沙箱）：验证挂载可见性、单文件 inode 不变、目录镜像（含删除与空目录保留）、容器内仍只读、宿主原件零接触。

## 优先风险

| 风险 | 影响 | 处置口径 |
|---|---|---|
| **挂载身份**：只读 bind mount 绑的是文件身份，`rename` 换 inode 后容器内仍读旧内容 | 单文件刷新「看起来没生效」 | 一律**原位写**（同一 inode），用 `st_dev` + `st_ino` 断言钉住 |
| **枚举不全被判成「源为空」** | 误删副本成员，**无备份不可回滚** | 枚举必须完整返回才允许执行删除；读不全一律拒绝并保持副本不动 |
| **root 写沙箱用户可控路径** | 提权写入面扩大 | 写入降到沙箱用户身份；目标用验证过的 inode / 目录句柄 |
| **特权通道放宽** | 免密 sudo 规则进一步变宽 | helper 自包含、仅标准库、随包分发；不加 `/usr/local` 安装、不加 env 配置、不加 sudo 规则 |
| **不承诺原子性** | 读者可能看到写入中间状态 | 口径写进文档与错误文案；验收只断言最终状态收敛 |
