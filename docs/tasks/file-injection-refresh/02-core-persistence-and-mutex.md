# 任务：核心实例持久化与互斥 / 真沙箱

> 需求见 [[prds/file-injection-refresh.md|文件注入副本手动刷新 PRD]]；机制与信任边界见 [[architecture/decisions/0012-文件注入采用复制加改属主而非改造挂载预检.md|ADR 0012 文件注入采用复制加改属主而非改造挂载预检]]。
> 前置：[[tasks/file-injection-refresh/01-refresh-mechanism-and-probe.md|01 安全刷新机制与真机探针]]（helper 与预检 / 写入口径必须先落地并验证）。

## 目标

### 一、元数据：additive 注入声明记录

- 实例元数据**新增**一块注入声明记录：**来源宿主源路径 / 托管副本路径 / 容器目标路径 / 类型（普通文件 | 目录）/ 目标文件身份**。
- 原 `files` 字段**语义保留**（不改、不删、不重解释）；既有读取路径**零回归**。
- 创建路径把**已校验**的源路径写进元数据——**实例事实**，不反查模板、不做动态查找。
- **旧实例读出无刷新条目**：缺这条记录的实例**不迁移、不补录**，仍可正常查看 / 管理 / 删除。

### 二、刷新执行与互斥

- 核心包提供刷新能力入口（生命周期服务层），复用 [[tasks/file-injection-refresh/01-refresh-mechanism-and-probe.md|01]] 的 helper 与预检 / 写入口径。
- 互斥复用**生命周期 name lock**：同一沙箱的 refresh 与 **start / stop / delete** 互斥（已钉死，**不另按条目分互斥**）。
- **同一平台数据根多进程**同样互斥：锁文件放在**平台数据根**的锁目录（`flock` 口径，与既有名字占位同族），**不放**在沙箱用户可控路径、**不放宽**为任意用户可写。
- **只处理运行中沙箱**：不停机、不 stop/start、不重挂载、不 `docker cp`。

## 优先风险

| 风险 | 影响 | 处置口径 |
|---|---|---|
| **元数据 schema 变更**波及既有读取 | 旧实例读不出 / 既有字段语义漂移 | 纯 **additive**；`from_dict` 对未知 / 缺失字段宽容；原 `files` 不动 |
| **跨进程互斥** | 同平台数据根第二进程可与刷新并发 | 锁落**平台数据根锁目录** + `flock`；不放沙箱可控路径、不放宽权限 |
| **锁粒度错配** | 刷新与 start / stop / delete 交错 | 复用生命周期 name lock 这一把，不另起第二把锁（两把锁互不感知） |
| **「不停机」被破坏** | 容器重建 → 终端 / agent 状态全丢 | 刷新路径**不**触发 stop/start、不重挂载、不 `docker cp`；以容器 id / 启动时间断言 |
| **旧实例误给刷新入口** | 用户点到没有源的条目 | 旧实例读出无条目 ⇒ 无可刷对象，界面不出现入口 |

## 定向验证（**不跑全量**）

- core 包 pytest 定向用例（新增的刷新 / 元数据 / 互斥用例）。
- 真沙箱一次：运行中沙箱刷新单文件与目录，断言容器不重建、容器内读到新内容、注入路径仍只读、原件未变。
