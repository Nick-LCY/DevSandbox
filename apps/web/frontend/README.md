# 网页控制台前端

沙箱平台的网页控制台：**单页工作台**。左侧边栏是沙箱列表，右侧工作区是选中沙箱的摘要与网页终端；新建沙箱 / 沙箱详情 / 设置（代理设置 + 启动模板）都是**右侧滑出、宽度可拖拽的抽屉**。

- 技术栈：React 19 + Vite 7 + TypeScript 5.9 + Tailwind v4 + shadcn/ui（Base UI 原语），pnpm 管理，Node ≥ 22。
- 产物由后端服务在 `/` 路径直接托管，单端口对外，**前端不含任何认证逻辑**（只按连接配置发 `Authorization` 头）；**请求恒为绝对地址**（基址默认 `http://127.0.0.1:8000`，可在界面里改），**也可以在界面里配远端后端地址**（见下方「连接配置」）。
- 接口契约以 `apps/web/backend/API.md` 为唯一权威，本前端只做编排与展示。

## 安装

```bash
cd apps/web/frontend
nvm use 22          # Node ≥ 22
pnpm install
```

## 开发启动

```bash
pnpm dev            # 起在 5173
```

开发模式下页面在 5173，但**请求恒为绝对地址**（基址默认 `http://127.0.0.1:8000`）：`/api`（含网页终端的 WebSocket）**直接打到后端的 8000 端口**，不走 Vite 代理（后端已放开 CORS，跨源直连可用）。

| 前端 | 后端 |
|---|---|
| `http://127.0.0.1:5173/` | `http://127.0.0.1:8000/` |

换后端的正确做法是**在界面里改「连接配置」的后端地址**（基址恒非空、恒绝对地址），
不是改环境变量：开发模式下也不靠环境变量换后端。

代理配置在 `vite.config.ts`：`'/api'` 一条规则同时覆盖 REST 与 WebSocket（`ws: true`）——**它只是兜底**：
只有当连接配置里的基址指向 Vite 自己（`http://127.0.0.1:5173`）时代理才生效，**一般无需设置**。

## 构建

```bash
pnpm run build      # = tsc --noEmit && vite build
```

产物落在 `apps/web/frontend/dist`，后端启动时自动挂载到 `/`：

```bash
uv run --project apps/web/backend python -m sandbox_console        # 默认监听 127.0.0.1:8000
```

**`base: './'`（相对路径基址）**：产物里的资源引用是 `./assets/...` 而不是 `/assets/...`。两种部署形态都能解析——网页形态（后端 `StaticFiles` 挂在 `/`）与桌面形态（Tauri 自定义协议，Windows 上是 `http://tauri.localhost/`）都是从根路径解析。开发模式下 Vite 仍按 `/` 提供服务（`base: './'` 只影响构建产物）。

后端相关环境变量：

| 变量 | 作用 | 默认 |
|---|---|---|
| `SANDBOX_CONSOLE_HOST` | 监听地址 | `127.0.0.1` |
| `SANDBOX_CONSOLE_PORT` | 监听端口 | `8000` |
| `SANDBOX_CONSOLE_DIST` | 前端构建产物目录 | `apps/web/frontend/dist` |

## 端到端验收

验收脚本在 `apps/web/frontend/tests/`：Playwright 驱动真实浏览器，打真实控制台服务与真实沙箱。

```bash
pnpm install                # 首次：装 @playwright/test
pnpm run test:acceptance    # 一条命令跑完全部用例，退出码 0 = 通过
```

宿主 8000 端口被无关进程占用时用环境变量换端口（默认 8100）：

```bash
CONSOLE_TEST_PORT=8200 pnpm run test:acceptance
```

环境前提：Playwright chromium 1.64.1、免密 sudo、宿主 Docker、镜像代理在跑。
验收脚本自己会先跑 `cd apps && uv sync --all-packages --all-groups` 同步 Python 工作区环境（核心包与服务端包共用同一个虚拟环境），
再构建前端产物、构建一个「不存在于任何仓库」的测试镜像、拉起控制台服务并在收尾时清理干净。
用例清单、断言口径与产物位置见 `apps/web/frontend/tests/README.md`；实测数据见 `apps/web/frontend/RESULTS.md`。

## 字体

字体自托管：Noto Sans SC 400/500/600/700 与 Geist Mono 400/500 的子集化 woff2 已入库 `public/fonts/`，构建不依赖外网；文件缺失时浏览器自动回退系统字体栈。

- **字符集来源共四处**：控制台前端源码、控制台测试源码、后端沙箱平台源码（后端中文错误文案必须覆盖）、ASCII 可打印区与一组界面常用符号，最后并入**常用汉字表**。

- **字符集规模**：并入常用汉字表那次重生成，字符集由 **1104 个字符涨到 3636 个字符**（产物 `scripts/fonts/charset.txt` 与 `public/fonts/*.woff2` 同步入库）。
- **文件缺失时报错退出**：`bash scripts/build-fonts.sh` 在 `common-hanzi.txt` 不存在时直接失败，**不静默跳过**（静默跳过会产出缺字形的子集）。
- **新增中文文案后必须重跑脚本**：`bash apps/web/frontend/scripts/build-fonts.sh`（脚本会重建字符集 → 按字重实例化 → 子集化 → 整体替换 `public/fonts/`，任一字重失败则丢弃暂存产物、保留原产物）。产物入库，仓库里的字体比界面实际用到的字符多（常用汉字表全量并入）。

## 路由（两层）

前端用**哈希路由**：后端把构建产物挂在 `/` 上（静态目录托管），深链接没有服务端回退规则会直接 404；哈希路由不依赖服务端回退，刷新与粘贴链接都能落到同一个页面。

路由只有两层：工作台本身，以及「工作台 + 选中的沙箱（可选终端会话）」。

| 路由 | 地址 | 说明 |
|---|---|---|
| 工作台 | `#/` | 左侧沙箱列表，右侧空态引导块 |
| 选中沙箱 | `#/sandboxes/<名字>` | 右侧显示该沙箱的摘要与终端会话标签 |
| 选中沙箱 + 终端会话 | `#/sandboxes/<名字>/<会话标识>` | 右侧工作区直接落在该终端会话上 |

- 新建沙箱 / 沙箱详情 / 设置**不是路由**：它们是抽屉，开关状态不入路由，刷新页面自然关闭。
- 地址里的沙箱名与会话标识会做一次百分号解码；解码失败（畸形编码，如 `#/sandboxes/%`）不会抛异常打断渲染，一律退回工作台。
- 旧四页地址（`#/new`、`#/settings` 等）不再有对应路由，解析时也退回工作台。

## 连接配置（基址 / 凭据 / 未配置态）

**后端在哪、用什么令牌**是一份独立状态，收敛在 `src/lib/connection.ts`（存取 + 推导 + Hook，纯逻辑，有单元测试）。
**决策 D：基址恒非空**——默认 `http://127.0.0.1:8000`，允许编辑、**不允许置空**；「空 = 同源」语义废除（请求恒为绝对地址）。**两种形态在连接配置上没有差别**：同一份前端产物（网页端与桌面端）都能配任意后端地址。

| 口径 | 规定 |
|---|---|
| 模型 | `{ backendBaseUrl, token }`；`backendBaseUrl` **恒非空**（默认 `http://127.0.0.1:8000`），非空 = 连那台主机（**两种形态都能填**） |
| 基址默认值 | **`http://127.0.0.1:8000`**（`DEFAULT_BACKEND_BASE_URL`）：地址框**预填**它，**允许编辑**，**不允许置空**（网页形态与桌面形态一个口径）。**存量配置里基址为空的，读到时归一为这个默认值**（决策 D 之前「空 = 同源」留下的数据，存量用户不受影响） |
| 令牌随地址走 | **后端地址填的是哪台主机，访问令牌就会随请求发到哪台主机；填错地址等于把令牌交给那台机器。** |
| 存储 | 存储键 `sandbox-console-connection`，localStorage；存取口径与 `src/lib/theme.ts` 同款（非法值 / 读取失败回落默认 = 未配置；存储不可用时静默忽略） |
| 落盘时机 | **只有用户主动保存才写存储**；挂载时不写 |
| 基址归一 | 去空白、补 scheme（`127.0.0.1:8000` → `http://127.0.0.1:8000`）、去尾部斜杠（基址后面直接拼 `/api/...`，不出双斜杠）；**空值落回默认地址**（不再表示「同源」）。**归一规则只有 `normalizeBaseUrl` 一处**（`src/lib/connection.ts`）：配置存取、请求基址、桌面 CSP 同步、终端 WS 推导都用它 |
| 基址形状 | **只到主机与端口**：带路径 / 查询 / 片段一律拒绝（红字「后端地址不要带路径、参数或 #」）——后端接口都在根路径下，填了路径反而对不上；**空值也拒**（红字「请填写后端地址」） |
| 配置归一 | 基址与令牌在**配置层**统一归一（`cacheConnectionConfig` / `setConnectionConfig`）：基址补 scheme、去尾部斜杠，令牌去空白。**不再按形态收敛**（曾经网页形态的基址恒为空，现已取消） |
| 请求基址 | `resolveApiBaseUrl()`：**恒为绝对地址**（`<基址>`，去尾部斜杠）；**没有「空 = 同源」的相对路径分支** |
| 凭据 | **每个请求都带 `Authorization: Bearer <token>`**（后端对全部 `/api` 生效，含 `/api/health`） |
| 令牌缺失 | **一个请求都不发**：接口层抛 `ConnectionNotConfiguredError`，上层进引导态（不拿 401 刷屏） |
| 运行期失效 | 轮询路径上拿到 `ConnectionNotConfiguredError` → **回到引导面板**（置 `configured=false`），**不弹普通错误 toast**——「去配置连接」比「读取沙箱列表失败」有用 |
| 终端地址 | `terminalSocketUrl()`：**恒从基址推导**（`http→ws` / `https→wss`，**不保留路径**，与 HTTP 侧口径一致）；**不再按 `window.location` 回退**。推导前**先过归一层**（`normalizeBaseUrl`）：用户填 `10.0.0.5:8000`（漏 scheme）也推得出来 |
| 终端地址非法 | 基址为空或**推导不出来**（如 `ftp://`）时**不猜一个地址**：`terminalSocketUrl()` 返回 `null`，终端视图进「连接地址非法」状态——猜地址会把「连错了地址」变成「连到了别的地方」。**主机名带非 ASCII 字符**（如中文）同样判非法：URL 解析会按 IDNA 把它编成 punycode 主机（`不是地址` → `xn--ihqq6tnb086g`），那是用户没写过的地址，不猜 |
| 终端票据 | 浏览器发起的 WebSocket 不能设请求头，握手靠 `?ticket=`：每次连接 / 重连前先 `POST /api/auth/ticket` 现取一张（30 秒有效、用过即废，**不缓存**） |
| 运行形态 | 特性探测 `window.__TAURI_INTERNALS__`（**不引 `@tauri-apps/api`**）：只用于**桌面运行时的 CSP 同步**，不再决定「地址能不能填」 |

### 桌面形态：动态 CSP 的同步与主文档重载

桌面壳的主文档 CSP 里要带上**用户配的后端主机**（host 级放行，口径与时序契约见
`apps/desktop/README.md` 的「CSP」一节与 `apps/desktop/src-tauri/src/csp.rs`）。前端这边：

- `syncDesktopBackend(baseUrl)`（`src/lib/connection.ts`）：先 `invoke('set_backend_base_url')` 更新桌面壳的状态，
  再 `invoke('csp_needs_reload')` 问「这一版主文档的 CSP 跟上了吗」，**没跟上就 `location.reload()`**。
- **送出去的基址恒为「非空且已归一」**（过 `normalizeBaseUrl`）：用户可能填漏了 scheme 的 `10.0.0.5:8000`，
  原串送进 Rust 侧的 `Url::parse` 会解析失败 → `connect-src` 静默少掉那台主机 → 跨主机请求全被 CSP 拦死
  （界面上看不出原因）。
- **同一个后端基址只送一次**（本次页面会话内，**按归一值比较**：`10.0.0.5:8000` 与 `http://10.0.0.5:8000` 算同一个）：
  桌面壳的状态已经是它了，重复送没有意义。
- **桌面形态启动时先同步再挂载工作台**：那一版主文档的 CSP 还拦着跨主机请求，工作台的轮询先发出去只会白跑。
- **改了后端地址 → 主文档会重载一次**（重载后这一版 CSP 才带上新主机）。这是正常现象，配置存在 localStorage 里，重载后直接进工作台。

### 未配置态（引导面板）

**未配置 = 令牌为空**（基址恒有默认值，不参与判定；两种形态一个口径）。

- 未配置时**不渲染工作台**，改渲染 `src/components/workbench/ConnectionSetup.tsx`（后端地址 + 访问令牌 + 「保存并连接」）。
- **未配置态不是路由**：地址栏仍然是 `#/`，刷新页面回到这里。
- 未配置时工作台**整体不挂载**：沙箱列表轮询（5 秒）与健康自检轮询（15 秒）**一个都不启动**；保存配置后工作台挂载，轮询立即开始。
- 后端地址**两种形态都能填**：**预填默认值 `http://127.0.0.1:8000`**，填了就连那台主机（网页端也一样，不再固定同源）。
  **基址恒非空**：留空由**通用必填校验**就地红字拦下（文案「请填写后端地址」，带 `role="alert"`）——
  **网页形态与桌面形态一个口径**（不再有桌面特判），且**不进「写 pending → 同步 CSP → 重载 → 体检」那套流程**。
- 「保存并连接」的动作口径：**先体检再保存**——只有健康检查通过才保存配置、才挂载工作台；
  不通过就**就地红字**报错，**配置不落盘、工作台不挂载**。红字分两种（`describeHealthFailure`）：
  「令牌无效：<后端 detail>」与「后端不可达：<原因>」（两种失败态不混）。
- 桌面形态的「保存并连接」多一步：**先同步 CSP（可能要重载主文档）再体检**。跨主机的健康检查会被
  旧 CSP 拦死，所以草稿先落在**待验证配置**（存储键 `sandbox-console-connection-pending`）里，
  重载回来时用它体检，**体检通过才提升为生效配置**；不通过就清掉待验证配置、回引导面板并就地红字。
- 令牌从哪来：后端部署处的 `<平台数据根>/console-token.json` 文件，或用环境变量 `SANDBOX_CONSOLE_TOKEN` 注入。

### 设置抽屉的「连接配置」区

设置抽屉第三区（代理设置、启动模板之后）：后端地址 + 访问令牌 + 「测试连接」+「保存配置」。

- 「测试连接」拿**还没保存的草稿值**打一次 `GET /api/health`，成功弹成功 toast、失败弹失败 toast（来源 `connection`）。
- 「保存配置」把草稿落盘（桌面形态下顺带把后端基址经 IPC 告诉 Rust 侧，让动态 CSP 跟着走）。
  **顺序是先落盘再同步**：同步可能要重载主文档，重载后配置得还在。
- **桌面形态下「保存配置」还会重启已开启的本机监听**（`restartForwardListeners`）：
  令牌与后端基址是**开启监听那一刻的快照**，不重启的话旧监听仍拿着旧凭据，隧道会以 `1008`（策略违规）收场。
  口径：`forward_listeners` 拿当前状态 → 逐个 `stop_forward` → 用新凭据 `start_forward` **同端口**重开；
  **逐条独立**，一条失败弹一条失败提示（来源 `port-forward`），不中断其余条与保存流程。
- 后端地址**两种形态都能填**：**预填默认值 `http://127.0.0.1:8000`**，填了就连那台主机。
  **基址恒非空**：留空由**通用必填校验**就地红字拦下（文案「请填写后端地址」）——**网页形态与桌面形态一个口径**，
  **不落盘、不同步 CSP**。
- 本地校验（地址为空 / 格式非法 / 带路径参数 / 令牌为空）**就地红字**展示（带 `role="alert"`，读屏能播报），不发请求。
- 已知边界：桌面形态下**改了后端地址后，第一次「测试连接」会被 CSP 拦掉**（这一版主文档的 CSP 里还是旧主机，
  表现是「后端不可达」）。先「保存配置」（重载一次主文档），再测。

## 后端健康自检

侧栏底部常驻一条健康自检（`GET /api/health`，每 15 秒一次）：后端不可达时直接提示「后端服务不可达」并给出原因；后端可用但前端产物未挂载时提示「前端产物未挂载」。

**令牌无效与后端不可达分开说**（`describeHealthFailure`，两种失败态不混）：

| 失败 | 文案 |
|---|---|
| 令牌无效（401 / 403） | 「令牌无效：<后端 detail 原文>」 |
| 其余失败（网络不通 / 超时 / 后端 500） | 「后端不可达：<原因>」 |

健康自检在折叠态只留一个状态点（文字用 `sr-only` 收起来：视觉隐藏，**仍留在可访问树里**），可访问名也不会丢——容器带 `aria-label="后端健康：<健康文案>"`，跟随健康状态变化。

## 侧栏折叠

侧栏可折叠成一个只留图标的窄条（56px），状态自持（`src/lib/sidebar-collapsed.ts`），不入路由、不入 URL。

| 口径 | 规定 |
|---|---|
| 宽度 | 展开 264px（`w-[264px]`）↔ 折叠 56px（`w-14`），宽度变化带 200ms 过渡 |
| 存储 | 存储键 `sandbox-console-sidebar-collapsed`，存 `'1'`（折叠）/ `'0'`（展开）；**默认展开**，非法值与读取失败一律回落展开 |
| 落盘时机 | **只有用户主动点折叠按钮才写存储**；挂载时不写（读到什么就是什么） |
| 隐藏方式 | **只切样式不卸 DOM**（`hidden` / `sr-only`）：「新建沙箱」按钮始终挂载，**页面上恒有两个 `page-sandbox-list-create-button`**（侧栏顶部 + 右侧空态引导块），验收脚本取第一个即可 |
| 底部工具 | 健康状态点 / 设置 / 主题切换 / 折叠按钮**永远贴在侧边栏底部**（容器带 `mt-auto`）：它不依赖列表撑高——列表折叠收起后，底部工具也不会浮到顶部去 |
| 开关语义 | 折叠按钮是「动作名随状态变化」的普通按钮：可访问名与 `title` 在「收起侧栏 / 展开侧栏」之间切换，**不带 `aria-expanded`**（它不是开关，是两个动作） |

## 终端全屏与焦点回填

终端面板右上角有一个全屏开关（`page-sandbox-detail-terminal-fullscreen-button`）。

**全屏口径**：

- **纯 CSS 覆盖**：面板切到 `fixed inset-0 z-40`，盖住整页；**不用 `requestFullscreen`**（那会进浏览器全屏态，退出得靠 Esc / F11，与「再点按钮退出」的口径不合）。
- **层高必须低于浮层**：全屏层 `z-40`，弹窗 / 抽屉是 `z-50`，toast 是 `z-[100]`——弹窗与提示永远浮在全屏面板之上。
- **状态不入存储、不入路由**：只活在本地面板状态里，刷新页面回到常规布局；换沙箱时自动退出全屏。
- **退出 = 再点同一个按钮**：不绑 Esc、不绑 F11（Esc 归容器 shell 管）。
- **不接管浏览器保留键**：全屏不改变键盘口径，`Ctrl+N` / `Ctrl+W` / `F5` 等仍然是浏览器保留键（见下方「快捷键全量拦截」）。

**焦点回填口径**（会话切换会让终端**整块重挂载**，重挂载后浏览器焦点落到 body，新终端就成了看得见、敲不进 pty 的「空心光标」）：

- **回填只在两种情况下发生**：① 用户刚点了标签 / 点了终端表面 / 新建了会话（明确的操作意图）；② 判定当下焦点就在终端表面内（重挂载把焦点弄丢了，要恢复）。
- **绝不抢别处的焦点**：焦点在抽屉输入框等终端表面之外时，一律不回填。
- **判定活读 `document.activeElement`**（口径在 `src/lib/terminal-focus.ts`）：终端重挂载会把 xterm 的 helper textarea 从 DOM 摘掉，浏览器把焦点复位到 body 且**不派发 `focusin`**——只靠事件跟踪记下来的标志会永远停在 true，门控会退化成「永远回填」。
- 一个终端实例**只回填一次**：重试连接（重建 WebSocket）不会把挂载时刻的值再拿出来用一次。

## 操作反馈（toast）

**所有操作结果反馈都从右上角以 toast 弹出**，不再在页面里挂内嵌的结果横幅。
底座是 Base UI 自带的 Toast 原语（`src/components/Toast.tsx`），全局只挂一个
`ToastProvider`（在 `src/App.tsx`），不引第二套组件库。

| 口径 | 规定 |
|---|---|
| 位置 | 右上角固定视口（`page-toast-region`），`Portal` 挂到 `body`；视口补 `data-console-shell`，选中态与 `color-scheme` 规则照样命中 |
| 类型 | 成功=品牌绿（`--app-success` / `--app-success-soft`）、失败=红（`--app-destructive` / `--app-destructive-soft`）、提示=蓝（`--app-info` / `--app-info-soft`）；组件里不写裸色值 |
| 时长 | 出现后 **5 秒自然消失**（倒计时由 `ToastProvider` 层的自有计时器统一管：Base UI 的自动关闭置 0，圆环画满与 toast 消失共用同一份时间，不会各走各的） |
| 关闭键 | 每条 toast 右上角有 `×` 关闭键，可提前关闭 |
| 倒计时 | 关闭键外围一圈描边圆环（SVG `stroke-dasharray` / `stroke-dashoffset`），5 秒线性画满，与自动消失同步（画满即消失）；关键帧 `app-toast-countdown` 写在 `src/styles/globals.css`，时长取同一个常量。反馈被顶替时圆环按「代次」重建（代次只增不减），画满与消失始终同步 |
| 同时几条 | 同一时刻只留**最新一条**：新的操作结果直接顶掉旧的（轮询失败不会刷屏） |
| 谁弹 | 用户主动触发的操作失败**立刻弹**；**首次加载失败也立刻弹**；后台轮询（沙箱列表 5 秒一轮、终端会话表 10 秒一轮、沙箱详情 + 转发记录合并轮询 10 秒一轮）**逐次失败不弹，连续失败 3 次弹一条**（任一次成功即清零）——后端整体不可达时侧栏底部的健康自检已经常驻提示，但端点级失败（接口 500）它兜不住，必须另有提示 |
| 倒计时何时会停 | **只有窗口失焦会停**（`window` 的 blur 事件）：失焦时倒计时停表、圆环停画；回前台时整条**重走 5 秒**（圆环重画 + 计时器重走），不是接着上次剩的时间继续。页面上悬停、点提示区、聚焦提示区、按下提示条、按 F6 都**不**暂停（Base UI 默认会暂停，还会接管 F6 把提示区聚焦并按停倒计时，已逐条拦掉） |
| 滑动关闭 | 关掉（`swipeDirection={[]}`）：Base UI 的滑动会顺带挂 pointerdown 处理器，触摸按下会把倒计时按停 |

不归 toast 管的就地展示（豁免）：

- **本地表单校验红字**：留在抽屉内就地展示（如新建沙箱的沙箱名 / 挂载 / 环境变量校验）；
- **删除确认弹窗里的绿色提示块**（`page-sandbox-detail-delete-untouched-note`，「用户挂载的宿主机目录不受影响」）：留在弹窗原位，不走 toast；
- **镜像列表读取失败的就地说明**（`page-sandbox-create-image-status`，`role="status"`）：一行灰色环境状态说明（「镜像列表读取失败，原因见右上角提示：…」）。它是**环境状态**不是操作结果（操作结果仍走右上角 toast），但 toast 5 秒就消失，只留 toast 会让抽屉里只剩一个没有解释的空的选择器；
- **模板列表读取失败的就地说明**（`page-sandbox-create-template-status` 与 `page-settings-template-status`，`role="status"`）：同上口径，镜像那份的孪生兄弟；
- **文件目录读取失败的就地错误态**（`page-file-browser-error`，`role="alert"`）：面板状态不是操作结果，只在面板里显示（不弹 toast）；
- 加载态、状态点与胶囊、空态、确认弹窗文案：一律不动。**按钮的加载态**（新建沙箱 / 刷新镜像 / 停止 / 删除 / 关闭会话 / 重启代理）统一是「旋转图标 + 无省略号文字」（图标用 lucide `Loader2`，尺寸 `size-3.5`，旋转用 `animate-spin`，图标在文字前、间距沿用按钮既有的 `gap-1.5`）；**不是按钮的加载文案**（`正在读取沙箱列表…` / `正在读取沙箱详情…` / `正在读取代理状态…` 等段落文字）保持省略号不变。

## 删除确认弹窗

弹窗支持 `Esc` 关闭与点遮罩关闭（删除进行中两者都不响应）。

删除沙箱是**一次确认**：点「确认删除」就直接发 `DELETE`。删除前不再预取回收清单，
弹窗只说两件事——删了会怎样（容器、网络、守护进程与系统用户都会被回收，不可撤销）、
哪些东西不受影响（「用户挂载的宿主机目录不受影响」，绿色提示块）。

## 停止确认弹窗

停止沙箱也要确认：工作区头部的「停止」按钮只开弹窗，不直接发请求。
弹窗标题是「停止沙箱 {名字}」，内容是后果说明（容器退出、文件与配置保留、可随时再启动）
加一个「同时停止依赖容器」复选框（**默认勾选**，与命令行默认一致）。
点「确认停止」才发 `POST /api/sandboxes/{name}/stop`；停止进行中 Esc 与遮罩都不响应。

- **每次打开都回到默认勾选**：上一次取消时的勾选状态不粘到下一次（否则会误停别的依赖容器）。
- **停止失败不关弹窗**：请求失败只弹一条失败 toast，弹窗留在原地可以直接重试（只有成功才关）。

## 弹窗与焦点管理

确认类弹窗走 `src/components/workbench/ModalShell.tsx`，底层是 Base UI 的 Dialog 原语（`src/components/ui/dialog.tsx`，`@base-ui/react`）。

- **焦点陷阱**：弹窗打开时焦点落进面板，`Tab` / `Shift+Tab` 在面板里循环，不会跑到背后的页面上。
- **背景不可交互**：弹窗开着时背景内容被标记为 `aria-hidden`（辅助技术读不到），`Tab` 走不到背景上；遮罩盖住整页，背景也点不到。
- **焦点归位**：弹窗关闭后焦点回到打开它的那个按钮。
- **关闭途径三条**：Esc、点遮罩、点右上角 `×`（lucide 图标）；三条都走 `onOpenChange(false)`，调用方可以按业务需要拦住（比如删除进行中一律不响应）。
- **默认宽度 440px**，确认类弹窗都按内容大小再单独收窄（删除 400px、停止 400px、关闭会话 360px）。
- **宽度只收像素数字**：`ModalShell` 的 `maxWidthPx` 属性收的是像素值，类名从源码里的字面量表（`WIDTH_CLASS`）取。**不能改成运行期拼类名**：Tailwind v4 只为源码里的字面量生成 CSS，运行期拼出来的 `sm:max-w-[…]` 根本没有对应规则，面板会一路撑到视口宽度（曾因此把 400px 的弹窗渲染成 1872px 满宽）。`globals.css` 里有三条 `@source inline(...)` 兜底。
- **窄屏回落**：视口窄于 640px 时不套断点变体，按视口留边（`max-w-[calc(100%-3rem)]`）。

## 抽屉（右侧滑出）

新建沙箱 / 沙箱详情 / 设置走 `src/components/workbench/DrawerShell.tsx`，底层是 Base UI 的 Drawer 原语（`src/components/ui/drawer.tsx`，零新增依赖）。

- **右侧滑出**：抽屉从右侧滑入，`swipeDirection="right"`。
- **宽度可拖拽**：面板左边缘一条 14 像素竖条（`page-drawer-resize-handle`，`role="separator"`），条子中间竖直放一个抓握图标（lucide `GripVertical`）提示这里能拖。拖动时只更新抽屉内部的本地状态，**松手才**把最终宽度上抛并写入存储（避免每像素重渲染整个工作台）。把手上按左右方向键每次调 2 个百分点，`Home` 回默认宽度。
- **已知边界（窄屏）**：视口宽度 < 640px 时抽屉**占满整屏**（宽度百分比不生效），**拖拽把手不提供入口**（`hidden sm:flex`）——可见但拖不动的把手会把脏宽度写进存储，窄屏干脆不给拖拽入口。窄屏下想调宽度得把窗口拉宽。
- **宽度共用一个存储键**：`sandbox-console-drawer-width`（`src/lib/drawer-width.ts`），存的是视口宽度的百分比，默认 40，钳位区间 [20, 80]。三个抽屉共用一份宽度：拖动任意一个，其余两个跟着变；刷新页面后保持。
- **滑动关闭**：Base UI 的横向滑动关闭**没有开关**，因此拖拽把手挂了 `data-base-ui-swipe-ignore="x"`，正文容器挂了 `data-base-ui-swipe-ignore`（表单里拖选文本不会被吃掉）。验收脚本一律用「点 × / Esc」关闭，不写滑动关闭。
- **传送 body 后配色不丢**：抽屉传送挂到 `body`，脱离了 `[data-console-shell]` 作用域，因此面板上自己挂 `data-console-shell=""`，选中态与 `color-scheme` 规则照样命中。
- **关闭途径**：Esc、点遮罩、点右上角 `×`；三条都走 `onOpenChange(false)`。
- **退场动画两层同长（150ms）**：遮罩（`ui/drawer.tsx` 的 `duration-150`）与面板（`DrawerShell.tsx` 的 `[--tw-duration:150ms]`）必须一致——Base UI 只等**面板**上的动画结束就卸载整棵树，遮罩若先播完，淡出结束后会闪回全屏（实测透明度 0.07 → 1.00）。两层都带 `data-closed:[--tw-animation-fill-mode:forwards]`，动画播完停在末帧，不回弹。
- **面板不挂 `duration-*`**：Tailwind 的 `duration-*` 会同时输出 `transition-duration`，默认 `transition-property: all` 会把宽度一起过渡，拖拽把手时面板滞后 150ms 不跟手。动画时长只写 `[--tw-duration:…]`（只影响 `animation` 简写）。

## 关键行为

### 沙箱详情与转发记录的合并轮询

工作台选中一个沙箱后，**每 10 秒一拍**，并行刷两份数据（`GET /api/sandboxes/<名>` + `GET /api/forwards?sandbox=<名>`）：

| 口径 | 规定 |
|---|---|
| 触发条件 | **当前有选中沙箱**（`selectedName` 非空）才跑；换沙箱 / 清空选中时定时器重建 |
| 与抽屉无关 | **不管沙箱详情抽屉开没开都跑**（抽屉关着时数据也得是最新的） |
| 打开抽屉 | 抽屉**从关到开的瞬间立即刷一次**（不等下一拍）；这一拍是**非 silent**（用户主动触发的操作，失败**立即弹** toast），**不计入**周期节拍的连续失败计数 |
| 落点 | 详情进 `detail`、转发记录进 `forwards`；两份各带**请求序号护栏**（旧响应回来直接丢弃，不许乱序回写） |
| 失败口径 | 周期节拍是 **silent**：**逐次不弹**（会刷屏），**连续 3 次失败弹一条失败 toast**（来源 `sandbox-detail`，任一次成功即清零）；**页面不可见时整拍跳过**（省一次往返，也不让后台标签页堆积请求） |
| 手动刷新 | 工作区头部的刷新按钮**只刷详情**，失败**立即弹**（维持现状） |
| 数据流向 | **转发记录由工作台持有**，经 props 传给详情抽屉 → 端口转发区；**面板自己不拉**（web 形态的面板连数据都不读） |
| 形态差异 | **转发记录的读取在工作台层且仅桌面形态执行**：**web 形态只刷详情**，转发记录一个都不读（面板不渲染行，没有读它的理由） |

纯逻辑（一拍算不算失败、失败文案怎么拼）在 `src/lib/sandbox-poll.ts`，有单元测试；轮询定时器本身留在组件层（与终端会话表的轮询同款骨架）。

### 新建沙箱

- 镜像选择器（输入即本地筛选）来自 `GET /api/images`（后端返回**裸数组**，前端按数组消费）。底座是 Base UI 的 Combobox 原语（`src/components/ui/combobox.tsx`）：输入框里打字只在前端筛，不发请求；选中后输入框回填镜像引用。
- **不自动选中任何镜像**：抽屉打开后输入框是空的（只有 placeholder 引导），详情行为空，选中由用户显式决定；没选中就提交会就地报「请选择沙箱镜像」。曾经自动选中默认镜像，原语随即把 label 回填进输入框，真实用户是在预填文字后追加，打字永远命中不了。
- **「输入框显示」与「实际提交」同一份**：提交用的镜像引用就是输入框文字完全匹配上的那张；用户改字等于放弃原选择，两者不会分叉。
- 输入框**内部右侧**有下拉箭头（`page-sandbox-create-image-trigger`，lucide `ChevronDown`，`size-4`）：箭头是**纯指示器**——绝对定位贴在输入框内、`pointer-events-none`、对辅助技术隐藏，**点击穿透到输入框**（原语默认点输入框即展开弹层）；弹层展开时输入组带 `data-popup-open`，箭头据此**旋转 180°**（带过渡）。弹层内容区限高 288px 且不超过视口可用高度，选项超高时列表内部滚动。
- 候选项**逐项给指针光标**（`cursor-pointer`）：选项渲染成 `role="option"` 的 div，不是 button，`globals.css` base 层的 `[role=option]` 兜底会被组件层的工具类盖住，因此光标在 `ui/combobox.tsx` 的选项层直接写死。
- **候选为空时列表不留空白带**：列表带 `data-empty`，据此去掉内边距（`data-[empty]:p-0`），弹层高度贴合内容（空态提示之外不多出一截）。
- 镜像选择器的弹层挂在 body 上（`page-sandbox-create-image-popup`）：脱离控制台外壳的作用域，因此 Portal 上补了 `data-console-shell`（配色作用域照样命中）与 `data-base-ui-swipe-ignore`（抽屉的横向滑动关闭不误伤弹层）。
- 镜像选择器在**页面重新可见时**（`visibilitychange`）会补拉一次，贴合「实时」要求：切回标签页就能看到宿主上的最新镜像。
- 挂载按 `宿主路径:容器路径[:ro]` 语法声明，可多条；前端先做一遍格式与敏感路径校验，**容器路径重复也在前端先拦**（少一次往返），后端仍会再校验一次。
- **文件注入**按 `宿主路径:容器路径` 语法声明（固定两段，容器内一律只读），可多条；平台把宿主文件复制到沙箱用户家目录后以只读方式挂进容器。抽屉里对应「文件注入」区（挂在载区之后、命令输入框之前），行里**没有只读开关**（容器内本来就只读），这一区**除空态提示外不挂任何解释性文案**（只有区标题、「添加文件」按钮、两个输入框与「移除」按钮；一行都没声明时显示一句「暂未声明注入。」，与挂载区的「暂未声明挂载。」同形态）。前端同样先做一遍校验（格式 / 敏感路径 / 宿主与容器路径重复），后端仍会再校验一次。
- 提交时固定带 `image_source=host`：平台把镜像从宿主导出注入沙箱守护进程，不经镜像代理拉取。
- 读镜像列表失败与提交失败都弹**失败 toast**；本地校验（沙箱名 / 镜像 / 挂载 / 环境变量）仍在抽屉里就地展示红字。镜像列表读不到时，抽屉里另留一行就地环境状态说明（`page-sandbox-create-image-status`），免得只剩一个没有解释的空的选择器。
- **创建成功后直接关抽屉**并弹一条**成功 toast**「沙箱 X 创建成功」，列表自动刷新；不再有成功面板，也**不自动选中**新建的沙箱（需要时从左侧边栏选）。
- **创建请求在途时抽屉不响应关闭**（Esc / 遮罩 / × 一律不关）：请求已经发出，不能半途退出（与删除 / 停止弹窗口径一致）。

### 加载模板与保存为模板

新建沙箱抽屉里**最上方**（沙箱名输入之前）就是「加载模板」块；「保存为模板」按钮在抽屉**页脚**，紧靠「创建沙箱」主按钮的左侧（次级按钮样式）：

- **加载模板**是可搜索下拉（复用 `src/components/ui/combobox.tsx`，与镜像选择器同一套写法），候选来自 `GET /api/templates`（后端返回裸数组），**前端本地按模板名做子串筛选**，不发请求。
- **选中即回填**：选中模板后直接按合并口径改写表单（不另设「应用」按钮）。
- **模板声明原样回填**：模板里的字符串**不做任何占位符替换**（含 `{name}` 这样的字面量），模板里写了什么，表单里就是什么。
- **模板里的镜像不在宿主本地镜像列表里**：镜像选择器留空（不回填一个选不上的镜像），提交时走既有的「请选择沙箱镜像」校验红字。
- **保存为模板**走 `ModalShell` 命名弹窗（面板宽 400px）：名称输入 + 保存 / 取消，**空名禁提交**（按钮直接禁用 + 就地红字），保存成功弹一条**成功 toast**（来源 `sandbox-template`）并关掉弹窗、刷新模板列表。
- 抽屉打开时**并行**拉镜像列表与模板列表；两个列表读不到时各自弹失败 toast，并在抽屉里留一行就地环境状态说明。
- 模板管理区在设置抽屉里（见下）。

### 启动模板

模板是一份「沙箱启动配置」：镜像、挂载声明、文件注入声明、启动命令、工作目录、环境变量、网桥网络。口径四条：

| 口径 | 规定 |
|---|---|
| **合并语义** | 模板里**出现**的字段**整体替换**表单值（挂载列表整组替换，不是逐条并入；文件注入列表整组替换；环境变量整组替换），**没出现**的字段保持表单现状。「出现」用 `hasOwnProperty` 判——`{"image": null}`（填了空值）与缺 `image` 字段（没填过）是两回事 |
| **声明原样透传** | 模板配置里的字符串**不做任何占位符替换**：加载时原样回填表单，提交时原样进创建请求（挂载路径、环境变量值、启动命令、工作目录、网桥网络名一律不替换）。模板里写了 `{name}` 这样的字面量，平台就收到这个字面量，由后端既有校验兜底（路径不存在会得到明确报错） |
| **命令可以是数组** | 后端契约收 `str \| list[str] \| null`：字符串命令按 shell 引号规则切分；**数组命令前端装不进单行输入框**，加载模板时进隐藏状态原样透传（每个元素同样原样保留），命令输入框留空，提交时**隐藏的数组命令优先于表单命令** |
| **`~` 口径** | 挂载声明的宿主路径允许家目录写法（`~`、`~/data`）；前端解析器放行，后端落库前把 `~` 展开成服务运行用户的家目录。`~other`（别人的家目录）不展开也不放过。**服务以 root 身份运行时 `~` 展开为 `/root`，命中敏感目录拒绝清单返回 400**——这是既有契约的自然结果，不是缺陷 |

- 模板里的**网络**不在新建沙箱抽屉里渲染输入项（表单默认用平台自建网络），但模板携带的网络会**透传**进 `POST /api/sandboxes`。
- **模板回填的镜像**：只有宿主镜像列表**已经拿到过**时才判「模板镜像在不在宿主上」——镜像列表是秒级的宿主枚举、模板列表是毫秒级的文件读，模板几乎总是先到；列表没到手时**先原样保留**模板镜像（不能拿空列表当全集），列表到齐后由既有的清理逻辑兜底（镜像真不在就清空，提交时报既有校验）。
- 保存为模板时**只写有值的字段**（镜像 / 命令 / 工作目录 / 网络非空、挂载列表非空、文件注入列表非空、环境变量非空才写入），没值字段不进配置（空配置会让「出现即替换」变成「清空用户填的东西」）；**空挂载行不进配置**（宿主路径与容器路径同时为空的行是假声明），两段路径先 trim 再入库。文件注入行同理：全是空行时**不写 `files` 键**（写了等于「出现即替换」把用户填的行清空）。
- 模板里的挂载声明解析采用**宽松口径**：宿主路径不要求已存在、不查宿主敏感目录；解析不了的声明**整条跳过**并报条数（提示 toast，来源 `sandbox-template`），不让一条畸形声明把整份模板废掉。模板里的文件注入声明同样是宽松口径（段数必须恰好两段、宿主段允许绝对路径或 `~/` 开头、容器段必须绝对、路径含逗号整条跳过），跳过条数**另弹一条 toast**（与挂载那条分开，文案各说各的）。

### 删除沙箱

点「删除」直接开确认弹窗（**不预取回收清单**），点「确认删除」才发 `DELETE`，点「取消」一个删除请求都不发。删除后弹一条 toast 告知回收了多少项，沙箱没了则回到工作台首页。

### 网页终端

- xterm.js（`@xterm/xterm`）+ fit 插件（`@xterm/addon-fit`），随窗口自适应。
- **终端表面分两层**：外层是视觉层（圆角、边框、内边距、深色底，`overflow-hidden` 不滚动），内层是测量/挂载盒（`page-sandbox-detail-terminal-mount`，无内边距无边框，xterm 根元素挂在这里）。fit 插件量的是父容器的**边框盒**且只减终端元素自身的 padding，所以测量盒必须单独一层：放在带 padding 与 border 的表面上，那 26 像素（padding 24 + border 2）会被漏算，终端恒定溢出、外层长出原生滚动条。
- **终端区域只有一根滚动条**：xterm 内部那根（`.xterm-viewport`，承载 5000 行回滚），暗色定制样式在 `src/styles/globals.css`（8 像素宽、半透明滑块、悬停加深；Firefox 走标准属性兜底）。外层任何容器都不滚动，字符不会越过暗色面边缘。
- 自托管字体 swap 晚到会让列数失配（fit 用的是量出来的字符宽度），字体就绪后补一次 fit。
- **尺寸自适应带去抖**：侧栏宽度过渡（200 毫秒）期间主列宽度逐帧变化，挂载盒的 `ResizeObserver` 逐帧触发；不去抖的话每一帧都会 fit + sendResize，把一串尺寸帧逐个回打到 pty。去抖窗口 100 毫秒，窗口内只保留最后一次（口径在 `src/lib/terminal-fit.ts`）。
- **终端全屏**：面板**纯 CSS 覆盖**整页（`fixed inset-0 z-40`，层高低于弹窗 / 抽屉的 `z-50` 与 toast 的 `z-[100]`）；状态不入存储、不入路由，刷新页面复原；退出全屏 = 再点同一个按钮（不绑 Esc / F11）；**不接管浏览器保留键**。详见「终端全屏与焦点回填」。
- **焦点回填**：会话切换后终端整块重挂载，浏览器焦点落到 body（看得见、敲不进 pty）。只在「用户刚点了标签 / 点了终端表面 / 新建了会话」或「判定当下焦点就在终端表面内」时回填，**绝不抢抽屉输入框的焦点**。详见「终端全屏与焦点回填」。
- **标签 = 会话**：标签条的数据源就是后端的会话表（`GET /api/terminal/sessions?sandbox=<名>`），一个标签一个会话；点标签即附着到该会话（服务端回放现场缓冲），标签尾的 `×` 是**关闭会话**（会终止容器内该会话的进程树），先弹确认。
- 终端配色与字体固定（两套主题恒定）：`Geist Mono` 12.5px，背景 `#152019`、前景 `#e3ebe5`、光标 `#a7d8af`、选区 `#2b3d31`。
- **快捷键全量拦截**：带 Ctrl / Meta / Alt 的组合一律 `preventDefault`（不让浏览器抢走），但仍然编码后送进容器内的 shell（`Ctrl+C` 必须能到 pty）。浏览器保留键交回浏览器：`Ctrl+N`/`Ctrl+Shift+N`、`Ctrl+T`/`Ctrl+Shift+T`、`Ctrl+W`/`Ctrl+Shift+W`、`Ctrl+Q`、`Ctrl+Tab`/`Ctrl+Shift+Tab`、`F5`、`F11`、`F12`、`Alt+F4`、`Ctrl+P`、`Ctrl+S`。
- **剪贴板快捷键**：`Ctrl+Shift+C` 把终端里的选区复制到系统剪贴板，`Ctrl+Shift+V` 把系统剪贴板的内容粘贴进终端（走 xterm 的 `paste`，括号粘贴模式与换行归一由它自己做，不直接往 socket 塞字节）。macOS 的 `Cmd+Shift+C` / `Cmd+Shift+V` 同样触发。**成功路径零 UI 反馈**；没有选区时按 `Ctrl+Shift+C` 静默不做任何事；剪贴板 API 不可用（非安全上下文）或读写失败时弹**失败 toast**（来源 `terminal-clipboard`，文案「复制到系统剪贴板失败」/「读取系统剪贴板失败」）。剪贴板接口要安全上下文（127.0.0.1 或后续反代 TLS），首用读取可能弹一次浏览器授权，属预期行为。快捷键的分类规则在 `src/lib/terminal-shortcuts.ts`（纯函数，可单测）：`Ctrl+C` 仍然是发往容器的 SIGINT、`Ctrl+V` 仍然是字面量 0x16、浏览器保留键仍然放行，这三条语义不受剪贴板快捷键影响。
- 帧协议按 `API.md` 12.3：客户端二进制帧 = 终端输入字节，客户端文本帧 = `{"type":"resize","cols":..,"rows":..}`；服务端二进制帧 = 终端输出字节，服务端文本帧 = `hello` / `exit` / `error`。
- 同一沙箱可开多个终端标签，每个标签一个独立会话（容器内一个带真实 TTY 的 shell）；标签标题是「终端 N」，**N 是会话自己的登记号**（见下）。
- **标签序号跟会话身份绑定**：会话第一次被看到时按递增顺序分配一个序号（同一个沙箱内从 1 开始），之后不再变动——关掉中间的标签，其余标签的序号不重排，用户正在用的那个不会改名字。标签的**顺序**按会话的创建时间排（同一时刻创建的按会话标识排）。
- **会话表轻轮询**：面板可见时每 10 秒重新拉一次会话表（页面不可见时不拉），保证标签条与后端一致，关闭确认弹窗的「还在跑」判定也拿到较新的记录。**首次加载失败立刻弹失败 toast**；轮询失败静默（面板沿用旧数据），**连续 3 次失败弹一条失败 toast**，任一次成功即清零。
- **连接状态按会话存**：每个会话各记各的连接状态，状态栏只反映当前选中的会话；切换标签的瞬间不会还挂着上一个会话的「已连接」。
- **切沙箱不会串台**：详情加载与会话表刷新都带请求序号护栏，旧沙箱的在途响应回来时直接丢弃，不会覆盖新沙箱的头部或标签条。
- 断线后按退避节奏自动重连，**始终携带原 `session_id`**：服务端先回放环形缓冲再接实时流，现场不丢。页面刷新后（会话还在后端会话表里）点标签就能重新挂回原会话。
- **退避计数只在连接真的可用时才清零**：收到服务端的 `hello` 帧，或连接稳定存活超过 5 秒。握手成功不等于连上了——服务端握手后立刻关闭时，如果在 `onopen` 就清零计数，会退化成每 500ms 一次的连接风暴。
- 连续失败 10 次即停掉自动重连，界面显示「重连失败，点击重试」，由用户点「重试连接」手动触发。
- **取票失败单独一类**（策略纯函数在 `src/lib/terminal-connection.ts`，有单元测试）：浏览器发起的WebSocket 不能设请求头，握手靠一次性票据，**票据取不到 = 根本没连上**（不是「连上之后断了」）：
  - **状态文案单列**：「取不到终端票据：<原因>；N 秒后自动重连…」（不说「连接断开」）；
  - **令牌无效（401）→ 停掉自动重连**：重试多少次都是 401，白跑；状态栏写「令牌无效：<后端 detail>；请到设置抽屉更新令牌后重试」，等用户换完令牌点「重试连接」；
  - 其余失败（后端不可达 / 后端 500）按退避节奏重试，失败 toast 单独弹（来源 `terminal-connection`），**同一句不重复弹**（重连会反复取票据）。
- 后端服务重启会让全部会话失效：此时前端明确提示「终端会话已失效（后端服务已重启），请新建终端」，并停止重连。
- 服务端发来的 `error` 帧与「会话失效」都弹**失败 toast**（会话失效的文案是「终端会话已失效（后端服务已重启），请新建终端」），不会与状态栏的「已连接」混成一个文案。
- **终态也有反馈**：进程正常退出（退出码 0）弹**提示 toast**「终端会话已结束」；退出码非 0 弹**失败 toast**（文案带退出码）；**退出码未知**（后端没给退出码）同样弹**失败 toast**（文案「终端会话异常结束（退出码未知）」）；退避重连中弹**提示 toast**（文案带退避秒数）；重连到上限弹**失败 toast**「重连失败，点击重试」。同一会话的同一条提示不重复弹（服务端可能反复推同一个 error 帧）；连接恢复后清掉记录，下一轮失败能重新提示。

### 删除终端会话

- **一个标签就是一个会话**，没有第二份「后端保留的会话」列表。标签尾的 `×` 就是关闭会话：点一下弹确认弹窗，确认后发 `DELETE /api/terminal/sessions/{session_id}`；后端先完整关闭（终止宿主伪终端、容器内按会话标识清进程树）再删记录。
- **运行中的会话**：确认弹窗的标题是「关闭终端会话」，后果说明是「关闭会终止容器内该会话的进程树，终端现场不保留」，按钮文案是「关闭并移除」。
- **已退出的会话**：确认弹窗的标题是「移除终端会话记录」，后果说明是「会话已退出，只移除记录，容器内无残留进程」，按钮文案是「移除记录」。
- **确认口径保守**：标签状态与后端记录任一为 `running` 就算会话还在跑，一律按「运行中」处理（终止现场不可逆，宁可多问一句）。
- 已退出的会话**保留显示，不做自动清理**：后端不做空闲回收（无附着、长时间没人用的会话也不会被自动收走），已退出的会话一直列在标签条上，等用户手动删。
- 删除成功后标签消失；删除失败时展示后端 `detail` 原文。
- 删除**本体成功**与**列表刷新失败**分开提示：两者合进同一条**提示 toast（蓝色）**，不把已成功的删除说成失败；后端回报 `removed=false` 时提示「记录已不存在（可能已被删除）」，回报 `closed=false` 时提示关闭流程未走完。

### 端口转发

**界面位置**：沙箱详情抽屉（`page-sandbox-detail-dialog`）底部的「端口转发」区
（组件 `src/components/workbench/PortForwardPanel.tsx`）。

**两种形态的差异**（决策 C，2026-11-03；2026-11-04 改为五列表格）：

| 形态 | 渲染什么 | 不渲染什么 |
|---|---|---|
| **web 形态** | 一张说明卡（**「网页形态无法管理端口转发，请使用桌面端」**）+「安装桌面端」按钮（点开 `ModalShell` 安装指引弹窗） | **表格 / 新建 / 同步 / 编辑 / 删除等一切管理操作**——本机端口的监听由桌面端持有，在网页上建转发只会给出「建了却连不上」的半截功能；**面板自己不读任何数据**（转发记录由工作台经 props 送来，本机监听表不查）；**转发记录的读取在工作台层且仅桌面形态执行**（web 形态只刷详情） |
| **桌面形态** | 完整管理：**新建表单卡在上 + 五列表格在下**，表格行 = **后端记录 ∪ 本机监听的并集**，操作列三个 icon 按钮：**同步 / 编辑本机端口 / 删除转发** | — |

- **本机端口规则**（ADR 0014 第 4 节）：**默认 = 容器端口**、**可编辑**、**不可为空**（空值在表单层就拦掉）、**被占自动换空闲端口并显示实际值**、**允许 <1024**（低端口能不能绑由操作系统说了算：Windows 可绑、macOS 现代版可绑，**Linux 非 root 绑不了时由桌面端明确报错**，不静默失败）。
- **界面显示的必须是实际端口**：桌面端开启监听时返回的是**实际生效**的端口（用户输入的端口被占时会被换成空闲端口），**本机端口列**与提示里都显示它；没有本机监听时该列显示「—」。
- **本机端口只在桌面端存在**：后端的三条转发 REST 不带本机端口字段（链路两点化，后端宿主零端口）。
- **五列表格**（真 `<table>` 语义，样式手写、不引组件库）：
  - 列顺序 = **本机端口 | 容器端口 | 本地状态 | 容器状态 | 操作**；表头 `text-[11.5px] text-muted-foreground` 左对齐，两个状态列居中，操作列右对齐；端口两列 `font-mono text-[12.5px]`。
  - **行集合 = 后端记录 ∪ 本机监听**（按转发标识对齐）：
    - 有记录有监听 = 正常行；
    - 有记录无监听 = 正常行，本地状态点显示「未开启」**红点**；
    - **无记录有监听 = 孤儿行**（记录被删了、本机还在听）：照常渲染，容器端口取监听携带的值，容器状态点为红点，提示「无后端转发记录」。
  - 行样式：行间 `border-t border-border` 分隔，表头 `border-b`，**不做斑马纹**。
- **状态是纯圆点 + tooltip**（不再是「带文字的徽标」）：本地状态与容器状态两列各一个圆点（`size-[7px] rounded-full bg-current`，颜色类与圆点放同一元素）。
  - 本地状态四态（优先级：开启中 > 监听中 > 失败 > 未开启）：绿 = 监听中、黄（脉动）= 开启中、红 = 失败 / 未开启；**容器状态列不用脉动**（后端没有中间态，黄色语义预留不落地）：绿 = 可用、红 = 已停止 / 无后端记录。
  - 提示用 `src/components/ui/tooltip.tsx`（Base UI Tooltip，全库首例）：表格容器外包一层 `TooltipProvider`，触发器用 `render` 渲染成 `<span>`（**纯展示的圆点不得渲染成 button**），`delay={0}`；**提示文案同时作为圆点的 `aria-label`**（可访问名不能丢）：
    监听中 · `127.0.0.1:<实际端口>` / 正在开启本机监听… / 本机监听未开启 / 本机监听失败；后端转发可用 / 后端转发已停止 / 无后端转发记录。
  - **隧道致命失败不动摇监听中的绿色**：监听还活着就是绿的，失败原因走行内红字（`page-forward-item-error`）。
- **操作列三个单 icon 按钮**（全部 icon-only、`size-7`、都带 `aria-label` 与 `title`）：
  - **同步**（lucide `RefreshCw`，`page-forward-row-sync-button`）：两个方向按需执行——
    ① 后端可用 + 本机无监听 → `start_forward`（`localPort` 传 `null`：Rust 侧默认取容器端口、被占自动从 18000 段扫空闲，**前端不复刻扫描逻辑**）；
    ② 本机有监听 + 后端无记录 / 已停 → `create_forward`（后端幂等：复用旧记录并写回「可用」，记录已删则新建）。
    **记录重建后 `id` 可能与本机监听表里的旧标识不同**（隧道按转发标识寻址，旧标识已失效）→ **必须把本机监听迁到新 id**（`stop_forward` 旧 id → `start_forward` 新 id，端口不变）；id 相同（复用场景）则监听不动。
    迁移时旧标识 `stop_forward` 停不掉 → **中止迁移**（不对新 id 再开监听，避免端口冲突），弹提示「本机监听仍指向旧的转发标识，请删除该行后重新同步」，新记录行仍立即出现。
    两者已经一致时**不发任何请求**，只弹一条成功提示「转发已同步」。
  - **编辑**（lucide `Pencil`，`page-forward-row-edit-button`）：**仅本机监听中可用**（未开启时按钮禁用，提示「本机监听未开启，先同步或新建后再编辑」）。点开进入**行内编辑态**：本机端口单元格里换成一个小输入框 + 确认 / 取消两个小按钮，校验 1~65535、非空（红字就地，`role="alert"`）；确认执行「停旧监听 → 按新端口重开」，提示里说清**实际生效**的端口。
  - **删除**（lucide `Trash2`，`page-forward-row-delete-button`）：先 `stop_forward` 再 `DELETE /api/forwards/{id}`（顺序不能反：先收本机监听再删记录，不留僵尸监听）。**本机没在听的行不调 `stop_forward`**（停了也停不掉，只会误报一条「停止失败」）。`stop_forward` 失败**不中断**删除，弹失败提示「本机监听停止失败，该端口可能仍被占用；…」。**孤儿行（后端无记录）只调 `stop_forward`**（没有可删的记录，DELETE 跳过）。无确认弹窗。
- **本机监听的生命周期完全手动**：**没有任何自动开启 / 自动关闭**——轮询只把**数据**刷回来，绝不碰监听。监听只随「新建 / 删除 / 行内同步 / 行内编辑 / 连接配置变更重开」变化。
- **单条隧道断开不关监听**：监听器活到用户显式关闭为止，断开的只是那一条本机连接（桌面端上报连接级状态）。
- **桌面 IPC 的两处硬约束**（`src/lib/desktop-forward.ts`）：
  - **invoke 的拒绝值可能是裸字符串**（Rust 侧 `Result<_, String>`）：桥层统一收口成 `Error`，
    调用方只读 `exc.message` 就能拿到 Rust 侧的固定中文原文，**不写兜底文案分支**（会把原文顶掉）。
  - **事件订阅需要桌面壳的 `core:event` 权限**（`apps/desktop/src-tauri/capabilities/default.json`）：
    Tauri v2 对 `plugin:event|listen` 一律走 ACL 校验，缺了能力清单就订阅不上；
    订阅的 `target` 传**对象** `{"kind":"Any"}`（Rust 侧的 `EventTarget` 是带标签的枚举）。
    订阅失败会打一条 `console.warn`（降级标记），不静默。
- **改连接配置后自动重启已开启的监听**（设置抽屉「保存配置」，**仅桌面形态**）：
  令牌与后端基址是**开启监听那一刻的快照**，不重启的话旧监听仍拿着旧凭据（隧道会以 `1008` 收场）。
  口径：`forward_listeners` 拿当前状态 → 逐个 `stop_forward` → 用新凭据 `start_forward` **同端口**重开；
  **逐条独立**，一条失败弹一条失败提示，不中断其余条与保存流程。
- **校验红字就地展示**（`role="alert"`，留在抽屉里）；操作结果走右上角 toast，来源标识固定 `port-forward`。
- 纯逻辑（端口校验、状态文案、圆点配色、tooltip 文案、本机地址拼接）在 `src/lib/port-forward.ts`，有单元测试；
  桌面 IPC 桥在 `src/lib/desktop-forward.ts`，有单元测试。

### 设置（代理设置 + 启动模板 + 连接配置）

设置是抽屉（侧边栏底部的入口文案是「设置」，图标是 lucide `Settings`）。抽屉分三区：

**第一区：代理设置**。直接展示六个字段：容器运行状态、健康状态、端口连通、缓存目录占用、证书就绪状态与代理访问地址。读状态失败与重启失败都弹**失败 toast**；点「重启代理」后弹一条**提示 toast（蓝色）**「代理正在重启，重启期间依赖镜像拉取会失败，属预期行为」（toast 5 秒后消失；按钮自身的加载态是「旋转图标 + 正在重启」）；重启结果按 `restarted` / `ca_changed` / `ca_reinstalled` / `reinstalled_users` / `failed_users` 如实展示，不把未修复报成已修复。**「刷新状态」与「重启代理」两个按钮在第一区里**（状态字段区之后、右对齐）：它们只管代理，挨着代理设置区更贴切；因此**抽屉不再有全局页脚**（两个按钮的 `data-testid` 与行为一个没变）。

**第二区：启动模板**（`src/components/workbench/TemplateManager.tsx`）：

- 列表每行给**模板名 + 最近更新时间**，另有「重命名」与「删除」两个行内按钮；列表为空时给一句空态说明，列表读不到时弹失败 toast（来源 `settings-template`）并在抽屉里留一行就地环境状态说明。
- **行内重命名**：该行变成输入框，**回车提交 / Esc 取消**，**空名禁提交**（按钮禁用 + 就地红字）；成功后弹成功 toast（来源 `settings-template`）。模板**标识不变**（标识由服务端生成，与名称解耦）。
- **删除**走 `ModalShell` 确认弹窗（面板宽 400px），文案写明**只删模板、不影响已创建的沙箱**（沙箱一旦创建就不再依赖模板）；删除失败弹失败 toast，弹窗留在原地可以重试。

**第三区：连接配置**（详见上方「连接配置」一节）。后端地址 + 访问令牌 + 「测试连接」+「保存配置」；结果按 toast 规范反馈（来源 `connection`）。**桌面形态下「保存配置」还会把已开启的本机监听用新凭据重启一遍**（端口不变；失败逐条弹失败提示，来源 `port-forward`，不中断保存流程）——令牌与基址是开启监听那一刻的快照，不重启旧监听会拿着旧凭据收场。

**重复元素的定位方式**：沙箱列表项与终端标签在同一个页面上会重复出现，标识本身保持一致，另带一个属性用于区分：

```ts
// 列表项：按沙箱名筛出那一项
const item = page.getByTestId('page-sandbox-list-item').filter({ hasText: 'demo-01' });

// 终端标签：按会话标识区分
const tab = page.locator('[data-testid="page-sandbox-detail-terminal-tab"][data-session-id="abc123"]');
```

列表项额外带 `data-sandbox-name` 与 `data-sandbox-state`，终端标签与终端表面额外带 `data-session-id`（终端标签还带 `data-active`）。

toast 条目另带 `data-toast-kind` 区分类型（`success` / `error` / `info`），可选再带 `data-toast-source` 区分来源：

```ts
// 失败 toast：右上角唯一一条
const failed = page.locator('[data-testid="page-toast-item"][data-toast-kind="error"]');

// 只认「沙箱详情读取失败」这一条：同页上残留的无关失败提示不算数
const detailFailed = page.locator(
  '[data-testid="page-toast-item"][data-toast-kind="error"][data-toast-source="sandbox-detail"]',
);
```

`data-toast-source` 的取值（没写的 toast 不带这个属性）：

| 来源 | 什么时候弹 |
|---|---|
| `sandbox-list` | 沙箱列表读取失败（首次加载 / 连续 3 次轮询失败） |
| `sandbox-detail` | 沙箱详情读取失败（手动刷新立即弹）；**沙箱详情 + 转发记录的合并轮询**连续 3 次失败弹一条；**转发列表的非 silent 首读失败**（打开抽屉那一拍）同样用这个来源 |
| `sandbox-lifecycle` | 启动 / 停止沙箱的结果 |
| `sandbox-delete` | 删除沙箱的结果 |
| `terminal-sessions` | 终端会话表读取失败、关闭会话的副作用提示 |
| `terminal-status` | 终端会话状态变化（失效 / 报错 / 退出 / 重连） |
| `sandbox-create` | 新建沙箱抽屉里的镜像列表读取失败、提交失败 |
| `sandbox-template` | 新建沙箱抽屉里的模板列表读取失败、保存模板的结果、模板里有解析不了的挂载声明 |
| `proxy-settings` | 代理状态读取失败、代理重启结果 |
| `file-browser` | 运行期文件浏览：上传 / 下载结果（失败时是后端 `detail` 原文）、覆盖确认的「已跳过」、取消上传 |
| `settings-template` | 设置抽屉里的模板列表读取失败、重命名与删除模板的结果 |
| `connection` | 连接配置相关的操作结果（引导面板的「保存并连接」、设置抽屉的「测试连接」与「保存配置」） |
| `terminal-connection` | 终端连接失败（一次性票据取不到 / 连不上） |
| `port-forward` | 端口转发的操作结果（新建转发、同步转发、编辑本机端口、删除转发、开启本机监听失败、隧道连接级失败） |

toast 5 秒后自动消失，断言要放在动作之后立即执行。

**同页双挂载的标识**（页面上同时存在多个，取第一个即可）：

- `page-sandbox-list-create-button`：侧栏顶部的「新建沙箱」按钮与右侧空态引导块里的「新建沙箱」按钮各挂一个。用 `page.getByTestId('page-sandbox-list-create-button').first().click()` 即可。
- `page-sandbox-detail-dialog-*`（状态 / 镜像）：这两个字段在工作区头部也有同名元素（`page-sandbox-detail-state` / `-image`），抽屉里的版本加了 `dialog-` 前缀，两者不会撞名。

## 接口一览

| 方法 | 路径 | 前端用途 |
|---|---|---|
| GET | `/api/health` | 侧栏底部的健康自检；设置抽屉「测试连接」也用它 |
| GET | `/api/sandboxes` | 侧栏沙箱列表（裸数组） |
| POST | `/api/sandboxes` | 新建沙箱（带 `image_source=host`） |
| GET | `/api/sandboxes/{name}` | 工作区摘要与详情抽屉 |
| POST | `/api/sandboxes/{name}/start` | 启动 |
| POST | `/api/sandboxes/{name}/stop` | 停止（带 `stop_dependencies`） |
| GET | `/api/sandboxes/{name}/reclaim` | 删除前的回收清单（控制台页面已不再调用，保留给脚本与将来的清单预览）|
| DELETE | `/api/sandboxes/{name}` | 删除 |
| GET | `/api/images` | 新建抽屉的镜像选择器（裸数组） |
| GET | `/api/proxy/status` | 代理设置抽屉 |
| POST | `/api/proxy/restart` | 重启代理 |
| GET | `/api/templates` | 启动模板列表（裸数组；新建抽屉的模板选择器与设置抽屉的模板管理区共用） |
| POST | `/api/templates` | 保存为模板（名称 + 配置体） |
| POST | `/api/templates/{id}/rename` | 重命名模板（只改名称，标识不变） |
| DELETE | `/api/templates/{id}` | 删除模板 |
| POST | `/api/terminal/sessions` | 新建终端会话 |
| GET | `/api/terminal/sessions?sandbox=` | 终端标签条的数据源（裸数组） |
| DELETE | `/api/terminal/sessions/{session_id}` | 删除会话（运行中＝先关后删，已退出＝走一遍收尾再删） |
| WS | `/api/terminal/sessions/{session_id}` | 终端帧桥接（握手带一次性票据 `?ticket=`）|
| POST | `/api/auth/ticket` | 换一次性终端票据（每次连接 / 重连前现取，不缓存）|
| GET | `/api/forwards?sandbox=` | 端口转发列表（裸数组；**不含本机端口**——本机端口由桌面端持有）|
| POST | `/api/forwards` | 建立端口转发（入参 `{sandbox, port}`，`port` 是**容器端口**）|
| DELETE | `/api/forwards/{id}` | 停止端口转发（删转发容器 + 删记录）|
| WS | `/api/forward/tunnel/{forward_id}` | 转发隧道（**桌面端 Rust 侧**握手带 `Authorization: Bearer`，浏览器不走这条）|

错误消息一律直接展示后端 `{"detail": "中文消息"}` 里的 `detail`，前端不另造说法。
